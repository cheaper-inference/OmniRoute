> ഏത് റൂട്ടുകളിലേക്കും റെസ്പോൺസ് പാതകളിലേക്കും ഹുക്കുകൾ എത്തുന്നു എന്നത്, ലയിപ്പിക്കപ്പെട്ട ഡിസേബിൾ ഹെഡറുകൾ (#16412), ഇഞ്ചക്ഷൻ
> ബ്ലോക്ക് മോഡ് ഒരു നിർബന്ധ അതിർത്തിയായി (#16413), കൂടാതെ പോസ്റ്റ്-കോളിന് മുമ്പ് ഒരു റെസ്പോൺസിനെ എന്താണ് കാണുന്നത് എന്നത്)

ഗാർഡ്റെയിലുകൾ OmniRoute-നും അപ്സ്ട്രീം പ്രൊവൈഡറുകൾക്കും ഇടയിലുള്ള അതിർത്തിയിൽ സുരക്ഷാ, നയ,
ഉള്ളടക്ക പരിവർത്തനങ്ങൾ എന്നിവ നടപ്പിലാക്കുന്നു. ഓരോ ഗാർഡ്റെയിലിനും റിക്വസ്റ്റ് പേലോഡുകൾ (`preCall`),
അപ്സ്ട്രീം റെസ്പോൺസുകൾ (`postCall`) എന്നിവ പരിശോധിക്കാനും (ഓപ്ഷനലായി നിരസിക്കാനും, ട്രാൻസ്ഫോം ചെയ്യാനും,
അനോട്ടേറ്റ് ചെയ്യാനും) കഴിയും.

സിസ്റ്റം **ഫെയിൽ-ഓപ്പൺ** ആണ്: ഒരു ഗാർഡ്റെയിൽ എക്സിക്യൂട്ട് ചെയ്യുന്നതിനിടയിൽ ത്രോ ചെയ്താൽ,
റിക്വസ്റ്റ് പരാജയപ്പെടുത്തുന്നതിന് പകരം റെജിസ്ട്രി എറർ രേഖപ്പെടുത്തുകയും അടുത്ത ഗാർഡ്റെയിലിലൂടെ
തുടരുകയും ചെയ്യും. ബ്ലോക്കിംഗ് ഒരു വ്യക്തമായ തീരുമാനമാണ് (`block: true`), ഒരിക്കലും അബദ്ധമല്ല.
ഒരേയൊരു അപവാദം അബോർട്ട് ചെയ്ത റിക്വസ്റ്റാണ്: കോളറുടെ `signal` അബോർട്ട് ചെയ്യുമ്പോൾ,
ത്രോ ചെയ്യുന്ന ഗാർഡ്റെയിൽ ഒഴിവാക്കപ്പെടുന്നതിന് പകരം ഹുക്ക് റണ്ണിനെ നിരസിക്കുന്നു.

എല്ലാ റൂട്ടിലോ എല്ലാ റെസ്പോൺസിലോ ഹുക്കുകൾ പ്രവർത്തിക്കുന്ന**ില്ല**. ഒരു ഗാർഡ്റെയിലിനെ
സെക്യൂരിറ്റി നിയന്ത്രണമായി ആശ്രയിക്കുന്നതിന് മുമ്പ്
[കവറേജും പരിമിതികളും](#coverage-and-limits) വായിക്കുക.

## ബിൽറ്റ്-ഇൻ ഗാർഡ്റെയിലുകൾ

ഇംപോർട്ട് ചെയ്യുമ്പോൾ റെജിസ്ട്രി ആറ് ഗാർഡ്റെയിലുകൾ പ്രായോറിറ്റി ഓർഡറിൽ ഓട്ടോ-ലോഡ് ചെയ്യുന്നു
(`registry.ts` → `registerDefaultGuardrails()` കാണുക):

| പ്രായോറിറ്റി | പേര്                | ഘട്ടം(ങ്ങൾ)    | ഫയൽ                   |
| ------------ | ------------------- | -------------- | --------------------- |
| `5`          | `vision-bridge`     | `preCall`      | `visionBridge.ts`     |
| `6`          | `audio-bridge`      | `preCall`      | `audioBridge.ts`      |
| `7`          | `video-bridge`      | `preCall`      | `videoBridge.ts`      |
| `10`         | `pii-masker`        | `pre` + `post` | `piiMasker.ts`        |
| `20`         | `prompt-injection`  | `preCall`      | `promptInjection.ts`  |
| `95`         | `credential-masker` | `pre` + `post` | `credentialMasker.ts` |

കുറഞ്ഞ പ്രായോറിറ്റി നമ്പറുകൾ **ആദ്യം** പ്രവർത്തിക്കുന്നു.

### വിഷൻ ബ്രിഡ്ജ് (`visionBridge.ts`) — മൊഡാലിറ്റി ബ്രിഡ്ജ് PR-1

GLM 5.3 ബേസ് മോഡലിനും `glm-5.3-{low,high,max}`-നും വ്യക്തമായ
`supportsVision:false` റെജിസ്ട്രി/സ്പെക് മെറ്റാഡാറ്റയുണ്ട്. GLM 5.3 Flash വേരിയന്റുകൾ
നേറ്റീവ്-വിഷൻ മോഡലുകളായി തുടരുന്നു. Claude Code-ന്റെ `/v1/messages` റൂട്ട്
Claude-to-OpenAI വിവർത്തനത്തിന് **മുമ്പ്** പങ്കിട്ട `handleChat` പ്രീ-കോൾ ഗാർഡ്റെയിൽ
ചെയിനിൽ പ്രവേശിക്കുന്നു; നെസ്റ്റഡ് `Read` ടൂൾ-റിസൾട്ട് ഇമേജുകൾ, ആ വിവർത്തനം അവയെ
OpenAI `image_url` ഉള്ളടക്കത്തിലേക്ക് ഉയർത്തുന്നതിന് മുമ്പ് വിവരിക്കപ്പെടുകയോ
കൈകാര്യം ചെയ്യപ്പെടുകയോ വേണം (#17069).

**നോൺ-വിഷൻ മോഡലുകളെ** ലക്ഷ്യമിട്ടുള്ള ഇമേജുകൾ ഉൾക്കൊള്ളുന്ന റിക്വസ്റ്റുകളെ ഇന്റർസെപ്റ്റ്
ചെയ്യുകയും, മുഴുവൻ റിക്വസ്റ്റിനെയും വിഷൻ-ശക്തമായ ഒരു മോഡലിലേക്ക് റീറൂട്ട് ചെയ്യുകയോ,
അല്ലെങ്കിൽ അപ്സ്ട്രീം കോളിന് മുമ്പ് കോൺഫിഗർ ചെയ്യാവുന്ന ഒരു വിഷൻ മോഡൽ നിർമ്മിക്കുന്ന
ടെക്സ്റ്റ് വിവരണങ്ങളാൽ ഇമേജ് ഭാഗങ്ങളെ മാറ്റിസ്ഥാപിക്കുകയോ ചെയ്യുന്നു. ഇത് ടെക്സ്റ്റ്-ഓൺലി
പ്രൊവൈഡറുകളെ മൾട്ടിമോഡൽ പേലോഡുകൾ സുതാര്യമായി കൈകാര്യം ചെയ്യാൻ അനുവദിക്കുന്നു.

ഫ്ലോ:

1. ലക്ഷ്യ മോഡൽ ഇതിനകം വിഷനെ പിന്തുണക്കുന്നുണ്ടെങ്കിൽ ഒഴിവാക്കുക (അത്
   ഫോഴ്സ്ഡ്-ബ്രിഡ്ജ് ലിസ്റ്റായ `isVisionBridgeForcedModel`-ൽ ദൃശ്യമാകുന്നില്ലെങ്കിൽ).
2. `extractImageParts(messages)` (`visionBridgeHelpers.ts`) വഴി ഇമേജ് ഭാഗങ്ങൾ
   എക്സ്ട്രാക്റ്റ് ചെയ്യുക, അത് `open-sse/utils/mediaParts.ts`-ലെ **യൂണിഫൈഡ് മീഡിയ
   ഡിറ്റക്ടർ** ആയ `detectMediaParts()`-ലേക്ക് ഡെലിഗേറ്റ് ചെയ്യുന്നു — കോംബോ കംപാറ്റിബിലിറ്റി
   ഫിൽട്ടറുമായി പങ്കിടുന്ന ഏക സത്യ ഉറവിടം.
   എക്സ്ട്രാക്ഷൻ `replaceImageParts`-ന് തിരികെ സ്പ്ലൈസ് ചെയ്യാൻ കഴിയുന്ന ഷേപ്പുകളിലേക്ക്
   അലോലിസ്റ്റ് ചെയ്യപ്പെട്ടിരിക്കുന്നു (എക്സ്ട്രാക്റ്റ്↔റീപ്ലേസ് കരാർ): OpenAI `image_url`,
   Anthropic base64 `source.type:"base64"`, Anthropic URL `source.type:"url"`,
   Responses API `input_image` എന്നിവ. Claude Code `tool_result.content`-ലും
   Responses ടൂൾ ഔട്ട്പുട്ടുകളിലും നെസ്റ്റ് ചെയ്യപ്പെട്ട പൊരുത്തപ്പെടുന്ന ഇമേജുകളും
   എക്സ്ട്രാക്റ്റ് ചെയ്യപ്പെടുകയും അവയുടെ യഥാർത്ഥ പാതകളിൽ മാറ്റിസ്ഥാപിക്കപ്പെടുകയും ചെയ്യുന്നു;
   ഇൻഡിക്കേറ്റർ-ഓൺലി ഷേപ്പുകൾ കോംബോ-ഫിൽട്ടർ മെറ്റീരിയലാണ്, അവ എക്സ്ട്രാക്റ്റ്
   ചെയ്യപ്പെടുന്നില്ല.
   ഒന്നും കണ്ടെത്തിയില്ലെങ്കിൽ ഒഴിവാക്കുക.
3. `resolveVisionBridgeRuntimeSettings()` (`src/shared/constants/modalityBridgeDefaults.ts`)
   വഴി റൺടൈം കോൺഫിഗ് റിസോൾവ് ചെയ്യുക: പുതിയ `modalityBridge*` സെറ്റിംഗ്സ് കീകൾക്ക്
   മുൻഗണന ലഭിക്കുന്നു; ലെഗസി `visionBridge*` കീകൾ **ഒരു-സൈക്കിൾ ഫോൾബാക്ക്** ആയി
   തുടരുന്നു (റോൾബാക്ക് വിൻഡോ). ബ്രിഡ്ജ് ഡിസേബിൾ ചെയ്തിരിക്കുമ്പോൾ ഏത് മീഡിയ
   ട്രാവേഴ്സലിനും മുമ്പ് ഒഴിവാക്കുക.
4. മോഡ് സെലക്ടർ (`modalityBridgeVisionMode`, താഴെയുള്ള ടേബിൾ കാണുക) റീറൂട്ട് vs
   ഡിസ്ക്രൈബ് തീരുമാനിക്കുന്നു. റീറൂട്ട് `model` മാത്രം മാറ്റിയ `modifiedPayload` തിരികെ
   നൽകുന്നു, കൂടാതെ മെറ്റ `{ rerouted, fromModel, toModel, imagesKept }` ഉം.
5. ഡിസ്ക്രൈബ് പാത: ഇമേജുകൾ `maxImages`-ൽ പരിമിതപ്പെടുത്തുക, ടാസ്ക്-അവേർ പ്രോംപ്റ്റ്
   രചിക്കുക, ഡിസ്ക്രൈബ് കാഷെ പരിശോധിക്കുക, വിഷൻ മോഡലിനെ **സമാന്തരമായി**
   (`Promise.allSettled`) വിളിക്കുക, അവയുടെ സ്ഥാനത്ത് `[Image N]: <description>`
   ടെക്സ്റ്റ് ഭാഗങ്ങൾ ഇൻജക്ട് ചെയ്യുക. പരാജയപ്പെട്ട ഒരു ഡിസ്ക്രൈബ് `null` നൽകുന്നു:
   അജ്ഞാത/വിഷൻ-ശക്തമായ ലക്ഷ്യങ്ങൾക്കായി റോ ഇമേജ് സംരക്ഷിക്കപ്പെടുന്നു (#4012), എന്നാൽ
   ഒരു **സ്ഥിരീകരിച്ച ടെക്സ്റ്റ്-ഓൺലി ഡയറക്ട് ലക്ഷ്യത്തിനോ** സീറോ-വിഷൻ കോംബോയ്ക്കോ
   ഓരോ വിവരിക്കപ്പെടാത്ത ഇമേജിനും — ഭാഗിക പരാജയങ്ങളും ഡിസ്ക്രൈബ്-കോൾ പരിധിക്ക്
   അപ്പുറത്തുള്ള ഇമേജുകളും ഉൾപ്പെടെ — വ്യക്തമായ `(unavailable — no vision-capable provider connected)`
   ടെക്സ്റ്റ് സ്റ്റബ് ലഭിക്കുന്നു (#17069). നിലവിലുള്ള എല്ലാം-പരാജയപ്പെട്ട കോംബോ
   ഡിസ്ക്രൈബ് ഫോൾബാക്ക് നിലനിൽക്കുന്നു (#8430).
6. `modifiedPayload` + മെറ്റ (`imagesProcessed`, `descriptions`,
   `processingTimeMs`, `visionModel`) തിരികെ നൽകുക.

#### API-കീ സ്കോപ്പ് (`visionBridgeKeyScope.ts`)

കോളറുടെ API കീ `allowedConnections`, ക്വോട്ട പൂളുകൾ (`allowedQuotas`) അല്ലെങ്കിൽ മോഡലുകൾ (`allowedModels` / `blockedModels` / `modelAccessMode: "restricted"` / `disableNonPublicModels`) എന്നിവ പരിമിതപ്പെടുത്തുമ്പോൾ, കീയ്ക്ക് ഉപയോഗിക്കാവുന്ന കണക്ഷനുകളിൽ, കീയ്ക്ക് ഉപയോഗിക്കാവുന്ന റീറൂട്ട്, describe മോഡലുകൾ മാത്രമേ ബ്രിഡ്ജ് തിരഞ്ഞെടുക്കൂ. തുടർന്ന് describe കോൾ എല്ലായ്പ്പോഴും `x-omniroute-self-loop-key-id` ഹെഡറോടുകൂടി OmniRoute സെൽഫ്-ലൂപ്പ് വഴിയാണ് പോകുന്നത്, അതിനാൽ സ്വീകരിക്കുന്ന ചാറ്റ് റിക്വസ്റ്റ് ആ കീയുടെ കണക്ഷൻ, മോഡൽ പോളിസി വീണ്ടും നടപ്പിലാക്കുന്നു. `enforceApiKeyPolicy()` ആ ഹെഡർ സെൽഫ്-ലൂപ്പ് ബിയററിനൊപ്പം മാത്രമേ അംഗീകരിക്കൂ, അതിനാൽ അതിന് ആക്സസ് കുറയ്ക്കാൻ മാത്രമേ കഴിയൂ, റെസോൾവ് ചെയ്യാത്ത ഒരു id നിരസിക്കപ്പെടുന്നു.

കീയ്ക്ക് ഒരു വിഷൻ മോഡലും അനുവദനീയമല്ലെങ്കിൽ, ഒരു **സ്ഥിരീകരിച്ച ടെക്സ്റ്റ്-ഓൺലി ടാർഗെറ്റ്** ഇമേജ് ബൈറ്റുകൾ അസമർത്ഥമായ അപ്സ്ട്രീമിലേക്ക് ഫോർവേഡ് ചെയ്യുന്നതിന് പകരം വ്യക്തമായ ഒരു HTTP 400 ഉപയോഗിച്ച് ഇമേജ് റിക്വസ്റ്റ് ലോക്കലായി നിരസിക്കുന്നു (#17069). അജ്ഞാതമോ നേറ്റീവ് വിഷൻ കപ്പാബിലിറ്റിയോ ഉള്ള ടാർഗെറ്റുകൾക്ക്, describe പാത്ത് മുമ്പത്തെ fail-open പെരുമാറ്റം നിലനിർത്തുന്നു (മെറ്റ `{ skipped: true, reason: "no_permitted_vision_model" }`). കീ ഇല്ലാത്ത റിക്വസ്റ്റുകളും, ഈ നിയന്ത്രണങ്ങളില്ലാത്ത കീകളും, മുമ്പത്തെപ്പോലെ തന്നെ പെരുമാറുന്നു.

#### ടാസ്ക്-അവേർ describe പ്രോംപ്റ്റ് (`modalityBridgeVisionTaskAware`)

ഡിഫോൾട്ട് **true**. `composeVisionPrompt()` (`visionBridgeHelpers.ts`) **അവസാന ഉപയോക്തൃ സന്ദേശത്തിന്റെ** ടെക്സ്റ്റ് (500 അക്ഷരങ്ങളിൽ ചെറുപ്പിച്ചത്) ബേസ് describe പ്രോംപ്റ്റിനോട് ചേർക്കുന്നു, ഉപയോക്താവ് യഥാർത്ഥത്തിൽ ചോദിച്ചതിലേക്ക് വിവരണത്തെ നയിക്കുകയും (codex-vision-proxy പാറ്റേൺ) ദൃശ്യമാകുന്ന ടെക്സ്റ്റ് ട്രാൻസ്ക്രൈബ് ചെയ്യാൻ വിഷൻ മോഡലിനോട് ആവശ്യപ്പെടുകയും ചെയ്യുന്നു. ഫ്ലാഗ് ഓഫ് ആണെങ്കിൽ — അല്ലെങ്കിൽ ഉപയോക്തൃ ടെക്സ്റ്റ് ഇല്ലെങ്കിൽ — ബേസ് പ്രോംപ്റ്റ് മാറ്റമില്ലാതെ ഉപയോഗിക്കുന്നു.

describe സെൽഫ്-ലൂപ്പിന്റെ സ്വന്തം OpenAI-കംപാറ്റിബിൾ റിക്വസ്റ്റ് (`visionBridgeHelpers.ts`-ലെ `callVisionModelSingle()`) എല്ലായ്പ്പോഴും `image_url.detail: "high"` ആവശ്യപ്പെടുന്നു — നിബന്ധനകളൊന്നുമില്ലാതെ, ഓരോ കോളർ/പ്രൊവൈഡർക്കും, ഒരു ക്ലയന്റ് സിഗ്നലിനെയും ആശ്രയിക്കാതെ. ഈ പ്രോംപ്റ്റ് ആവശ്യപ്പെടുന്ന ടെക്സ്റ്റ്-ട്രാൻസ്ക്രിപ്ഷൻ ടാസ്കിന് തന്നെ ലോ-ഡീറ്റെയിൽ സാമ്പിളിംഗ് OCR കൃത്യത കുറയ്ക്കുന്നു, അതിനാൽ ഒറിജിനൽ ഇൻബൗണ്ട് റിക്വസ്റ്റ് ഏത് ഡീറ്റെയിൽ ലെവൽ ഉപയോഗിച്ചാലും describe കോൾ തന്നെ എല്ലായ്പ്പോഴും ഹൈ ഡീറ്റെയിൽ ആവശ്യപ്പെടുന്നു. ഇത് ഇന്റേണൽ describe റിക്വസ്റ്റ് ബോഡിയെ മാത്രമേ ബാധിക്കൂ; പ്രൈമറി റിക്വസ്റ്റിൽ OmniRoute കോളറുടെ സ്വന്തം `image_url.detail` എങ്ങനെ ഫോർവേഡ് ചെയ്യുന്നു എന്നത് ഇത് മാറ്റുന്നില്ല — ആ ഡിഫോൾട്ട് പ്രത്യേകമായി, കണ്ടെത്തിയ OpenCode ക്ലയന്റുകൾക്ക് മാത്രമായി, `defaultImageDetail()`-ൽ (`open-sse/handlers/chatCore/upstreamBody.ts`) പ്രയോഗിക്കുന്നു. describe സെൽഫ്-ലൂപ്പിന്റെ Anthropic വയർ-ഫോർമാറ്റ് ബ്രാഞ്ചിന് `detail` ഫീൽഡ് ഇല്ല, രണ്ട് ഡിഫോൾട്ടുകളാൽയും അത് ബാധിക്കപ്പെടുന്നില്ല.

#### Describe ഔട്ട്പുട്ട് ക്യാപ്പ് (`modalityBridgeVisionMaxChars`)

| കീ                             | ഡിഫോൾട്ട് | റേഞ്ച്                   |
| ------------------------------ | --------- | ------------------------ |
| `modalityBridgeVisionMaxChars` | `0`       | `0` അല്ലെങ്കിൽ 100–50000 |

`0` (ഡിഫോൾട്ട്) എന്നാൽ **ക്യാപ്പ് ഇല്ല** — `callVisionModel()` തിരികെ നൽകുന്ന വിവരണം മാറ്റമില്ലാതെ കടത്തിവിടുന്നു, നിലവിലെ പെരുമാറ്റം നിലനിർത്തുന്നു. 100–50000 റേഞ്ചിലെ ഏത് മൂല്യവും `[Image N]: <description>` ആയി തിരികെ ചേർക്കുന്നതിന് മുമ്പ് `…` സഫിക്സോടെ വിവരണത്തെ ചെറുപ്പിക്കുന്നു (`src/lib/guardrails/visionBridge.ts`-ലെ `VisionBridgeGuardrail.preCall()`). ഡൗൺസ്ട്രീം മോഡലിന് പൂർണ്ണ ട്രാൻസ്ക്രിപ്ഷൻ ആവശ്യമായ ഡീറ്റെയിൽ-ഹെവി OCR ടാസ്കുകൾക്ക് ഇത് ഉയർത്തുക; സംസാരം കൂടുതലുള്ള വിഷൻ മോഡലുകളിൽ ടോക്കൺ ഉപയോഗം പരിമിതപ്പെടുത്താൻ കുറയ്ക്കുക. ഡാഷ്ബോർഡ് ഫീൽഡ് Vision ടാബിന്റെ Advanced പാനലിലാണ് (`ModalityBridgeVisionTab.tsx`-ലെ `modality-bridge-max-chars`), 1 നും 99 നും ഇടയിലുള്ള ഏത് മൂല്യത്തെയും 100 ഫ്ലോറിലേക്ക് ക്ലാംപ് ചെയ്യുന്നു, വ്യക്തമായ `0` മാറ്റമില്ലാതെ നിലനിർത്തുന്നു — `0` സ്വന്തംനിലയിൽ സാധുവായ ഒരു Zod മൂല്യമാണ് (`z.union([z.literal(0), z.number().int().min(100).max(50000)])`), വെറും "സെറ്റ് ചെയ്യാത്ത" ഡിഫോൾട്ട് മാത്രമല്ല.

#### Describe ക്യാഷ് (`modalityBridge/bridgeCache.ts`)

describe ഔട്ട്പുട്ടുകൾക്കുള്ള ഇൻ-മെമ്മറി LRU + TTL ക്യാഷ്, പ്രോസസ്-വ്യാപകമായി പങ്കിടപ്പെടുന്നു. കീ = `sha256(imageRef + composedPrompt + configuredBridgeModel)`, ലെങ്ത്-പ്രിഫിക്സ് ഫ്രെയിമിംഗോടെ (ഫീൽഡ്-ബൗണ്ടറി കൊളിഷനുകളില്ല). മോഡൽ കോമ്പോണന്റ് **കോൺഫിഗർ ചെയ്ത** ബ്രിഡ്ജ് മോഡലാണ്, യഥാർത്ഥത്തിൽ മറുപടി നൽകിയ മോഡലല്ല — `callVisionModel` ഇന്റേണലായി ഫോൾബാക്ക് ചെയ്യാം, ഓരോ ശ്രമത്തിനും വെവ്വേറെ കീ ചെയ്താൽ ക്യാഷ് ഫ്രാഗ്മെന്റ് ആകും. പരാജയപ്പെട്ട describe-കൾ ഒരിക്കലും ക്യാഷ് ചെയ്യുന്നില്ല. ക്രമീകരണങ്ങൾ:

| കീ                              | ഡിഫോൾട്ട് | റേഞ്ച്  |
| ------------------------------- | --------- | ------- |
| `modalityBridgeCacheEnabled`    | `true`    | —       |
| `modalityBridgeCacheTtlMinutes` | `60`      | 1–1440  |

മോഡൽ ടെക്സ്റ്റ് ട്രാൻസ്ക്രിപ്റ്റുകളുമായി തുടരുകയും ചെയ്യുന്നു.

ഫ്ലോ:

1. `getResolvedModelCapabilities()` വഴി `supportsAudio` പരിഹരിക്കുക. വ്യക്തമായ provider-registry മെറ്റാഡാറ്റയ്ക്ക് മുൻഗണന ലഭിക്കും, പിന്നീട് സ്റ്റാറ്റിക് മോഡൽ മെറ്റാഡാറ്റ, തുടർന്ന് സമന്വയിപ്പിച്ച `modalities_input`. `audio` ഇല്ലാത്ത പ്രഖ്യാപിച്ച ഇൻപുട്ട് ലിസ്റ്റ് `false` ആണ്; കാപബിലിറ്റി തെളിവുകളൊന്നുമില്ലെങ്കിൽ `null` ആയി തുടരും. `false`, `null` എന്നിവ രണ്ടും കൺസർവേറ്റീവ് ബ്രിഡ്ജ് സജീവമാക്കും, അതേസമയം `true` അതിനെ മറികടക്കും.
2. `modalityBridgeAudio*` ക്രമീകരണങ്ങൾ പരിഹരിച്ച്, പങ്കിട്ട `detectMediaParts()` ഡിറ്റക്ടർ വഴി ഓരോ സന്ദേശത്തിലും നിന്ന് സ്പ്ലൈസ് ചെയ്യാവുന്ന ടോപ്പ്-ലെവൽ ഓഡിയോ ഭാഗങ്ങൾ എക്സ്ട്രാക്ട് ചെയ്യുക. പിന്തുണയ്ക്കുന്ന വയർ ഷേപ്പുകൾ OpenAI `input_audio`, `audio_url`, `source.media_type: "audio/*"` എന്നിവയാണ്. നെസ്റ്റഡ് ഓഡിയോ റൂട്ടിംഗിനായി കണ്ടെത്തും, പക്ഷേ സ്പ്ലൈസ് പാത്ത് അതിനെ നീക്കം ചെയ്യില്ല. ജോലി `modalityBridgeAudioMaxClips` കൊണ്ട് പരിമിതപ്പെടുത്തിയിരിക്കുന്നു; പിന്നീടുള്ള ഭാഗങ്ങൾ മാറ്റമില്ലാതെ നിലനിൽക്കും.
3. കോൺഫിഗർ ചെയ്ത ഒരു `provider/model` പാലിക്കുക, അല്ലെങ്കിൽ `selectAudioBridgeModel()` സ്ഥിരമായ കാറ്റലോഗ് ക്രമത്തിൽ `AUDIO_TRANSCRIPTION_PROVIDERS` സഞ്ചരിച്ച്, ഉപയോഗയോഗ്യമായ സജീവ പ്രൊവൈഡർ ക്രെഡൻഷ്യൽ ഉള്ള ആദ്യ മോഡൽ തിരഞ്ഞെടുക്കാൻ അനുവദിക്കുക.
4. `callAudioTranscription()` base64/data-URI ഓഡിയോയെ ഒരു multipart `file` ആക്കി മാറ്റുന്നു, അല്ലെങ്കിൽ DNS പിന്നിംഗും 25 MB പരിധിയും ഉള്ള public-only ഔട്ട്ബൗണ്ട് ഗാർഡ് വഴി വിദൂര `audio_url` ഡൗൺലോഡ് ചെയ്യുന്നു. തുടർന്ന് അത് `resolveSelfLoopBearer()` ഉപയോഗിച്ച് പ്രാമാണീകരിച്ച ലോക്കൽ `/v1/audio/transcriptions` സെൽഫ്-ലൂപ്പിലേക്ക് ഫയലും തിരഞ്ഞെടുത്ത മോഡലും POST ചെയ്യുന്നു. നിലവിലുള്ള ട്രാൻസ്ക്രിപ്ഷൻ റൂട്ട് സാധാരണ ക്രെഡൻഷ്യൽ ലുക്കപ്പ്, കൂൾഡൗൺ/റേറ്റ്-ലിമിറ്റ് ഹാൻഡ്ലിംഗ്, പ്രൊവൈഡർ ഡിസ്പാച്ച് എന്നിവ നടത്തുന്നു.
5. വിജയകരമായ കോളുകൾ അവയുടെ ഭാഗങ്ങളെ `[Audio N]: <transcript>` ആക്കി മാറ്റും. കോളുകൾ `Promise.allSettled` ഉപയോഗിച്ചാണ് പ്രവർത്തിക്കുന്നത്: ഒരു വ്യക്തിഗത പരാജയം ആ യഥാർത്ഥ ഓഡിയോ ഭാഗം സംരക്ഷിക്കും (#4012 കരാർ). എല്ലാ കോളുകളും പരാജയപ്പെട്ട്, ടാർഗെറ്റ് `supportsAudio === false` ആണെന്ന് തെളിഞ്ഞാൽ, ഭാഗങ്ങൾ `[Audio N]: (unavailable — no STT provider connected)` ആയും മാറും (#8430 കരാർ). അജ്ഞാത ടാർഗെറ്റിന് (`null`), എല്ലാം-പരാജയപ്പെട്ട ഫലം മാറ്റമില്ലാതെ നിലനിൽക്കും. ഉപയോഗയോഗ്യമായ STT ക്രെഡൻഷ്യൽ ഇല്ലാത്ത, ടെക്സ്റ്റ്-ഓൺലി ആണെന്ന് തെളിഞ്ഞ ടാർഗെറ്റിന്, നെറ്റ്വർക്ക് കോൾ നടത്താതെ തന്നെ അതേ വ്യക്തമായ സ്റ്റബ് ലഭിക്കും.

വിജയകരമായ ട്രാൻസ്ക്രിപ്റ്റുകൾ പ്രോസസ്സ്-വ്യാപക മോഡാലിറ്റി ബ്രിഡ്ജ് LRU/TTL കാഷെ ഉപയോഗിക്കുന്നു. കീ, ഓഡിയോ റഫറൻസും സ്ഥിരമായ `audio-transcription` ഓപ്പറേഷൻ ലേബലും തിരഞ്ഞെടുത്ത STT മോഡലും സംയോജിപ്പിക്കുന്നു; പരാജയങ്ങൾ ഒരിക്കലും കാഷെ ചെയ്യില്ല. ഓഡിയോ ശ്രമങ്ങൾ പങ്കിട്ട `bridged`, `cacheHits`, `failures`, `lastUsedAt` കൗണ്ടറുകൾ അപ്ഡേറ്റ് ചെയ്യുന്നു. രൂപാന്തരപ്പെടുത്തിയ റെസ്പോൺസുകൾ `x-omniroute-modality-bridge: audio->text;model=<sttModel>;parts=<n>` വഹിക്കുന്നു; മാറ്റമില്ലാത്ത റിക്വസ്റ്റുകൾക്ക് ഓഡിയോ ബ്രിഡ്ജ് സെഗ്മെന്റ് ലഭിക്കില്ല.

റൺടൈം ക്രമീകരണങ്ങൾ DB-ബാക്കഡും Zod-വാലിഡേറ്റഡും ആണ്:

| കീ                            | ഡിഫോൾട്ട് | പരിധി                   |
| ----------------------------- | --------- | ----------------------- |
| `modalityBridgeAudioEnabled`  | `true`    | —                       |
| `modalityBridgeAudioModel`    | `""`      | ഓട്ടോ അല്ലെങ്കിൽ STT ID |
| `modalityBridgeAudioTimeout`  | `60000`   | 1000–300000             |
| `modalityBridgeAudioMaxClips` | `3`       | 1–10                    |

പങ്കിട്ട കാഷെ `modalityBridgeCacheEnabled`, `modalityBridgeCacheTtlMinutes`, `modalityBridgeCacheMaxEntries` എന്നിവയുടെ നിയന്ത്രണത്തിൽ തുടരും.

### വീഡിയോ ബ്രിഡ്ജ് (`videoBridge.ts`, `videoBridgePipeline.ts`)

അറിയാവുന്ന നേറ്റീവ് വീഡിയോ പിന്തുണയില്ലാത്ത ഒരു ടാർഗെറ്റിനെ വിളിക്കുന്നതിന് മുമ്പ്, ചാറ്റ് പൂർത്തീകരണങ്ങൾ `messages`, പ്രതികരണങ്ങൾ API `input` എന്നിവയിലെ ഉയർന്ന തലത്തിലുള്ള വീഡിയോ ഭാഗങ്ങൾ തടസ്സപ്പെടുത്തുന്നു. `input_video`, `video_url`, `video_source`, HTTPS URLs, `data:video/*;base64,...` ഡാറ്റ URIs എന്നിവയാണ് പിന്തുണയ്ക്കുന്ന രൂപങ്ങൾ. വാചകത്തിലെ പ്ലെയിൻ ഫയൽനാമങ്ങൾ വീഡിയോ ആയി കണക്കാക്കില്ല.

`VideoBridgeGuardrail.preCall` (`videoBridge.ts`) അഭ്യർത്ഥന ട്രാവെർസൽ, capability/policy ചെക്ക്, ഓരോ അഭ്യർത്ഥന അഗ്രഗേഷൻ, പ്രതികരണ പേലോഡ് എന്നിവയും സ്വന്തമാക്കി. ഓരോ വീഡിയോ വർക്ക് — ഏറ്റെടുക്കൽ, ഒരു ഫ്രെയിം സീക്വൻസ് വിവരിക്കുന്ന മുഴുവൻ ഫല കാഷെ (ഏത് കോളർ പ്രഖ്യാപിച്ച ഓഡിയോ ട്രാൻസ്ക്രിപ്റ്റും സംയോജിപ്പിക്കുന്നു), ഓരോ ശ്രമത്തിനും metrics/abort/cleanup — `videoBridgePipeline.ts` ൽ `processVideoPart` പിന്നിൽ മറച്ചിരിക്കുന്നു, `preCall` യുടെ ലൂപ്പിനുള്ളിലെ ഓരോ വീഡിയോ ഭാഗത്തിനും ഒരിക്കൽ വിളിക്കുന്നു. ആ മൊഡ്യൂൾ `VideoMediaBrokerPort` (ബൈറ്റുകൾ ഏറ്റെടുക്കൽ, സാമ്പിൾ ഫ്രെയിമുകൾ എക്സ്ട്രാക്റ്റുചെയ്യൽ), `VideoAudioTranscriptionPort` (സാമ്പിൾ അടിക്കുറിപ്പുകൾക്കൊപ്പം കോളർ പ്രഖ്യാപിച്ച ഓഡിയോ ട്രാൻസ്ക്രിപ്റ്റ് സംയോജിപ്പിക്കൽ), `VideoDrilldownPort` (ലെഗസി റോ-സ്റ്റോർ ആകൃതി) എന്നിവയും വ്യക്തമായ പോർട്ട് അതിർത്തികൾ നിർവചിക്കുന്നു. പ്രൊഡക്ഷൻ STT, ഫ്രെയിം നിലനിർത്തൽ എന്നിവ `createVideoSttAdapter`, `createVideoDrilldownAdapter` എന്നിവയിലൂടെ വിവരിക്കുന്ന പോർട്ടിന് ചുറ്റും രചിച്ചിരിക്കുന്നു; രണ്ടാമത്തേത് പങ്കിട്ട അതാര്യ-ഹാൻഡിൽ ജീവിതചക്രം ഉപയോഗിക്കുന്നു.

പൊതു `/v1` അഭ്യർത്ഥന പാത ഒരിക്കലും ഒരു ഉപപ്രോസസ്സ് ഇറക്കുമതി ചെയ്യുകയോ ആവശ്യപ്പെടുകയോ ചെയ്യുന്നില്ല. റിമോട്ട് വീഡിയോകൾ ഡൗൺലോഡ് ചെയ്യുന്നത് 50 MiB ബൗണ്ടിൽ; ഇൻലൈൻ ബേസ്64 വീഡിയോകൾക്ക് യാഥാസ്ഥിതിക 36 MiB ഡീകോഡ് ചെയ്ത ഓരോ വീഡിയോ ക്യാപ്പും ഉള്ളതിനാൽ model/messages/framing എൻവലപ്പിന് 50 MiB എന്ന പൊതു JSON അഭ്യർത്ഥന പ്രവേശന പരിധിക്കുള്ളിൽ തന്നെ തുടരാനാകും. അലോക്കേഷന് മുമ്പ് ഇൻലൈൻ ദൈർഘ്യവും ഡീകോഡ് ചെയ്ത അളവും പരിശോധിക്കും. പ്രാരംഭ റിമോട്ട് URL ലും എല്ലാ റീഡയറക്ടിലും HTTPS ആവശ്യമാണ്, DNS പിന്നിംഗിനൊപ്പം നിലവിലുള്ള പൊതു-മാത്രം ഔട്ട്ബൗണ്ട് ഗാർഡ് ഉപയോഗിക്കുന്നു. ബൈറ്റുകൾ പിന്നീട് കൃത്യമായ ആന്തരിക `POST /api/modality-bridge/video/extract` ബ്രോക്കർ അതിർത്തി കടക്കുന്നു. ആ റൂട്ട് `LOCAL_ONLY` ഉം `SPAWN_CAPABLE` ഉം ആണ്, ഓരോ പ്രോസസ്സിനും ആധികാരികമായ, വിശ്വസനീയമായ ലൂപ്പ്ബാക്ക് അഭ്യർത്ഥന മാത്രമേ സ്വീകരിക്കുകയുള്ളൂ, കൂടാതെ URL, ഫയൽസിസ്റ്റം പാത്ത്, എക്സിക്യൂട്ടബിൾ അല്ലെങ്കിൽ ആർഗ്യുമെൻ്റ് ലിസ്റ്റ് എന്നിവ ഒരിക്കലും സ്വീകരിക്കില്ല. API ബോഡി-സൈസ് പൈപ്പ് ലൈനും ഹാൻഡ്ലറിൻ്റെ ഇൻക്രിമെൻ്റൽ ബോഡി റീഡറും ഒരു 50 MiB ബ്രോക്കർ ഇൻപുട്ട് ക്യാപ് സ്വതന്ത്രമായി നടപ്പിലാക്കുന്നു. അതിൻ്റെ ബൗണ്ടഡ് ക്യൂ ഒരു സമയം ഒരു എക്സ്ട്രാക്ഷൻ നടത്തുന്നു, തീർച്ചപ്പെടുത്താത്ത നാല് ജോലികൾ അനുവദിക്കുന്നു, കൂടാതെ 100 MiB ൽ ശേഷിക്കുന്ന ഇൻപുട്ട് ക്യാപ്സ് ചെയ്യുന്നു.

ബ്രോക്കറിനുള്ളിൽ, `ffprobe` ഒരു സ്വകാര്യ ലോക്കൽ ഫയൽ വായിക്കുന്നു; നിശ്ചിത ഫോർമാറ്റ് അനുമതിലിസ്റ്റ് പ്ലേലിസ്റ്റും മാനിഫെസ്റ്റ് ഫോർമാറ്റുകളും ഒഴിവാക്കുന്നു. അനുവദനീയമായ MOV-ഫാമിലി കണ്ടെയ്നറുകൾക്ക്, ബാഹ്യ MOV ഡാറ്റ റഫറൻസുകൾ ഡിഫോൾട്ടായി പ്രവർത്തനരഹിതമായി തുടരും, കൂടാതെ നിശ്ചിത കമാൻഡ് അവ തിരഞ്ഞെടുക്കില്ല. `ffprobe` ഉം `ffmpeg` ഉം `file` -only പ്രോട്ടോക്കോൾ വൈറ്റ്ലിസ്റ്റ്, ഒരു ത്രെഡ്, ഫിക്സഡ് ആർഗ്യുമെൻ്റ് അറേകൾ, ഷെൽ ഇല്ല, കൂടാതെ `PATH` ൽ നിന്ന് പരിഹരിച്ച എക്സിക്യൂട്ടബിളുകൾ എന്നിവ ഉപയോഗിക്കുന്നു. അറ്റാച്ച് ചെയ്ത ചിത്ര കവർ സ്ട്രീമുകൾ പ്ലേ ചെയ്യാവുന്ന കാൻഡിഡേറ്റുകളല്ല. പ്ലേ ചെയ്യാവുന്ന എല്ലാ സ്ട്രീമുകളും പരിധികൾ പാലിക്കണം, കൂടാതെ ഡിറ്റർമിനിസ്റ്റിക് ലോസ്റ്റ്-ഇൻഡക്സ് ഫാൾബാക്കിന് മുമ്പ് ഒരു വ്യക്തമായ ഡിഫോൾട്ട് സ്ട്രീം തിരഞ്ഞെടുക്കപ്പെടും. വീഡിയോകൾ 600 സെക്കൻഡ്, ഓരോ അളവിലും 8,192 പിക്സലുകൾ, 33,554,432 സോഴ്സ് പിക്സലുകൾ എന്നിങ്ങനെ പരിമിതപ്പെടുത്തിയിരിക്കുന്നു. FFmpeg സാമ്പിളുകൾ 1–16 മിഡ്പോയിൻ്റ് JPEG ഫ്രെയിമുകൾ, ചെറിയ ഇൻപുട്ടുകൾ ഉയർത്താതെ നീളമുള്ള അരികിൽ നിന്ന് പരമാവധി 1,024 പിക്സലുകളിലേക്ക് സ്കെയിൽ ചെയ്യുന്നു, ഒരിക്കലും ഒരു URL ലഭിക്കില്ല. സ്ഥിരസ്ഥിതിയായി സാമ്പിൾ `uniform` ആണ്. ഓപ്ഷണൽ `scene_aware`, പരീക്ഷണാത്മക `segment_aware` നയങ്ങൾ ഇതിനകം സാധൂകരിച്ച ലോക്കൽ സ്ട്രീമിലൂടെ ഒരു അധിക ഫിക്സഡ് FFmpeg പാസ് നടത്തുന്നു, ബൗണ്ടഡ് `showinfo` സീൻ ടൈംസ്റ്റാമ്പുകൾ തിരഞ്ഞെടുത്ത് ഡിറ്റക്റ്റർ പരാജയം, കാലഹരണപ്പെടൽ, തെറ്റായ ഔട്ട്പുട്ട് അല്ലെങ്കിൽ ശൂന്യമായ കാൻഡിഡേറ്റ് സെറ്റ് എന്നിവയിൽ അതേ ഏകീകൃത മിഡ്പോയിൻ്റുകളിലേക്ക് നിർണ്ണായകമായി മടങ്ങുന്നു. സെഗ്മെൻ്റ്-അവയർ മോഡ് സാധുതയുള്ള സീൻ ഇടവേളകൾക്ക് ആനുപാതികമായി മിഡ്പോയിൻ്റ് സാമ്പിളുകൾ അനുവദിക്കുന്നു; സെഗ്മെൻ്റ്-അവബോധ തെളിവുകളും ഫാൾബാക്ക് പെരുമാറ്റവും ചുവടെ വിശദമായി വിവരിച്ചിരിക്കുന്നു. എല്ലാ പോളിസിയിലും തിരഞ്ഞെടുത്തതിന് ശേഷം ഹാർഡ് 16-ഫ്രെയിം ക്യാപ് പ്രയോഗിക്കുന്നു. ഒരു സീൻ-അവേർ അഭ്യർത്ഥനയ്ക്ക് ഒരു-ഫ്രെയിം ബജറ്റ് മാത്രമുള്ളപ്പോൾ, അത് സജീവമായ ഫുൾ-വീഡിയോ അല്ലെങ്കിൽ ഫോക്കസ് വിൻഡോയുടെ ഏകീകൃത മധ്യഭാഗം ഉപയോഗിക്കുകയും `policyEffective: uniform` റിപ്പോർട്ട് ചെയ്യുകയും ചെയ്യുന്നു: ഒരു തിരഞ്ഞെടുത്ത സീൻ ഫ്രെയിമിന് രണ്ട് താൽക്കാലിക അറ്റങ്ങളും സംരക്ഷിക്കാൻ കഴിയില്ല. ഒരു കോളർ ഓപ്ഷണലായി ഒരു പരിമിത ഫോക്കസ് വിൻഡോ നൽകാം (`start`/`end` സെക്കൻഡ്); പരിധികൾ മീഡിയ കാലയളവിലേക്ക് ഘടിപ്പിച്ചിരിക്കുന്നു, റിവേഴ്സ് അല്ലെങ്കിൽ നോൺ-ഫിനിറ്റ് വിൻഡോകൾ നിരസിക്കുന്നു, കൂടാതെ എല്ലാ സാംപ്ലിംഗ് പോളിസികളും നോർമലൈസ് ചെയ്ത ഇടവേളയിൽ മാത്രമേ നടപ്പിലാക്കൂ. തത്ഫലമായുണ്ടാകുന്ന വിൻഡോ സാമ്പിൾ മെറ്റാഡാറ്റയിലും വിശ്വസനീയമല്ലാത്ത വിവരണ പ്രിഫിക്സിലും ഉൾപ്പെടുത്തിയിരിക്കുന്നതിനാൽ ഡൗൺസ്ട്രീം മോഡലുകൾക്ക് ഫുൾ ടൈംലൈനിൽ നിന്ന് ഫോക്കസ് ചെയ്ത ഉദ്ധരണിയെ വേർതിരിച്ചറിയാൻ കഴിയും.

സെമാൻ്റിക് അടിക്കുറിപ്പ് ഫോക്കസ് എന്നത് ഒരു പ്രത്യേക, വ്യക്തമായ ക്രമീകരണമാണ്. ഡിഫോൾട്ട് `full` അനാലിസിസ് മോഡ് നിലവിലുള്ള ഫ്രെയിം പ്രോംപ്റ്റ് സംരക്ഷിക്കുകയും അഭ്യർത്ഥന വാചകം അടിക്കുറിപ്പ് മോഡലിലേക്ക് കൈമാറുകയും ചെയ്യുന്നില്ല. `focused` മോഡിൽ, ബ്രിഡ്ജ് അതേ ചാറ്റ് അല്ലെങ്കിൽ റെസ്പോൺസ് കണ്ടെയ്നറിൽ നിന്ന് ഏറ്റവും പുതിയ നോൺ-ശൂന്യമായ ഉപയോക്താവ് എഴുതിയ `text`/`input_text` മാത്രമേ വായിക്കൂ, അതിനെ NFC ലേക്ക് നോർമലൈസ് ചെയ്യുന്നു, നിയന്ത്രണ പ്രതീകങ്ങളും വൈറ്റ്സ്പെയ്സും ചുരുക്കി, അതിനെ 500 യൂണികോഡ് കോഡ് പോയിൻ്റുകളായി പരിമിതപ്പെടുത്തുന്നു. ഒരു ശൂന്യമായ ഫലം കൃത്യമായ `full` പ്രോംപ്റ്റിലേക്ക് തിരികെ വരുന്നു. ഉപയോഗയോഗ്യമായ ഒരു സൂചന JSON ആയി ഒരു സമർപ്പിത വിശ്വസനീയമല്ലാത്ത-ഉപയോക്തൃ-സന്ദർഭ ബ്ലോക്കിൽ സീരിയലൈസ് ചെയ്തിരിക്കുന്നു, കൂടാതെ നിരീക്ഷിക്കാവുന്ന വിശദാംശങ്ങൾക്ക് മാത്രം മുൻഗണന നൽകാം; മീഡിയയിൽ ദൃശ്യമായതോ കേൾക്കാവുന്നതോ ആയ ഇനിപ്പറയുന്ന നിർദ്ദേശങ്ങൾക്കെതിരെയുള്ള പ്രത്യേക മുന്നറിയിപ്പ് മറികടക്കാൻ ഇതിന് കഴിയില്ല. ടെക്സ്ച്വൽ ഫോക്കസ് ഒരിക്കലും `start`/`end` അനുമാനിക്കുകയോ ടെമ്പറൽ സാമ്പിളിനെ മാറ്റുകയോ ചെയ്യുന്നില്ല.

#### FU-07 ഘടനാപരമായ സെഗ്മെൻ്റ് തെളിവുകൾ

ഇതിനകം സാധൂകരിച്ച പ്രാദേശിക വീഡിയോ സ്ട്രീമിൽ `segment_aware` ഒരു ബൗണ്ടഡ് പ്രീ-അനാലിസിസ് പാസ് ഉപയോഗിക്കുന്നു. നിശ്ചിത ഫിൽട്ടർ ശൃംഖല ആദ്യം പരമാവധി 320 പിക്സൽ വീതിയിലേക്ക് സ്കെയിലുചെയ്യുന്നു, സീൻ മാറ്റങ്ങളും ഫ്രീസുചെയ്ത ഇടവേളകളും കണ്ടെത്തുന്നു, തുടർന്ന് മങ്ങൽ, ശരാശരി ലൂമ, spatial/temporal വിവരങ്ങൾ എന്നിവയ്ക്കായി സെക്കൻഡിൽ 1 ഫ്രെയിമിൽ സാമ്പിളുകൾ നൽകുന്നു. 600 ഘടനാപരമായ സാമ്പിളുകൾ, ഒരു FFmpeg/filter ത്രെഡ്, ഒരേ `file` -only പ്രോട്ടോക്കോൾ, കണ്ടെയ്നർ അനുവദനീയമായ ലിസ്റ്റുകൾ, 1 MiB പ്രോസസ്സ്-ഔട്ട്പുട്ട് ബൗണ്ട്, കൂടാതെ ബ്രോക്കറുടെ പങ്കിട്ട abort/deadline. ഉള്ളിൽ പരമാവധി 30 സെക്കൻഡ് ഇത് ഒരിക്കലും അഭ്യർത്ഥനയിൽ നിന്ന് ഒരു കമാൻഡും ഫിൽട്ടറും പാത്തും URL സ്വീകരിക്കില്ല.

ഘടനാപരമായ മൂല്യങ്ങൾ നിർണ്ണായക സാമ്പിൾ തെളിവുകളാണ്, സെമാൻ്റിക് വീഡിയോ മനസ്സിലാക്കലല്ല. അവർ വിഷയങ്ങളോ പ്രവൃത്തികളോ അടിക്കുറിപ്പുകളോ സംഭാഷണമോ ഉപയോക്തൃ ഉദ്ദേശ്യമോ അനുമാനിക്കുന്നില്ല. സീനും ഫ്രീസ് ബൗണ്ടറികളും സെഗ്മെൻ്റുകളായി മാറുന്നു; ഫ്രീസ് കവറേജ്, മങ്ങൽ, എക്സ്പോഷർ, സ്പേഷ്യൽ വിശദാംശങ്ങൾ, താൽക്കാലിക മാറ്റം എന്നിവ നിലവിലുള്ള 1–16 ഫ്രെയിം ബജറ്റ് എങ്ങനെ നീക്കിവയ്ക്കുന്നു എന്നതിനെ സ്വാധീനിക്കുന്നു. പൂർണ്ണമായും ഫ്രീസുചെയ്ത സെഗ്മെൻ്റ് ഒരു ഫ്രെയിമിൽ അടച്ചിരിക്കുന്നു, അതേസമയം ഫ്രീസ് ചെയ്യാത്ത സെഗ്മെൻ്റുകൾ ശേഷിക്കുന്ന ബജറ്റിനായി മത്സരിക്കുന്നു. അതിരുകൾ ഫ്രെയിമുകളെക്കാൾ കൂടുതലാകുമ്പോൾ, യൂണിഫോം ടൈംലൈൻ കവറേജ് നിലനിർത്തുന്നു, അതിനാൽ ദ്രുതഗതിയിലുള്ള ആദ്യകാല മുറിവുകൾക്ക് ഒരു നീണ്ട ട്രെയിലിംഗ് സെഗ്മെൻ്റ് മറയ്ക്കാൻ കഴിയില്ല. ഒരു ഫ്രീസ് ബൗണ്ടറിയുടെ 1-സെക്കൻഡ് വിശകലന മിഴിവിനുള്ളിലെ സീൻ അതിരുകൾ സംയോജിപ്പിച്ചിരിക്കുന്നു.

നഷ്ടമായ ഫിൽട്ടറുകൾ, malformed/empty തെളിവുകൾ, ഒരു ഡിറ്റക്ടർ പിശക് അല്ലെങ്കിൽ ബൗണ്ടഡ് പ്രീ-അനാലിസിസ് ടൈംഔട്ട് എന്നിവ കൃത്യമായ ഏകീകൃത മിഡ്പോയിൻ്റ് പോളിസിയിൽ പരാജയപ്പെടുന്നു. ഒരു കോളർ അബോർട്ട് അല്ലെങ്കിൽ ബ്രോക്കർ ഡെഡ്ലൈൻ തുറക്കുന്നത് പരാജയപ്പെടില്ല: ഇത് ഇൻ-ഫ്ലൈറ്റ് സബ്പ്രോസസ് അവസാനിപ്പിക്കുന്നു, പിന്നീട് ഫ്രെയിം എക്സ്ട്രാക്ഷൻ തടയുന്നു, കൂടാതെ സ്വകാര്യ താൽക്കാലിക ട്രീ `finally` ൽ നീക്കംചെയ്യുന്നു.

പോസ്റ്റ്-ഡെഡപ്പ് ക്യാപ്ഷൻ-കോൾ സേവിംഗ്സ്, ഡെൻസ്-മോഷൻ ബഡ്ജറ്റ് അലോക്കേഷൻ, blur/exposure/SI-TI തെളിവുകൾ, നീളമുള്ള വാലുള്ള വേഗത്തിലുള്ള മുറിവുകൾ, ക്രമാനുഗതമായ മങ്ങൽ തെറ്റായ പോസിറ്റീവുകൾ എന്നിവയ്ക്കായി`scripts/perf/video-bridge-fu07-eval.ts` നിർണ്ണായക യഥാർത്ഥ FFmpeg ഫിക്ചറുകൾ സൃഷ്ടിക്കുന്നു. ഇത് വിശകലനത്തിന് മുമ്പുള്ള മതിൽ സമയവും, `/usr/bin/time` ലഭ്യമാകുന്നിടത്ത്, ചൈൽഡ് CPU, പീക്ക് RSS എന്നിവയും രേഖപ്പെടുത്തുന്നു. അതിൻ്റെ ഗുണനിലവാര പരിശോധനകൾ ഘടനാപരമായ ഒറാക്കിളുകൾ മാത്രമാണ്. ഈ ഹാർനെസിന് അംഗീകൃത എൻഡ് പോയിൻ്റോ ഫ്രോസൺ ജഡ്ജിയോ ഇല്ലാത്തതിനാൽ യഥാർത്ഥ അടിക്കുറിപ്പ്-മോഡൽ നിലവാരം `HOLD` ആയി തുടരുന്നു. ഓരോ കോളിനും വ്യക്തമായ പോസിറ്റീവ് എസ്റ്റിമേറ്റ് `--caption-cost-per-call-usd` നൽകുന്നില്ലെങ്കിൽ പണ സമ്പാദ്യവും `HOLD` ആയി തുടരും; സ്ക്രിപ്റ്റ് ഒരിക്കലും ഒരു ഫലവും കെട്ടിച്ചമയ്ക്കുന്നില്ല.

ഓരോ ഫ്രെയിമും 4 MiB ആയി പരിമിതപ്പെടുത്തിയിരിക്കുന്നു, എല്ലാ അസംസ്കൃത ഫ്രെയിമുകളും ഒരുമിച്ച് 23 MiB ആയി പരിമിതപ്പെടുത്തിയിരിക്കുന്നു, കൂടാതെ സീരിയലൈസ് ചെയ്ത ബ്രോക്കർ പ്രതികരണം 32 MiB ലേക്ക് പരിമിതപ്പെടുത്തിയിരിക്കുന്നു. `finally` ൽ ഒരു സ്വകാര്യ താൽക്കാലിക ഡയറക്ടറി നീക്കം ചെയ്തു. OmniRoute FFmpeg ബണ്ടിൽ ചെയ്യുന്നില്ല കൂടാതെ ഒരു ഇഷ്ടാനുസൃത എക്സിക്യൂട്ടബിൾ പാത്ത് അംഗീകരിക്കുന്നില്ല. അടിക്കുറിപ്പ് നൽകുന്നതിന് മുമ്പ്, ബ്രിഡ്ജ് ഒരു യാഥാസ്ഥിതിക വിഷ്വൽ ഡ്യൂപ്ലിക്കേഷൻ പാസ് പ്രയോഗിക്കുന്നു: ഓരോ JPEG യും 16 × 16 ഗ്രേസ്കെയിൽ ബഫറായി ചുരുക്കി, അവസാനമായി നിലനിർത്തിയ ഫ്രെയിമുമായി മാത്രം താരതമ്യം ചെയ്യുന്നു. ഒരു ഫ്രെയിമിന് മുകളിലുള്ള ഒരു അഭ്യർത്ഥിച്ച അടിക്കുറിപ്പ് ബജറ്റിന്, എക്സ്ട്രാക്ഷൻ ബൗണ്ടഡ് കാൻഡിഡേറ്റ് പൂൾ ബഡ്ജറ്റിൻ്റെ ഇരട്ടി വരെ നൽകുന്നു, ഒരിക്കലും 16 ഫ്രെയിമുകളിൽ കൂടരുത്. അഭ്യർത്ഥിച്ച തൊപ്പി ഡ്യൂപ്ലിക്കേഷനുശേഷം മാത്രമേ പ്രയോഗിക്കൂ, ആദ്യത്തേയും അവസാനത്തേയും തിരഞ്ഞെടുത്ത കാൻഡിഡേറ്റുകൾ, ബഡ്ജറ്റ് കുറഞ്ഞത് രണ്ടായിരിക്കുമ്പോൾ, അന്തിമ കട്ടിയാക്കൽ സമയത്ത് സംരക്ഷിക്കപ്പെടും. വേർഷൻ ചെയ്ത `grayscale-16x16-mean-cells-v2` പോളിസി, ശരാശരി ലുമ ഡെൽറ്റയുടെ വലിയതും, നോർമലൈസ് ചെയ്ത ഡെൽറ്റ കുറഞ്ഞത് 0.05 ആയ ലഘുചിത്ര സെല്ലുകളുടെ അനുപാതവും ഉപയോഗിക്കുന്നു. ഡ്യൂപ്ലിക്കേറ്റ് ത്രെഷോൾഡ് സ്ഥിരമായ 0.04 ആണ്, ഇത് ഒരു റൺടൈം ക്രമീകരണമായി തുറന്നുകാട്ടുന്നതിനുപകരം പ്രവചനാത്മകതയ്ക്കായി തിരഞ്ഞെടുത്തു. ഈ ദ്വിതീയ ഉയർന്ന ദൃശ്യതീവ്രത സിഗ്നൽ ചെറിയ ചലനവും ദൃശ്യ-ടെക്സ്റ്റ് മാറ്റങ്ങളും സംരക്ഷിക്കുന്നു, ഇത് ഒരു ശരാശരി-മാത്രം താരതമ്യം മറയ്ക്കാൻ കഴിയും. കംപാറേറ്റർ അല്ലെങ്കിൽ ഡീകോഡർ പിശകുകൾ പരാജയപ്പെടുകയും കവറേജ് നിലനിർത്തുകയും ചെയ്യുന്നു. ഔട്ട്പുട്ട് മെറ്റാഡാറ്റ എക്സ്ട്രാക്റ്റുചെയ്ത കാൻഡിഡേറ്റുകൾ, വിജയകരമായി ഉപയോഗിച്ച ഫ്രെയിമുകൾ, വിഷ്വൽ ഡ്യൂപ്ലിക്കേറ്റുകൾ എന്നിവ വേർതിരിക്കുന്നു.

വ്യക്തമായി അടയാളപ്പെടുത്തിയ വീഡിയോ ഭാഗം ടൈംസ്റ്റാമ്പ് ചെയ്ത കോൺടാക്റ്റ് ഷീറ്റ് അഭ്യർത്ഥിച്ചേക്കാം. പാലം പരമാവധി 4-കോളം, 16-ഫ്രെയിം JPEG ഗ്രിഡ് നിർമ്മിക്കുന്നു. ഓരോ 512-പിക്സൽ സെല്ലും അതിൻ്റെ സോഴ്സ് ടൈംസ്റ്റാമ്പിനെ ഉയർന്ന കോൺട്രാസ്റ്റ് ബോട്ടം ബാൻഡിലേക്ക് ബേൺ ചെയ്യുന്നു, അതേ ടൈംസ്റ്റാമ്പുകൾ ഡൗൺസ്ട്രീം അസോസിയേഷനും ഓഡിറ്റിനുമായി ടെക്സ്റ്റ്വൽ മെറ്റാഡാറ്റയിൽ നിലനിൽക്കും. പൂർണ്ണമായ JPEG 32 MiB ആയി പരിമിതപ്പെടുത്തിയിരിക്കുന്നു. `sharp` ഗ്രിഡ് ഡീകോഡ് ചെയ്യാനോ രചിക്കാനോ കഴിയുന്നില്ലെങ്കിൽ, ബ്രിഡ്ജ് വ്യക്തിഗത JPEG ഫ്രെയിമുകളിലേക്ക് മടങ്ങുന്നു; ഒരു ക്ലയൻ്റ് അബോർട്ട് ഇപ്പോഴും ഷീറ്റ് പ്രവർത്തനത്തിലൂടെ പ്രചരിപ്പിക്കുന്നു.

പ്രൊമോഷൻ തെളിവുകൾ സിന്തറ്റിക് കോമ്പോസിഷൻ മൈക്രോബെഞ്ച്മാർക്കിൽ നിന്ന് മനഃപൂർവ്വം വേറിട്ടുനിൽക്കുന്നു. യഥാർത്ഥ OpenAI-അനുയോജ്യമായ വിഷൻ മോഡലുകൾക്കായി `scripts/perf/video-bridge-contact-sheet-eval.ts` ഒരു സ്കീമ പതിപ്പ് A/B ഹാർനെസ് നിർവചിക്കുന്നു. ഇത് ദാതാവ് റിപ്പോർട്ട് ചെയ്ത ടോക്കണുകൾ, എൻഡ്-ടു-എൻഡ് വാൾ ലേറ്റൻസി (ഷീറ്റ് കോമ്പോസിഷൻ ഉൾപ്പെടെ), മോഡൽ-കോൾ കൗണ്ട്, മാനിഫെസ്റ്റ്-നിർവ്വചിച്ച വസ്തുത നിലനിർത്തൽ എന്നിവ അളക്കുന്നു. റോ മോഡൽ പ്രതികരണങ്ങൾ റിപ്പോർട്ടിൽ എഴുതിയിട്ടില്ല; SHA-256 ഡൈജസ്റ്റുകളും പൊരുത്തപ്പെടുന്ന വസ്തുത IDs മാത്രം നിലനിർത്തുന്നു. `--execute-real` കടന്നുപോകുകയും `--model`, `OMNIROUTE_BASE_URL`, `OMNIROUTE_API_KEY` എന്നിവ കോൺഫിഗർ ചെയ്യുകയും ചെയ്തില്ലെങ്കിൽ ഹാർനെസ് നെറ്റ്വർക്കോ പണമടച്ചുള്ള മോഡൽ കോളോ നടത്തില്ല. വ്യക്തമായ യഥാർത്ഥ റൺ കൂടാതെ, അതിൻ്റെ മെഷീൻ-റീഡബിൾ വിധി `HOLD` തുടരും; സിന്തറ്റിക് payload/call-count അളവുകൾ മാത്രം പ്രൊമോഷൻ തെളിവുകൾ അല്ല.

വിളിക്കുന്നവർ ഇതിനകം വിന്യസിച്ച വാചകം കൈവശം വയ്ക്കുമ്പോൾ പിന്തുണയ്ക്കുന്ന വീഡിയോ ഭാഗത്തേക്ക് ഒരു ഓപ്ഷണൽ `transcript.cues` അറേ അറ്റാച്ചുചെയ്യാം. ഓരോ ക്യൂവും `text`, പ്രോബ്ഡ് കാലയളവിനുള്ളിൽ ഒരു പരിമിതമായ `start`/`end` ഇടവേള, ഒരു വൈറ്റ്ലിസ്റ്റ് ചെയ്ത `source` (`client`, `embedded`, അല്ലെങ്കിൽ `audio-bridge`) എന്നിവ ഉണ്ടായിരിക്കണം; `confidence` സ്ഥിരസ്ഥിതിയായി `1` ലേയ്ക്കും `0` നും `1` ഇടയിൽ നിലനിൽക്കുകയും വേണം. കൃത്യമായ ഡ്യൂപ്ലിക്കേറ്റ് സൂചനകൾ ചുരുക്കിയിരിക്കുന്നു. OmniRoute ഒരിക്കലും ഈ മെറ്റാഡാറ്റയിൽ നിന്ന് ട്രാൻസ്ക്രിപ്ഷൻ ആരംഭിക്കുന്നില്ല: സാധുതയുള്ള സൂചകങ്ങൾ വിവരിച്ച ഫലത്തിലേക്ക് ഉറവിടം, ആത്മവിശ്വാസം, ഇടവേള എന്നിവ ഉപയോഗിച്ച് പകർത്തുകയും ഫ്രെയിം അടിക്കുറിപ്പുകൾക്കൊപ്പം വിശ്വസനീയമല്ലാത്ത നിരീക്ഷണങ്ങളായി റെൻഡർ ചെയ്യുകയും ചെയ്യുന്നു. അസാധുവായ, പരിധിക്ക് പുറത്തുള്ള, അല്ലെങ്കിൽ തെളിവില്ലാത്ത ടെക്സ്റ്റ് അടിക്കുറിപ്പ് സ്ട്രീമിൽ കലർത്തുന്നതിനുപകരം നിരസിക്കപ്പെടും. രണ്ട് അഭ്യർത്ഥന-ബോഡി ട്രാൻസ്ക്രിപ്റ്റ് ചാനലുകളും `client` ലേക്ക് വിതരണം ചെയ്ത പ്രോവിൻസ് നോർമലൈസ് ചെയ്യുന്നു, സ്വയം ഉറപ്പിച്ച `embedded` അല്ലെങ്കിൽ `audio-bridge` ലേബലുകൾ ഉൾപ്പെടെ. ഒരു സെർവറിൻ്റെ ഉടമസ്ഥതയിലുള്ള അഡാപ്റ്ററിന് മാത്രമേ ആ വിശ്വസനീയമായ ലേബലുകൾ കോഡ്-മാത്രം `trustedSource` ആർഗ്യുമെൻ്റിലൂടെ നൽകാനാവൂ; ഒരു അഭ്യർത്ഥന JSON ഫീൽഡിന് ആ ആർഗ്യുമെൻ്റിൽ എത്താൻ കഴിയില്ല. ട്രാൻസ്ക്രിപ്റ്റ് ടെക്സ്റ്റ് അതിൻ്റെ ആധിപത്യം പരിഗണിക്കാതെ തന്നെ അവിശ്വസനീയമാംവിധം മീഡിയയിൽ നിന്ന് ഉരുത്തിരിഞ്ഞ ഉള്ളടക്കമായി തുടരുന്നു, ഒരിക്കലും അംഗീകാരം നിർണ്ണയിക്കാൻ പാടില്ല.

ഒരു നൂതന കോളർ അതേ വീഡിയോയ്ക്കായി ഒരു `audioTranscript` ട്രാക്ക് നൽകിയേക്കാം; ഇത് ക്ലയൻ്റ് നൽകിയ ടെക്സ്റ്റായി കണക്കാക്കുന്നു, സെർവർ ട്രാൻസ്ക്രിപ്ഷൻ്റെ തെളിവല്ല. ഫ്യൂഷൻ സീം ഒരു സമയപരിധിക്ക് കീഴിൽ വിഷ്വൽ, ഓഡിയോ നിരീക്ഷണങ്ങൾ പ്രവർത്തിപ്പിക്കുകയും സിഗ്നൽ നിർത്തലാക്കുകയും ചെയ്യുന്നു, അവ ഒരു പൊതു ടൈംലൈനിൽ ഓർഡർ ചെയ്യുന്നു, കൃത്യമായ ഡ്യൂപ്ലിക്കേറ്റുകൾ ചുരുക്കുന്നു, ഒരു വശം മാത്രം വിജയിക്കുമ്പോൾ ഭാഗിക ഫലം റിപ്പോർട്ടുചെയ്യുന്നു. ഒരു അസാധുവായ `audioTranscript` ആ ഭാഗിക ഫലമായ — ലേക്ക് തരംതാഴ്ത്തുന്നു, ദൃശ്യ വിവരണം സൂക്ഷിക്കുകയും ഓഡിയോ ബ്രാഞ്ച് മുഴുവൻ വീഡിയോയും പരാജയപ്പെടുന്നതിന് പകരം ഒരു സാനിറ്റൈസ്ഡ് പരാജയ കോഡ് — രേഖപ്പെടുത്തുകയും ചെയ്യുന്നു. ഓരോ ബ്രാഞ്ചിലും ലഭ്യത, ഭാഗിക ഫ്ലാഗ്, സാനിറ്റൈസ്ഡ് പരാജയ കോഡുകൾ എന്നിവ വിവരിച്ച ഫലത്തിലും ഗാർഡ്റെയിൽ മെറ്റാഡാറ്റയിലും (`audioFusionRuns`/`audioFusionPartials`/ `audioFusionFailureCodes`), ഫല-കാഷെ മെറ്റാഡാറ്റയിലും ബ്രിഡ്ജ് ഫ്യൂഷൻ കൗണ്ടറുകളിലും സംരക്ഷിച്ചിരിക്കുന്നു. ഡിഫോൾട്ട് വീഡിയോ ബ്രിഡ്ജ് പാത്ത് സംഭാഷണം-ടു-വാചകം ആവശ്യപ്പെടുകയോ രണ്ടാമത്തെ മീഡിയ കോപ്പി ഡൗൺലോഡ് ചെയ്യുകയോ ചെയ്യുന്നില്ല; വ്യക്തമായ ട്രാക്ക് ഇല്ലാതെ, അത് വീഡിയോ മാത്രം ആയി തുടരുന്നു.

**ട്രാൻസ്ക്രിപ്റ്റ് നിലനിർത്തൽ (#12150 P1).** വീഡിയോ ബ്രിഡ്ജ് (സ്വയം ഓപ്റ്റ്-ഇൻ) ഒരു ട്രാൻസ്ക്രിപ്റ്റ് ക്യൂ — റെൻഡർ ചെയ്യുമ്പോഴെല്ലാം ഇത് സ്വയമേവ ബാധകമാകും, പ്രത്യേക റിട്ടൻഷൻ ഫ്ലാഗ് ഇല്ല. ഒരു അഭ്യർത്ഥന ഏതെങ്കിലും ട്രാൻസ്ക്രിപ്റ്റ് ക്യൂ (കോളർ പ്രഖ്യാപിച്ച `transcript` അല്ലെങ്കിൽ ഒരു ഫ്യൂസ്ഡ് `audioTranscript`) റെൻഡർ ചെയ്യുമ്പോൾ, ഗാർഡ്റെയിൽ അതിനെ `videoBridgeObserved` അടയാളപ്പെടുത്തുകയും വീഡിയോ വിവരണത്തിൻ്റെ — ൻ്റെ ഒരു പുനർനിർമിച്ച നിഴൽ സൃഷ്ടിക്കുകയും ചെയ്യുന്നു, അതിൽ എല്ലാ ക്യൂവിൻ്റെ ഫ്രീ-ടെക്സ്റ്റ് ബോഡിയും `[redacted-video-transcript]` മുമ്പായി നിർമ്മിച്ച ഘടന ഉപയോഗിച്ച് മാറ്റിസ്ഥാപിക്കുന്നു. അസംബിൾ ചെയ്തത് (ഒരിക്കലും പരന്ന ടെക്സ്റ്റ് പാഴ്സ് ചെയ്യുന്നതിലൂടെയല്ല, അതിനാൽ `[inaudible]`/`[music]` — പോലുള്ള `]` അടങ്ങിയ ബോഡികൾ ഉൾപ്പെടെ — എതിരാളിയോ സാധാരണമോ ആയ ഒരു ക്യൂ ഉള്ളടക്കവും നിലനിൽക്കില്ല). സ്ഥിരമായ കോൾ-ലോഗ് അഭ്യർത്ഥന ബോഡി, ഉള്ളടക്ക സമത്വവുമായി പൊരുത്തപ്പെടുന്ന, ആ തിരുത്തിയ നിഴലിനായി ഓരോ വീഡിയോ-ഉത്ഭവിച്ച വാചക ഭാഗവും സ്വാപ്പ് ചെയ്യുന്നു; പൂർത്തിയായ പ്രീ-കോൾ ഗാർഡ്റെയിൽ പേലോഡിൽ നിന്ന് `fullText` ആങ്കർ വീണ്ടും വായിക്കുന്നു, അതിനാൽ പിന്നീടുള്ള ചെയിൻ ഗാർഡ്റെയിലുകൾ ( PII, ക്രെഡൻഷ്യൽ മാസ്ക്കറുകൾ, മുൻഗണനകൾ 10/95) വിവരണ വാചകം മാറ്റി എഴുതുകയും system-prompt/handoff/memory കുത്തിവയ്പ്പിന് ശേഷം സന്ദേശ നിരയെ പുനഃക്രമീകരിക്കുകയും ചെയ്തതിന് ശേഷവും മത്സരം വിജയിക്കുന്നു. മോഡലിലേക്ക് അപ്സ്ട്രീമിലേക്ക് അയച്ച ബോഡിക്ക് മാറ്റമില്ല. നിരീക്ഷിച്ച ഒരു അഭ്യർത്ഥനയ്ക്ക് ഡ്യൂറബിൾ മെമ്മറി പോപ്പുലേറ്റ് ചെയ്യുന്നില്ല (അഭ്യർത്ഥനയും പ്രതികരണത്തിൽ നിന്ന് വേർതിരിച്ചെടുക്കലും ഒഴിവാക്കിയിരിക്കുന്നു), അതിനാൽ മോഡലിൻ്റെ സ്വന്തം മറുപടിക്ക് ട്രാൻസ്ക്രിപ്റ്റ് ടെക്സ്റ്റ് മെമ്മറിയിലേക്ക് മാറ്റാൻ കഴിയില്ല.

**റോ വീഡിയോ ഫീൽഡുകൾ (#12430).** ബ്രിഡ്ജ് പ്രവർത്തനക്ഷമമാക്കുകയും നേറ്റീവ് വീഡിയോ പിന്തുണ അജ്ഞാതമാകുകയോ ഇല്ലാതിരിക്കുകയോ ചെയ്യുമ്പോൾ, നിർവചിക്കപ്പെട്ട `transcript`/`audioTranscript` ഫീൽഡുകളും `videoBridgeObserved` സജീവമാക്കുന്നു, വിവരണ പരാജയം അല്ലെങ്കിൽ `maxVideos` പരിധിക്ക് ശേഷവും. `null`, ശൂന്യമായ സ്ട്രിംഗുകളുടെ എണ്ണം; ഇല്ലാത്ത ഫീൽഡുകളും വീഡിയോ ഇതര മെറ്റാഡാറ്റയും ഇല്ല. നിലനിർത്തിയ പകർപ്പുകൾ ഈ ഫീൽഡുകൾ തിരുത്തുകയോ അഭ്യർത്ഥന ഒഴിവാക്കുകയോ ചെയ്യുന്നു, കൂടാതെ caches/Memory ബൈപാസ് ചെയ്യുന്നു.

ആ ഫോൾബാക്ക് പാതകളിൽ, സാധുവായ കോളർ ക്യൂകൾ നിലവാരമില്ലാത്ത ദാതാവിൻ്റെ ഫീൽഡുകളേക്കാൾ പിന്തുണയ്ക്കുന്ന `text`/`input_text` ഭാഗങ്ങളായി മാറുന്നു. അഭ്യർത്ഥന നൽകിയ രണ്ട് ട്രാക്കുകളും വിശ്വസനീയമല്ലാത്ത `client` നിരീക്ഷണങ്ങളായി തുടരുന്നു, വീഡിയോ വിവരിച്ചിട്ടില്ലെന്നും മീഡിയയ്ക്കെതിരെ ടൈംസ്റ്റാമ്പുകൾ പരിശോധിച്ചിട്ടില്ലെന്നും വ്യക്തമായ മുന്നറിയിപ്പ് നൽകുന്നു. നിലവിലുള്ള 256-cue/64-KiB മൊത്തവും ഓരോ ക്യൂ ബജറ്റും രണ്ട് ട്രാക്കുകളിലുടനീളം ഒരുമിച്ച് ബാധകമാണ്; ടൈംസ്റ്റാമ്പുകൾ ബ്രോക്കറുടെ 600 സെക്കൻഡ് സീലിംഗിനും വിതരണം ചെയ്ത ഫോക്കസ് വിൻഡോയ്ക്കും യോജിച്ചതായിരിക്കണം. അസാധുവായ ട്രാക്കുകൾ നിരസിച്ചു, അനിയന്ത്രിതമായ വാചകമായി ഫോർവേഡ് ചെയ്യപ്പെടുന്നില്ല; സാധുവായ ഒരു സഹോദരനെ അവരുടെ സംയോജിത ബജറ്റ് കവിയുന്നില്ലെങ്കിൽ തുടർന്നും ഉപയോഗിക്കാം. Null/empty ഫീൽഡുകൾ ടെക്സ്റ്റ് ചേർക്കുന്നില്ല. ഈ ഫാൾബാക്ക് വഴി മീഡിയ ലഭ്യമാക്കലോ ട്രാൻസ്ക്രിപ്ഷനോ ചേർത്തിട്ടില്ല. ട്രാൻസ്ക്രിപ്റ്റ് എക്സ്റ്റൻഷൻ ഫീൽഡുകൾ ഫാൾബാക്ക് വീഡിയോ കാരിയറിൽ നിന്നും അതിൻ്റെ `video_url`/`source` ഒബ്ജക്റ്റുകളിൽ നിന്നും നീക്കംചെയ്യുന്നു. OpenAI വയർ അനുവദനീയ പട്ടിക കർശനമായി തുടരുന്നു; അജ്ഞാത-നേറ്റീവ് വീഡിയോ കാരിയറുകൾ ലഭ്യമാണ്, കൂടാതെ അറിയപ്പെടുന്ന ടെക്സ്റ്റ്-മാത്രം ലക്ഷ്യങ്ങൾ സുരക്ഷിത മാർക്കറുകൾ നിലനിർത്തുന്നു. ഘടനാപരമായ റിഡക്ഷൻ ഷാഡോകൾ അനുബന്ധ ട്രാൻസ്ക്രിപ്റ്റ് ടെക്സ്റ്റിനെ സംരക്ഷിക്കുന്നു, അതേസമയം യഥാർത്ഥ കോളർ ഉടമസ്ഥതയിലുള്ള അഭ്യർത്ഥന മാറ്റമില്ലാതെ തുടരുന്നു. പ്രാദേശിക പിന്തുണയുള്ള ടാർഗെറ്റുകളും അപ്രാപ്തമാക്കിയ പാലങ്ങളും അവയുടെ നിലവിലുള്ള ബൈപാസ് സ്വഭാവം നിലനിർത്തുന്നു.

അധിക നിലനിർത്തിയ പകർപ്പുകൾ ഒരേ നിരീക്ഷിച്ച-അഭ്യർത്ഥന സിഗ്നൽ ഉപയോഗിക്കുന്നു. റോ പ്രീ-ഗാർഡ്രെയിൽ ക്ലയൻ്റ്-അഭ്യർത്ഥന സ്നാപ്പ്ഷോട്ട്, ഇൻ-മെമ്മറി തീർച്ചപ്പെടുത്താത്ത അഭ്യർത്ഥന, നേരത്തെ നിരസിച്ച അഭ്യർത്ഥന ലോഗ് എന്നിവ വീഡിയോ ഭാഗങ്ങളിൽ ട്രാൻസ്ക്രിപ്റ്റ് ഫീൽഡുകൾ ഘടനാപരമായി മാറ്റിസ്ഥാപിക്കുന്നു; പൈപ്പ്ലൈൻ ഘട്ടങ്ങളിലൂടെയും സന്ദർഭ ഹാൻഡ്ഓഫിലൂടെയും സമന്വയിപ്പിച്ച സ്ട്രിംഗ് പ്രോംപ്റ്റുകൾ പെർസിസ്റ്റഡ്-അഭ്യർത്ഥന-ബോഡി സിങ്കിൽ പുനഃക്രമീകരിക്കപ്പെടുന്നു. മനപ്പൂർവ്വം നിരസിച്ച വാചകം പുനർനിർമ്മിക്കുന്നതിനുപകരം `previous_response_id` തുടർച്ചയെ പരാജയപ്പെടുത്തുന്നതാണ് `video_content_removed` മാർക്കർ. ഒരു നിരീക്ഷിച്ച അഭ്യർത്ഥന ലോഗിംഗ് ചെയ്യുന്നതിനുമുമ്പ് അതിൻ്റെ ഓരോ ഭാഗവും പുനഃസ്ഥാപിക്കുന്നതിനുള്ള ഷാഡോ നഷ്ടപ്പെടുകയോ അല്ലെങ്കിൽ പിന്നീടുള്ള അഭ്യർത്ഥന മ്യൂട്ടേഷനുകൾക്ക് ശേഷം നിരവധി വീഡിയോ ഷാഡോകളിൽ ഒന്ന് പോലും പൊരുത്തപ്പെടുന്നില്ലെങ്കിലോ, ഭാഗികമായി പുനർനിർമ്മിച്ച ട്രാൻസ്ക്രിപ്റ്റ് നിലനിർത്തുന്നതിന് പകരം നിലനിർത്തിയ അഭ്യർത്ഥന ബോഡി പൂർണ്ണമായും ഒഴിവാക്കപ്പെടും.

നിരീക്ഷിച്ച ഒരു അഭ്യർത്ഥനയ്ക്കായി, ഒരു മാതൃകാ പ്രതികരണം ട്രാൻസ്ക്രിപ്റ്റിൻ്റെ ഏതെങ്കിലും ഭാഗത്തെ ഘടനാപരമായ ക്യൂ അതിർത്തിയില്ലാതെ ഉദ്ധരിച്ചേക്കാം. അതിനാൽ അതിൻ്റെ സ്ഥിരമായ കോൾ-ലോഗ് `responseBody` ഒരു ഒഴിവാക്കൽ മാർക്കർ ഉപയോഗിച്ച് മാറ്റിസ്ഥാപിക്കുന്നു; വിശദമായ പൈപ്പ് ലൈൻ ആർട്ടിഫാക്റ്റ് (അതിൽ upstream/client ബോഡികളും സ്ട്രീം ചങ്കുകളും ഉൾപ്പെടാം) നിലനിർത്തിയിട്ടില്ല. സെമാൻ്റിക്, ഐഡംപോട്ടൻസി, റീസണിംഗ്-റിപ്ലേ കാഷെകൾ ആ അഭ്യർത്ഥനയ്ക്കായി വായിക്കുകയും എഴുതുകയും ചെയ്യുന്നു. ദാതാവിൻ്റെ അഭ്യർത്ഥനയും ക്ലയൻ്റ്-ദൃശ്യമായ പ്രതികരണവും മാറ്റമില്ലാതെ തുടരുന്നു. വിശദമായ ആർട്ടിഫാക്റ്റ് ഒഴിവാക്കുമ്പോൾ താത്കാലിക ബഫറിൽ നിന്ന് ആദ്യകാല കീപ്പലൈവ് ബൈറ്റുകൾ ചോർന്നുപോകുന്നു. Kiro യുടെ തെറ്റായ രൂപത്തിലുള്ള EventStream മുന്നറിയിപ്പ് പേലോഡ് ബൈറ്റിൻ്റെ എണ്ണം മാത്രമേ റിപ്പോർട്ട് ചെയ്യുന്നുള്ളൂ, ഒരിക്കലും അതിൻ്റെ ഉള്ളടക്കമോ JSON പാർസറിൻ്റെ അസംസ്കൃത പിശകോ അല്ല. ബന്ധമില്ലാത്ത എല്ലാ provider/plugin ഡയഗ്നോസ്റ്റിക്സും ഓഡിറ്റ് ചെയ്തതായി ഇത് അവകാശപ്പെടുന്നില്ല; വിശാലമായ നിലനിർത്തിയ-സിങ്ക് സ്വീപ്പ് #11658 ൽ ട്രാക്ക് ചെയ്യപ്പെടുന്നു.

ആന്തരിക `/api/modality-bridge/video/drilldown` ജീവിതചക്രം ഒരു പ്രത്യേക loopback/token-authenticated കാഷെ സബ്സ്ട്രേറ്റാണ്. എല്ലാ പ്രവർത്തനത്തിനും ഒരു കാനോനിക്കൽ അതാര്യമായ പ്രിൻസിപ്പൽ ID ആവശ്യമാണ്. ഒരു പ്രൊഡക്ഷൻ കോളർ പ്രവർത്തനക്ഷമമാക്കുന്നതിന് മുമ്പ്, അത് ആധികാരികമായ വാടകക്കാരനിൽ നിന്ന് ആ ID നേടിയിരിക്കണം കൂടാതെ ക്ലയൻ്റ് തിരഞ്ഞെടുത്ത മൂല്യം ഒരിക്കലും ഫോർവേഡ് ചെയ്യരുത്. കാഷെ കീകൾ ആ പ്രിൻസിപ്പലിനെ കാനോനിക്കൽ സെഷനിലേക്കും വീഡിയോ-റഫറൻസ് IDs യിലേക്കും ബന്ധിപ്പിക്കുന്നു, അവയുടെ SHA-256-derived കീകൾ മാത്രം സംഭരിക്കുന്നു, കൂടാതെ ഒരേ പ്രിൻസിപ്പലിലേക്ക് റീഡുകളും ഇല്ലാതാക്കലും സ്കോപ്പ് ചെയ്യുന്നു. കാഷെ ഓരോ എൻട്രിയിലും പരമാവധി 16 ഡിറൈവ്ഡ് JPEG ഫ്രെയിമുകൾ സംഭരിക്കുന്നു, പത്ത് മിനിറ്റിന് ശേഷം അവ കാലഹരണപ്പെടും, കൂടാതെ പരിമിതപ്പെടുത്തിയ `start`/`end` റീഡുകൾ അല്ലെങ്കിൽ വ്യക്തമായ സെഷൻ ഇല്ലാതാക്കൽ പിന്തുണയ്ക്കുന്നു.

ഓരോ പ്രിൻസിപ്പലും 16 എൻട്രികളിലും 64 MiB കാനോനിക്കൽ JPEG ഡാറ്റയിലും പരിമിതപ്പെടുത്തിയിരിക്കുന്നു. ആ പരിധികൾ ആഗോള 64-entry/256 MiB പരിധിയിൽ നിന്ന് സ്വതന്ത്രമാണ്: ആഗോള LRU കുടിയൊഴിപ്പിക്കലിന് മുമ്പ് പ്രിൻസിപ്പലിൻ്റെ ഏറ്റവും കുറച്ച്-അടുത്തിടെ ഉപയോഗിച്ച എൻട്രികൾ മാത്രമേ പ്രിൻസിപ്പൽ ക്വാട്ട സമ്മർദ്ദം ഒഴിപ്പിക്കുന്നുള്ളൂ. കാലഹരണപ്പെട്ട എൻട്രികൾ കാഷെ പ്രവർത്തനത്തെക്കുറിച്ചുള്ള പ്രിൻസിപ്പൽ, ഗ്ലോബൽ അക്കൗണ്ടിംഗിൽ നിന്ന് സ്വീപ്പ് ചെയ്യപ്പെടുന്നു, അതേസമയം റദ്ദാക്കലും മൂല്യനിർണ്ണയ പരാജയവും ഭാഗികമായി മാറ്റിസ്ഥാപിക്കില്ല.

ബൗണ്ടഡ് ഫുൾ-ഇമേജ് `sharp` ഡീകോഡ് സമയത്ത് മുന്നറിയിപ്പ് നൽകുന്ന നോൺ-കാനോനിക്കൽ Base64, അധിക പാഡിംഗ്, നോൺ-ജെപിഇജി മീഡിയ, വികലമായ അല്ലെങ്കിൽ വെട്ടിച്ചുരുക്കിയ JPEGs, JPEGs എന്നിവ കാഷെ നിരസിക്കുന്നു. ഇത് ഓരോ അംഗീകൃത ചിത്രത്തെയും ഒരു കാനോനിക്കൽ JPEG ആയി വീണ്ടും എൻകോഡ് ചെയ്യുന്നു, കോളർ ഫീൽഡുകളെ വിശ്വസിക്കുന്നതിനുപകരം ഡീകോഡ് ചെയ്ത ബൈറ്റുകളിൽ നിന്ന് വീതിയും ഉയരവും നേടുന്നു, കൂടാതെ പിന്തുടരുന്ന പോളിഗ്ലോട്ട് ബൈറ്റുകൾ നിലനിർത്തുന്നതിന് പകരം അവ നിരസിക്കുന്നു. ബൗണ്ടഡ് കാനോനിക്കൽ കംപ്രസ്ഡ് ബഫർ മാത്രമാണ് രണ്ട് ക്വാട്ടകളിലേക്കും ചാർജ് ചെയ്യുന്നത്. JSON വയർ പരിധിയിൽ 32 MiB ഡീകോഡ്-ഇൻപുട്ട് സീലിംഗിനുള്ള Base64 ഓവർഹെഡ് ഉൾപ്പെടുന്നു. സംഭരിച്ച ഓരോ ഡെറിവേഷനും അതിൻ്റെ സാധുതയുള്ള JPEG format/resolution, സാമ്പിൾ പോളിസി, ഡെറിവേഷൻ പതിപ്പ്, സൃഷ്ടി സമയം, സെർവർ-കമ്പ്യൂട്ടുചെയ്ത ഉള്ളടക്ക ഹാഷ്, ഹാഷ് ചെയ്ത പാരൻ്റ് റഫറൻസും കൂടാതെ വിശ്വസനീയ കോളറിൻ്റെ പാരൻ്റ്-ഉള്ളടക്ക ഹാഷും രേഖപ്പെടുത്തുന്നു. ആറ്റോമിക് കാഷെ കമ്മിറ്റിന് മുമ്പ് അസിൻക്രണസ് decode/hash ഘട്ടങ്ങൾക്കിടയിൽ റദ്ദാക്കൽ പരിശോധിക്കുന്നു.

രണ്ടാമത്തെ വീഡിയോ download/extraction. കൂടാതെ, വിജയകരമായ വിഷ്വൽ വിശകലനത്തിന് ശേഷം മാത്രമേ പ്രൊഡക്ഷൻ പ്രൊഡ്യൂസർ ഇതിനകം ലഭിച്ച ബ്രോക്കർ ഫ്രെയിമുകൾ വീണ്ടും ഉപയോഗിക്കുകയുള്ളൂ, ഇതിന് ഓപ്പറേറ്റർ `modalityBridgeVideoDrilldownEnabled=true`, കർശനമായ പെർ-പാർട്ട് `drilldown: true`, ഒരു ആധികാരികമായ API-കീ റെക്കോർഡ് ID എന്നിവ ആവശ്യമാണ്. ക്ലയൻ്റ് പ്രഖ്യാപിച്ച principal/session മൂല്യങ്ങൾ ഒരിക്കലും ഉടമസ്ഥാവകാശം സ്ഥാപിക്കുന്നില്ല. മൂന്ന് വ്യവസ്ഥകളും കൂടാതെ അത് ഹാഷ് ചെയ്യുകയോ വലുപ്പം മാറ്റുകയോ അധിക ഫ്രെയിമുകൾ നിലനിർത്തുകയോ ചെയ്യുന്നില്ല. നിലനിർത്തൽ പരാജയം ഉപയോഗയോഗ്യമായ ദൃശ്യ പ്രതികരണത്തെ സംരക്ഷിക്കുന്നു. സമ്മതമുള്ള അഭ്യർത്ഥനകൾ മുഴുവൻ-വീഡിയോ ഫല കാഷെ മറികടക്കുന്നതിനാൽ കാഷെ ചെയ്ത ഫലങ്ങൾ ഒരിക്കലും ഹാൻഡിൽ റീപ്ലേ ചെയ്യില്ല.

വിജയകരമായ JSON, SSE പ്രതികരണങ്ങൾ ബൗണ്ടഡ് `x-omniroute-video-drilldown` ഹെഡറിൽ പരമാവധി നാല് അതാര്യമായ ഹാൻഡിലുകളെ തുറന്നുകാട്ടുന്നു. അംഗീകൃത ബ്രൗസർ ഒറിജിനുകൾക്ക് CORS ഒറിജിൻ നയം വിശാലമാക്കാതെ തന്നെ ആ തലക്കെട്ട് വായിക്കാൻ കഴിയും. പുതിയ ഹാൻഡിലുകൾ `v1.<32-byte random base64url token>` ഉപയോഗിക്കുന്നു, രജിസ്ട്രി അവരുടെ SHA-256 ഹാഷുകൾ മാത്രം നിലനിർത്തുന്നു. reader/header പാഴ്സർ ലെഗസി 64-ഹെക്സ് ടോക്കണുകളും സ്വീകരിക്കുന്നു. അംഗീകൃത പൊതു ഉപഭോക്താവ് `GET /api/v1/video-bridge/drilldown?handle=...` ആണ്, സ്വതന്ത്രമായി `modalityBridgeVideoDrilldownRemoteEnabled=true` ഗേറ്റ് ചെയ്യുന്നു. ലെഗസി `OMNIROUTE_VIDEO_BRIDGE_DRILLDOWN_REMOTE_ENABLED` env ഫാൾബാക്ക് പ്രവർത്തനക്ഷമമാക്കിയിരിക്കുമ്പോൾ പോലും വ്യക്തമായ സ്ഥിരതയുള്ള തെറ്റായ അസാധുവാക്കൽ ആക്സസ്സ്. ഉൽപ്പാദന നിലനിർത്തലിന് സമാനമായ ലെഗസി `OMNIROUTE_VIDEO_BRIDGE_DRILLDOWN_ENABLED` ഫാൾബാക്ക് ഉണ്ട്. രണ്ട് ഫാൾബാക്കുകളും ഡിഫോൾട്ട് ഓഫ്.

ഉപഭോക്താവ് ആധികാരിക കീയിൽ നിന്ന് ഉടമസ്ഥാവകാശം നേടുകയും കീ നയം പ്രയോഗിക്കുകയും ചെയ്യുന്നു: GET, DELETE എന്നിവയും `/v1`, `/api/v1` അപരനാമങ്ങൾ ഉൾപ്പെടെ `video` എൻഡ്പോയിൻ്റ് വിഭാഗത്തിൽ പെടുന്നു. ശൂന്യമല്ലാത്ത എൻഡ്പോയിൻ്റ് അനുവദനീയമായ കീകളിൽ `video` ഉൾപ്പെടുത്തണം; അനിയന്ത്രിതമായ കീകൾ പൊരുത്തപ്പെടുന്നു. അറിയാത്തതും കാലഹരണപ്പെട്ടതും മറ്റൊരു കീയുടെ ഹാൻഡിലുകൾക്കും ഉപഭോക്താവ് അതേ 404 തിരികെ നൽകുന്നു. ഇത് `variant=preview|standard|detail` (പരമാവധി JPEG അളവ് 320/640/1280, ഒരിക്കലും ഉയർത്തിയിട്ടില്ല), `limit=1..8` (അല്ലെങ്കിൽ ലെഗസി `frames` അപരനാമം, രണ്ടും അല്ല), പൂജ്യം അടിസ്ഥാനമാക്കിയുള്ള `page`, കൂടാതെ ഓപ്ഷണൽ `start`/`end` ഫോക്കസ് സെക്കൻഡുകൾ എന്നിവ സ്വീകരിക്കുന്നു. ഡ്യൂപ്ലിക്കേറ്റ് ക്വറി കീകളും റിവേഴ്സ്ഡ് ഫോക്കസ് വിൻഡോകളും നിരസിച്ചു. തിരികെ നൽകിയ ഓരോ വേരിയൻ്റിനും അതിൻ്റെ യഥാർത്ഥ ഉള്ളടക്കത്തിൻ്റെയും യഥാർത്ഥ റെസല്യൂഷൻ മെറ്റാഡാറ്റയുടെയും ഒരു ഹാഷ് ഉണ്ട്, നിലനിർത്തിയ ഉറവിടവുമായി ലിങ്ക് ചെയ്തിരിക്കുന്നു. അധിക നിലനിർത്തിയ പകർപ്പുകളായി സൂക്ഷിക്കുന്നതിനുപകരം വായനയിൽ നിന്നാണ് വേരിയൻ്റുകൾ ഉരുത്തിരിഞ്ഞത്. Base64/envelope ഉൾപ്പെടെയുള്ള JSON പ്രതികരണം 32 MiB ആയി പരിമിതപ്പെടുത്തിയിരിക്കുന്നു; ഒരു വലിയ പേജ് 413 നൽകുന്നു, ക്ലയൻ്റ് കുറച്ച് ഫ്രെയിമുകൾ അഭ്യർത്ഥിക്കണം. തിരിച്ച് വരുന്നതിന് മുമ്പ് ഓരോ വലുപ്പം മാറ്റുന്നതിനും ഹാൻഡിൽ സാധുത പുനഃപരിശോധിക്കുന്നതിനും ചുറ്റുമുള്ള പരിശോധന റദ്ദാക്കൽ വായിക്കുന്നു. ഉടമയുടെ `DELETE` ബുദ്ധിശൂന്യമാണ്; ഇല്ലാതാക്കൽ അല്ലെങ്കിൽ TTL കാലഹരണപ്പെടൽ നിലനിർത്തിയ ഉറവിടവും ഉപയോഗ അക്കൗണ്ടിംഗും റിലീസ് ചെയ്യുന്നു.

പങ്കിട്ട സ്റ്റോർ പ്രോസസ്സ്-ലോക്കൽ ആണ്: പുനരാരംഭിക്കുമ്പോൾ ഹാൻഡിലുകൾ കാലഹരണപ്പെടും കൂടാതെ സ്വതന്ത്ര OmniRoute പ്രോസസ്സുകൾക്കിടയിൽ കൈമാറ്റം ചെയ്യാനാകില്ല. മാനേജ്മെൻ്റ് സ്ഥിതിവിവരക്കണക്കുകൾ ഫലപ്രദമായ നിലനിർത്തൽ/വിദൂര നയം തുറന്നുകാട്ടുന്നു, കൂടാതെ സംഗ്രഹം നിലനിർത്തിയ entries/bytes മാത്രം, ഒരിക്കലും മീഡിയ, റഫറൻസുകൾ, പ്രധാന IDs അല്ലെങ്കിൽ ഹാൻഡിലുകൾ. വീഡിയോ ക്രമീകരണ പാനൽ ആ മൂല്യങ്ങൾ കാണിക്കുന്നു, രണ്ട് സമ്മത സ്വിച്ചുകളും നിലനിൽക്കും. ഈ നടപ്പാക്കൽ ഡോക്യുമെൻ്റേഷൻ തത്സമയ വിന്യാസമോ പ്രമോഷൻ തെളിവോ അല്ല; യഥാർത്ഥ മോഡൽ സ്വീകാര്യത പ്രത്യേകം ട്രാക്ക് ചെയ്യുന്നു.

കോൺഫിഗർ ചെയ്ത വീഡിയോ മോഡലിനൊപ്പം ഫ്രെയിമുകൾ തുടർച്ചയായി അടിക്കുറിപ്പ് നൽകിയിരിക്കുന്നു. ഒരു ശൂന്യമായ വീഡിയോ അസാധുവാക്കൽ വിഷൻ ക്രമീകരണം അവകാശമാക്കുന്നു; രണ്ടും ശൂന്യമാണെങ്കിൽ, വിഷൻ ഓട്ടോ-റൗട്ടർ ഫലപ്രദമായ കാഴ്ച-പ്രാപ്തിയുള്ള മോഡൽ തിരഞ്ഞെടുക്കുന്നു. വിജയകരമായ അടിക്കുറിപ്പുകൾ യഥാർത്ഥ ഭാഗത്തെ സ്ഥിരതയുള്ള `[Video description:` പ്രിഫിക്സ് ഉപയോഗിച്ച് മാറ്റിസ്ഥാപിക്കുന്നു, അത് വാചകത്തെ വിശ്വസനീയമല്ലാത്ത മീഡിയയിൽ നിന്ന് ലഭിച്ച നിരീക്ഷണമായി അടയാളപ്പെടുത്തുകയും മീഡിയയിൽ കാണുന്ന നിർദ്ദേശങ്ങൾ പാലിക്കരുതെന്ന് ഡൗൺസ്ട്രീം മോഡലുകളോട് പറയുകയും ചെയ്യുന്നു. ഫ്രെയിം-ക്യാപ്ഷൻ കാഷെ കീകളിൽ JPEG ബൈറ്റുകൾ, പ്രോംപ്റ്റ്, ടൈംസ്റ്റാമ്പ്, ഫലപ്രദമായ മോഡൽ എന്നിവ ഉൾപ്പെടുന്നു; വിജയകരമായ അടിക്കുറിപ്പുകൾ മാത്രമേ കാഷെ ചെയ്തിട്ടുള്ളൂ. കാഷെ എൻട്രികൾ ഒരു ഫാൾബാക്ക് മോഡൽ ഉൾപ്പെടെ യഥാർത്ഥ വിജയകരമായ പ്രൊഡ്യൂസർ മോഡൽ നിലനിർത്തുന്നു; വ്യത്യസ്ത മോഡലുകൾ വ്യത്യസ്ത ഫ്രെയിമുകൾ നിർമ്മിക്കുമ്പോൾ ബ്രിഡ്ജ് `mixed` റിപ്പോർട്ട് ചെയ്യുന്നു. ഒരു കാഷെ ഹിറ്റ് ആ പ്രൊഡ്യൂസർ ഐഡൻ്റിറ്റിയെ അഭ്യർത്ഥിച്ച റൂട്ടിംഗ് പ്ലാൻ ആയി വീണ്ടും ലേബൽ ചെയ്യുന്നതിന് പകരം വീണ്ടും ഉപയോഗിക്കുന്നു. ഔട്ട്പുട്ട് — പ്രോംപ്റ്റ്, ഫലപ്രദമായ മോഡൽ, സാമ്പിൾ പോളിസി, ഫ്രെയിം കൗണ്ട്, സെമാൻ്റിക് അനാലിസിസ് മോഡ്, നോർമലൈസ്ഡ് ഫോക്കസ് സൂചനയുടെ SHA-256 ഫിംഗർപ്രിൻ്റ്, ഫോക്കസ് വിൻഡോ, `transcript`, `audioTranscript`, കൂടാതെ കോൺടാക്റ്റ്-ഷീറ്റ് ഫ്ലാഗ് — എന്നിവ മാറ്റുന്ന എല്ലാ ഇൻപുട്ടിലും പൂർണ്ണ-വീഡിയോ ഫല കാഷെ കീ ചെയ്യുന്നു. വിഷ്വൽ ഡെഡപ്പ് പോളിസി പതിപ്പ്, ത്രെഷോൾഡ്, ബൗണ്ടഡ് കാൻഡിഡേറ്റ്-ഫ്രെയിം കൗണ്ട് എന്നിവ ഫല-കാഷെ കീയിലും മെറ്റാഡാറ്റയിലും വ്യക്തമാണ്; അതിനാൽ ഒരു നയ മാറ്റത്തിന് പഴകിയ പൂർണ്ണ വീഡിയോ വിവരണം വീണ്ടും ഉപയോഗിക്കാൻ കഴിയില്ല. റിസൾട്ട്-കാഷെ v4 മെറ്റാഡാറ്റ മോഡും ഫിംഗർപ്രിൻ്റും നിലനിർത്തുന്നു, ഒരിക്കലും അസംസ്കൃത ഉപയോക്തൃ ടാസ്ക് അല്ല. Guardrail മെറ്റാഡാറ്റ അഭ്യർത്ഥിച്ചതും ഫലപ്രദവുമായ വിശകലന മോഡുകൾ റിപ്പോർട്ടുചെയ്യുന്നു; ഉപയോഗയോഗ്യമായ ഉപയോക്തൃ വാചകം ഇല്ലാത്ത ഒരു അഭ്യർത്ഥിച്ച `focused` മോഡ് ഫലപ്രദമായി `full` ആയി റിപ്പോർട്ട് ചെയ്യപ്പെടുന്നു.

ഗാർഡ്റെയിൽ പിന്തുണയ്ക്കുന്ന എല്ലാ വീഡിയോ ഭാഗങ്ങളും എക്സ്ട്രാക്റ്റുചെയ്യുന്നു, പക്ഷേ `modalityBridgeVideoMaxVideos` യിൽ കൂടുതൽ വിവരിക്കുന്നില്ല. `supportsVideo === false` ഉണ്ടെന്ന് തെളിയിക്കപ്പെട്ട ഒരു ടാർഗെറ്റിന്, പരാജയപ്പെട്ടതും അതിരുകടന്നതുമായ വീഡിയോകൾ വ്യക്തമായ സുരക്ഷിത ടെക്സ്റ്റ് മാർക്കറുകളായി മാറുന്നു, അതിനാൽ ഒരു റോ വീഡിയോയും നിലനിൽക്കുന്നില്ല. കഴിവ് അജ്ഞാതമാകുമ്പോൾ, ആ ഭാഗങ്ങൾ അവരുടെ വീഡിയോ കാരിയർ നിലനിർത്തുന്നു; ഏതൊരു ഫാൾബാക്ക് ട്രാൻസ്ക്രിപ്റ്റും മുകളിലുള്ള ബൗണ്ടഡ് ടെക്സ്റ്റ് പരിവർത്തനത്തെ പിന്തുടരുന്നു. `supportsVideo === true` ഉപയോഗിച്ചുള്ള ലക്ഷ്യങ്ങൾ പാലത്തെ മറികടക്കുന്നു. ഡൗൺലോഡ്, ബ്രോക്കർ ക്യൂ, സബ്പ്രോസസുകൾ, അടിക്കുറിപ്പ് കോളുകൾ എന്നിവയിലൂടെ ക്ലയൻ്റ് അഭ്യർത്ഥന അബോർട്ട് സിഗ്നൽ പ്രചരിപ്പിക്കുന്നു; വീഡിയോകൾക്കിടയിൽ നിർത്തുന്നു, അസംസ്കൃത മീഡിയയിൽ ഒരിക്കലും പരാജയപ്പെടില്ല.

ലെഗസി പെർസിസ്റ്റഡ് വീഡിയോ ടൈംഔട്ട് മൂല്യങ്ങൾ 120 സെക്കൻഡിന് മുകളിലുള്ളത് ബ്രോക്കർ ഡെഡ്ലൈനിലേക്ക് ഘടിപ്പിച്ചിരിക്കുന്നു; പരിധിക്ക് മുകളിലുള്ള പുതിയ ക്രമീകരണങ്ങൾ നിരസിക്കപ്പെടും. പ്രാമാണീകരണത്തിനോ റൺടൈം അന്വേഷണത്തിനോ മുമ്പായി `GET /api/modality-bridge/video/runtime` വിശ്വസനീയമായ സ്റ്റാമ്പ്ഡ് ലൂപ്പ്ബാക്ക് ലോക്കാലിറ്റി ആവശ്യമാണ്, തുടർന്ന് മാനേജ്മെൻ്റ് ഓത്ത് ആവശ്യമാണ്. ഇത് `available`, സാനിറ്റൈസ് ചെയ്ത FFmpeg/ffprobe പതിപ്പുകൾ, റൺടൈം ലഭ്യമല്ലാത്തപ്പോൾ ഒരു നിശ്ചിത കാരണം എന്നിവ മാത്രം നൽകുന്നു. ഇൻ്റേണൽ എക്സ്ട്രാക്ഷൻ എൻഡ്പോയിൻ്റ് ഒരു പൊതു അപ്ലോഡ് API അല്ല: ക്യൂ സാച്ചുറേഷൻ `503` പ്ലസ് `Retry-After` നൽകുന്നു, ഒരു കോളർ ഡിസ്കണക്റ്റ് `499` നൽകുന്നു, സ്ഥിരമായ ബ്രോക്കർ ഡെഡ്ലൈൻ `504` നൽകുന്നു. പരിവർത്തനം ചെയ്ത പ്രതികരണങ്ങൾ വിഷൻ അല്ലെങ്കിൽ ഓഡിയോ സെഗ്മെൻ്റുകൾ നീക്കം ചെയ്യാതെ സെൻട്രൽ `x-omniroute-modality-bridge` ഹെഡറിലേക്ക് `video->text;model=<visionModel>;parts=<videos>` ചേർക്കുന്നു.

### PII മാസ്കർ (`piiMasker.ts`)

ഓടുന്നു**രണ്ടും** ഘട്ടങ്ങൾ.

- **`preCall`** പേലോഡ് ക്ലോൺ ചെയ്യുന്നു, `system`, `messages`, `input`, `prompt` എന്നിവ നടത്തുന്നു (പ്ലെയിൻ സ്ട്രിംഗ് ഇനങ്ങൾ ഉൾപ്പെടെ), `processPII()` ( `@/shared/utils/inputSanitizer` മുതൽ ) സ്ട്രിംഗ് `content`/`text` ഫീൽഡുകളിലേക്ക് പ്രയോഗിക്കുന്നു. `PII_REDACTION_ENABLED=true` ചെയ്യുമ്പോൾ, കണ്ടെത്തിയ PII ഔട്ട്ബൗണ്ട് പേലോഡിൽ റിഡാക്റ്റ് ചെയ്യപ്പെടും. ഇത് `INPUT_SANITIZER_MODE` ൽ നിന്ന് സ്വതന്ത്രമാണ് (ഇത് പ്രോംപ്റ്റ്-ഇഞ്ചക്ഷൻ നയം മാത്രം നിയന്ത്രിക്കുന്നു). റീഡക്ഷൻ ഓഫായിരിക്കുമ്പോൾ, കോൾ റെക്കോർഡ് ഡിറ്റക്ഷൻ കൗണ്ടുകൾ ഉള്ളടക്കം മാറ്റിയെഴുതാതെ തന്നെ.
- **`postCall`** പ്രതികരണത്തെ ആഴത്തിൽ ക്ലോൺ ചെയ്യുന്നു, `sanitizePIIResponse()` കൂടാതെ പ്രതികരണങ്ങൾ-API-ആകൃതിയിലുള്ള മാസ്കറും പ്രവർത്തിപ്പിക്കുന്നു (`maskResponsesOutput` — `output_text`, `output[].content[].text` എന്നിവ ഉൾക്കൊള്ളുന്നു). എന്തെങ്കിലും തിരുത്തൽ സംഭവിക്കുകയാണെങ്കിൽ, പരിഷ്കരിച്ച പ്രതികരണം ഒറിജിനലിനെ മാറ്റിസ്ഥാപിക്കും.

കാവൽപ്പാത ഒരിക്കലും തടയുന്നില്ല; ഇത് വ്യാഖ്യാനിക്കുക (`meta.detections`, `meta.redacted`) അല്ലെങ്കിൽ വീണ്ടും എഴുതുന്നു.

#### ഓരോ തരം തിരഞ്ഞെടുക്കലും ഇഷ്ടാനുസൃത പാറ്റേണുകളും കണ്ടെത്തൽ കൗണ്ടറുകളും

**ഡാഷ്ബോർഡ് → ക്രമീകരണങ്ങൾ → സെക്യൂരിറ്റി → PII മാസ്കിംഗ്** മാസ്ക് ചെയ്തത്_ എന്താണെന്ന് തിരഞ്ഞെടുക്കുന്നു. ഇത് മാസ്കിംഗ് ഓണാക്കുന്നില്ല: അത് ഇപ്പോഴും `PII_REDACTION_ENABLED` (അഭ്യർത്ഥന), `PII_RESPONSE_SANITIZATION` (പ്രതികരണം + SSE) എന്നിവയാണ്.

- **ഓരോ തരത്തിലുള്ള തിരഞ്ഞെടുപ്പ്** — ബിൽറ്റ്-ഇൻ ഐഡികൾ `src/shared/constants/piiTypes.ts` (`PII_BUILTIN_TYPES`) ൽ ലിസ്റ്റ് ചെയ്തിരിക്കുന്നു. സജ്ജീകരിക്കാത്തത് അർത്ഥമാക്കുന്നത് എല്ലാ തരത്തിലുമുള്ള (ഈ ക്രമീകരണത്തിന് മുമ്പുള്ള പെരുമാറ്റം) എന്നാണ്. അഭ്യർത്ഥന എഞ്ചിൻ്റെ `ssn_us` പാറ്റേൺ `ssn` ലേക്ക് മാപ്പ് ചെയ്യുന്നു. ടെംപ്ലേറ്റുകൾ (മിനിമൽ, സ്റ്റാൻഡേർഡ്, ഫിനാൻഷ്യൽ, ബ്രസീലിയൻ, USA, GDPR, POPIA, പൂർണ്ണം) UI യിലെ ചെക്ക്ബോക്സുകൾ മാത്രം പൂരിപ്പിക്കുക.
- **GDPR, POPIA ഐഡൻ്റിഫയറുകൾ** EU, ദക്ഷിണാഫ്രിക്കൻ വ്യക്തിഗത ഐഡൻ്റിഫയറുകൾ എന്നിവ ഉൾക്കൊള്ളുന്ന — പന്ത്രണ്ട് ബിൽറ്റ്-ഇൻ ഐഡികൾ (ചുവടെയുള്ള പട്ടിക). പ്രതികരണ സാനിറ്റൈസറും (`src/lib/piiSanitizer.ts`) അഭ്യർത്ഥന മാസ്കറും (`src/shared/utils/inputSanitizer.ts`) ഉപയോഗിക്കുന്ന `src/shared/utils/piiPatterns.ts` എന്ന ഒരു ടേബിളിലാണ് അവയുടെ റീജക്സുകളും വാലിഡേറ്ററുകളും അധികാരപരിധിയിലുള്ള ടാഗുകളും താമസിക്കുന്നത്. ഒരു പൊരുത്തം അതിൻ്റെ വാലിഡേറ്റർ സ്വീകരിക്കുമ്പോൾ മാത്രമേ അത് തിരുത്തപ്പെടുകയുള്ളൂ; നഗ്നമായ അക്കങ്ങൾ ഒരിക്കലും മതിയാകില്ല. ഈ ഐഡികൾ ഉണ്ടാകുന്നതിന് മുമ്പ് ഒരു ഇടുങ്ങിയ തിരഞ്ഞെടുപ്പ് സംരക്ഷിച്ച ഒരു ഓപ്പറേറ്റർ, പുതിയ ഐഡികൾ ടിക്ക് ചെയ്യപ്പെടുന്നതുവരെ അതിൻ്റെ സ്വഭാവം നിലനിർത്തുന്നു.
- **ഇഷ്ടാനുസൃത പാറ്റേണുകൾ** — 20 വരെ റീജക്സ് അല്ലെങ്കിൽ വൈൽഡ്കാർഡ് പാറ്റേണുകൾ (`*` = 64 നോൺ-വൈറ്റ്സ്പേസ് പ്രതീകങ്ങൾ വരെ, `?` = ഒന്ന് വരെ). മത്സരങ്ങൾ `[CUSTOM_REDACTED]` ആയി മാറുന്നു. എല്ലാ പാറ്റേണും `compilePiiCustomPattern()` (`src/shared/utils/piiCustomPatterns.ts`) വഴി കടന്നുപോകുന്നു: പരമാവധി 500 പ്രതീകങ്ങൾ, `g i m s u` ലേക്ക് പരിമിതപ്പെടുത്തിയിരിക്കുന്ന ഫ്ലാഗുകൾ കംപൈൽ ചെയ്യണം, `safe-regex` (ദുരന്തമായ ബാക്ക്ട്രാക്കിംഗ്) കടന്നുപോകണം, കൂടാതെ ഒരു ശൂന്യമായ സ്ട്രിംഗുമായോ റീഡക്ഷൻ പ്ലെയ്സ്ഹോൾഡറുമായോ പൊരുത്തപ്പെടരുത്. സംരക്ഷിച്ചിരിക്കുമ്പോഴും പരീക്ഷിക്കുമ്പോഴും പരാജയപ്പെടുന്ന ഒരു പാറ്റേൺ നിരസിക്കപ്പെടും, കൂടാതെ പരാജയപ്പെട്ട ഒരു സംഭരിച്ച വരി കംപൈൽ ചെയ്യുന്നതിനുപകരം റൺടൈമിൽ ഒഴിവാക്കപ്പെടും. മാസ്കിംഗ് ഓണായിരിക്കുമ്പോൾ മാത്രമേ ഇഷ്ടാനുസൃത പാറ്റേണുകൾ പ്രവർത്തിക്കൂ.
- **ഡിറ്റക്ഷൻ കൗണ്ടറുകൾ** ഓരോ തരത്തിലുള്ള — എണ്ണങ്ങൾ (ഒരിക്കലും പൊരുത്തപ്പെടാത്ത മൂല്യങ്ങൾ), മെമ്മറിയിൽ സൂക്ഷിക്കുകയും പുനരാരംഭിക്കുമ്പോൾ പുനഃസജ്ജമാക്കുകയും ചെയ്യുന്നു (`src/lib/pii/piiDetectionStats.ts`). മാസ്കിംഗ് ഓണായിരിക്കുമ്പോൾ മാത്രമേ അവ വർദ്ധിക്കുകയുള്ളൂ.

ക്രമീകരണങ്ങൾ `key_value` പട്ടികയിൽ (നാംസ്പേസ് `pii_settings`, `src/lib/db/piiSettings.ts`) തത്സമയവും 1 സെ കാഷെ വഴി വായിക്കുകയും ചെയ്യുന്നു. API:

| Method | Path                     | ഉദ്ദേശ്യം                                                                                             |
| ------ | ------------------------ | ----------------------------------------------------------------------------------------------------- |
| `GET`  | `/api/settings/pii`      | ഫ്ലാഗ് നില, `enabledTypes`, `customPatterns`, ഡിറ്റക്ഷൻ കൗണ്ടറുകൾ                                     |
| `PUT`  | `/api/settings/pii`      | `enabledTypes` (`null` = എല്ലാം) ഒപ്പം/അല്ലെങ്കിൽ `customPatterns` മാറ്റിസ്ഥാപിക്കുന്നു               |
| `POST` | `/api/settings/pii/test` | പരമാവധി 8 KB വരെയുള്ള ഒരു സാമ്പിളിനെതിരെ ഒരു പാറ്റേൺ ഡ്രൈ-റൺ ചെയ്യുന്നു; ഒന്നും സംഭരിക്കപ്പെടുന്നില്ല |

മൂന്നിനും മാനേജ്മെൻ്റ് ഓത്ത് ആവശ്യമാണ് കൂടാതെ Zod (`src/shared/validation/schemas/piiSettings.ts`) ഉപയോഗിച്ച് ബോഡി സാധൂകരിക്കുകയും ചെയ്യുന്നു. ലോഗിൻ പ്രവർത്തനരഹിതമാക്കിയപ്പോൾ (`requireLogin=false`) `GET`, ടെസ്റ്റ് എൻഡ്പോയിൻ്റ് തുറന്നിരിക്കുന്നു, പക്ഷേ `PUT` ഇപ്പോഴും ഒരു ഡാഷ്ബോർഡ് സെഷൻ, `manage` -scope API കീ, റൈറ്റ് സ്കോപ്പോ അതിലും ഉയർന്നതോ ആയ `oma_` ആക്സസ് ടോക്കൺ അല്ലെങ്കിൽ ലൂപ്പ്ബാക്കിൽ നിന്ന് അയച്ച CLI ടോക്കൺ അല്ലെങ്കിൽ ഇൻ്റേണൽ-സർവീസ് ടോക്കൺ എന്നിവ ആവശ്യമാണ്.

അക്കങ്ങൾ മാത്രമുള്ള ഫോർമാറ്റുകൾ ഓർഡർ നമ്പറുകളും ബിൽഡ് നമ്പറുകളും ടൈംസ്റ്റാമ്പുകളും കൂട്ടിമുട്ടുന്നതിനാൽ, ഏറ്റവും ദുർബലമായവയ്ക്ക് (`za_vat`, `za_tax_ref`) കീവേഡ് ക്യൂ ആവശ്യമാണ്, കൂടാതെ വെറും പത്തക്ക `0..` നമ്പർ ദക്ഷിണാഫ്രിക്കൻ ഫോൺ നമ്പറായി കണക്കാക്കില്ല. സ്പേസ്ഡ് IBANs (`GB29 NWBK ...`) പൊരുത്തപ്പെടുന്നില്ല. സ്ട്രീമിംഗ് പാതയിൽ ക്യൂ നിലവിലെ ചങ്കിനുള്ളിൽ മാത്രം നോക്കുന്നു. ഐഡികൾ ജനറിക് ഫോൺ പാറ്റേണുകളേക്കാൾ മുന്നിലാണ്, അതിനാൽ സാധുതയുള്ള ഒരു ഐഡൻ്റിഫയർ അതിൻ്റേതായ പ്ലെയ്സ്ഹോൾഡർ (`[IBAN_REDACTED]`, `[NL_BSN_REDACTED]`, ...) സൂക്ഷിക്കുന്നു. `gdpr`, `popia` ടെംപ്ലേറ്റുകൾ യഥാക്രമം EU, ദക്ഷിണാഫ്രിക്കൻ ഐഡികൾ തിരഞ്ഞെടുക്കുന്നു. മാസ്കിംഗ് തന്നെ ഓപ്റ്റ്-ഇൻ ആയി നിലകൊള്ളുന്നു (ഹാർഡ് റൂൾ #20): ഇവിടെ ഒന്നും ഒരു ഫീച്ചർ-ഫ്ലാഗ് ഡിഫോൾട്ടിനെ മാറ്റുന്നു.

### പ്രോംപ്റ്റ് ഇഞ്ചക്ഷൻ (`promptInjection.ts`)

ഉപയോക്താവ് നൽകിയ ഉള്ളടക്കത്തിലെ എതിരാളി ഘടനകൾ കണ്ടെത്തുകയും കോൺഫിഗർ ചെയ്ത
നയം നടപ്പിലാക്കുകയും ചെയ്യുന്നു. പെരുമാറ്റം പരിസ്ഥിതി വേരിയബിളുകളും
കൺസ്ട്രക്ടർ ഓപ്ഷനുകളും നിയന്ത്രിക്കുന്നു:

| ക്രമീകരണം      | Env var                                                                                                | ഡിഫോൾട്ട് | ഫലം                                                                                                                                                                                                                                              |
| -------------- | ------------------------------------------------------------------------------------------------------ | --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| പ്രവർത്തനക്ഷമം | `INPUT_SANITIZER_ENABLED`                                                                              | `true`    | `false` ആയിരിക്കുമ്പോൾ, ഗാർഡ്റെയിൽ ഷോർട്ട്-സർക്യൂട്ട് ചെയ്യുന്നു.                                                                                                                                                                                |
| മോഡ്           | `INJECTION_GUARD_MODE` / `INPUT_SANITIZER_MODE`                                                        | `warn`    | ഇഞ്ചക്ഷൻ നയം: `block`, `warn`, അല്ലെങ്കിൽ `log`. (ബാക്ക്-കംപാറ്റിബിലിറ്റിക്കായി `redact` സ്വീകരിക്കുന്നു, പക്ഷേ ഇഞ്ചക്ഷൻ ടെക്സ്റ്റ് നീക്കം ചെയ്യുന്നത് **അല്ല**; റിക്ക്വസ്റ്റ് PII പുനഃരേഖപ്പെടുത്തൽ `PII_REDACTION_ENABLED` നിയന്ത്രിക്കുന്നു.) |
| ബ്ലോക്ക് പരിധി | `blockThreshold` ഓപ്ഷൻ / `INPUT_SANITIZER_BLOCK_THRESHOLD` (അപരനാമം `INJECTION_GUARD_BLOCK_THRESHOLD`) | `high`    | തടയാൻ ആവശ്യമായ ഏറ്റവും കുറഞ്ഞ തീവ്രത. ഡിഫോൾട്ടിൽ മീഡിയം നിരീക്ഷണം-മാത്രമാണ്.                                                                                                                                                                     |

**മോഡ് മുൻഗണന** (`getMode`): കോളർ `options.mode` →
`INJECTION_GUARD_MODE` **DB ഫീച്ചർ-ഫ്ലാഗ് ഓവർറൈഡ്** (ഡാഷ്ബോർഡ് →
ക്രമീകരണങ്ങൾ → ഫീച്ചർ ഫ്ലാഗുകൾ) → `INJECTION_GUARD_MODE` env →
`INPUT_SANITIZER_MODE` env → `warn`. അതിനാൽ ഒരു ഡാഷ്ബോർഡ് ഓവർറൈഡ് എൻവ്
വേരിയബിളുകളെ അതിജയിക്കുന്നു, അതായത് ഫീച്ചർ ഫ്ലാഗ്സ് UI പ്രവർത്തിക്കുന്ന
ഗാർഡിനെ തത്സമയം നിയന്ത്രിക്കുന്നു (റീസ്റ്റാർട്ട് ആവശ്യമില്ല). DB റീഡ്
ഫെയിൽ-സേഫ് ആണ്: അത് പിശകായാൽ, ഗാർഡ് എൻവ്-അടിസ്ഥാന പെരുമാറ്റത്തിലേക്ക്
മടങ്ങുന്നു, ഓവർറൈഡ് ഒന്നും സെറ്റ് ചെയ്തിട്ടില്ലെങ്കിൽ പെരുമാറ്റം
എൻവ്-മാത്രം റെസല്യൂഷന് തുല്യമാണ്.

കണ്ടെത്തൽ ഉറവിടങ്ങൾ:

1. `@/shared/utils/inputSanitizer`-ൽ നിന്നുള്ള `sanitizeRequest()` (പൈപ്പ്ലൈനിൽ
   മറ്റിടങ്ങളിലും ഉപയോഗിക്കുന്ന പങ്കിട്ട ഡിറ്റക്ടർ സെറ്റ്).
2. ബിൽറ്റ്-ഇൻ `DEFAULT_GUARD_PATTERNS` (നിലവിൽ `system_override_inline`,
   `markdown_system_block` എന്നിവ, രണ്ടും `high` തീവ്രത).
3. കൺസ്ട്രക്ടർ ഓപ്ഷനുകൾ വഴി പാസ് ചെയ്യുന്ന ഓപ്ഷണൽ `customPatterns`
   (സ്ട്രിംഗുകൾ, റെജക്സ്, അല്ലെങ്കിൽ `{ name, pattern, severity }`
   റെക്കോർഡുകൾ).

`mode === "block"` ആണ് **ഒപ്പം** കുറഞ്ഞത് ഒരു ഡിറ്റക്ഷൻ തീവ്രതാ പരിധിയിൽ
എത്തുന്നുവെങ്കിൽ, `preCall` `{ block: true, message: "Request rejected:
suspicious content detected" }` തിരിച്ചുനൽകുന്നു. `warn`/`log` മോഡുകളിൽ
ഗാർഡ്റെയിൽ ലോഗ് ചെയ്യും, പക്ഷേ കോൾ അനുവദിക്കും. റെജിസ്ട്രി വഴി
കടന്നുപോകാതെ പ്രോംപ്റ്റുകൾ വിലയിരുത്തേണ്ടതുള്ള കോളറുകൾക്കായി ഷേർഡ് ഹെൽപ്പർ
`evaluatePromptInjection()`-ം എക്സ്പോർട്ട് ചെയ്യുന്നു.

**സ്കാൻ പരിധി (v3.8.20):** ഡിറ്റക്ടർ ചേർക്കപ്പെട്ട പ്രോംപ്റ്റ് ടെക്സ്റ്റിന്റെ
**ആദ്യ 16 KB** മാത്രമേ പരിശോധിക്കൂ — `src/shared/utils/inputSanitizer.ts`-ൽ
`MAX_INJECTION_SCAN_BYTES = 16 * 1024` (16 384 ബൈറ്റുകൾ). `detectInjection()`-ഉം
`evaluatePromptInjection()`-ഉം പാറ്റേൺ ലൂപ്പ് റൺ ചെയ്യുന്നതിന് മുമ്പ്
`slice(0, MAX_INJECTION_SCAN_BYTES)` ചെയ്യുന്നു. ഇൻജക്ഷൻ നിർദ്ദേശങ്ങൾ
ഇൻപുട്ടിന്റെ മുകൾഭാഗത്തായിരിക്കും സ്ഥിതിചെയ്യുന്നത്, അതിനാൽ ഡിറ്റക്ഷനെ
ദുർബലപ്പെടുത്താതെ നൂറുകണക്കിന് KB-കളുള്ള പേലോഡുകളിൽ regex CPU/GC
പരിമിതപ്പെടുത്തുന്നു (cf. #3932, #4041).

### ക്രെഡൻഷ്യൽ മാസ്ക്കർ (`credentialMasker.ts`)

**രണ്ട്** സ്റ്റേജുകളിലും പ്രവർത്തിക്കുന്നു, ഡിഫോൾട്ട് ചെയിനിൽ അവസാനത്തേതായി
(പ്രയോറിറ്റി `95`). അറിയപ്പെടുന്ന API-കീ / സീക്രട്ട്-ടോക്കൺ പാറ്റേണുകൾ
ഔട്ട്ബൗണ്ട് പേലോഡിൽ നിന്ന് (മെസേജ് ഉള്ളടക്കം, ടൂൾ-കോൾ ആർഗ്യുമെന്റുകൾ, ടൂൾ
ഫലങ്ങൾ) **ഒപ്പം** പ്രൊവൈഡർ റെസ്പോൺസിൽ നിന്നും റെഡാക്ട് ചെയ്യുന്നു, അതിനാൽ ഒരു
പ്രോംപ്റ്റിൽ ഒട്ടിച്ച (അല്ലെങ്കിൽ ഒരു ടൂൾ ഫലം തിരിച്ചുപകരിച്ച) ക്രെഡൻഷ്യൽ
അപ്സ്ട്രീം പ്രൊവൈഡറിലേക്കോ തിരികെ ക്ലയന്റിലേക്കോ ചോർന്നുപോകില്ല.

- **ഓപ്റ്റ്-ഇൻ മാത്രം**, PII റെഡാക്ഷനിലെതുപോലുള്ള രീതി (Hard Rule #20-ന്
  അനുബന്ധമായത്): `settings.credentialRedactionEnabled === true` **അല്ലെങ്കിൽ**
  `CREDENTIAL_REDACTION_ENABLED=true` ആയില്ലെങ്കിൽ പ്രവർത്തനരഹിതം. ഓഫ്
  ആയിരിക്കുമ്പോൾ, ഗാർഡ്റെയിൽ ഒരു no-op ആണ് — അത് ഒരിക്കലും ബ്ലോക്ക് ചെയ്യുന്നില്ല,
  ഒരിക്കലും റീറൈറ്റ് ചെയ്യുന്നില്ല.
- `redactCredentials()` മുഴുവൻ പേലോഡ്/റെസ്പോൺസ് ട്രീയും സഞ്ചരിക്കുന്നു
  (`walkValue()`, പ്രോട്ടോടൈപ്പ്-പൊല്യൂഷൻ-സേഫ്, `WeakSet` വഴി സൈക്കിൾ-സേഫ്),
  പൊരുത്തങ്ങൾ `[REDACTED:<type>]` പ്ലേസ്ഹോൾഡർ ഉപയോഗിച്ച് മാറ്റിസ്ഥാപിക്കുന്നു,
  യഥാർത്ഥത്തിൽ മാറിയ ശാഖകൾ മാത്രമേ ക്ലോൺ ചെയ്യൂ.
- `CREDENTIAL_PATTERNS` LLM പ്രൊവൈഡർ കീകൾ (OpenAI, OpenAI-proj,
  Anthropic, Google, Hugging Face, Replicate), VCS/SaaS ടോക്കണുകൾ (GitHub, Slack,
  Linear, Notion, npm, Postman, Discord), പേയ്മെന്റ് കീകൾ (Stripe, Square), ക്ലൗഡ്
  കീകൾ (AWS ആക്സസ് കീ, Twilio, SendGrid, Mailgun), പ്രൈവറ്റ് കീകൾ / JWT-കൾ,
  ക്രെഡൻഷ്യൽ അടങ്ങിയ കണക്ഷൻ സ്ട്രിംഗുകൾ (`mongodb://user:pass@...`
  മുതലായവ), ഒരു ജെനറിക് `Authorization`/`x-api-key`/`api-key`/`apikey`
  ഹെഡർ-വാല്യൂ പാറ്റേൺ എന്നിവ ഉൾക്കൊള്ളുന്നു. ഹെഡർ ആകൃതിയിലുള്ള കീകൾ
  (`authorization`, `x-api-key`, `api-key`, `apikey`) ജെനറിക് ടെക്സ്റ്റ് regex
  ഉപയോഗിച്ചല്ല, ഘടനാപരമായി (മൂല്യം മാത്രം, `Bearer `/`Basic ` പോലുള്ള സ്കീം
  പ്രിഫിക്സ് സംരക്ഷിച്ച്) റെഡാക്ട് ചെയ്യുന്നു.
- ഗാർഡ്റെയിൽ ഒരിക്കലും ബ്ലോക്ക് ചെയ്യുന്നില്ല; അത് റീറൈറ്റ് ചെയ്യുക
  (`modifiedPayload` / `modifiedResponse`), അനോട്ടേറ്റ് ചെയ്യുക
  (`meta.credentialsRedacted`, `meta.count`) എന്നിവ മാത്രമേ ചെയ്യൂ.

റിഗ്രഷൻ ഗാർഡ്: `tests/unit/credential-masker-guardrail.test.ts`.

## അടിസ്ഥാന കരാർ (`base.ts`)

```typescript
class BaseGuardrail {
  enabled: boolean;
  name: string;
  priority: number;

  constructor(name: string, options?: { enabled?: boolean; priority?: number });

  async preCall(payload: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;

  async postCall(response: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;
}

interface GuardrailResult<TValue = unknown> {
  block?: boolean; // true ആണെങ്കിൽ ചെയിനെ ഉടൻ നിർത്തുന്നു
  message?: string; // തടയുമ്പോൾ പ്രദർശിപ്പിക്കുന്നത്
  meta?: Record<string, unknown> | null;
  modifiedPayload?: TValue; // അഭ്യർത്ഥന തിരുത്തിയെഴുതാൻ preCall നൽകുന്നത്
  modifiedResponse?: TValue; // പ്രതികരണം തിരുത്തിയെഴുതാൻ postCall നൽകുന്നത്
}

interface GuardrailContext {
  apiKeyInfo?: Record<string, unknown> | null;
  disabledGuardrails?: string[] | null;
  endpoint?: string | null;
  headers?: Headers | Record<string, unknown> | null;
  log?: GuardrailLog | Console | null;
  method?: string | null;
  model?: string | null;
  provider?: string | null;
  signal?: AbortSignal;
  sourceFormat?: string | null;
  stream?: boolean;
  targetFormat?: string | null;
}
```

ഒരു ഗാർഡ്റെയിൽ `void`, `{}`, അല്ലെങ്കിൽ `{ block: false }` എന്നിവയിൽ ഏതെങ്കിലും തിരികെ നൽകിയാണ് "മാറ്റമില്ല" എന്ന് സൂചിപ്പിക്കുന്നത്. `modifiedPayload`/`modifiedResponse` തിരികെ നൽകുന്നത്, താഴെയുള്ള ഡൗൺസ്ട്രീം ഗാർഡ്റെയിലുകൾക്കായി ചെയിനിലൂടെ ഒഴുകുന്ന മൂല്യത്തെ മാറ്റിസ്ഥാപിക്കുന്നു. `signal?: AbortSignal` കോളറുടെ ലൈഫ്സൈക്കിൾ ഗാർഡ്റെയിലുകളിലേക്ക് കൊണ്ടുപോകുന്നു. ഒരു അഭ്യർത്ഥന അബോർട്ട് ബോധപൂർവ്വമായ ഫെയിൽ-ഓപ്പൺ അപവാദമാണ്: അസംസ്കൃത മീഡിയ അത് പിന്തുണയ്ക്കില്ലെന്ന് അറിയാവുന്ന ലക്ഷ്യത്തിലേക്ക് പുനഃസ്ഥാപിക്കാതെ മീഡിയ ബ്രിഡ്ജുകൾ പ്രവർത്തി നിർത്തി ശുചീകരണം നടത്തുന്നു.

## രജിസ്ട്രി (`registry.ts`)

സിംഗിൾടൺ `guardrailRegistry` താഴെ പറയുന്നവ നൽകുന്നു:

- `register(guardrail)` — ഒരു ഗാർഡ്റെയിൽ ചേർക്കുന്നു (അല്ലെങ്കിൽ നോർമലൈസ് ചെയ്ത പേര് അനുസരിച്ച് മാറ്റിസ്ഥാപിക്കുന്നു), കൂടാതെ `priority` ആരോഹണ ക്രമത്തിൽ വീണ്ടും അടുക്കുന്നു.
- `clear()` / `list()` — അഡ്മിനിസ്ട്രേറ്റീവ് സഹായികൾ.
- `runPreCallHooks(payload, context)` — സജീവ ഗാർഡ്റെയിലുകളിലൂടെ ആവർത്തിക്കുന്നു, പേലോഡിനെ `modifiedPayload` വഴി കടത്തിവിടുന്നു, ആദ്യത്തെ `block: true`-ൽ നിർത്തുന്നു.
- `runPostCallHooks(response, context)` — പ്രതികരണ വശത്തും അതേ ഒഴുക്ക്.
- `resetGuardrailsForTests({ registerDefaults })` — വൃത്തിയുള്ള ടെസ്റ്റ് ഐസൊലേഷനായി സ്റ്റേറ്റ് മായ്ക്കുകയും ആവശ്യമെങ്കിൽ ഡിഫോൾട്ടുകൾ വീണ്ടും രജിസ്റ്റർ ചെയ്യുകയും ചെയ്യുന്നു.

രണ്ട് റണ്ണറുകളും `{ blocked, payload|response, results, guardrail?, message? }` തിരികെ നൽകുന്നു; ഇവിടെ `results` എന്നത് ഓരോ ഗാർഡ്റെയിലിനും `blocked`, `skipped`, `modified`, `error`, `meta` എന്നീ ഫീൽഡുകൾ ഉൾക്കൊള്ളുന്ന `GuardrailExecutionResult` റെക്കോർഡുകളുടെ അറേയാണ്, ഇത് ട്രേസിംഗിന് ഉപകരിക്കും.

### ഓരോ അഭ്യർത്ഥനയ്ക്കും ഗാർഡ്റെയിലുകൾ പ്രവർത്തനരഹിതമാക്കൽ

`resolveDisabledGuardrails({ apiKeyInfo, body, headers })` നിലവിലെ അഭ്യർത്ഥനയിൽ ഒഴിവാക്കേണ്ട ഗാർഡ്റെയിൽ പേരുകളുടെ, ഇരട്ടികൾ നീക്കിയ പട്ടിക സമാഹരിക്കുന്നു. അഞ്ച് ചാനലുകളുണ്ട്; ഈ ക്രമത്തിൽ വായിച്ച് ഒരു പട്ടികയായി ലയിപ്പിക്കുന്നു (ഇരട്ടികൾ നീക്കുമ്പോൾ ആദ്യ സംഭവത്തിന് മുൻഗണന):

1. `apiKeyInfo.disabledGuardrails`
2. അഭ്യർത്ഥന ബോഡി `disabledGuardrails` (ടോപ്പ്-ലെവൽ)
3. അഭ്യർത്ഥന ബോഡി `metadata.disabledGuardrails` (`metadata` ഒരു ഒബ്ജക്റ്റ് ആയിരിക്കുമ്പോൾ മാത്രം)
4. ഹെഡർ `x-omniroute-disabled-guardrails`
5. ലെഗസി ഹെഡർ `x-disabled-guardrails`

രണ്ട് ഹെഡറുകളും ഉൾപ്പെടെ അഞ്ച് ചാനലുകളും ലയിപ്പിക്കും: `x-omniroute-disabled-guardrails` ഉം `x-disabled-guardrails` ഉം രണ്ടും അയച്ചാൽ അവയുടെ പട്ടികകളുടെ സംയോജനമാണ് ഒഴിവാക്കുന്നത്, ഒപ്പം ശൂന്യമായ ആധുനിക ഹെഡർ ഇനി ലെഗസി ഹെഡറെ മറയ്ക്കില്ല ([#16412](https://github.com/diegosouzapw/OmniRoute/issues/16412), [#16805](https://github.com/diegosouzapw/OmniRoute/pull/16805)-ൽ പരിഹരിച്ചു).

മൂല്യങ്ങൾ സ്ട്രിംഗുകളുടെ അറേകളോ കോമ-വേർതിരിച്ച സ്ട്രിംഗോ ആയിരിക്കാം; പേരുകൾ ട്രിം ചെയ്യുകയും ചെറിയക്ഷര kebab-case-ലേക്ക് നോർമലൈസ് ചെയ്യുകയും ചെയ്യും (`pii_masker` → `pii-masker`), ശൂന്യമായ എൻട്രികൾ ഉപേക്ഷിക്കും. ഫലം `context.disabledGuardrails` വഴി രജിസ്ട്രിയിലേക്ക് കൈമാറുന്നു; രജിസ്ട്രി പൊരുത്തപ്പെടുന്ന ഗാർഡ്റെയിലുകൾ ഒഴിവാക്കും (`results`-ൽ `skipped: true`).

ഡിസേബിൾ പട്ടിക **രജിസ്ട്രിയെ** മാത്രമേ ബാധിക്കൂ. പ്രോംപ്റ്റ്-ഇൻജക്ഷൻ `block` മോഡ് ഒരു നിർബന്ധിത അതിർത്തിയാണ്: ഇൻജക്ഷൻ-ഗാർഡ് മിഡിൽവെയർ (`src/middleware/promptInjectionGuard.ts`) യാതൊരു കോളർ-നിയന്ത്രിത ഡിസേബിൾ പട്ടികയും ഇല്ലാതെ `evaluatePromptInjection()`-നെ വിളിക്കുന്നു (അത് നേരത്തെ നടത്തിയിരുന്ന അനാവശ്യ `resolveDisabledGuardrails({ body })` കോൾ [#16934](https://github.com/diegosouzapw/OmniRoute/pull/16934)-ൽ നീക്കം ചെയ്തു), അതിനാൽ `prompt-injection` പ്രവർത്തനരഹിതമാക്കുന്ന ഒരു അഭ്യർത്ഥനയും `block` മോഡിൽ തള്ളിക്കളയും. ഇത് രൂപകൽപ്പന അനുസരിച്ചുള്ളതാണ്. ഡിസേബിൾ ചാനലുകൾ കോളർ-നിയന്ത്രിതമാണ് (അഭ്യർത്ഥന ബോഡി, മെറ്റാഡാറ്റ, ഹെഡറുകൾ), ഓപ്പറേറ്റർ സജ്ജമാക്കിയ ഒരു സുരക്ഷാ നിയന്ത്രണം കോളർക്ക് ഓഫ് ചെയ്യാൻ കഴിയരുത് ([#16413](https://github.com/diegosouzapw/OmniRoute/issues/16413)). [#16412](https://github.com/diegosouzapw/OmniRoute/issues/16412)-ൽ നിന്നുള്ള ഹെഡർ സംയോജനം ഏത് രജിസ്ട്രി ഗാർഡ്റെയിലുകളാണ് ഒഴിവാക്കുന്നതെന്ന് മാത്രമേ മാറ്റൂ; അതിന് ഒരു ക്ലയന്റിനെ മിഡിൽവെയർ മറികടക്കാൻ അനുവദിക്കില്ല. നിർബന്ധിത ഓരോ-കീ, ഓരോ-ഗ്രൂപ്പ് ഗാർഡ്റെയിൽ നയങ്ങൾ v4 RFC [#16417](https://github.com/diegosouzapw/OmniRoute/issues/16417)-ൽ ട്രാക്ക് ചെയ്യുന്നു. [കവറേജും പരിമിതികളും](#coverage-and-limits) കാണുക.

## പ്രവർത്തന ക്രമം

`src/sse/handlers/chat.ts`, `open-sse/handlers/chatCore.ts` എന്നിവയിലൂടെ ഒഴുകുന്ന
ഓരോ അഭ്യർത്ഥനയ്ക്കും ([പരിധിയും പരിമിതികളും](#coverage-and-limits) എന്നതിന്റെ കീഴിൽ
ലിസ്റ്റ് ചെയ്തിരിക്കുന്ന ചാറ്റ്-കുടുംബ റൂട്ടുകൾ):

1. `resolveDisabledGuardrails(...)` API കീ, ബോഡി, ഹെഡറുകൾ എന്നിവയിൽ നിന്ന്
   സ്കിപ്പ് ലിസ്റ്റ് നിർമ്മിക്കുന്നു.
2. `guardrailRegistry.runPreCallHooks(body, ctx)` മുൻഗണനയുടെ ആരോഹണ ക്രമത്തിൽ
   ഗാർഡ്റെയിലുകൾ പ്രവർത്തിപ്പിക്കുന്നു:
   - ഡിസേബിൾ ചെയ്ത ഗാർഡ്റെയിലുകൾ `skipped` ആയി രേഖപ്പെടുത്തുന്നു.
   - ഓരോ ഗാർഡ്റെയിലിന്റെയും `preCall`-ന് `modifiedPayload` വഴി പേലോഡ്
     റീറൈറ്റ് ചെയ്യാൻ കഴിയും.
   - ആദ്യത്തെ `block: true` ചെയിനെ ഷോർട്ട്-സർക്യൂട്ട് ചെയ്യും, അപ്പോൾ ഹാൻഡ്ലർ
     ഒരു ഗാർഡ്റെയിൽ നിരസിക്കൽ പ്രതികരണം തിരികെ നൽകുന്നു.
3. (റീറൈറ്റ് ചെയ്യപ്പെട്ടിരിക്കാവുന്ന) പേലോഡ് കോംബോ റൂട്ടിംഗിലേക്കും അപ്സ്ട്രീം
   ഡിസ്പാച്ചിലേക്കും ഒഴുകുന്നു.
4. **നോൺ-സ്ട്രീമിംഗ് മാത്രം:** പ്രതികരണം അസംബിൾ ചെയ്ത ശേഷം,
   `guardrailRegistry.runPostCallHooks(...)` പ്രതികരണത്തിന് മുകളിൽ അതേ ചെയിൻ
   പ്രവർത്തിപ്പിക്കുന്നു. ഇവിടെ `block: true` ആയാൽ അപ്സ്ട്രീം പ്രതികരണം ഡ്രോപ്പ്
   ചെയ്ത് HTTP 400 തിരികെ നൽകുന്നു. സ്ട്രീം ചെയ്യുന്ന പ്രതികരണങ്ങൾ ഈ ഘട്ടം
   പൂർണ്ണമായും ഒഴിവാക്കുന്നു.

ത്രോ ചെയ്യുന്ന ഗാർഡ്റെയിലുകൾ `error: <message>` എന്ന് രേഖപ്പെടുത്തുകയും
`logger.warn` വഴി ലോഗ് ചെയ്യുകയും ചെയ്യും, എന്നാൽ ചെയിൻ തുടരും — ഡിസൈൻ പ്രകാരം
ഫെയിൽ-ഓപ്പൺ ആണ്.

| ഇഞ്ചക്ഷൻ-ഗാർഡ് മിഡിൽവെയർ (ലെഗസി) | പ്രോംപ്റ്റ് അടങ്ങിയ എല്ലാ `/v1` റൂട്ടുകളിലും, ചാറ്റ്-കുടുംബം ഉൾപ്പെടെ ([റൂട്ട് കവറേജ്](#injection-guard-route-coverage--red-team-phase-8--block-d) കാണുക). പ്രോംപ്റ്റ് ഇഞ്ചക്ഷൻ മാത്രം.                                                                                                                                                                                                                                                                                             |

### ഉൾപ്പെടാത്തവ

- **മീഡിയ, എംബെഡിംഗ്, ഡാറ്റ റൂട്ടുകൾ** (`/v1/images/*`, `/v1/embeddings`,
  `/v1/audio/*`, `/v1/videos/generations`, `/v1/music/generations`,
  `/v1/rerank`, `/v1/search`, `/v1/moderations`) ഒരിക്കലും രജിസ്ട്രിയിൽ
  എത്തുന്നില്ല. അവിടെ PII മാസ്കിംഗോ ക്രെഡൻഷ്യൽ മാസ്കിംഗോ മൊഡാലിറ്റി ബ്രിഡ്ജോ
  പ്രവർത്തിക്കുന്നില്ല. അവയുടെ ഏക പരിശോധന ലെഗസി ഇഞ്ചക്ഷൻ-ഗാർഡ് മിഡിൽവെയർ ആണ്.
- **സ്ട്രീം ചെയ്യുന്ന പ്രതികരണങ്ങൾ**ക്ക് പോസ്റ്റ്-കോൾ ഗാർഡ്റെയിലുകളൊന്നും
  ലഭിക്കുന്നില്ല: `pii-masker` അല്ലെങ്കിൽ `credential-masker` പോസ്റ്റ്-കോൾ ഇല്ല,
  പോസ്റ്റ്-കോൾ ബ്ലോക്കും ഇല്ല. സ്ട്രീമിംഗ് PII ട്രാൻസ്ഫോം മാത്രമേ ബാധകമാകൂ
  (`PII_RESPONSE_SANITIZATION` ഓൺ ആയിരിക്കുമ്പോൾ). സ്ട്രീം ചെയ്യുന്ന
  പ്രതികരണത്തിൽ തിരികെ എക്കോ ചെയ്യുന്ന ഒരു ക്രെഡൻഷ്യൽ റിഡാക്റ്റ് ചെയ്യപ്പെടുന്നില്ല.
- **ഡിസേബിൾ ചാനലുകൾ vs. മിഡിൽവെയർ (ഡിസൈൻ പ്രകാരം):** മിഡിൽവെയർ, കോളർ-നിയന്ത്രിത
  ഡിസേബിൾ ലിസ്റ്റ് ഒന്നും കൈമാറാതെ, `evaluatePromptInjection()`-ലേക്കുള്ള സ്വന്തം
  കോൾ ഉപയോഗിച്ചാണ് പ്രോംപ്റ്റ് ഇഞ്ചക്ഷൻ വിലയിരുത്തുന്നത്. `block` മോഡ് ഒരു
  നിർബന്ധാത്മക അതിർത്തിയാണ്; ചാറ്റ്-കുടുംബ റൂട്ടുകളിൽ പോലും കോളർ-നിയന്ത്രിത
  ഡിസേബിളുകൾക്ക് അതിനെ മറികടക്കാൻ കഴിയില്ല
  ([#16413](https://github.com/diegosouzapw/OmniRoute/issues/16413)).
  `prompt-injection` ഡിസേബിൾ ചെയ്യുന്നത് രജിസ്ട്രി ഗാർഡ്റെയിലിനെ മാത്രമേ ഒഴിവാക്കൂ.

### പോസ്റ്റ്-കോളിന് മുമ്പ് പ്രതികരണം എന്താണ് കാണുന്നത്

നോൺ-സ്ട്രീമിംഗ് പാതയിൽ ക്രമം ഇതാണ്: മെമ്മറി എക്സ്ട്രാക്ഷൻ → ബിൽറ്റ്-ഇൻ ടൂൾ
എക്സിക്യൂഷൻ → പോസ്റ്റ്-കോൾ ഗാർഡ്റെയിലുകൾ → പോസ്റ്റ്-കോൾ ബ്ലോക്ക് എക്സിറ്റ് →
സെമാന്റിക്-കാഷെ സ്റ്റോർ.

- **മെമ്മറി എക്സ്ട്രാക്ഷനും** **ടൂൾ എക്സിക്യൂഷനും** പോസ്റ്റ്-കോൾ
  ഗാർഡ്റെയിലുകൾ അത് റീറൈറ്റ് ചെയ്യുകയോ ബ്ലോക്ക് ചെയ്യുകയോ ചെയ്യുന്നതിന് മുമ്പേ
  റെസ്പോൺസ് കാണുന്നു.
  [#16401](https://github.com/diegosouzapw/OmniRoute/pull/16401) മുതൽ,
  `PII_RESPONSE_SANITIZATION` ഓൺ ആയിരിക്കുമ്പോൾ (സ്ട്രീമിംഗിലും നോൺ-സ്ട്രീമിംഗിലും),
  മെമ്മറി എക്സ്ട്രാക്ഷൻ എക്സ്ട്രാക്ട് ചെയ്ത ടെക്സ്റ്റ് `sanitizePII`-ലൂടെ കടത്തിവിടുന്നു,
  എന്നാൽ പോസ്റ്റ്-കോൾ പിന്നീട് ബ്ലോക്ക് ചെയ്യുന്ന ഒരു റെസ്പോൺസ് ഇതിനകം മെമ്മറിക്കും
  ടൂളുകൾക്കും ലഭ്യമാക്കിക്കഴിഞ്ഞിരിക്കും.
- **സെമാന്റിക് കാഷെ** പോസ്റ്റ്-കോളിന് ശേഷമാണ് റെസ്പോൺസ് സംഭരിക്കുന്നത്, അതിനാൽ
  റീറൈറ്റ് ചെയ്ത റെസ്പോൺസാണ് അത് സംഭരിക്കുന്നത്, ബ്ലോക്ക് ചെയ്യപ്പെട്ട റെസ്പോൺസ്
  ഒരിക്കലും കാഷെ ചെയ്യപ്പെടുന്നില്ല. കാഷെ എൻട്രികൾ API കീ അനുസരിച്ചാണ് കീ ചെയ്യുന്നത്.

## കോൺഫിഗറേഷൻ

ബിൽറ്റ്-ഇൻ ഗാർഡ്റെയിലുകൾ വായിക്കുന്ന എൻവയോൺമെന്റ് വേരിയബിളുകൾ:

| വേരിയബിൾ                              | ഉപയോഗിക്കുന്നത്           | ഫലം                                                                                                                |
| ------------------------------------- | ------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `INPUT_SANITIZER_ENABLED`             | `prompt-injection`        | ഡിറ്റക്ഷൻ പൂർണ്ണമായും പ്രവർത്തനരഹിതമാക്കാൻ `false` ആയി സെറ്റ് ചെയ്യുക.                                             |
| `INPUT_SANITIZER_MODE`                | `prompt-injection`        | ഇൻജക്ഷൻ നയം: `warn`, `block`, അല്ലെങ്കിൽ `log`. ലെഗസി മൂല്യം `redact` ഇൻജക്ഷൻ ടെക്സ്റ്റ് പുനഃരേഖപ്പെടുത്തുന്നില്ല. |
| `INJECTION_GUARD_MODE`                | `prompt-injection`        | ഇൻജക്ഷൻ ഗാർഡിന്റെ മോഡ്; എൻവ് വേരിയബിളുകളെ **ഓവർറൈഡ്** ചെയ്യുന്ന ഒരു DB ഫീച്ചർ ഫ്ലാഗ് കൂടിയാണ് (DB > ENV).          |
| `INPUT_SANITIZER_BLOCK_THRESHOLD`     | `prompt-injection`        | `MODE=block` നിരസിക്കുന്ന ഏറ്റവും കുറഞ്ഞ തീവ്രത: `high` (ഡിഫോൾട്ട്), `medium`, അല്ലെങ്കിൽ `low`.                   |
| `INJECTION_GUARD_BLOCK_THRESHOLD`     | `prompt-injection`        | `INPUT_SANITIZER_BLOCK_THRESHOLD`-ന്റെ ലെഗസി അപരനാമം.                                                              |
| `PII_REDACTION_ENABLED`               | `pii-masker`              | `true` ആകുമ്പോൾ, റിക്വസ്റ്റ് PII എഡാക്റ്റ് ചെയ്യപ്പെടും (ഇൻജക്ഷൻ മോഡിൽ നിന്ന് സ്വതന്ത്രമായി).                      |
| `PII_RESPONSE_SANITIZATION` / `_MODE` | `pii-masker` (ഡൗൺസ്ട്രീം) | റെസ്പോൺസ്-സൈഡ് മാസ്ക്കർ പെരുമാറ്റം നിയന്ത്രിക്കുന്നു.                                                              |

Modality Bridge ഗാർഡ്റെയിലുകൾ റൺടൈം കോൺഫിഗറേഷൻ എൻവ് വേരിയബിളുകളിൽ നിന്നല്ല, DB-ബാക്ഡ്
സെറ്റിംഗ്സ് സ്റ്റോറിൽ നിന്നാണ് (`getSettings()`) വായിക്കുന്നത്. Vision-ന്റെ പ്രാഥമിക കീകൾ
`modalityBridgeVisionEnabled`, `modalityBridgeVisionMode`,
`modalityBridgeVisionModel`, `modalityBridgeVisionTaskAware`,
`modalityBridgeVisionPrompt`, `modalityBridgeVisionTimeout`,
`modalityBridgeVisionMaxImages`, `modalityBridgeVisionMaxChars`,
`modalityBridgeCacheEnabled`, `modalityBridgeCacheTtlMinutes`, കൂടാതെ
`modalityBridgeCacheMaxEntries` എന്നിവയാണ്. ലെഗസി
`visionBridge*` കീകൾ ഡോക്യുമെന്റ് ചെയ്യപ്പെട്ട ഒറ്റ-സൈക്കിൾ റീഡ്
ഫോൾബാക്കായി മാത്രമേ അംഗീകരിക്കപ്പെടൂ; ഡാഷ്ബോർഡ് എഴുത്തുകൾ പ്രാഥമിക കീകൾ ഉപയോഗിക്കുന്നു.
ഡിഫോൾട്ടുകളും ഫോൾബാക്ക് റിസോൾവറും `src/shared/constants/modalityBridgeDefaults.ts`-ൽ ആണുള്ളത്,
ലെഗസി കോൺസ്റ്റന്റുകൾ `src/shared/constants/visionBridgeDefaults.ts`-ൽ സൂക്ഷിച്ചിരിക്കുന്നു.

ഓഡിയോ `modalityBridgeAudioEnabled`, `modalityBridgeAudioModel`,
`modalityBridgeAudioTimeout`, `modalityBridgeAudioMaxClips` എന്നിവ ഉപയോഗിക്കുന്നു,
കൂടാതെ പങ്കിട്ട `modalityBridgeCache*` സെറ്റിംഗ്സും. ഈ കീകൾ Modality Bridge
സ്കീമയോടൊപ്പമാണ് അവതരിപ്പിക്കപ്പെട്ടതിനാൽ ഓഡിയോയ്ക്ക് ലെഗസി-കീ ഫോൾബാക്ക് ഇല്ല.

വീഡിയോ `modalityBridgeVideoEnabled`, `modalityBridgeVideoAnalysisMode`,
`modalityBridgeVideoModel`,
`modalityBridgeVideoFrameCount`, `modalityBridgeVideoSamplingPolicy`,
`modalityBridgeVideoMaxVideos`, കൂടാതെ
`modalityBridgeVideoTimeout` എന്നിവ ഉപയോഗിക്കുന്നു, ഒപ്പം പങ്കിട്ട
`modalityBridgeCache*` സെറ്റിംഗ്സും. FFmpeg/ffprobe ഓപ്ഷണൽ പ്രവർത്തന
ഡിപെൻഡൻസികളായതിനാലും ഫ്രെയിം ക്യാപ്ഷനിംഗ് ലേറ്റൻസിയും മോഡൽ ചെലവും
വർധിപ്പിക്കുന്നതിനാലും ഇത് ഡിഫോൾട്ടായി പ്രവർത്തനരഹിതമാക്കിയിരിക്കുന്നു.

## ഇഷ്ടാനുസൃത ഗാർഡ്റെയിലുകൾ

```typescript
import { BaseGuardrail, guardrailRegistry } from "@/lib/guardrails";

class BudgetGuardrail extends BaseGuardrail {
  constructor() {
    super("budget", { priority: 50 });
  }

  async preCall(payload, ctx) {
    if (ctx.apiKeyInfo?.budgetExceeded) {
      return { block: true, message: "Daily budget exceeded" };
    }
    return { block: false };
  }
}

guardrailRegistry.register(new BudgetGuardrail());
```

ഘട്ടങ്ങൾ:

1. `BaseGuardrail` വിപുലീകരിച്ച് `src/lib/guardrails/myGuardrail.ts` സൃഷ്ടിക്കുക.
2. `preCall` ഒപ്പം/അല്ലെങ്കിൽ `postCall` നടപ്പിലാക്കുക.
3. ഇംപോർട്ട് സമയത്ത് രജിസ്റ്റർ ചെയ്യുക (`registerDefaultGuardrails`-ൽ നിന്ന് push ചെയ്യുക) അല്ലെങ്കിൽ
   റൺടൈമിൽ `guardrailRegistry.register(...)` വിളിക്കുക — ഒരേ നോർമലൈസ് ചെയ്ത പേരുള്ള
   മുൻ ഗാർഡ്റെയിലിനെ റെജിസ്ട്രി മാറ്റിസ്ഥാപിക്കും.
4. `tests/unit/`-ൻ കീഴിൽ ടെസ്റ്റുകൾ ചേർക്കുക (നിലവിലുള്ള ഉദാഹരണങ്ങൾ:
   `tests/unit/guardrails-registry.test.ts`,
   `tests/unit/prompt-injection-guard.test.ts`,
   `tests/unit/guardrails/visionBridge.test.ts`).

## ടെസ്റ്റിംഗ്

അറിയപ്പെടുന്ന സ്ഥിതിയിൽ നിന്ന് ആരംഭിക്കാൻ ടെസ്റ്റുകൾക്കിടയിൽ `resetGuardrailsForTests()` ഉപയോഗിക്കുക.
ശൂന്യമായ റെജിസ്ട്രിയിൽ നിന്ന് ആരംഭിക്കാനും ടെസ്റ്റ് ചെയ്യുന്ന ഗാർഡ്റെയിലുകൾ മാത്രം രജിസ്റ്റർ
ചെയ്യാനും `{ registerDefaults: false }` നൽകുക. Vision Bridge ഡിപെൻഡൻസി ഇൻജക്ഷൻ
സ്വീകരിക്കുന്നു (`deps.getSettings`, `deps.callVisionModel`); Audio Bridge ക്രമീകരണങ്ങൾ,
കഴിവുകൾ, STT മോഡൽ തിരഞ്ഞെടുപ്പ്, ക്രെഡൻഷ്യൽ പരിശോധനകൾ, ട്രാൻസ്ക്രിപ്ഷൻ എന്നിവയ്ക്കായി
തത്തുല്യമായ സീമുകൾ തുറന്നുകൊടുക്കുന്നു. അതിനാൽ DBയോ നെറ്റ്വർക്ക് ആക്സസോ ഇല്ലാതെ
ടെസ്റ്റുകൾക്ക് രണ്ട് ഫ്ലോകളും പരീക്ഷിക്കാൻ കഴിയും.

  പ്രവർത്തിപ്പിക്കുന്ന പങ്കിട്ട ഡിറ്റക്ടർ

  ഫോഴ്സ്ഡ്-ബ്രിഡ്ജ് മോഡൽ ലിസ്റ്റും

- `docs/architecture/RESILIENCE_GUIDE.md` — ഓർത്തഗണൽ ലെയർ (സർക്യൂട്ട് ബ്രേക്കർ, കൂൾഡൗണുകൾ)
- `docs/reference/ENVIRONMENT.md` — സമ്പൂർണ്ണ env വേരിയബിൾ റഫറൻസ്

## ഇൻജക്ഷൻ-ഗാർഡ് റൂട്ട് കവറേജും റെഡ്-ടീമും (ഘട്ടം 8 · ബ്ലോക്ക് D)

ഉപയോക്തൃ പ്രോംപ്റ്റുകൾ സ്വീകരിക്കുന്ന എല്ലാ റൂട്ടുകളെയും ഇൻജക്ഷൻ-ഗാർഡ്
(`createInjectionGuard` / `withInjectionGuard`) ഉൾക്കൊള്ളുന്നു. ഇത് `INJECTION_GUARD_MODE`
പാലിക്കുന്നു (ഡിഫോൾട്ട് `warn` = ലോഗ് മാത്രം; `block` = HTTP 400 `SECURITY_001` തിരിച്ചുനൽകുന്നു).

| തരം                       | റൂട്ടുകൾ                                                                                                                                             | ഡിഫോൾട്ട് മോഡ് |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | -------------- |
| ടെക്സ്റ്റ് (നിലവിലുള്ളത്) | `/v1/chat/completions`, `/v1/completions`, `/v1/relay/chat/completions`                                                                              | warn           |
| ജനറേറ്റീവ്                | `/v1/messages`, `/v1/responses`, `/v1/images/generations`, `/v1/images/edits`, `/v1/videos/generations`, `/v1/music/generations`, `/v1/audio/speech` | warn           |
| ഡാറ്റ                     | `/v1/embeddings`, `/v1/rerank`, `/v1/search`, `/v1/moderations`                                                                                      | warn           |

ടെക്സ്റ്റ് എക്സ്ട്രാക്ഷൻ (`extractMessageContents`)
`messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system` എന്നിവ ഉൾക്കൊള്ളുന്നു.

**റെഡ്-ടീം (രാത്രിമുഴുവൻ, `nightly-llm-security.yml`):** `INJECTION_GUARD_MODE=block`-ൽ ഓരോ
റൂട്ടും OWASP-LLM കോർപസിനെ തടയുന്നുവോ എന്ന് promptfoo സാധൂകരിക്കുന്നു; garak പ്രോബുകൾ
ഓടിക്കുന്നു (സീക്രട്ട് ഇല്ലാത്തിടത്ത് ഒഴിവാക്കുന്നു). സ്ഥിരതയ്ക്കായി `moderations`
ഉൾപ്പെടുത്തിയിരിക്കുന്നു. ബ്ലോക്ക് മോഡ് ഒരു നിർബന്ധിത അതിർത്തിയാണ്: മിഡിൽവെയർ കൈമാറുന്ന
ഓരോ അഭ്യർത്ഥനയിലുമുള്ള ഡിസേബിൾ ലിസ്റ്റ് `evaluatePromptInjection()` അവഗണിക്കുന്നു, അതിനാൽ
`disabledGuardrails` ഒരു റൂട്ടിനെയും ഇതിൽ നിന്ന് ഒഴിവാക്കുന്ന**ല്ല**
([#16413](https://github.com/diegosouzapw/OmniRoute/issues/16413)).

നൈറ്റ്ലി വർക്ക്ഫ്ലോയ്ക്ക് (`.github/workflows/nightly-llm-security.yml`, cron + മാനുവൽ
ഡിസ്പാച്ച്) രണ്ട് ജോബുകളുണ്ട്:

- **`promptfoo-guard` (ബ്ലോക്കിംഗ്)** — `INJECTION_GUARD_MODE=block`-ൽ
  `promptfoo eval -c promptfooconfig.yaml` ഓടിക്കുന്നു. ഓരോ എതിരാളി കേസും (ഉദാ. "ignore all
  previous instructions…", DAN-ശൈലിയിലുള്ള ജെയിൽബ്രേക്കുകൾ) പ്രതികരണത്തിൽ
  `error.code === "SECURITY_001"` ഉണ്ടെന്ന് ഉറപ്പാക്കുന്നു, അതായത് ഗാർഡ് യഥാർത്ഥത്തിൽ
  അഭ്യർത്ഥന നിരസിച്ചു.
- **`garak` (ഉപദേശകം)** — പ്രാദേശിക OmniRoute ഇൻസ്റ്റൻസിനെതിരെ (`http://localhost:20128/v1`)
  garak `--probes promptinject,dan,leakreplay` ഓടിക്കുന്നു. ഒരു പ്രൊവൈഡർ സീക്രട്ടിൽ
  (`PROMPTFOO_PROVIDER_KEY`) ഗേറ്റ് ചെയ്തിരിക്കുന്നു; ശരിയായി ഒഴിവാക്കുകയും `|| true` എന്ന്
  സഫിക്സ് ചെയ്യുകയും ചെയ്യുന്നു, അതിനാൽ CI പരാജയപ്പെടുത്താതെ റിപ്പോർട്ട് ചെയ്യുന്നു.

ഗാർഡ് ഹെൽപ്പറിന്റെ (`createInjectionGuard` / `withInjectionGuard`) കവറേജ് പ്രോംപ്റ്റ്
വഹിക്കുന്ന ഓരോ `/v1` റൂട്ടിലും വ്യാപിക്കുന്നു; `src/shared/utils/inputSanitizer.ts`-ലെ
`extractMessageContents()` വഴി
`messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system` എന്നിവയിൽ നിന്ന്
പ്രോംപ്റ്റ് ടെക്സ്റ്റ് എടുക്കുന്നു.
