OmniRoute npm + Docker ആർട്ടിഫാക്റ്റുകൾ പ്രസിദ്ധീകരിക്കുന്നു. ഈ ഗേറ്റുകൾ പ്രൊവനൻസ്, ഇൻവെന്ററി (SBOM), CVE സ്കാനിംഗ് എന്നിവ നൽകുന്നു, ഇവയെല്ലാം OSS ആണ്, റിലീസ് വർക്ക്ഫ്ലോകളുമായി ബന്ധിപ്പിച്ചിരിക്കുന്നു.
**ഉപദേശം-ആദ്യ സമീപനം** — അവ ഇപ്പോൾ റിപ്പോർട്ട് ചെയ്യുന്നു, ആദ്യത്തെ ഗ്രീൻ റിലീസിന് ശേഷം തടസ്സപ്പെടുത്തുന്നതിലേക്ക് മാറ്റുന്നു.

| ഗേറ്റ്                | ടൂൾ                                            | എവിടെ                         | തടസ്സപ്പെടുത്തുമോ?                  | ഔട്ട്പുട്ട്                                             |

| SBOM npm              | `@cyclonedx/cyclonedx-npm`                     | `npm-publish.yml`             | ജനറേഷൻ പരാജയപ്പെട്ടാൽ മാത്രം        | Release asset + artifact                                |
| SBOM image            | `anchore/sbom-action` (syft)                   | `docker-publish.yml` (merge)  | ഉപദേശക സ്വഭാവം                      | CycloneDX artifact                                      |

| OpenSSF Scorecard     | `ossf/scorecard-action`                        | `scorecard.yml` (cron)        | ഉപദേശക സ്വഭാവം                      | SARIF → Security + badge                                |

ഇമേജ് CVE റാച്ചറ്റ് `docker-publish.yml`-ൽ **രണ്ട് ഘട്ടങ്ങൾ** ഉപയോഗിക്കുന്നു: SARIF ഘട്ടം (`HIGH,CRITICAL`, `exit-code: 0`) HIGH+CRITICAL എന്നിവയെ തടസ്സപ്പെടുത്താതെ സുരക്ഷാ ടാബിൽ ദൃശ്യമാക്കുന്നു; _CRITICAL ഗേറ്റ്_ ഘട്ടം (`severity: CRITICAL`, `ignore-unfixed: true`, `exit-code: 1`) ഒരു CRITICAL CVE-യിൽ **പരിഹാരം ലഭ്യമാണെങ്കിൽ** റിലീസ് പരാജയപ്പെടുത്തുന്നു. `ignore-unfixed` ഒരു അപ്സ്ട്രീം പാച്ച് ഇല്ലാത്ത ഒരു ബേസ്-ഇമേജ് CVE-യുടെ റിലീസ് തടസ്സപ്പെടുത്തുന്നത് തടയുന്നു.

## ⚠️ CVE വ്യതിയാനം (osv/Trivy ഗേറ്റുകളെ തടയുന്നത്)

osv-യും Trivy-യും ഡിപ്പെൻഡൻസികളെ **തുടർച്ചയായി വളരുന്ന** CVE ഡാറ്റാബേസുകളുമായി താരതമ്യം ചെയ്യുന്നു. **ഡിപ്പെൻഡൻസികളൊന്നും മാറ്റാത്ത** ഒരു PR പോലും നിലവിലുള്ള ഒരു ഡിപ്പെൻഡൻസിയിൽ പുതിയൊരു CVE വെളിപ്പെടുത്തപ്പെടുന്നതിനാൽ പെട്ടെന്ന് പരാജയപ്പെടാം (osv: അളന്ന `vulnCount` > ബേസ്ലൈൻ; Trivy: ഇമേജിൽ പരിഹരിക്കാവുന്ന പുതിയ CRITICAL). **ഇത് തടയുന്ന CVE ഗേറ്റിന്റെ പ്രതീക്ഷിത പ്രവർത്തന സ്വഭാവമാണ്, ഉൽപ്പന്നത്തിലെ റിഗ്രഷനല്ല.**

പുതുതായി വെളിപ്പെടുത്തിയ CVE കാരണം osv അല്ലെങ്കിൽ Trivy പരാജയപ്പെടുമ്പോൾ, പരിഹാരം:

1. **ബാധിച്ച ഡിപ്പെൻഡൻസി അപ്ഡേറ്റ് ചെയ്യുക** (അഭികാമ്യം) — `package.json`
   `overrides` (ട്രാൻസിറ്റീവ് ഡിപ്പെൻഡൻസികൾ) വഴി പാച്ച് ചെയ്ത പതിപ്പിലേക്ക് അപ്ഗ്രേഡ് ചെയ്യുക, അല്ലെങ്കിൽ പാച്ച് ചെയ്ത ബേസ് ഉപയോഗിച്ച് ഇമേജ് പുനർനിർമ്മിക്കുക.
2. **അപ്സ്ട്രീം പരിഹാരമില്ലെങ്കിൽ:**
   - **osv:** `config/quality/quality-baseline.json`-ലെ `metrics.vulnCount` വീണ്ടും ബേസ്ലൈൻ ചെയ്യുക
     (`npm run quality:ratchet -- --update` സമർപ്പിത ഗേറ്റുകളെ ഉൾക്കൊള്ളുന്നില്ല — ന്യായീകരണ കുറിപ്പും + ട്രാക്കിങ് ഇഷ്യൂവും ചേർത്ത് മൂല്യം
     നേരിട്ട് എഡിറ്റ് ചെയ്യുക, `direction:down`).
   - **Trivy:** ന്യായീകരണ കമന്റും + ട്രാക്കിങ് ഇഷ്യൂവും ചേർത്ത് `.trivyignore`-ൽ ഒരു എൻട്രി ചേർക്കുക
     (ഓരോ വരിയിലും CVE-ID). പാച്ചുകളില്ലാത്ത CVE-കളെ `ignore-unfixed: true` ഇതിനകം
     സ്വയമേവ ഉൾക്കൊള്ളുന്നു.

സ്കാനർ, റിപ്പോർട്ട്, അല്ലെങ്കിൽ ബേസ്ലൈൻ സാധൂകരിക്കാൻ കഴിയാത്തപ്പോൾ ആവശ്യമായ OSV നിർവഹണങ്ങൾ (`check:vuln-ratchet -- --ratchet`)
`INCOMPLETE` എന്ന നിലയിലും എക്സിറ്റ് കോഡ് 2-ഉം നൽകി പരാജയപ്പെടുന്നു.
അളന്ന റിഗ്രഷൻ എക്സിറ്റ് കോഡ് 1 നൽകുന്നു. ഉപദേശാത്മക നിർവഹണത്തിന് ഇപ്പോഴും `SKIP` റിപ്പോർട്ട് ചെയ്യാനും
എക്സിറ്റ് കോഡ് 0 നൽകാനും കഴിയും; ഇത് ഡിപ്പെൻഡൻസികൾ സ്കാൻ വിജയിച്ചതായി സ്ഥാപിക്കുന്നില്ല. തടയുന്ന
Trivy ഘട്ടത്തിനും വിജയകരമായ അളക്കൽ ആവശ്യമാണ്: ലഭ്യമല്ലാത്ത ടൂളുകൾ, പരാജയപ്പെട്ട ജോലികൾ,
ഇമേജ് തെളിവിന്റെ അഭാവം എന്നിവ ഉപയോഗിച്ച് ഒരു ഇമേജ് പ്രശ്നരഹിതമാണെന്ന് സാക്ഷ്യപ്പെടുത്താൻ കഴിയില്ല.

## പിൻവലിച്ച ആശ്രിതത്വത്തിന്റെ അപകടസാധ്യത

പിൻ ചെയ്ത promptfoo ഡെവലപ്മെന്റ് ടൂൾ അപ്ഗ്രേഡ് ചെയ്തതിനെ തുടർന്ന്, റൂട്ട് ലോക്ക്ഫയലിൽ ഇനി `extract-zip` അല്ലെങ്കിൽ അതിലേക്കുള്ള ഒരു ആശ്രിതത്വ എഡ്ജ് ഉൾപ്പെടുന്നില്ല. ഇത് #14482-ൽ ട്രാക്ക് ചെയ്തിരുന്ന, മുമ്പ് അംഗീകരിച്ച `promptfoo` → `@openai/codex-security` → `extract-zip` ശൃംഖലയെ പിൻവലിക്കുന്നു. `tests/unit/extract-zip-14482-exposure.test.ts`-ലെ റിഗ്രഷൻ പരിശോധനകൾ അതിന്റെ പുനരവതരണം നിരസിക്കുകയും പ്രൊഡക്ഷൻ കോഡിൽ നിന്നുള്ള ഇംപോർട്ടുകൾക്കുള്ള വിലക്ക് നിലനിർത്തുകയും ചെയ്യുന്നു.

നിലവിലെ ആശ്രിതത്വ പരിഹാരം, കോംപാറ്റിബിലിറ്റി ഓവർറൈഡുകളെ Azure identity-യുടെ MSAL ക്ലയന്റ്, get-uri-യുടെ FTP ക്ലയന്റ്, OpenCode v1 SDK-യുടെ Zod ആശ്രിതത്വം എന്നിവയിലേക്കും പരിമിതപ്പെടുത്തുന്നു. Azure ടോക്കൺ നേടലും FTP റിട്രീവലും നിയന്ത്രിത ട്രാൻസ്പോർട്ടുകൾ ഉപയോഗിച്ച് പരിശോധിക്കുന്നു; രണ്ട് OpenCode പാക്കേജുകളും അവയുടെ സ്വന്തം ബിൽഡ്, ടെസ്റ്റ് സ്യൂട്ടുകൾ പ്രവർത്തിപ്പിക്കുന്നു. രജിസ്ട്രി അഡ്വൈസറി എണ്ണങ്ങൾ ഒരു നിർദിഷ്ട സമയബിന്ദുവിലെ അളവുകളാണ്; ലോക്ക്ഫയൽ കമ്മിറ്റ് ചെയ്തതിന് ശേഷം അവ മാറാം.

## ബാക്ക്ലോഗ്: സ്കോർകാർഡ് അഡ്വൈസറി → തടസ്സപ്പെടുത്തുന്നു

സ്കോർകാർഡ് റിപ്പോർട്ടിംഗോടുകൂടിയ ആദ്യത്തെ ഗ്രീൻ റിലീസിന് ശേഷം:

- സ്കോർകാർഡ്: സ്കോർ റാച്ചറ്റ് (അളന്ന സ്കോർ മരവിപ്പിക്കുന്നു; കുറയ്ക്കാൻ കഴിയില്ല).
