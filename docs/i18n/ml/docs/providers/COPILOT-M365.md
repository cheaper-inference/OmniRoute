`copilot-m365-web` (`m365copilot` എന്ന അപരനാമം) `m365.cloud.microsoft/chat`-ലെ
പ്രാമാണീകരിച്ച Microsoft 365 Copilot BizChat ബ്രൗസർ സെഷനിലൂടെ OpenAI-ഫോർമാറ്റിലുള്ള ചാറ്റ് അഭ്യർത്ഥനകൾ അയയ്ക്കുന്നു. ഇത് ഒരു അനൗദ്യോഗിക സംയോജനമാണ്.

> **Web Cookie പ്രൊവൈഡറുകൾ ആദ്യമായാണോ ഉപയോഗിക്കുന്നത്?**
>
> ഈ പ്രൊവൈഡറിനായുള്ള നിർദ്ദിഷ്ട മാർഗ്ഗനിർദ്ദേശം പിന്തുടരുന്നതിന് മുമ്പ് പൊതുവായ സജ്ജീകരണ പ്രക്രിയ, പ്രാമാണീകരണ മാർഗ്ഗനിർദ്ദേശങ്ങൾ, പരിമിതികൾ, പ്രശ്നപരിഹാരം എന്നിവയ്ക്കായി **`docs/getting-started/WEB-COOKIE-GUIDE.md`** വായിക്കുക.
>
> **പ്രധാനം:** ഈ പ്രൊവൈഡറിന്റെ ക്രെഡൻഷ്യൽ **ഒരു cookie അല്ല**. `m365.cloud.microsoft`-ൽ നിന്ന്
> cookies പകർത്തരുത്. ക്രെഡൻഷ്യൽ ഒരു WebSocket URL ക്വറി
> പാരാമീറ്ററും പാത്ത് സെഗ്മെന്റുമാണ്; രണ്ടും DevTools Network ടാബിൽ നിന്നാണ് വായിക്കുന്നത്.

## മുൻവ്യവസ്ഥകൾ

- `m365.cloud.microsoft/chat`-ലെ BizChat-ലേക്ക് ആക്സസുള്ള ഒരു Microsoft 365 അക്കൗണ്ട്
- DevTools WebSocket പരിശോധനയ്ക്കായി Chromium അടിസ്ഥാനമാക്കിയുള്ള ഒരു ബ്രൗസർ (Chrome, Edge)
- ഒരു M365 Copilot ലൈസൻസ് (നിരവധി Microsoft 365 Business/Enterprise പ്ലാനുകളിൽ ഉൾപ്പെടുത്തിയിട്ടുണ്ട്)

## ക്രെഡൻഷ്യൽ ശേഖരണം (WebSocket രീതി)

1. `https://m365.cloud.microsoft/chat`-ൽ സൈൻ ഇൻ ചെയ്ത് ഒരു സംഭാഷണം ആരംഭിക്കുക.
2. **DevTools → Network** തുറക്കുക.
3. **WS** (WebSocket) ഉപയോഗിച്ച് ഫിൽട്ടർ ചെയ്യുക.
4. Chathub WebSocket കണക്ഷനിൽ ക്ലിക്ക് ചെയ്യുക. താഴെപ്പറയുന്നതിൽ ആരംഭിക്കുന്ന ഒരു URL കണ്ടെത്തുക:
   `wss://substrate.office.com/m365Copilot/Chathub/`.
5. അതിന്റെ **Request URL**-ൽ നിന്ന് ഇനിപ്പറയുന്നവ പകർത്തുക:
   - `access_token` ക്വറി പാരാമീറ്റർ മൂല്യം (ഹ്രസ്വകാല സാധുതയുള്ള JWT).
   - `/Chathub/`-ന് ശേഷമുള്ള Chathub പാത്ത് സെഗ്മെന്റ് (ഉദാ. `<oid>@<tenant>`).

പൂർണ്ണ URL-ന്റെ രൂപം:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. OmniRoute-ൽ **Providers → Add Provider** എന്നതിലേക്ക് പോകുക, **Microsoft 365 Copilot
   (BizChat)** തിരഞ്ഞെടുക്കുക, തുടർന്ന് ക്രെഡൻഷ്യൽ ഇനിപ്പറയുന്ന ഫോർമാറ്റിൽ ഒട്ടിക്കുക:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. **Test Connection** ക്ലിക്ക് ചെയ്തശേഷം **Save** ക്ലിക്ക് ചെയ്യുക.

## ക്രെഡൻഷ്യൽ ശേഖരണം (HAR ഇറക്കുമതി)

WebSocket URL-ൽ നിന്ന് മൂല്യങ്ങൾ നേരിട്ട് പകർത്തുന്നതിനു പകരം, നിങ്ങൾക്ക് ഒരു DevTools HAR
ഫയൽ എക്സ്പോർട്ട് ചെയ്യാം:

1. **DevTools → Network** തുറക്കുക.
2. ഒരു BizChat സംഭാഷണം ആരംഭിക്കുകയോ തുടരുകയോ ചെയ്യുക (ഇത് WebSocket കണക്ഷൻ പ്രവർത്തനക്ഷമമാക്കുന്നു).
3. Network പാനലിൽ റൈറ്റ്-ക്ലിക്ക് ചെയ്ത് **Save all as HAR with content** തിരഞ്ഞെടുക്കുക.
4. OmniRoute-ൽ, പ്രൊവൈഡർ കണക്ഷൻ ഡയലോഗിലെ **Import .har file** ബട്ടൺ ഉപയോഗിക്കുക.

OmniRoute, Chathub WebSocket URL കണ്ടെത്തുന്നതിനായി HAR സ്കാൻ ചെയ്യുകയും
`access_token`, `chathubPath` എന്നിവ വേർതിരിച്ചെടുക്കുകയും ക്രെഡൻഷ്യൽ ഫീൽഡുകൾ സ്വയമേവ പൂരിപ്പിക്കുകയും ചെയ്യുന്നു.
HAR ഇറക്കുമതി JWT കാലഹരണ സമയം ഡീകോഡ് ചെയ്യുകയും ടോക്കണിന്റെ ശേഷിക്കുന്ന കാലാവധി കാണിക്കുകയും ചെയ്യുന്നു.

> **യഥാർത്ഥ HAR എക്സ്പോർട്ട്, ആക്സസ് ടോക്കൺ, അല്ലെങ്കിൽ റിഫ്രഷ് ടോക്കൺ ഒരിക്കലും commit ചെയ്യരുത്.** പരിശോധനാ,
> ഡോക്യുമെന്റേഷൻ മൂല്യങ്ങൾ എപ്പോഴും പ്ലേസ്ഹോൾഡറുകളായിരിക്കണം.

## ടോക്കൺ കാലാവധിയും പുതുക്കലും

`access_token` ഹ്രസ്വകാലികമാണ് (സാധാരണയായി **~75 മിനിറ്റ്**). ഉപയോഗിക്കാവുന്ന റിഫ്രെഷ്
ടോക്കൺ ഇല്ലെങ്കിൽ, കാലാവധി കഴിഞ്ഞതിന് ശേഷം ക്രെഡൻഷ്യൽ വീണ്ടും ശേഖരിക്കണം.

### `refreshToken` ഉപയോഗിച്ചുള്ള സ്വയമേവയുള്ള പുതുക്കൽ

Microsoft 365 പ്രൊവൈഡറിലെ **കണക്ഷൻ ചേർക്കുക** അല്ലെങ്കിൽ **കണക്ഷൻ എഡിറ്റ് ചെയ്യുക** ഡയലോഗിൽ,
**വിപുലമായ ക്രമീകരണങ്ങൾ → റിഫ്രെഷ് ടോക്കൺ (ഓപ്ഷണൽ)** തുറക്കുക. `substrate.office.com/sydney`
സ്കോപ്പിനായുള്ള Microsoft OAuth റിഫ്രെഷ് ടോക്കൺ ഒട്ടിച്ച് സംരക്ഷിക്കുക. ഇൻപുട്ട് മറച്ചുവെക്കും, സംഭരിച്ച
ടോക്കൺ ഉപയോഗിച്ച് ഇത് ഒരിക്കലും മുൻകൂട്ടി പൂരിപ്പിക്കില്ല. എഡിറ്റ് ചെയ്യുമ്പോൾ, നിലവിലുള്ള ടോക്കൺ
നിലനിർത്താൻ ഇത് ശൂന്യമായി വിടുക; മാറ്റിസ്ഥാപിക്കാൻ പുതിയ ടോക്കൺ ഒട്ടിക്കുക.

`substrate.office.com/sydney` സ്കോപ്പിലേക്ക് പരിമിതപ്പെടുത്തിയ Microsoft device-code അല്ലെങ്കിൽ
authorization-code ഫ്ലോയിൽ നിന്ന് റിഫ്രെഷ് ടോക്കൺ നേടുക; ഡാഷ്ബോർഡ് ഇത് നിങ്ങൾക്കായി നേടില്ല.
റിഫ്രെഷ് ടോക്കൺ ക്രമീകരിച്ചിട്ടുണ്ടെങ്കിൽ, അഭ്യർത്ഥനകൾക്ക് മുമ്പ് OmniRoute `access_token` പരിശോധിക്കുകയും
പുതുക്കേണ്ടപ്പോൾ മാത്രം അത് പുതുക്കുകയും ചെയ്യും. വിജയകരമായ പുതുക്കൽ റൊട്ടേറ്റ് ചെയ്ത റിഫ്രെഷ് ടോക്കണും
സംരക്ഷിക്കും; അതിനാൽ റിഫ്രെഷ് ടോക്കൺ സാധുവായിരിക്കുന്നിടത്തോളം ഇത് വീണ്ടും മാനുവലായി ശേഖരിക്കേണ്ടതില്ല.

`refreshToken` സജ്ജീകരിച്ചിട്ടില്ലെങ്കിൽ, ഓരോ കാലാവധി കഴിഞ്ഞതിന് ശേഷവും WebSocket ക്രെഡൻഷ്യൽ
മാനുവലായി വീണ്ടും ശേഖരിക്കണം.

### ടിയർ തിരഞ്ഞെടുക്കൽ

| ടിയർ         | അപരനാമം     | സർഫേസ്                 |
| ------------ | ----------- | ---------------------- |
| `individual` | _(default)_ | Consumer M365 Copilot  |
| `edu`        | `included`  | Education M365 Copilot |
| `enterprise` | `work`      | M365 Copilot for Work  |

**വിപുലമായ ക്രമീകരണങ്ങൾ → Copilot ടിയർ** എന്നതിൽ ടിയർ സജ്ജീകരിക്കുക. ടിയർ
BizChat റൂട്ടിംഗിനെയും മോഡൽ ആക്സസിനെയും ബാധിക്കുന്നു.

## സുരക്ഷാ മാതൃക

- **അനൗദ്യോഗിക സംയോജനം.** ഈ പ്രൊവൈഡർ BizChat WebSocket പ്രോട്ടോക്കോൾ റിവേഴ്സ്-എഞ്ചിനീയർ ചെയ്യുന്നു. Microsoft എൻഡ്പോയിന്റിൽ മാറ്റം വരുത്തുമ്പോൾ ഇത് മുന്നറിയിപ്പില്ലാതെ പ്രവർത്തനരഹിതമായേക്കാം.
- ഈ സംയോജനം രേഖപ്പെടുത്താത്ത ഒരു എൻഡ്പോയിന്റിനെ ആശ്രയിക്കുന്നതിനാലാണ് `subscriptionRisk: true` ഫ്ലാഗ് നൽകിയിരിക്കുന്നത്. അക്കൗണ്ട് നിയന്ത്രണങ്ങൾ ഉണ്ടാകാൻ സാധ്യതയുണ്ടെങ്കിലും അത് സ്ഥിരീകരിച്ചിട്ടില്ല.
- ആക്സസ് ടോക്കൺ ഹ്രസ്വകാല സാധുതയുള്ള ഒരു JWT ആണ്. അതിനെ ഒരു പാസ്വേഡ് പോലെ പരിഗണിക്കുക: അത് കമ്മിറ്റ് ചെയ്യുകയോ ലോഗ് ചെയ്യുകയോ പങ്കിടുകയോ ചെയ്യരുത്.
- റിഫ്രഷ് ടോക്കൺ BizChat ഇന്റർഫേസിലേക്ക് ദീർഘകാല ആക്സസ് നൽകുന്നു. ഒരു API കീ സൂക്ഷിക്കുന്ന അതേ ജാഗ്രതയോടെ അത് സംഭരിക്കുക.

## പ്രശ്നപരിഹാരം

### Authentication ഉടൻ പരാജയപ്പെടുന്നു

- നിങ്ങൾ **WebSocket URL**-ൽ നിന്നാണ് പകർത്തിയതെന്ന് ഉറപ്പാക്കുക, XHR/Fetch അഭ്യർത്ഥനയിൽ നിന്നല്ല. Chathub WebSocket കണക്ഷന്റെ `access_token` query parameter-ലാണ് credential ഉള്ളത് — `Authorization: Bearer` header-ലല്ല.
- `chathubPath`-ൽ URL path-ൽ നിന്നുള്ള പൂർണ്ണമായ `<oid>@<tenant>` segment ഉൾപ്പെട്ടിട്ടുണ്ടെന്ന് ഉറപ്പാക്കുക.

### ഏകദേശം 75 മിനിറ്റിന് ശേഷം token കാലഹരണപ്പെടുന്നു

ഇത് പ്രതീക്ഷിക്കാവുന്നതാണ്. `refreshToken` ഇല്ലാതെ access token-ന്റെ കാലാവധി ചുരുങ്ങിയതാണ്. ഇനിപ്പറയുന്നവയിൽ ഒന്ന് ചെയ്യുക:

- DevTools-ൽ നിന്ന് credential വീണ്ടും പകർത്തുക, അല്ലെങ്കിൽ
- സ്വയമേവ പുതുക്കുന്നതിനായി Add or Edit connection ഡയലോഗിലെ **Advanced Settings → Refresh token (optional)** കോൺഫിഗർ ചെയ്യുക.

### Test Connection വിജയിച്ചെങ്കിലും chat 401 നൽകുന്നു

Validation-നും ആദ്യ അഭ്യർത്ഥനയ്ക്കുമിടയിൽ token കാലഹരണപ്പെട്ടിരിക്കാം. പുതിയ credential വീണ്ടും പകർത്തുക.

### Provider പട്ടികയിൽ Copilot ദൃശ്യമാകുന്നില്ല

**Dashboard → Providers**-ൽ `copilot-m365-web` പ്രവർത്തനക്ഷമമാക്കിയിട്ടുണ്ടെന്ന് ഉറപ്പാക്കുക. ചില tiers-ൽ provider സ്ഥിരസ്ഥിതിയായി മറച്ചുവച്ചിരിക്കാം.
