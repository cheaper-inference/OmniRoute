`copilot-m365-web` (അപരനാമം `m365copilot`) `m365.cloud.microsoft/chat` യിലെ ഒരു ആധികാരിക Microsoft 365 Copilot സെഷനിലൂടെ OpenAI- ഫോർമാറ്റ് ചാറ്റ് അഭ്യർത്ഥനകൾ അയയ്ക്കുന്നു. ഇതൊരു അനൗദ്യോഗിക നേറ്റീവ് ഇൻ്റഗ്രേഷനാണ്: പ്രത്യേക പ്രോക്സി പ്രോസസ്സോ ലോക്കൽ ഹോസ്റ്റോ അപ്സ്ട്രീം ആവശ്യമില്ല. ദാതാവ് ID, അപരനാമവും നിലവിലുള്ള ഇറക്കുമതി ചെയ്ത കണക്ഷനുകളും മാറ്റമില്ല. `copilot-web` ഉപഭോക്തൃ സേവനത്തിൻ്റെ വ്യത്യസ്തമായ ദാതാവാണ് `copilot.microsoft.com`.

> **വെബ് കുക്കി ദാതാക്കളിൽ പുതിയ ആളാണോ?**
>
> വായിക്കുക**`docs/getting-started/WEB-COOKIE-GUIDE.md`** ഈ പ്രൊവൈഡർ-നിർദ്ദിഷ്ട ഗൈഡ് പിന്തുടരുന്നതിന് മുമ്പ് പൊതുവായ സജ്ജീകരണ പ്രക്രിയ, പ്രാമാണീകരണ മാർഗ്ഗനിർദ്ദേശം, പരിമിതികൾ, ട്രബിൾഷൂട്ടിംഗ് എന്നിവയ്ക്കായി.
>
> **പാരമ്പര്യ ഇറക്കുമതിക്ക്:** ഈ ദാതാവിനുള്ള യോഗ്യതയാണ്** ഒരു കുക്കി അല്ല** . `m365.cloud.microsoft` ൽ നിന്ന് കുക്കികൾ പകർത്തരുത്. ക്രെഡൻഷ്യൽ ഒരു WebSocket URL ക്വറി പാരാമീറ്ററും പാത്ത് സെഗ്മെൻ്റുമാണ്, രണ്ടും DevTools നെറ്റ്വർക്ക് ടാബിൽ നിന്ന് വായിക്കുന്നു.

## മുൻവ്യവസ്ഥകൾ

- `m365.cloud.microsoft/chat` ൽ Copilot ലേക്ക് ആക്സസ് ഉള്ള ഒരു Microsoft 365 അക്കൗണ്ട്
- DevTools WebSocket പരിശോധനയ്ക്കായി ഒരു Chromium-അധിഷ്ഠിത ബ്രൗസർ (Chrome, Edge).
- ആ അക്കൗണ്ടിലെ അഭ്യർത്ഥിച്ച മോഡലിലേക്കുള്ള ആക്സസ്; വാടകക്കാരനും ലൈസൻസും അനുസരിച്ച് ലഭ്യത വ്യത്യാസപ്പെടുന്നു

## നേറ്റീവ് സൈൻ ഇൻ (ജോലി അല്ലെങ്കിൽ സ്കൂൾ അക്കൗണ്ടുകൾ)

തിരഞ്ഞെടുക്കുക**Microsoft 365 Copilot → ബന്ധിപ്പിക്കുക** ഒപ്പം ഒരു സൈൻ ഇൻ ശ്രമം തയ്യാറാക്കുക. ഡാഷ്ബോർഡ് PKCE ഉള്ള ഒരു ആധികാരിക-കോഡ് ഫ്ലോ ഉപയോഗിക്കുന്നു; ഇത് നിങ്ങളുടെ Microsoft പാസ്വേഡോ MFA കോഡോ ആവശ്യപ്പെടുന്നില്ല.

1. എ തുറക്കുക** ശൂന്യമായ ബ്രൗസർ ടാബ്** , പിന്നെ തുറക്കുക**DevTools → നെറ്റ്വർക്ക്** കൂടാതെ പ്രവർത്തനക്ഷമമാക്കുക** ലോഗ് സൂക്ഷിക്കുക** . Microsoft ലേക്ക് നാവിഗേറ്റ് ചെയ്യുന്നതിന് മുമ്പ് ഇത് ചെയ്യുക : Windows SSO ഉടനടി അവസാനിച്ചേക്കാം.
2. കണക്ഷൻ ഡയലോഗ് കാണിക്കുന്ന അംഗീകാരം URL പകർത്തി ആ തയ്യാറാക്കിയ ടാബിൽ അതിലേക്ക് നാവിഗേറ്റ് ചെയ്യുക. അഭ്യർത്ഥിച്ചാൽ Microsoft ൻ്റെ അക്കൗണ്ട് തിരഞ്ഞെടുക്കൽ അല്ലെങ്കിൽ MFA പൂർത്തിയാക്കുക.
3. സംരക്ഷിത നെറ്റ്വർക്ക് ലോഗിൽ, `https://login.microsoftonline.com/common/oauth2/nativeclient` എന്നതിനുള്ള അഭ്യർത്ഥന കണ്ടെത്തി അതിൻ്റെ പൂർണ്ണരൂപം പകർത്തുക** URL അഭ്യർത്ഥിക്കുക** .
4. കണക്ഷൻ ഡയലോഗിൽ ആ URL ഒട്ടിച്ച് ബന്ധിപ്പിക്കുക. ഒരു റോ കോഡോ അവസാന `wrongplace` വിലാസ-ബാർ URL ഒട്ടിക്കരുത്: ആവശ്യമായ കോൾബാക്ക് ഒരു താൽക്കാലിക നാവിഗേഷനാണ്.

ഓരോ ശ്രമവും പത്ത് മിനിറ്റിന് ശേഷം കാലഹരണപ്പെടും, ഒരു തവണ മാത്രമേ ഉപയോഗിക്കാനാകൂ. കോഡ് കൈമാറ്റം ചെയ്യുന്നതിന് മുമ്പ് സെർവർ അതിൻ്റെ അവസ്ഥ, PKCE വെരിഫയർ, വീണ്ടും പ്രാമാണീകരണ ലക്ഷ്യം എന്നിവ പരിശോധിക്കുന്നു. കാലഹരണപ്പെടൽ അല്ലെങ്കിൽ ഒരു എക്സ്ചേഞ്ച് പരാജയത്തിന് ശേഷം, ഒരു പുതിയ ശ്രമം ആരംഭിക്കുക. സെർവർ പുനരാരംഭിക്കുന്നതിനെ ഒരു ശ്രമത്തിന് അതിജീവിക്കാൻ കഴിയില്ല.

ടോക്കണുകൾ നിലവിലുള്ള കണക്ഷൻ ക്രെഡൻഷ്യൽ സ്റ്റോറും പുതുക്കിയ പാതയും ഉപയോഗിക്കുന്നു. ഒരു കണക്ഷൻ വീണ്ടും പ്രാമാണീകരിക്കുന്നതിന് ഒരേ Microsoft tenant/object ഐഡൻ്റിറ്റി ആവശ്യമാണ്, ഒരേ ഇമെയിൽ മാത്രമല്ല. ഇത് ഓപ്പറേറ്റർ naming/settings സംരക്ഷിക്കുകയും കാലഹരണപ്പെട്ട ഇറക്കുമതി ചെയ്ത ക്രെഡൻഷ്യലുകൾ മാറ്റിസ്ഥാപിക്കുകയും ചെയ്യുന്നു. നേറ്റീവ് സൈൻ-ഇൻ work/school അക്കൗണ്ടുകൾക്കുള്ളതാണ്; നിലവിലുള്ള കണക്ഷനുകൾക്കും പിന്തുണയ്ക്കുന്ന ടയർ കോൺഫിഗറേഷനുകൾക്കും ലെഗസി ഇംപോർട്ട് പാത്ത് ലഭ്യമാണ്.

മുഴുവൻ കോൾബാക്ക് URL ഒറ്റത്തവണ ക്രെഡൻഷ്യലാണ്. സ്ക്രീൻഷോട്ടുകളിലോ ലോഗുകളിലോ പിന്തുണാ സന്ദേശങ്ങളിലോ കമ്മിറ്റുകളിലോ ഒരിക്കലും ഇത് ഉൾപ്പെടുത്തരുത്. ഈ ഫ്ലോ സെർവറിൽ ഒരു ബ്രൗസർ തുറക്കുകയോ നിങ്ങളുടെ ബ്രൗസർ ചരിത്രം പരിശോധിക്കുകയോ ഒരു ലോക്കൽ കോൾബാക്ക് സെർവർ ആരംഭിക്കുകയോ ചെയ്യുന്നില്ല.

## ക്രെഡൻഷ്യൽ ക്യാപ്ചർ (WebSocket രീതി)

1. `https://m365.cloud.microsoft/chat` യിൽ പ്രവേശിച്ച് ഒരു സംഭാഷണം ആരംഭിക്കുക.
2. തുറക്കുക**DevTools → നെറ്റ്വർക്ക്** .
3. ഇതനുസരിച്ച് ഫിൽട്ടർ ചെയ്യുക**WS** (WebSocket).
4. Chathub WebSocket കണക്ഷനിൽ ക്ലിക്ക് ചെയ്യുക. `wss://substrate.office.com/m365Copilot/Chathub/` യിൽ ആരംഭിക്കുന്ന ഒരു URL തിരയുക.
5. അതിൽ നിന്ന്** URL അഭ്യർത്ഥിക്കുക** , പകർത്തുക:
   - `access_token` ക്വറി പാരാമീറ്റർ മൂല്യം (ഒരു ഹ്രസ്വകാല JWT).
   - `/Chathub/` ശേഷമുള്ള Chathub പാത്ത് സെഗ്മെൻ്റ് (ഉദാ `<oid>@<tenant>`).

പൂർണ്ണമായ URL ഒരു രൂപമുണ്ട്:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. OmniRoute, തിരഞ്ഞെടുക്കുക**Microsoft 365 Copilot** , ലെഗസി API-key/import ഓപ്ഷൻ തിരഞ്ഞെടുത്ത് ക്രെഡൻഷ്യൽ ഫോർമാറ്റിൽ ഒട്ടിക്കുക:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. ക്ലിക്ക് ചെയ്യുക** ടെസ്റ്റ് കണക്ഷൻ** ഒപ്പം** സംരക്ഷിക്കുക** .

## ക്രെഡൻഷ്യൽ ക്യാപ്ചർ (HAR ഇറക്കുമതി)

WebSocket URL യിൽ നിന്ന് മൂല്യങ്ങൾ സ്വമേധയാ പകർത്തുന്നതിന് പകരം, നിങ്ങൾക്ക് ഒരു DevTools HAR ഫയൽ എക്സ്പോർട്ട് ചെയ്യാം:

1. തുറക്കുക**DevTools → നെറ്റ്വർക്ക്** .
2. ഒരു Microsoft 365 Copilot സംഭാഷണം ആരംഭിക്കുക അല്ലെങ്കിൽ തുടരുക (ഇത് WebSocket കണക്ഷൻ പ്രവർത്തനക്ഷമമാക്കുന്നു).
3. നെറ്റ്വർക്ക് പാനലിൽ റൈറ്റ് ക്ലിക്ക് ചെയ്ത് തിരഞ്ഞെടുക്കുക** ഉള്ളടക്കം ഉപയോഗിച്ച് എല്ലാം HAR ആയി സംരക്ഷിക്കുക** .
4. OmniRoute ൽ, ഉപയോഗിക്കുക** .har ഫയൽ ഇറക്കുമതി ചെയ്യുക** ദാതാവിൻ്റെ കണക്ഷൻ ഡയലോഗിലെ ബട്ടൺ.

OmniRoute Chathub WebSocket URL നായി HAR സ്കാൻ ചെയ്യുന്നു, `access_token`, `chathubPath` എന്നിവ എക്സ്ട്രാക്റ്റ് ചെയ്യുന്നു, കൂടാതെ ക്രെഡൻഷ്യൽ ഫീൽഡുകൾ സ്വയമേവ പോപ്പുലേറ്റ് ചെയ്യുന്നു. HAR ഇറക്കുമതി JWT കാലഹരണപ്പെടൽ ഡീകോഡ് ചെയ്യുകയും ശേഷിക്കുന്ന ടോക്കൺ ആയുസ്സ് കാണിക്കുകയും ചെയ്യുന്നു.

> **ഒരു യഥാർത്ഥ HAR എക്സ്പോർട്ട്, ആക്സസ് ടോക്കൺ അല്ലെങ്കിൽ പുതുക്കിയ ടോക്കൺ ഒരിക്കലും ചെയ്യരുത്.** ടെസ്റ്റ്, ഡോക്യുമെൻ്റേഷൻ മൂല്യങ്ങൾ എല്ലായ്പ്പോഴും പ്ലെയ്സ്ഹോൾഡറുകളായിരിക്കണം.

## ടോക്കൺ ആയുസ്സ്, പുതുക്കൽ

`access_token` ഹ്രസ്വകാലമാണ് (സാധാരണയായി**~ 75 മിനിറ്റ്** ). ഉപയോഗയോഗ്യമായ പുതുക്കൽ ടോക്കൺ ഇല്ലാതെ, കാലഹരണപ്പെട്ടതിന് ശേഷം നിങ്ങൾ ക്രെഡൻഷ്യൽ വീണ്ടും ക്യാപ്ചർ ചെയ്യണം.

### `refreshToken` ഉപയോഗിച്ച് യാന്ത്രിക പുതുക്കൽ

Microsoft 365 ദാതാവിൽ** കണക്ഷൻ ചേർക്കുക** അല്ലെങ്കിൽ** കണക്ഷൻ എഡിറ്റ് ചെയ്യുക** ഡയലോഗ്, തുറക്കുക** വിപുലമായ ക്രമീകരണങ്ങൾ → പുതുക്കിയ ടോക്കൺ (ഓപ്ഷണൽ)** . `substrate.office.com/sydney` സ്കോപ്പിനായി ഒരു Microsoft OAuth പുതുക്കിയ ടോക്കൺ ഒട്ടിച്ച് സംരക്ഷിക്കുക. ഇൻപുട്ട് മാസ്ക് ചെയ്തിരിക്കുന്നു, സംഭരിച്ച ടോക്കൺ ഉപയോഗിച്ച് ഒരിക്കലും മുൻകൂട്ടി പൂരിപ്പിച്ചിട്ടില്ല. എഡിറ്റ് ചെയ്യുമ്പോൾ, നിലവിലുള്ള ടോക്കൺ നിലനിർത്താൻ അത് ശൂന്യമായി വിടുക; പകരം ഒരു പുതിയ ടോക്കൺ ഒട്ടിക്കുക.

Microsoft ഒന്ന് തിരികെ നൽകുമ്പോൾ നേറ്റീവ് സൈൻ-ഇൻ പുതുക്കൽ ടോക്കൺ നേടുന്നു. ലെഗസി ഇറക്കുമതികൾക്കായി, നിലവിലുള്ള അനുയോജ്യമായ Microsoft അംഗീകാര-കോഡ് ഗ്രാൻ്റ് ഉപയോഗിക്കുക; ഈ ദാതാവ് ഒരു ഉപകരണ-കോഡ് ഫ്ലോ നടപ്പിലാക്കുകയോ വാഗ്ദാനം ചെയ്യുകയോ ചെയ്യുന്നില്ല. ഒരു പുതുക്കൽ ടോക്കൺ കോൺഫിഗർ ചെയ്താൽ, അഭ്യർത്ഥനകൾക്ക് മുമ്പായി OmniRoute `access_token` പരിശോധിക്കുകയും പുതുക്കൽ ആവശ്യമുള്ളപ്പോൾ മാത്രം അത് പുതുക്കുകയും ചെയ്യുന്നു. ഒരു വിജയകരമായ പുതുക്കൽ, റൊട്ടേറ്റഡ് റിഫ്രഷ് ടോക്കണും നിലനിൽക്കും, റിഫ്രഷ് ടോക്കൺ സാധുവായി തുടരുമ്പോൾ സ്വമേധയാ വീണ്ടും ക്യാപ്ചർ ചെയ്യുന്നത് ഒഴിവാക്കുന്നു.

`refreshToken` സജ്ജീകരിച്ചിട്ടില്ലെങ്കിൽ, ഓരോ കാലഹരണപ്പെടലിന് ശേഷവും നിങ്ങൾ സ്വമേധയാ WebSocket ക്രെഡൻഷ്യൽ വീണ്ടും ക്യാപ്ചർ ചെയ്യണം.

### ടയർ തിരഞ്ഞെടുക്കൽ

| ടയർ          | അപരനാമം         | ഉപരിതലം                   |
| ------------ | --------------- | ------------------------- |
| `individual` | _(സ്ഥിരസ്ഥിതി)_ | ഉപഭോക്തൃ M365 Copilot     |
| `edu`        | `included`      | വിദ്യാഭ്യാസം M365 Copilot |
| `enterprise` | `work`          | ജോലിക്ക് M365 Copilot     |

ടയർ സജ്ജമാക്കുക** വിപുലമായ ക്രമീകരണങ്ങൾ → Copilot ടയർ** . നേറ്റീവ് സൈൻ-ഇൻ ഇത് സജ്ജീകരിക്കുന്നില്ല, അതിനാൽ ഒരു വർക്ക് അക്കൗണ്ട് `enterprise` (അപരനാമം `work`) കൂടാതെ ഒരു വിദ്യാഭ്യാസ അക്കൗണ്ട് `edu` എന്നിവയും തിരഞ്ഞെടുക്കണം, കൂടാതെ ഡോക്യുമെൻ്റഡ് മോഡൽ IDs ഉപയോഗിക്കുമ്പോൾ: അവർ അവരുടേതായ ടോൺ, സാഹചര്യം, ലൈസൻസ് തരം എന്നിവ തിരഞ്ഞെടുക്കുന്നു, എന്നാൽ ഏജൻ്റും ഇൻവോക്കേഷൻ ഓപ്ഷനുകളും ഇപ്പോഴും ടയറിൽ നിന്നാണ് വരുന്നത്, കൂടാതെ വ്യക്തിഗത സ്ഥിരസ്ഥിതികൾ ഒരു ജോലിക്കാരന് പരാജയപ്പെടാം. ടയർ മാറ്റുന്നത് ഒരു മാതൃകാ ലൈസൻസ് നൽകുന്നില്ല. വ്യക്തമായ വിപുലമായ പ്രോട്ടോക്കോൾ അസാധുവാക്കലുകൾക്ക് മുൻഗണന നൽകുകയും ആവശ്യമായ വയർ മൂല്യങ്ങൾ നിങ്ങൾക്കറിയുമ്പോൾ മാത്രമേ ഉപയോഗിക്കാവൂ.

## മോഡലുകളും റൂട്ടിംഗും

നേറ്റീവ് കാറ്റലോഗിൽ എല്ലാ ഡോക്യുമെൻ്റഡ് ഒറ്റപ്പെട്ട IDs കൂടാതെ നാല് യഥാർത്ഥ നേറ്റീവ് IDs ഉൾപ്പെടുന്നു. കാറ്റലോഗ് നിശ്ചലവും അക്കൗണ്ട്-സ്വതന്ത്രവുമാണ്, ഒരു അക്കൗണ്ട് അർഹതയുള്ള അന്വേഷണമല്ല: ബന്ധിപ്പിച്ച അക്കൗണ്ടിന് അവ ഉപയോഗിക്കാൻ കഴിയാത്തപ്പോഴും പണമടച്ചുള്ള റൂട്ടുകളും കോംപാറ്റിബിലിറ്റി അപരനാമങ്ങളും ലിസ്റ്റ് ചെയ്തിരിക്കും. മോഡൽ ഡിസ്പ്ലേ ലേബലുകൾ ദാതാവിൻ്റെ പേരും ഓരോ മോഡൽ ലഭ്യത ബോയിലർ പ്ലേറ്റും ഒഴിവാക്കുന്നു; ദാതാവ് അവശേഷിക്കുന്നു**Microsoft 365 Copilot** . ലേബലുകൾ അടയാളപ്പെടുത്തി** അപരനാമം** അല്ലെങ്കിൽ** പാരമ്പര്യം** നിലവിലുള്ള ഐഡൻ്റിഫയറുകളും പ്രോട്ടോക്കോൾ മാപ്പിംഗുകളും നിലനിർത്തുക, ചരിത്രപരമായ മോഡൽ പതിപ്പിൻ്റെ ഗ്യാരണ്ടിയല്ല. ഒറ്റപ്പെട്ട പ്രോക്സികൾ** / മോഡലുകളിൽ നിന്ന് ഇറക്കുമതി ചെയ്യുക** ഈ നേറ്റീവ് WebSocket ദാതാവിന് നിർദ്ദേശങ്ങൾ ബാധകമല്ല.

- ഒരു വ്യക്തമായ മോഡൽ ലൈസൻസ് നിരസിക്കൽ തിരികെ നൽകുന്നു** 403** `m365_model_not_licensed`, 502 അല്ല. connection/model ജോടിയാക്കുന്നതിനുള്ള റൂട്ടിംഗ് ലോക്കുകൾ, കണക്ഷനിൽ ലൈസൻസുള്ള മോഡലുകൾ ഉപയോഗയോഗ്യമാക്കുന്നു.
- `InvalidCopilotLicense` എന്നത് അക്കൗണ്ട്-ലെവൽ ലൈസൻസ് നിരസിക്കുന്നതാണ്, `m365_account_not_licensed` എന്ന് പ്രത്യേകം റിപ്പോർട്ടുചെയ്തു.
- ഓരോ ഉപയോക്താവിനും ഒരു ത്രോട്ടിൽ തിരികെ നൽകുന്നു** 429** `m365_throttled`, കണക്ഷൻ തണുപ്പിക്കുന്നു. മുൻഗണന-ആക്സസ് ക്ഷീണം മടങ്ങുന്നു** 429** `priority_access_exhausted`, മോഡൽ സ്കോപ്പ്. `errorCode: "ReasoningTurnExhausted"` റിട്ടേണുകളുള്ള `OutOfCredits` യുടെ ഫലം** 429** പകരം `reasoning_turns_exhausted`, മോഡൽ-സ്കോപ്പ്, റീസെറ്റ് സമയം ക്ലെയിം ചെയ്തിട്ടില്ല. ക്വിക്ക് ടോണുകൾ സേവിക്കുന്നതിനിടയിൽ "ആഴത്തിൽ ചിന്തിക്കുക" ടോണുകൾ ക്യാപ് ചെയ്യാൻ ഒരു ജോലിക്കാരൻ റിപ്പോർട്ട് ചെയ്തു; വ്യാപ്തി എന്നത് ഒരു ഉപഭോക്തൃ നിരീക്ഷണമാണ്, ഈ ശേഖരം പുനർനിർമ്മിച്ച ഒന്നല്ല. അതിനാൽ റൂട്ടിംഗ് മറ്റ് ഡോക്യുമെൻ്റ് ചെയ്ത `gpt-5.5`, `gpt-5.6` എന്നിവയുടെ ആഴത്തിലുള്ള മോഡലുകളെ അതേ കൂൾഡൗണിനായി ആ കണക്ഷനിലെ ഭ്രമണത്തിൽ നിന്ന് മാറ്റി, ദ്രുത ടോണുകളും മറ്റെല്ലാ പരാജയങ്ങളും അതിൻ്റെ സ്വന്തം മോഡലിൽ ഉപേക്ഷിക്കുന്നു. നൽകിയ പുനഃശ്രമ സൂചനകൾ സംരക്ഷിക്കപ്പെട്ടിരിക്കുന്നു; നഷ്ടമായ റീസെറ്റ് അറിയപ്പെടുന്ന റീസെറ്റ് സമയമായി പരസ്യപ്പെടുത്തിയിട്ടില്ല.
- ഒരു Copilot സുരക്ഷാ നിരസിക്കൽ (`Disengaged`) തിരികെ നൽകുന്നു** 400** `provider_safety_rejection`, പങ്കിട്ട ദാതാവിൻ്റെ സുരക്ഷാ-സ്റ്റോപ്പ് ലേബൽ. ഇത് കണക്ഷൻ്റെ ആരോഗ്യത്തിന് എതിരായി ഒരിക്കലും കണക്കാക്കില്ല, ക്ലയൻ്റ് SDKs 400 വീണ്ടും ശ്രമിക്കരുത്, കൂടാതെ മറ്റൊരു ടാർഗെറ്റിനെതിരെ അഭ്യർത്ഥന വീണ്ടും പ്ലേ ചെയ്യുന്നതിന് പകരം `PROVIDER_SAFETY_STOPS_TERMINAL` പ്രവർത്തനക്ഷമമാക്കിയ കോംബോ റൂട്ടിംഗ് അവിടെ നിർത്തുന്നു.
- ഒരു കണക്ഷനിലെ അഭ്യർത്ഥനകൾ നിലവിലുള്ള സെമാഫോർ അക്കൗണ്ട് വഴിയാണ് ക്രമീകരിച്ചിരിക്കുന്നത്. സമാന്തര പാനലുകളേക്കാൾ മുൻഗണനയുള്ള ഫാൾബാക്ക് തിരഞ്ഞെടുക്കുക; സീരിയലൈസേഷൻ മാത്രം Microsoft യുടെ സംഭാഷണ നിരക്ക് പരിധി ഇല്ലാതാക്കുന്നില്ല.

## പെരുമാറ്റവും പരിധികളും അഭ്യർത്ഥിക്കുക

- ഉപകരണങ്ങൾ ആകുന്നു** പ്രോംപ്റ്റ്-എമുലേറ്റഡ്** , നേറ്റീവ് Microsoft ഫംഗ്ഷൻ കോളുകളല്ല. ഒരു ടൂൾ പ്രവർത്തനക്ഷമമാക്കിയ അഭ്യർത്ഥന ഒരു ബഫർ ചെയ്ത ജനറേഷൻ ഉപയോഗിക്കുന്നു; ഉപകരണങ്ങൾ തിരഞ്ഞെടുക്കാൻ അത് മറ്റൊരു തലമുറയെ ചെലവഴിക്കുന്നില്ല. സാധുവായ പിന്തുണയ്ക്കുന്ന ആർഗ്യുമെൻ്റ് രൂപങ്ങളുള്ള പ്രഖ്യാപിത ടൂളുകൾ മാത്രമേ കോളുകളായി തിരികെ നൽകൂ.
- ഒരൊറ്റ പിന്നിലുള്ള ഉദാഹരണമുള്ള ഒരു നീണ്ട ഘടനാപരമായ ഉത്തരം ഗദ്യമായി സംരക്ഷിച്ചിരിക്കുന്നു. ഇതൊരു ഹ്യൂറിസ്റ്റിക് ആണ്, ഉദ്ദേശ്യത്തിൻ്റെ തെളിവല്ല; ആപ്ലിക്കേഷനുകൾ ഇപ്പോഴും സ്വന്തം ടൂൾ അനുമതികൾ നടപ്പിലാക്കണം.
- വെബ് ക്ലയൻ്റ് അയയ്ക്കുന്ന രീതിയിൽ ഇമേജ് ഇൻപുട്ട് പ്രവർത്തിക്കുന്നു. ഓരോ ചിത്ര ഭാഗവും (`image_url` ഒരു ഡാറ്റ URL അല്ലെങ്കിൽ ഒരു പൊതു HTTPS URL, അല്ലെങ്കിൽ ഒരു പ്രതികരണങ്ങൾ `input_image`) ചാറ്റ് ടോക്കൺ ഉപയോഗിച്ച് ടേൺ സംഭാഷണത്തിലേക്ക് `/m365Copilot/UploadFile` ലേക്ക് അപ്ലോഡ് ചെയ്യുന്നു, കൂടാതെ സന്ദേശം ഒരു `ImageFile` വ്യാഖ്യാനത്തോടെ അതിലേക്ക് പോയിൻ്റ് ചെയ്യുന്നു; വാചകം അത് ഇരുന്നിടത്ത് അടയാളപ്പെടുത്തുന്നു (`[image 1]`, …). ഒരു പുതിയ സംഭാഷണം ചരിത്രത്തിലെ എല്ലാ ചിത്രങ്ങളും അപ്ലോഡ് ചെയ്യുന്നു, പുതിയ സന്ദേശങ്ങളുടെ ചിത്രങ്ങൾ മാത്രം തുടരുന്നു. പരമാവധി 10 MiB വീതമുള്ള 10 PNG, JPEG, GIF അല്ലെങ്കിൽ WebP ചിത്രങ്ങൾ വരെ (ഓരോ അഭ്യർത്ഥനയ്ക്കും 40 MiB ); ബൈറ്റുകളിൽ നിന്ന് ഫോർമാറ്റ് വായിക്കുന്നു. HTTPS URLs ലഭിക്കുന്നത് പബ്ലിക്-ഒൺലി, ഡിഎൻഎസ് പിൻ ചെയ്ത റിമോട്ട് ഇമേജ് ഗാർഡിലൂടെയാണ്. പരാജയപ്പെട്ട അപ്ലോഡ് അഭ്യർത്ഥന പരാജയപ്പെടുന്നു (** 502** `m365_image_upload_failed`,** 400** `m365_image_rejected` അല്ലെങ്കിൽ `m365_image_invalid`); നൽകിയ പ്രതിച്ഛായയില്ലാതെ ഒരു വഴിത്തിരിവ് ഒരിക്കലും മുന്നോട്ട് പോകില്ല. മറ്റ് നോൺ-ടെക്സ്റ്റ് ഭാഗങ്ങൾ (ഓഡിയോ, ഫയലുകൾ) വ്യക്തമായി നിരസിക്കപ്പെടും, നിശബ്ദമായി ഡ്രോപ്പ് ചെയ്യപ്പെടുന്നില്ല.
- ഒരു ഫോളോ-അപ്പ് അഭ്യർത്ഥന അതേ അപ്സ്ട്രീം സംഭാഷണം തുടരുകയും മുമ്പത്തെ മറുപടിക്ക് ശേഷമുള്ള സന്ദേശങ്ങൾ മാത്രം അയയ്ക്കുകയും ചെയ്യുന്നു. അത് ആ മറുപടി കൃത്യമായി നീട്ടണം: ഒരേ കണക്ഷൻ, മോഡൽ പ്രൊഫൈൽ, ടൂൾ സെറ്റ്; ഒരു മാറ്റമില്ലാത്ത ചരിത്രം (എല്ലാ സന്ദേശത്തിനും മേലെ ഒരു sha256 ചെയിൻ); മറുപടിയുടെ ടൂൾ-കോൾ ഐഡികൾ അല്ലെങ്കിൽ വൈറ്റ്സ്പേസ് വരെയുള്ള ടെക്സ്റ്റ്. മറ്റെന്തെങ്കിലും (എഡിറ്റ് ചെയ്ത ചരിത്രം, അതേ ആദ്യ സന്ദേശമുള്ള മറ്റൊരു സെഷൻ, മറ്റൊരു മറുപടി, 30 മിനിറ്റ് നേരത്തേക്ക് നിഷ്ക്രിയമായ സംഭാഷണം അല്ലെങ്കിൽ Copilot യുടെ 600-മെസേജ് ക്യാപ്പിന് അടുത്ത്, ഒരു ഐഡി ഇല്ലാത്ത ഒരു കണക്ഷൻ) മുഴുവൻ ചരിത്രവുമായി ഒരു പുതിയ സംഭാഷണം ആരംഭിക്കുന്നു. പരാജയപ്പെട്ട ഒരു ടേൺ ഒരിക്കലും പുനരാരംഭിക്കില്ല, ഒരു പുതിയ സംഭാഷണത്തിൽ ഒരിക്കൽ ഉള്ളടക്കം കുറഞ്ഞ `InternalError` വീണ്ടും അയയ്ക്കും (** 502** വീണ്ടും പരാജയപ്പെടുകയാണെങ്കിൽ `m365_internal_error` ). തുടർച്ചകൾ പ്രോസസ്സ് മെമ്മറിയിൽ സൂക്ഷിച്ചിരിക്കുന്നു: പുനരാരംഭിക്കുന്നത് പുതിയ സംഭാഷണങ്ങൾ ആരംഭിക്കുന്നു.
- Copilot യുടെ താൽക്കാലിക ചാറ്റിൽ (`disableMemory=1`) ഓരോ തിരിവും പ്രവർത്തിക്കുന്നു: സംഭാഷണം പ്രവർത്തിക്കുമ്പോൾ അതിൻ്റെ സന്ദർഭം നിലനിർത്തുന്നു, അക്കൗണ്ടിൻ്റെ ചാറ്റ് ചരിത്രത്തിൽ ഒരിക്കലും ദൃശ്യമാകില്ല. മോഡൽ ടെസ്റ്റുകൾ, ടെസ്റ്റ് ഓൾ, കോംബോ ടെസ്റ്റുകൾ എന്നിവ അതിനാൽ സംഭാഷണങ്ങൾ ഉപേക്ഷിക്കാതെ തന്നെ ഈ ദാതാവിനെ പരിശോധിച്ചേക്കാം.
- ഒരു ടേണിന് 120-സെക്കൻഡ് നിഷ്ക്രിയ ഡെഡ്ലൈനും ബൗണ്ടഡ് മൊത്തത്തിലുള്ള ഡെഡ്ലൈനുമുണ്ട്. അന്തിമ ഉത്തരങ്ങൾ, പുരോഗതി ഫിൽട്ടറിംഗ്, റദ്ദാക്കൽ എന്നിവ കൈകാര്യം ചെയ്യുന്നത് നേറ്റീവ് transport/composer. ആണ്
- വെബ് അടിസ്ഥാനത്തിലുള്ള ഉത്തരങ്ങൾ അവയുടെ ഉറവിടങ്ങൾ സൂക്ഷിക്കുന്നു. Copilot സ്വകാര്യ ഉപയോഗ നിയന്ത്രണ പ്രതീകങ്ങൾ ഉപയോഗിച്ച് ഒരു അവലംബം അടയാളപ്പെടുത്തുകയും ഉറവിടങ്ങൾ `references` ആയി അയയ്ക്കുകയും ചെയ്യുന്നു; ഓരോ മാർക്കറും ഒരു അക്കമിട്ട മാർക്ക്ഡൗൺ ലിങ്കായി മാറുന്നു (`[1](https://…)`, അല്ലെങ്കിൽ Copilot ഒരു ലിങ്ക് ടാർഗെറ്റായി മാർക്കർ ഉപയോഗിക്കുമ്പോൾ ബെയർ URL ) ഒരു പൊരുത്തപ്പെടുന്ന `url_citation` വ്യാഖ്യാനം (`message.annotations`, അല്ലെങ്കിൽ ലിങ്ക് വഹിക്കുന്ന ചങ്കിൽ `delta.annotations` ). ഒരിക്കലും എത്താത്ത ഒരു ഉറവിടം ഉപേക്ഷിക്കപ്പെടുന്നു, അതിനാൽ മാർക്കറുകൾ ഒരിക്കലും ക്ലയൻ്റിലേക്ക് എത്തില്ല. സ്ട്രീം ചെയ്യുമ്പോൾ, ഒരു ഉദ്ധരണിക്ക് ശേഷമുള്ള വാചകം അതിൻ്റെ ഉറവിടം എത്തുന്നതുവരെ കാത്തിരിക്കുന്നു.
- Copilot യുടെ യുക്തി സംഗ്രഹം (`ChainOfThoughtSummary`), മോഡൽ ഒരെണ്ണം അയയ്ക്കുമ്പോൾ, `reasoning_content` ആയി തിരികെ നൽകും, ഒരിക്കലും ഉത്തരത്തിൻ്റെ ഭാഗമല്ല. സ്വയം തിരുത്തിയെഴുതുന്ന ഒരു സംഗ്രഹം ടേൺ പരാജയപ്പെടാതെ സ്ട്രീമിംഗ് നിർത്തുന്നു.
- ഏതെങ്കിലും ഉള്ളടക്കത്തിന് മുമ്പ്, സ്ട്രീമിംഗ് ആവശ്യപ്പെട്ടാലും licence/throttle പരാജയങ്ങൾ HTTP 403/429 നിലനിർത്തുന്നു. ഉള്ളടക്കം ആരംഭിച്ചതിന് ശേഷം, പരാജയങ്ങൾ SSE പിശക് സംഭവങ്ങളാണ്, ഒരിക്കലും വിജയകരമായ ഫിനിഷ് അല്ല. അനുബന്ധം മാത്രമുള്ള സ്ട്രീമിംഗ് പ്രതിനിധീകരിക്കാൻ കഴിയാത്ത ഒരു അപ്സ്ട്രീം റീറൈറ്റിംഗ് ഒരു വ്യക്തമായ സ്ട്രീം പിശകാണ്; നോൺ-സ്ട്രീമിംഗ്, ബഫർ ടൂൾ പ്രതികരണങ്ങൾ അന്തിമ വാചകം നിലനിർത്തുന്നു.
- Copilot കണക്ഷൻ തന്നെ നിരസിക്കുമ്പോൾ, അതിൻ്റെ ഉത്തരം ഇതുപോലെ റിപ്പോർട്ട് ചെയ്യപ്പെടും:** 401** നിരസിച്ചതോ കാലഹരണപ്പെട്ടതോ ആയ സൈൻ-ഇന്നിനായി `m365_unauthorized` (വീണ്ടും സൈൻ ഇൻ ചെയ്യുക),** 429** ത്രോട്ടിലിംഗിനുള്ള അതിൻ്റെ `Retry-After`, അല്ലാത്തപക്ഷം ഒരു ഹാൻഡ്ഷേക്ക് പരാജയം, ഒരിക്കലും ഒരു സാധാരണ കണക്ഷൻ പരാജയമല്ല.

## ഇമേജ് ജനറേഷൻ

വെബ് ക്ലയൻ്റ് ചെയ്യുന്നതുപോലെ, `model: "copilot-m365-web/m365-copilot-image"` (അലിയാസ് `m365copilot/m365-copilot-image`) ഉള്ള `POST /v1/images/generations`, Copilot ൻ്റെ ബിൽറ്റ്-ഇൻ ഇമേജ് ടൂൾ ഉപയോഗിച്ച് വരയ്ക്കുന്നു. ഓരോ ചിത്രവും ഒരു Copilot ടേൺ ആണ്: ഇത് വെബ് ക്ലയൻ്റിൻറെ ഇമേജ് ഓപ്ഷൻ സെറ്റ് ചെയ്ത് `GenerateGraphicArt` പ്രഖ്യാപിക്കുന്നു, കൂടാതെ Microsoft ൻ്റെ ഡിസൈനർ സേവനത്തിലെ ഒരു ആർട്ടിഫാക്റ്റിലേക്ക് പോയിൻ്റ് ചെയ്യുന്ന ഒരു പ്രോഗ്രസ് എൻട്രിയിൽ ചിത്രം എത്തിച്ചേരുന്നു. ആ ആർട്ടിഫാക്റ്റ് ചാറ്റ് ടോക്കൺ നിരസിക്കുന്നു, അതിനാൽ കണക്ഷൻ്റെ പുതുക്കൽ ടോക്കണിൽ നിന്ന് OmniRoute ഒരു ഡിസൈനർ ടോക്കൺ മിൻ്റ് ചെയ്യുകയും ബൈറ്റുകൾ ഡൗൺലോഡ് ചെയ്യുകയും ചെയ്യുന്നു; `designerapp.officeapps.live.com` ലേക്ക് മാത്രമേ ടോക്കൺ അയയ്ക്കൂ.

- ഒരു നേറ്റീവ് സൈൻ-ഇൻ കണക്ഷൻ ആവശ്യമാണ് (ഒരു പുതുക്കൽ ടോക്കൺ); ഒട്ടിച്ച ടോക്കൺ പരാജയപ്പെടുന്നു** 400** ഏതെങ്കിലും ഊഴം ചെലവഴിക്കുന്നതിനുമുമ്പ്.
- `n` 1-4 ആണ്, ഓരോ തവണയും. `size` പ്രോംപ്റ്റിൽ നിന്ന് Copilot വായിക്കുന്ന ഓറിയൻ്റേഷൻ (വിശാലമോ ഉയരമോ ചതുരമോ) മാത്രമേ നയിക്കൂ; Copilot റെൻഡർ വലുപ്പം തിരഞ്ഞെടുക്കുന്നു.
- ഇമേജുകൾ ഇൻലൈനിലേക്ക് തിരികെ നൽകുന്നു: സ്ഥിരസ്ഥിതിയായി `b64_json`, `response_format: "url"` എന്നതിനായുള്ള ഒരു ഡാറ്റ URL.
- ജനറേറ്റ് ചെയ്ത ചിത്രങ്ങൾ ചാറ്റിൽ നിന്ന് വേറിട്ട് ഒരു ചെറിയ പ്രതിദിന ബജറ്റിൽ വരയ്ക്കുന്നു. അത് ഉപയോഗിക്കുമ്പോൾ അഭ്യർത്ഥന പരാജയപ്പെടുന്നു** 429** . ഒരു ചിത്രവുമില്ലാതെ ഉത്തരം നൽകുന്ന ഒരു ടേൺ പരാജയപ്പെടുന്നു** 502** (അല്ലെങ്കിൽ** 400** /** 503** Copilot യുടെ വാചകം ഒരു വിസമ്മതം അല്ലെങ്കിൽ ശേഷി പ്രശ്നമായി വായിക്കുമ്പോൾ); എന്ന് സന്ദേശം പറയുന്നു.

## സുരക്ഷാ മോഡൽ

- **അനൗദ്യോഗിക ഏകീകരണം.** ഈ ദാതാവ് BizChat WebSocket പ്രോട്ടോക്കോൾ റിവേഴ്സ് എഞ്ചിനീയർ ചെയ്യുന്നു. Microsoft എൻഡ് പോയിൻ്റ് മാറ്റുമ്പോൾ അത് അറിയിപ്പ് കൂടാതെ തകർന്നേക്കാം.
- `subscriptionRisk: true` ഫ്ലാഗ് പ്രതിഫലിപ്പിക്കുന്നത്, സംയോജനം ഒരു രേഖകളില്ലാത്ത അവസാന പോയിൻ്റിനെ ആശ്രയിച്ചിരിക്കുന്നു എന്നാണ്. അക്കൗണ്ട് നിയന്ത്രണങ്ങൾ സാധ്യമാണെങ്കിലും സ്ഥിരീകരിച്ചിട്ടില്ല.
- ആക്സസ് ടോക്കൺ ഒരു ഹ്രസ്വകാല JWT ആണ്. ഇത് ഒരു പാസ്വേഡ് പോലെ പരിഗണിക്കുക: ഇത് സമർപ്പിക്കുകയോ ലോഗ് ചെയ്യുകയോ പങ്കിടുകയോ ചെയ്യരുത്.
- പുതുക്കിയ ടോക്കൺ Microsoft 365 ഉപരിതലത്തിലേക്കുള്ള പ്രവേശനം നൽകുന്നു. ഒരു API കീയുടെ അതേ ശ്രദ്ധയോടെ ഇത് സംഭരിക്കുക.

## ട്രബിൾഷൂട്ടിംഗ്

### പ്രാമാണീകരണം ഉടനടി പരാജയപ്പെടുന്നു

- ഇതിൽ നിന്ന് നിങ്ങൾ പകർത്തിയെന്ന് പരിശോധിക്കുക**WebSocket URL** , ഒരു XHR/Fetch അഭ്യർത്ഥനയിൽ നിന്നല്ല. ക്രെഡൻഷ്യൽ Chathub WebSocket കണക്ഷൻ്റെ `access_token` ക്വറി പാരാമീറ്ററിലാണ് — `Authorization: Bearer`.
- `chathubPath` URL പാതയിൽ നിന്നുള്ള മുഴുവൻ `<oid>@<tenant>` സെഗ്മെൻ്റും ഉൾപ്പെടുന്നുവെന്ന് ഉറപ്പാക്കുക.

### ~ 75 മിനിറ്റിന് ശേഷം ടോക്കൺ കാലഹരണപ്പെടും

ഇത് പ്രതീക്ഷിക്കുന്നു. ഒരു `refreshToken` ഇല്ലാതെ, ആക്സസ് ടോക്കൺ ഹ്രസ്വകാലമാണ്. ഒന്നുകിൽ:

- DevTools യിൽ നിന്ന് ക്രെഡൻഷ്യൽ വീണ്ടും ക്യാപ്ചർ ചെയ്യുക, അല്ലെങ്കിൽ
- കോൺഫിഗർ ചെയ്യുക** വിപുലമായ ക്രമീകരണങ്ങൾ → പുതുക്കിയ ടോക്കൺ (ഓപ്ഷണൽ)** യാന്ത്രിക പുതുക്കലിനായി കണക്ഷൻ ചേർക്കുക അല്ലെങ്കിൽ എഡിറ്റുചെയ്യുക ഡയലോഗിൽ.

### ടെസ്റ്റ് കണക്ഷൻ പാസായെങ്കിലും ചാറ്റ് 401 നൽകുന്നു

ഉപയോഗിച്ച് സൃഷ്ടിച്ച ഒരു കണക്ഷന്** Microsoft ഉപയോഗിച്ച് സൈൻ ഇൻ ചെയ്യുക** , ടെസ്റ്റ് കണക്ഷൻ ആക്സസ് ടോക്കണിൻ്റെ കാലഹരണപ്പെടൽ പരിശോധിക്കുകയും സംഭരിച്ച പുതുക്കിയ ടോക്കണിനൊപ്പം കാലഹരണപ്പെട്ട ടോക്കൺ പുതുക്കുകയും ചെയ്യുന്നു, അതിനാൽ റിഫ്രഷ് ടോക്കൺ ഇപ്പോഴും പ്രവർത്തിക്കുന്നുവെന്ന് പാസിംഗ് ടെസ്റ്റ് തെളിയിക്കുന്നു.

ഒട്ടിച്ച ക്രെഡൻഷ്യലിനായി, ടെസ്റ്റ് കണക്ഷൻ ക്രെഡൻഷ്യലിൻ്റെ ആകൃതി പരിശോധിക്കുന്നു, കൂടാതെ ടോക്കൺ കാലഹരണപ്പെടുമ്പോൾ, ദാതാവ് ഉപയോഗിക്കുന്ന ടോക്കൺ കാലഹരണപ്പെട്ടിട്ടില്ല (കണക്ഷൻ്റെ സംഭരിച്ച ടോക്കൺ ഒരു പഴകിയ പേസ്റ്റ് നേടുന്നു; പുതുക്കിയ ടോക്കൺ പുതുക്കാവുന്നതായി കണക്കാക്കുന്നു). കാലഹരണപ്പെടുന്നതിന് മുമ്പ് അസാധുവാക്കിയ ഒരു ടോക്കൺ ഇപ്പോഴും പരീക്ഷയിൽ വിജയിക്കുന്നു; ചാറ്റ് തുടർന്ന് മടങ്ങുന്നു** 401** `m365_unauthorized`. ഉപയോഗിക്കുക** Microsoft ഉപയോഗിച്ച് സൈൻ ഇൻ ചെയ്യുക** വീണ്ടും, അല്ലെങ്കിൽ ഒരു പുതിയ ക്രെഡൻഷ്യൽ വീണ്ടും പിടിച്ചെടുക്കുക.

### ദാതാക്കളുടെ പട്ടികയിൽ Copilot ദൃശ്യമാകുന്നില്ല

`copilot-m365-web` പ്രവർത്തനക്ഷമമാക്കിയിട്ടുണ്ടെന്ന് ഉറപ്പാക്കുക** ഡാഷ്ബോർഡ് → ദാതാക്കൾ** . ദാതാവിനെ ചില ടയറുകളിൽ ഡിഫോൾട്ടായി മറച്ചിരിക്കാം.
