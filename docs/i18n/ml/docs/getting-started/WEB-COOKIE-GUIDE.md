വെബ് കുക്കി പ്രൊവൈഡറുകൾ, API കീയ്ക്ക് പകരം നിങ്ങളുടെ നിലവിലുള്ള ബ്രൗസർ സെഷനിലൂടെ ഒരു AI സേവനം ഉപയോഗിക്കാൻ OmniRoute-നെ അനുവദിക്കുന്നു. ഒരു സേവനത്തിന്റെ വെബ്സൈറ്റ് വഴി നിങ്ങൾക്ക് ഇതിനകം ആക്സസ് ഉണ്ടായിരിക്കുകയും, അതേ പ്രാമാണീകരിച്ച സെഷൻ OmniRoute ഉപയോഗിക്കണമെന്ന് ആഗ്രഹിക്കുകയും ചെയ്യുമ്പോൾ ഇവ ഉപകാരപ്രദമാണ്.

API-കീ പ്രൊവൈഡറുകളിൽ നിന്ന് വ്യത്യസ്തമായി, നിങ്ങളുടെ ബ്രൗസർ വെബ്സൈറ്റിലേക്ക് അയയ്ക്കുന്ന ക്രെഡൻഷ്യലുകൾ ഉപയോഗിച്ചാണ് വെബ് കുക്കി പ്രൊവൈഡറുകൾ പ്രാമാണീകരിക്കുന്നത്.

# ആരംഭിക്കുന്നതിന് മുമ്പ്

> **പ്രധാനം:** ക്രെഡൻഷ്യലുകൾ എല്ലായ്പ്പോഴും ഒരു **തത്സമയ നെറ്റ്വർക്ക് അഭ്യർത്ഥനയിൽ** നിന്നാണ് പകർത്തേണ്ടത്, നിങ്ങളുടെ ബ്രൗസറിന്റെ കുക്കി സ്റ്റോറേജിൽ നിന്നല്ല.

തെറ്റായ സ്ഥലത്തുനിന്ന് കുക്കികൾ പകർത്തുന്നതാണ് പല പ്രാമാണീകരണ പ്രശ്നങ്ങൾക്കും കാരണം.

## കുക്കി സ്റ്റോറേജിൽ നിന്ന് പകർത്തരുത്

മിക്ക ബ്രൗസറുകളും സംഭരിച്ച കുക്കികൾ ഇനിപ്പറയുന്ന രീതിയിൽ കാണിക്കുന്നു:

```
DevTools
→ Application (or Storage)
→ Cookies
```

ഈ കുക്കികൾ ശരിയാണെന്ന് തോന്നുമെങ്കിലും, അവ:

- കാലഹരണപ്പെട്ടവയായിരിക്കാം
- അപൂർണ്ണമായിരിക്കാം
- പ്രാമാണീകരിച്ച അഭ്യർത്ഥനകളിൽ മാത്രം അയയ്ക്കുന്ന കുക്കികൾ ഉൾക്കൊള്ളാതിരിക്കാം

ഈ മൂല്യങ്ങൾ സാധുവാണെന്ന് തോന്നിയാലും, അവ ഉപയോഗിക്കുന്നത് പ്രാമാണീകരണ പരാജയങ്ങൾക്ക് കാരണമായേക്കാം.

## ഒരു തത്സമയ അഭ്യർത്ഥനയിൽ നിന്ന് പകർത്തുക

പകരം, വിജയകരമായ ഒരു അഭ്യർത്ഥനയിൽ നിന്നുള്ള കുക്കികൾ ഉപയോഗിക്കുക:

```
DevTools
→ Network
→ Refresh the page
→ Open a chat or conversation request
→ Request Headers
→ Cookie
```

നിങ്ങളുടെ ബ്രൗസർ വിജയകരമായി ഉപയോഗിച്ച കൃത്യമായ പ്രാമാണീകരണ വിവരങ്ങൾ `Cookie` അഭ്യർത്ഥനാ ഹെഡറിൽ അടങ്ങിയിരിക്കുന്നു.

മിക്ക വെബ് കുക്കി പ്രൊവൈഡറുകൾക്കും OmniRoute-ലേക്ക് ഒട്ടിക്കേണ്ട മൂല്യം ഇതാണ്.

# പൊതുവായ സജ്ജീകരണം

മിക്ക വെബ് കുക്കി പ്രൊവൈഡറുകൾക്കും സജ്ജീകരണ പ്രക്രിയ ഒരുപോലെയാണ്.

1. പ്രൊവൈഡറുടെ വെബ്സൈറ്റിൽ സൈൻ ഇൻ ചെയ്യുക.
2. ബ്രൗസറിന്റെ ഡെവലപ്പർ ടൂളുകൾ തുറക്കുക.
3. **Network** ടാബ് തുറക്കുക.
4. പേജ് പുതുക്കുക.
5. പ്രാമാണീകരിച്ച ഒരു ചാറ്റ് അല്ലെങ്കിൽ സംഭാഷണ അഭ്യർത്ഥന തുറക്കുക.
6. ആവശ്യമായ പ്രാമാണീകരണ ക്രെഡൻഷ്യലുകൾ പകർത്തുക.
7. OmniRoute തുറക്കുക.
8. **Providers → Add Provider** എന്നതിലേക്ക് പോകുക.
9. നിങ്ങളുടെ വെബ് കുക്കി പ്രൊവൈഡർ തിരഞ്ഞെടുക്കുക.
10. ക്രെഡൻഷ്യലുകൾ ഒട്ടിക്കുക.
11. **Test Connection** ക്ലിക്ക് ചെയ്യുക.
12. പ്രൊവൈഡർ സംരക്ഷിക്കുക.

ആവശ്യമായ കൃത്യമായ ക്രെഡൻഷ്യലുകൾ പ്രൊവൈഡറെ ആശ്രയിച്ചിരിക്കുന്നു.

## NoTrack (notrack-web)

NoTrack ([notrack.ai](https://notrack.ai)) സൈൻ അപ്പ് ആവശ്യമില്ലാത്ത ഒരു സൗജന്യ ഉപഭോക്തൃ ചാറ്റ് പ്ലാറ്റ്ഫോമാണ് — ആദ്യ സന്ദർശനത്തിൽ സെഷൻ അജ്ഞാതമായി സൃഷ്ടിക്കപ്പെടുകയും `uid`, `si_usr_id`, `si_ses_id` എന്നീ മൂന്ന് കുക്കികളിലൂടെ നിലനിൽക്കുകയും ചെയ്യുന്നു. ഒരൊറ്റ മോഡൽ ID (`notrack-c`, അപരനാമം `ntw`) ഉപയോഗിച്ച് അതേ `/api/dispatch` എൻഡ്പോയിന്റിനെ OmniRoute പ്രോക്സി ചെയ്യുന്നു.

### കണക്റ്റ് ചെയ്യാനുള്ള ഘട്ടങ്ങൾ

1. നിങ്ങളുടെ ബ്രൗസറിൽ [notrack.ai](https://notrack.ai) തുറന്ന് അജ്ഞാത സെഷൻ കുക്കി സജ്ജീകരിക്കാൻ അനുവദിക്കുക.
2. **DevTools → Network** തുറന്ന് പേജ് പുതുക്കിയശേഷം ഏതെങ്കിലും `/api` അഭ്യർത്ഥനയിൽ ക്ലിക്ക് ചെയ്യുക.
3. **Request Headers** എന്നതിൽ നിന്ന് പൂർണ്ണമായ `Cookie` ഹെഡർ മൂല്യം പകർത്തുക.
4. OmniRoute-ൽ **Providers → Add Provider → NoTrack Web (Free)** എന്നതിലേക്ക് പോകുക.
5. കുക്കി സ്ട്രിംഗ് `apiKey` ഫീൽഡിൽ ഒട്ടിച്ച് **Save** ചെയ്യുക.

ഒട്ടിച്ച സ്ട്രിംഗിൽ നിന്ന് `uid`, `si_usr_id`, `si_ses_id` എന്നിവ OmniRoute വേർതിരിച്ചെടുക്കുകയും ആ ജോഡികൾ മാത്രം ഉൾപ്പെടുത്തി ഒരു വൃത്തിയുള്ള `Cookie` ഹെഡർ പുനർനിർമ്മിക്കുകയും ചെയ്യുന്നു — കൂടാതെ, ലോഗിൻ ചെയ്ത അക്കൗണ്ടുകൾക്കായി സജ്ജീകരിച്ച `nt_session` (`ntk_…` ടോക്കൺ) ലഭ്യമാണെങ്കിൽ അതും ഉൾപ്പെടുത്തുന്നു. ഈ മൂന്നിൽ ഏതെങ്കിലും ഒന്ന് ഇല്ലെങ്കിൽ, ഓപ്പറേറ്റർമാർക്ക് ഇതര ഘടനകൾ പരീക്ഷിക്കാൻ കഴിയുന്നതിനായി ഒട്ടിച്ച അസംസ്കൃത സ്ട്രിംഗ് മാറ്റമില്ലാതെ ഫോർവേഡ് ചെയ്യപ്പെടും.

| മോഡൽ ID     | പ്രദർശന നാമം | കുറിപ്പുകൾ                                                      |
| ----------- | ------------ | --------------------------------------------------------------- |
| `notrack-c` | NoTrack C    | ഡിഫോൾട്ട് — അപ്സ്ട്രീം ഡിസ്പാച്ച് മോഡൽ `C`.                     |
| `C`         | NoTrack C    | `notrack-c`-ന്റെ അപരനാമം (അസംസ്കൃത അപ്സ്ട്രീം ഡിസ്പാച്ച് കോഡ്). |
| `notrack`   | NoTrack C    | `notrack-c`-ന്റെ അപരനാമം.                                       |
| `ntw`       | NoTrack C    | `notrack-c`-ന്റെ ഹ്രസ്വ അപരനാമം.                                |

നാല് മോഡൽ ID-കളും ഒരേ അപ്സ്ട്രീം ഡിസ്പാച്ച് മോഡലിലേക്കാണ് (`C`) മാപ്പ് ചെയ്യുന്നത്.

### അഭ്യർത്ഥനാ ഓപ്ഷനുകൾ

അഭ്യർത്ഥനാ ബോഡിയിൽ ഈ ഓപ്ഷണൽ ഫീൽഡുകൾ എക്സിക്യൂട്ടർ സ്വീകരിക്കുന്നു:

| ബോഡി ഫീൽഡ്            | ഡിഫോൾട്ട് | ഉദ്ദേശ്യം                                                                                        |
| --------------------- | --------- | ------------------------------------------------------------------------------------------------ |
| `notrack_mode`        | `usual`   | ഡിസ്പാച്ച് മോഡ് (സ്വതന്ത്ര-രൂപത്തിലുള്ള സ്ട്രിംഗ്; അപ്സ്ട്രീം `usual`, … എന്നിവ സ്വീകരിക്കുന്നു) |
| `notrack_max_turns`   | `6`       | ഉത്തരം നൽകുന്നതിന് മുമ്പ് അപ്സ്ട്രീമിന് നടത്താനാകുന്ന ആന്തരിക ടേണുകളുടെ എണ്ണം.                   |
| `notrack_chat_id`     | `null`    | നിലവിലുള്ള ഒരു അപ്സ്ട്രീം ചാറ്റ് പുനരാരംഭിക്കുക (പുതിയ ചാറ്റിനായി ഒഴിവാക്കുക).                   |
| `notrack_attachments` | `[]`      | അപ്സ്ട്രീം അറ്റാച്ച്മെന്റ് ഡിസ്ക്രിപ്റ്ററുകളുടെ പാസ്-ത്രൂ അറേ.                                   |
| `notrack_regenerate`  | `false`   | മുമ്പത്തെ ടേണിനായി വീണ്ടും സൃഷ്ടിച്ച ഉത്തരം അഭ്യർത്ഥിക്കാൻ `true` ആയി സജ്ജീകരിക്കുക.             |

### ശേഷികൾ

- **സ്ട്രീമിംഗ്, നോൺ-സ്ട്രീമിംഗ്** ചാറ്റ് പൂർത്തീകരണങ്ങൾ.
- **ടൂൾ കോളിംഗ്** — അഭ്യർത്ഥനയിൽ `tools: [...]` സജ്ജീകരിക്കുക; എക്സിക്യൂട്ടർ അവയെ ഒരു ടൂൾ-കോൾ എൻവലപ്പ് കോൺട്രാക്റ്റിലേക്ക് സീരിയലൈസ് ചെയ്യുകയും മോഡലിന്റെ പ്രതികരണങ്ങൾ തിരികെ OpenAI `tool_calls` ആയി പാഴ്സ് ചെയ്യുകയും ചെയ്യുന്നു.
- **`response_format`** — `json_object`, `json_schema` എന്നിവ പിന്തുണയ്ക്കുന്നു. മോഡലിന്റെ മറുപടിയിൽ നിന്നുള്ള ആദ്യ JSON ഒബ്ജക്റ്റ് എക്സിക്യൂട്ടർ വേർതിരിച്ചെടുത്ത്, തിരികെ നൽകുന്നതിന് മുമ്പ് അതിനെ സ്ട്രിംഗാക്കി മാറ്റുന്നു.
- **റീസണിംഗ് സൂചന** — അപ്സ്ട്രീം ഒരു `thinking` ഇവന്റ് അയയ്ക്കുമ്പോൾ എക്സിക്യൂട്ടർ ഒരു `reasoning` ഡെൽറ്റ പുറപ്പെടുവിക്കുന്നു.

### പരിമിതികൾ

- അപ്സ്ട്രീം അജ്ഞാത ഉപയോഗ ക്വാട്ടകൾ നടപ്പാക്കുന്നു — അവയുടെ പരിധി കടന്നാൽ, എക്സിക്യൂട്ടർ സൗഹൃദപരമായ ഒരു സന്ദേശത്തോടൊപ്പം 429 പിശക് നൽകുന്നു.
- എല്ലാ മോഡൽ ID-കളും ഒരേ അപ്സ്ട്രീം ഡിസ്പാച്ച് മോഡലിലേക്കാണ് പരിഹരിക്കപ്പെടുന്നത്; ഓരോ മോഡലിനും പ്രത്യേകം സ്വിച്ച് ഇല്ല.
- എക്സിക്യൂട്ടർ അപ്സ്ട്രീമിന്റെ `/api/chats` എൻഡ്പോയിന്റ് കോൾ ചെയ്യുന്നില്ല, അതിനാൽ ചാറ്റ് ചരിത്രം / സെഷനുകൾ സ്വയമേവ മാനേജ് ചെയ്യപ്പെടുന്നില്ല. നിലവിലുള്ള ഒരു അപ്സ്ട്രീം ചാറ്റ് പുനരാരംഭിക്കാൻ `notrack_chat_id` ഉപയോഗിക്കുക.

# വെബ് കുക്കി പ്രൊവൈഡർമാർക്ക് ചെയ്യാൻ കഴിയുന്നതും കഴിയാത്തതും

വെബ് കുക്കി പ്രൊവൈഡർമാർ ഒരു വെബ്സൈറ്റിന്റെ ചാറ്റ് ഇന്റർഫേസ് പുനരുപയോഗിക്കുന്നു. ഔദ്യോഗിക API-കളുടെ അതേ ശേഷികൾ അവ **നൽകുന്നില്ല**.

## പിന്തുണയ്ക്കുന്നവ

- നിലവിലുള്ള ബ്രൗസർ സെഷൻ ഉപയോഗിച്ച് പ്രാമാണീകരിക്കൽ
- നിങ്ങളുടെ അക്കൗണ്ടിലൂടെ ലഭ്യമായ മോഡലുകൾ ആക്സസ് ചെയ്യൽ
- ചാറ്റ് പ്രതികരണങ്ങൾ സ്ട്രീം ചെയ്യൽ
- API കീ ആവശ്യമില്ല

## പിന്തുണയ്ക്കാത്തവ

- ഫങ്ഷൻ കോളിംഗ്
- ടൂൾ കോളിംഗ്
- സ്വയമേവയുള്ള ഫയൽ എഡിറ്റിംഗ്
- ഏജന്റിക് IDE വർക്ക്ഫ്ലോകൾ
- API-യിൽ മാത്രം ലഭ്യമായ സവിശേഷതകൾ

ഇത് പ്രതീക്ഷിക്കുന്ന പ്രവർത്തനമാണ്, ഒരു ബഗ് **അല്ല**.

നിങ്ങൾക്ക് ടൂൾ എക്സിക്യൂഷൻ, സ്വയമേവയുള്ള ഫയൽ എഡിറ്റിംഗ്, അല്ലെങ്കിൽ മറ്റ് ഏജന്റ് വർക്ക്ഫ്ലോകൾ ആവശ്യമാണെങ്കിൽ, Web Cookie പ്രൊവൈഡറിന് പകരം ഒരു **API-key provider** ഉപയോഗിക്കുക.

# സാധൂകരണവുമായി ബന്ധപ്പെട്ട മുന്നറിയിപ്പ്

വിജയകരമായ **Test Connection** അല്ലെങ്കിൽ കുക്കി സാധൂകരണം, നൽകിയ ക്രെഡൻഷ്യലുകൾ പ്രതീക്ഷിക്കുന്ന ഫോർമാറ്റിലാണെന്ന് തോന്നുന്നു എന്നത് മാത്രമാണ് പരിശോധിക്കുന്നത്.

Issue #7857 പരിഹരിക്കുന്നതുവരെ, വിജയകരമായ സാധൂകരണം പ്രൊവൈഡർ വിജയകരമായി പ്രാമാണീകരിക്കുമെന്ന് **ഉറപ്പുനൽകുന്നില്ല**.

പ്രാമാണീകരണം തുടർന്നും പരാജയപ്പെടുകയാണെങ്കിൽ, ബ്രൗസർ കുക്കി സ്റ്റോറേജിൽ നിന്നല്ല, സജീവമായ ഒരു നെറ്റ്വർക്ക് അഭ്യർത്ഥനയിൽ നിന്നാണ് ക്രെഡൻഷ്യലുകൾ പകർത്തിയതെന്ന് സ്ഥിരീകരിക്കുക.

## പ്രാമാണീകരണം പരാജയപ്പെടുന്നു

ക്രെഡൻഷ്യലുകൾ ഇനിപ്പറയുന്നിടത്തുനിന്നാണ് പകർത്തിയതെന്ന് സ്ഥിരീകരിക്കുക:

```
Network
→ Request Headers
→ Cookie
```

ഇവിടെ നിന്നല്ല:

```
Application
→ Cookies
```

## കുക്കി ബ്രൗസറിൽ പ്രവർത്തിക്കുന്നു, എന്നാൽ OmniRoute-ൽ പ്രവർത്തിക്കുന്നില്ല

ചില പ്രൊവൈഡർമാർ പ്രാമാണീകരിച്ച അഭ്യർത്ഥനകളിൽ മാത്രം അയയ്ക്കുന്ന കുക്കികൾ ഉൾപ്പെടുത്തുന്നു.

ഒരു സംഭാഷണം വിജയകരമായി തുറന്നതിന് ശേഷം, പുതിയൊരു നെറ്റ്വർക്ക് അഭ്യർത്ഥനയിൽ നിന്ന് ക്രെഡൻഷ്യലുകൾ വീണ്ടും പകർത്തുക.

## സെഷൻ കാലഹരണപ്പെട്ടു

Web Cookie പ്രൊവൈഡർമാർ നിങ്ങളുടെ നിലവിലുള്ള ബ്രൗസർ സെഷനാണ് ഉപയോഗിക്കുന്നത്.

നിങ്ങളുടെ ബ്രൗസർ സെഷൻ കാലഹരണപ്പെടുകയോ നിങ്ങൾ സൈൻ ഔട്ട് ചെയ്യുകയോ ചെയ്താൽ, പുതിയൊരു ക്രെഡൻഷ്യൽ സെറ്റ് പകർത്തേണ്ടതുണ്ട്. പിന്തുണയ്ക്കുന്ന വെബ് പ്രൊവൈഡർമാർക്കായി കുക്കി പുതുക്കൽ ഓട്ടോമേറ്റ് ചെയ്യുന്നതിന്, അനുബന്ധ ടൂളായ [Browser Session Sync Extension](../guides/SESSION-SYNC-EXTENSION.md) കാണുക.

## "Unsupported ChatGPT integrity dependency" എന്ന പിശകോടെ ChatGPT Web പരാജയപ്പെടുന്നു

```
[502] ChatGPT Web first-party bridge module failed to load:
pageerror: Unsupported ChatGPT integrity dependency: DD
```

ക്രെഡൻഷ്യലിന് പ്രശ്നമില്ല — ആ പിശക് സെഷനിൽ നിന്നല്ല, ബ്രിഡ്ജിൽ നിന്നാണ് ഉണ്ടാകുന്നത്. ഓരോ ഡിപ്ലോയ്മെന്റിലും chatgpt.com അതിന്റെ
മൊഡ്യൂൾ ഐഡികൾ നൽകുന്നു, കൂടാതെ ബ്രിഡ്ജ് താൻ ഇൻസ്റ്റാൻഷ്യേറ്റ് ചെയ്യുന്ന Sentinel ഹെൽപ്പറിന്റെ ഐഡി പിൻ ചെയ്തിരുന്നു; അതിനാൽ
ഹെൽപ്പറിന്റെ പേര് മാറ്റിയ ഒരു chatgpt.com റീബിൽഡ്, കുക്കി സാധുവായി തുടർന്നപ്പോഴും എല്ലാ ടേണുകളും തകരാറിലാക്കി. കണക്ഷൻ വീണ്ടും ഓതറൈസ്
ചെയ്യുന്നതിലൂടെ ഇത് പരിഹരിക്കാനാവില്ല.

പേജിന്റെ സ്വന്തം റൺടൈമിലൂടെ മൊഡ്യൂൾ പരിഹരിക്കുന്ന ബിൽഡുകൾ ഒരു ഐഡിയും പിൻ ചെയ്യുന്നില്ല, അതിനാൽ ഈ പ്രശ്നം സംഭവിക്കുകയുമില്ല. ഈ
പിശക് കാണുകയാണെങ്കിൽ, OmniRoute അപ്ഗ്രേഡ് ചെയ്ത് കണക്ഷൻ പരിശോധന വീണ്ടും പ്രവർത്തിപ്പിക്കുക.

# മികച്ച രീതികൾ

- പുതുതായി പ്രാമാണീകരിച്ച ഒരു അഭ്യർത്ഥനയിൽ നിന്ന് ക്രെഡൻഷ്യലുകൾ പകർത്തുക.
- പഴയ കുക്കികൾ വീണ്ടും ഉപയോഗിക്കുന്നത് ഒഴിവാക്കുക.
- Web Cookie പ്രൊവൈഡർമാർ ഉപയോഗിക്കുമ്പോൾ നിങ്ങളുടെ ബ്രൗസർ സെഷൻ സജീവമായി നിലനിർത്തുക.
- പകർത്തിയ കുക്കികളെ സെൻസിറ്റീവ് ക്രെഡൻഷ്യലുകളായി പരിഗണിക്കുക.
- നിങ്ങൾക്ക് ഫങ്ഷൻ കോളിംഗ് അല്ലെങ്കിൽ ഏജന്റ് വർക്ക്ഫ്ലോകൾ ആവശ്യമുള്ളപ്പോൾ API-key പ്രൊവൈഡർമാർ ഉപയോഗിക്കുക.
