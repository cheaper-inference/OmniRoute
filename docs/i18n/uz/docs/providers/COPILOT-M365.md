`copilot-m365-web` (taxallus `m365copilot`) `m365.cloud.microsoft/chat` da autentifikatsiya qilingan Microsoft 365 Copilot sessiyasi orqali OpenAI formatidagi chat so‘rovlarini yuboradi. Bu norasmiy mahalliy integratsiya: alohida proksi-server jarayoni yoki yuqori oqimdagi localhost talab qilinmaydi. Provayder ID, taxallus va mavjud import qilingan ulanishlar o'zgarmadi. `copilot-web` - `copilot.microsoft.com` da maishiy xizmat ko'rsatish uchun boshqa provayder.

> **Web Cookie provayderlari uchun yangimi?**
>
> O'qing**`docs/getting-started/WEB-COOKIE-GUIDE.md`** umumiy sozlash jarayoni, autentifikatsiya boʻyicha koʻrsatmalar, cheklovlar va muammolarni bartaraf etish uchun ushbu provayderga tegishli qoʻllanmaga amal qilishdan oldin.
>
> **Eski import uchun:** Ushbu provayder uchun hisob ma'lumotlari** cookie emas** . Cookie fayllarini `m365.cloud.microsoft` dan nusxa ko'chirmang. Hisob maʼlumotlari WebSocket URL soʻrovi parametri va yoʻl segmenti boʻlib, ikkalasi ham DevTools Network yorligʻidan oʻqiladi.

## Old shartlar

- `m365.cloud.microsoft/chat`-da Copilot ga kirish huquqiga ega Microsoft 365 hisobi
- DevTools WebSocket tekshiruvi uchun Chromium-ga asoslangan brauzer (Chrome, Edge).
- Ushbu hisobda so'ralgan modelga kirish; mavjudligi ijarachi va litsenziyaga qarab farq qiladi

## Mahalliy tizimga kirish (ish yoki maktab hisoblari)

Tanlang**Microsoft 365 Copilot → Ulanish** va tizimga kirishga urinish tayyorlang. Boshqaruv paneli PKCE bilan avtorizatsiya-kod oqimidan foydalanadi; u sizning Microsoft parolingiz yoki MFA kodingizni so'ramaydi.

1. Ochish a** bo'sh brauzer yorlig'i** , keyin oching**DevTools → tarmog'i** va yoqish** Jurnalni saqlang** . Microsoft ga o'tishdan oldin buni bajaring: Windows SSO darhol tugashi mumkin.
2. Ulanish dialog oynasida ko'rsatilgan avtorizatsiya URL nusxasini oling va tayyorlangan yorliqda unga o'ting. Agar so'ralsa, Microsoft hisobini yoki MFA ni tanlang.
3. Saqlangan Tarmoq jurnalida `https://login.microsoftonline.com/common/oauth2/nativeclient` so'rovini toping va uni to'liq nusxa ko'chiring** URL so'rovi** .
4. U URL ulanish dialog oynasiga joylashtiring va ulaning. Xom kodni yoki yakuniy `wrongplace` manzil satrini joylashtirmang URL: kerakli qayta qo'ng'iroq - vaqtinchalik navigatsiya.

Har bir urinish o'n daqiqadan so'ng tugaydi va faqat bir marta foydalanish mumkin. Server kodni almashishdan oldin uning holatini, PKCE verifierini va qayta autentifikatsiya maqsadini tekshiradi. Yaroqlilik muddati tugagandan so'ng yoki almashtirish muvaffaqiyatsiz tugadi, yangi urinishni boshlang. Serverni qayta ishga tushirishga urinish omon qolmaydi.

Tokenlar mavjud ulanish hisob ma'lumotlarini saqlash va yangilash yo'lidan foydalanadi. Ulanishni qayta autentifikatsiya qilish bir xil elektron pochta manzilini emas, balki bir xil Microsoft tenant/object identifikatorini talab qiladi. U naming/settings operatorini saqlaydi va eskirgan import hisob ma'lumotlarini almashtiradi. Mahalliy tizimga kirish work/school hisoblari uchun; eski import yo'li mavjud ulanishlar va qo'llab-quvvatlanadigan darajadagi konfiguratsiyalar uchun mavjud bo'lib qoladi.

To'liq qayta qo'ng'iroq qilish URL bir martalik hisob ma'lumotlaridir. Hech qachon uni skrinshotlar, jurnallar, qo'llab-quvvatlash xabarlari yoki majburiyatlarga qo'shmang. Ushbu oqim serverda brauzerni ochmaydi, brauzer tarixini tekshirmaydi yoki mahalliy qayta qo'ng'iroq serverini ishga tushirmaydi.

## Hisob ma'lumotlarini olish (WebSocket usuli)

1. `https://m365.cloud.microsoft/chat` saytiga kiring va suhbatni boshlang.
2. Ochiq**DevTools → tarmog'i** .
3. Filtrlash**WS** (WebSocket).
4. Chathub WebSocket ulanishini bosing. `wss://substrate.office.com/m365Copilot/Chathub/` bilan boshlangan URL ni qidiring.
5. Undan** URL so'rang** , nusxa:
   - `access_token` so'rovi parametr qiymati (qisqa muddatli JWT).
   - `/Chathub/` dan keyingi Chathub yo'l segmenti (masalan, `<oid>@<tenant>`).

To'liq URL quyidagi shaklga ega:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. OmniRoute dan tanlang**Microsoft 365 Copilot** , eski API-key/import opsiyasini tanlang va hisob ma'lumotlarini quyidagi formatda joylashtiring:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. bosing** Sinov ulanishi** va** Saqlash** .

## Hisob ma'lumotlarini olish (HAR import)

WebSocket URL dan qiymatlarni qo'lda nusxalash o'rniga DevTools HAR faylini eksport qilishingiz mumkin:

1. Ochiq**DevTools → tarmog'i** .
2. Microsoft 365 Copilot suhbatini boshlang yoki davom ettiring (bu WebSocket ulanishini ishga tushiradi).
3. Tarmoq panelida sichqonchaning o'ng tugmachasini bosing va tanlang** Hammasini kontent bilan HAR sifatida saqlang** .
4. OmniRoute dan foydalaning** .har faylini import qiling** provayderga ulanish dialog oynasidagi tugmani bosing.

OmniRoute Chathub WebSocket URL uchun HAR skanerlaydi, `access_token` va `chathubPath` ni chiqaradi va hisob ma’lumotlari maydonlarini avtomatik ravishda to‘ldiradi. HAR importi JWT muddatini dekodlaydi va tokenning qolgan muddatini ko'rsatadi.

> **Hech qachon haqiqiy HAR eksportini, kirish tokenini yoki yangilash tokenini amalga oshirmang.** Sinov va hujjat qiymatlari har doim to'ldiruvchi bo'lishi kerak.

## Tokenning ishlash muddati va yangilanishi

`access_token` qisqa muddatli (odatda**~ 75 daqiqa** ). Foydalanish mumkin bo'lgan yangilash tokenisiz, amal qilish muddati tugagandan so'ng, hisob ma'lumotlarini qayta qo'lga kiritishingiz kerak.

### `refreshToken` bilan avtomatik yangilash

Microsoft 365 provayderlarida** Ulanish qo'shing** yoki** Ulanishni tahrirlash** dialog, ochish** Kengaytirilgan sozlamalar → tokenni yangilash (ixtiyoriy)** . `substrate.office.com/sydney` qamrovi uchun Microsoft OAuth yangilash tokenini joylashtiring va saqlang. Kirish maskalanadi va hech qachon saqlangan token bilan to'ldirilmaydi. Tahrirlashda mavjud tokenni saqlash uchun uni bo'sh qoldiring; uni almashtirish uchun yangi tokenni joylashtiring.

Mahalliy tizimga kirish Microsoft tokenini qaytarganda yangilash tokenini oladi. Eski import uchun mavjud mos Microsoft avtorizatsiya-kodi grantidan foydalaning; bu provayder qurilma-kod oqimini amalga oshirmaydi yoki va'da qilmaydi. Yangilash tokeni sozlangan boʻlsa, OmniRoute soʻrovlar oldidan `access_token` ni tekshiradi va uni faqat yangilash kerak boʻlganda yangilaydi. Muvaffaqiyatli yangilanish, shuningdek, aylantirilgan yangilash tokenini saqlab qoladi va yangilash tokeni amalda qolsa, qo'lda qayta yozib olishdan qochadi.

Agar `refreshToken` o'rnatilmagan bo'lsa, har bir muddat tugaganidan keyin WebSocket hisob ma'lumotlarini qo'lda qayta yozib olishingiz kerak.

## Xulq-atvor va cheklovlarni talab qiling

- Asboblar** tezkor taqlid qilingan** , mahalliy Microsoft funksiya chaqiruvlari emas. Asbob-yoqilgan so'rov bitta buferlangan avloddan foydalanadi; u boshqa avlodni asboblarni tanlashga sarflamaydi. Qo'llab-quvvatlanadigan argument shakllari faqat e'lon qilingan vositalar chaqiruv sifatida qaytariladi.
- Bitta keyingi misol bilan tuzilgan uzoq tuzilgan javob nasr sifatida saqlanadi. Bu niyatning isboti emas, evristik; ilovalar hali ham o'zlarining asbob ruxsatlarini qo'llashlari kerak.
- Tasvir kiritish veb-mijoz uni yuborgan tarzda ishlaydi. Har bir rasm qismi (`image_url` maʼlumotlari URL yoki ommaviy HTTPS URL yoki Javoblar `input_image`) `/m365Copilot/UploadFile` ga chat tokeni bilan navbat suhbatiga yuklanadi va xabar `ImageFile` izohi bilan unga ishora qiladi; matn o'tirgan joyini belgilaydi (`[image 1]`, …). Yangi suhbat tarixdagi har bir rasmni yuklaydi, davomi esa faqat yangi xabarlarning rasmlarini yuklaydi. Har biri 10 MiB dan 10 tagacha PNG, JPEG, GIF yoki WebP tasvirlar (har bir soʻrov uchun 40 MiB ); format baytlardan o'qiladi. HTTPS URLs faqat ommaviy, DNS bilan biriktirilgan masofaviy tasvir himoyasi orqali olinadi. Muvaffaqiyatsiz yuklash so'rovni bajara olmadi (** 502** `m365_image_upload_failed`,** 400** `m365_image_rejected` yoki `m365_image_invalid`); bir burilish u berilgan tasvir holda oldinga hech qachon. Boshqa matn bo'lmagan qismlar (audio, fayllar) aniq rad etiladi, jimgina tushirilmaydi.
- Kuzatuv so'rovi bir xil yuqoridagi suhbatni davom ettiradi va faqat oldingi javobdan keyin xabarlarni yuboradi. Bu javobni to'liq kengaytirishi kerak: bir xil ulanish, model profili va asboblar to'plami; o'zgarmas tarix (har bir xabar uchun sha256 zanjiri); va javobning asbob-chaqiruv identifikatorlari yoki uning matni bo'sh joygacha. Boshqa har qanday narsa (tahrirlangan tarix, bir xil birinchi xabarga ega boshqa seans, boshqa javob, 30 daqiqa davomida boʻsh turgan suhbat yoki Copilot ning 600 xabarli chegarasiga yaqin, identifikatorsiz ulanish) butun tarix bilan yangi suhbatni boshlaydi. Muvaffaqiyatsiz burilish hech qachon davom ettirilmaydi va yangi suhbatda mazmunsiz `InternalError` bir marta qayta yuboriladi (** 502** `m365_internal_error` agar u yana muvaffaqiyatsiz bo'lsa). Davomlar jarayon xotirasida saqlanadi: qayta ishga tushirish yangi suhbatlarni boshlaydi.
- Har bir burilish Copilot ning vaqtinchalik suhbatida (`disableMemory=1`) ishlaydi: suhbat ishlayotgan vaqtda o'z kontekstini saqlab qoladi va hech qachon hisobning chat tarixida ko'rinmaydi. Shunday qilib, namunaviy testlar, Hammasini sinab ko'ring va kombinatsiyalangan testlar ushbu provayderni suhbatni qoldirmasdan tekshirishi mumkin.
- Navbatda 120 soniya bo'sh turish muddati va cheklangan umumiy muddat mavjud. Faqat yakuniy javoblar, jarayonni filtrlash va bekor qilish mahalliy transport/composer. tomonidan amalga oshiriladi
- Veb-asoslangan javoblar o'z manbalarini saqlaydi. Copilot iqtibosni shaxsiy foydalanish uchun boshqarish belgilari bilan qatorda belgilaydi va manbalarni `references` sifatida yuboradi; har bir marker raqamlangan Markdown havolasiga (`[1](https://…)` yoki Copilot markerni havola nishoni sifatida ishlatganda yalang'och URL ) mos keladigan `url_citation` izohiga (`message.annotations` yoki havolani olib boradigan bo'lakda `delta.annotations` ) aylanadi. Hech qachon kelmaydigan manba o'chiriladi, shuning uchun markerlar mijozga hech qachon etib bormaydi. Striming paytida iqtibosdan keyingi matn manba yetib kelguncha kutadi.
- Copilot ning fikrlash xulosasi (`ChainOfThoughtSummary`), model bittasini yuborganda, hech qachon javobning bir qismi sifatida emas, `reasoning_content` sifatida qaytariladi. O'zini qayta yozadigan xulosa navbatni buzmasdan oqimni to'xtatadi.
- Har qanday kontentdan oldin, licence/throttle xatoliklari oqim so'ralganda ham HTTP 403/429 saqlab qoladi. Kontent boshlangandan so'ng, muvaffaqiyatsizliklar SSE xato hodisalari bo'lib, hech qachon muvaffaqiyatli yakunlanmaydi. Faqat qo'shimcha oqim bilan ifodalanishi mumkin bo'lmagan yuqori oqimdagi qayta yozish aniq oqim xatosidir; oqimsiz va buferlangan vosita javoblari yakuniy matnni saqlab qoladi.
- Agar Copilot ulanishni rad etsa, uning javobi quyidagicha xabar qilinadi:** 401** rad etilgan yoki muddati o'tgan tizimga kirish uchun `m365_unauthorized` (qayta kiring),** 429** o'z `Retry-After` bilan bostirish uchun, va qo'l siqilish xatosi aks holda, hech qachon umumiy ulanish xatosi.

## Tasvir yaratish

`model: "copilot-m365-web/m365-copilot-image"` (taxallus `m365copilot/m365-copilot-image`) bilan `POST /v1/images/generations` veb-mijoz kabi Copilot ning o'rnatilgan tasvir vositasi bilan chizadi. Har bir rasm bir Copilot burilish: u veb-mijozning tasvir opsiyasi bilan tanlanadi va `GenerateGraphicArt` e'lon qiladi va tasvir Microsoft ning Dizayner xizmatidagi artefaktga ishora qiluvchi jarayon yozuvida keladi. Bu artefakt chat tokenini rad etadi, shuning uchun OmniRoute ulanishni yangilash tokenidan Dizayner tokenini chiqaradi va baytlarni yuklab oladi; token faqat `designerapp.officeapps.live.com` ga yuboriladi.

- Mahalliy tizimga kirish ulanishi kerak (yangilash tokeni); yopishtirilgan token bilan bajarilmaydi** 400** har qanday navbat sarflanishidan oldin.
- `n` 1–4, har biri bittadan burilish. `size` faqat yo'nalishni boshqaradi (kengroq, balandroq yoki kvadrat), Copilot taklifdan o'qiydi; Copilot render hajmini tanlaydi.
- Tasvirlar qatorga qaytariladi: sukut bo'yicha `b64_json`, `response_format: "url"` uchun URL ma'lumotlari.
- Yaratilgan tasvirlar chatdan alohida, kichik kundalik byudjetga tortiladi. U ishlatilganda so'rov bajarilmaydi** 429** . Rasmsiz javob beradigan burilish muvaffaqiyatsiz tugadi** 502** (yoki** 400** /** 503** Copilot matni rad etish yoki qobiliyat muammosi sifatida o'qilganda); xabar qaysi ekanligini aytadi.

## Xavfsizlik modeli

- **Norasmiy integratsiya.** Bu provayder BizChat WebSocket protokolini teskari muhandislik qiladi. Microsoft oxirgi nuqtani o'zgartirganda, u ogohlantirmasdan uzilishi mumkin.
- `subscriptionRisk: true` bayrog'i integratsiya hujjatsiz yakuniy nuqtaga tayanishini aks ettiradi. Hisob cheklovlari mumkin, ammo tasdiqlanmagan.
- Kirish tokeni qisqa muddatli JWT hisoblanadi. Uni parol sifatida ko'ring: uni kiritmang, tizimga kirmang yoki baham ko'rmang.
- Yangilash tokeni Microsoft 365 yuzasiga doimiy kirish imkonini beradi. Uni API kaliti kabi ehtiyotkorlik bilan saqlang.

### Autentifikatsiya darhol bajarilmaydi

- dan nusxa olganingizni tasdiqlang**WebSocket URL** , XHR/Fetch so'rovidan emas. Hisob maʼlumotlari Chathub WebSocket ulanishining `access_token` soʻrovi parametrida — `Authorization: Bearer` emas.

### Token ~ 75 daqiqadan keyin tugaydi

Bu kutilmoqda. `refreshToken` bo'lmasa, kirish tokeni qisqa muddatli bo'ladi. Yoki:

- DevTools dan hisob ma'lumotlarini qaytadan oling yoki
- Sozlang** Kengaytirilgan sozlamalar → yangilash tokeni (ixtiyoriy)** avtomatik yangilash uchun ulanishni qo'shish yoki tahrirlash dialog oynasida.

### Sinov ulanishi o'tdi, lekin chat 401ni qaytaradi

bilan yaratilgan ulanish uchun** Microsoft bilan tizimga kiring** , Test ulanishi kirish tokenining amal qilish muddatini tekshiradi va saqlangan yangilash tokeni bilan muddati oʻtgan tokenni yangilaydi, shuning uchun oʻtgan sinov ham yangilash tokeni ishlayotganini tasdiqlaydi.

Joylashtirilgan hisob ma’lumotlari uchun Test ulanishi hisob ma’lumotlari shaklini tekshiradi va token muddati tugaganda, provayder foydalanadigan tokenning amal qilish muddati tugamaganligini tekshiradi (ulanishning saqlangan tokeni eskirgan ma’lumotlarni yutib oladi; yangilangan token yangilanishi mumkin bo‘lgan hisoblanadi). Muddati tugashidan oldin bekor qilingan token hali ham sinovdan o'tadi; chat keyin qaytadi** 401** `m365_unauthorized`. Foydalanish** Microsoft bilan tizimga kiring** yana yoki yangi hisob ma'lumotlarini qayta qo'lga kiriting.
