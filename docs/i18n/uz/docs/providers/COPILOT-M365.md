`copilot-m365-web` (`m365copilot` taxallusi) autentifikatsiya qilingan Microsoft 365 Copilot BizChat brauzer sessiyasi orqali `m365.cloud.microsoft/chat` manziliga OpenAI formatidagi chat soʻrovlarini yuboradi. Bu norasmiy integratsiyadir.

> **Web Cookie provayderlaridan ilk bor foydalanyapsizmi?**
>
> Ushbu provayderga oid qoʻllanmani bajarishdan oldin umumiy sozlash jarayoni, autentifikatsiya boʻyicha koʻrsatmalar, cheklovlar va muammolarni bartaraf etish haqida bilish uchun **`docs/getting-started/WEB-COOKIE-GUIDE.md`** faylini oʻqing.
>
> **Muhim:** Bu provayder uchun hisob maʼlumoti **cookie emas**. `m365.cloud.microsoft` saytidan cookie fayllarini nusxalamang. Hisob maʼlumoti WebSocket URL manzilining soʻrov parametri va yoʻl segmentidan iborat boʻlib, ularning ikkalasi ham DevTools vositasining Network ichki oynasidan olinadi.

## Talablar

- `m365.cloud.microsoft/chat` manzilidagi BizChat xizmatiga kirish huquqiga ega Microsoft 365 hisobi
- DevTools orqali WebSocket ulanishini tekshirish uchun Chromium asosidagi brauzer (Chrome, Edge)
- M365 Copilot litsenziyasi (koʻplab Microsoft 365 Business/Enterprise tariflariga kiritilgan)

## Hisob maʼlumotini olish (WebSocket usuli)

1. `https://m365.cloud.microsoft/chat` manzilida tizimga kiring va suhbatni boshlang.
2. **DevTools → Network** boʻlimini oching.
3. **WS** (WebSocket) boʻyicha filtrlang.
4. Chathub WebSocket ulanishini bosing. `wss://substrate.office.com/m365Copilot/Chathub/` bilan boshlanuvchi URL manzilini toping.
5. Uning **Request URL** maydonidan quyidagilarni nusxalang:
   - `access_token` soʻrov parametri qiymati (qisqa muddat amal qiluvchi JWT).
   - `/Chathub/` dan keyingi Chathub yoʻl segmenti (masalan, `<oid>@<tenant>`).

Toʻliq URL quyidagi koʻrinishga ega:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. OmniRoute ilovasida **Providers → Add Provider** boʻlimiga oʻting, **Microsoft 365 Copilot (BizChat)** provayderini tanlang va hisob maʼlumotini quyidagi formatda kiriting:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. **Test Connection** va **Save** tugmalarini bosing.

## Hisob maʼlumotini olish (HAR importi)

WebSocket URL manzilidan qiymatlarni qoʻlda nusxalash oʻrniga DevTools HAR faylini eksport qilishingiz mumkin:

1. **DevTools → Network** boʻlimini oching.
2. BizChat suhbatini boshlang yoki davom ettiring (bu WebSocket ulanishini ishga tushiradi).
3. Network panelida sichqonchaning oʻng tugmasini bosing va **Save all as HAR with content** bandini tanlang.
4. OmniRoute ilovasidagi provayder ulanishi dialog oynasida **Import .har file** tugmasidan foydalaning.

OmniRoute HAR faylini Chathub WebSocket URL manzili uchun tekshiradi, `access_token` va `chathubPath` qiymatlarini ajratib oladi hamda hisob maʼlumoti maydonlarini avtomatik ravishda toʻldiradi. HAR importi JWT amal qilish muddatini dekodlaydi va tokenning qolgan amal qilish vaqtini koʻrsatadi.

> **Haqiqiy HAR eksporti, kirish tokeni yoki yangilash tokenini hech qachon repozitoriyga commit qilmang.** Sinov va hujjatlardagi qiymatlar doimo oʻrinbosar qiymatlar boʻlishi kerak.

## Tokenning amal qilish muddati va yangilanishi

`access_token` qisqa muddat amal qiladi (odatda **~75 daqiqa**). Foydalanish mumkin bo‘lgan yangilash
tokenisiz, amal qilish muddati tugagach, hisob ma’lumotlarini qayta olishingiz kerak.

### `refreshToken` yordamida avtomatik yangilash

Microsoft 365 provayderining **Ulanish qo‘shish** yoki **Ulanishni tahrirlash** dialog oynasida
**Kengaytirilgan sozlamalar → Yangilash tokeni (ixtiyoriy)** bo‘limini oching. `substrate.office.com/sydney`
scope uchun Microsoft OAuth yangilash tokenini joylashtiring va saqlang. Kiritilgan qiymat yashiriladi va saqlangan token bilan oldindan to‘ldirilmaydi. Tahrirlashda mavjud tokenni saqlab qolish uchun maydonni bo‘sh qoldiring;
yangi tokenni almashtirish uchun uni joylashtiring.

Yangilash tokenini `substrate.office.com/sydney` scope bilan Microsoft qurilma kodi yoki avtorizatsiya kodi oqimidan oling; boshqaruv paneli uni siz uchun olmaydi.
Yangilash tokeni sozlangan bo‘lsa, OmniRoute so‘rovlar yuborishdan oldin `access_token`ni tekshiradi
va uni faqat yangilash zarur bo‘lgandagina yangilaydi. Muvaffaqiyatli yangilash yangilangan yangilash tokenini ham saqlaydi, bu esa yangilash tokeni amal qilishda davom etar ekan, hisob ma’lumotlarini qo‘lda qayta olish zaruratini bartaraf etadi.

Agar `refreshToken` o‘rnatilmagan bo‘lsa, har bir amal qilish muddati tugagandan keyin WebSocket hisob ma’lumotlarini qo‘lda qayta olishingiz kerak.

## Xavfsizlik modeli

- **Norasmiy integratsiya.** Ushbu provayder BizChat WebSocket protokolini teskari
  muhandislik orqali tahlil qiladi. Microsoft endpointni o‘zgartirganda u ogohlantirishsiz ishlamay qolishi mumkin.
- `subscriptionRisk: true` bayrog‘i integratsiya hujjatlashtirilmagan endpointga
  tayanishini bildiradi. Hisobga cheklovlar qo‘yilishi mumkin, ammo bu tasdiqlanmagan.
- Kirish tokeni qisqa muddatli JWT hisoblanadi. Uni parol kabi himoya qiling: commit
  qilmang, jurnalga yozmang yoki boshqalar bilan ulashmang.
- Yangilash tokeni BizChat interfeysidan uzoq muddat foydalanish imkonini beradi. Uni
  API kaliti kabi ehtiyotkorlik bilan saqlang.

## Muammolarni bartaraf etish

### Autentifikatsiya darhol muvaffaqiyatsiz tugaydi

- XHR/Fetch so‘rovidan emas, **WebSocket URL** manzilidan nusxa olganingizni tekshiring. Hisob ma’lumotlari Chathub WebSocket ulanishining `access_token` so‘rov parametrida joylashgan — `Authorization: Bearer` sarlavhasida emas.
- `chathubPath` URL yo‘lidagi to‘liq `<oid>@<tenant>` segmentini o‘z ichiga olganiga ishonch hosil qiling.

### Token ~75 daqiqadan keyin muddati tugaydi

Bu kutilgan holat. `refreshToken` bo‘lmasa, kirish tokenining amal qilish muddati qisqa bo‘ladi. Quyidagilardan birini bajaring:

- DevTools’dan hisob ma’lumotlarini qaytadan oling yoki
- Avtomatik yangilash uchun Add or Edit connection dialog oynasidagi **Advanced Settings → Refresh token (optional)** sozlamasini konfiguratsiya qiling.

### Test Connection muvaffaqiyatli o‘tadi, ammo chat 401 qaytaradi

Token tekshiruvdan o‘tish va birinchi so‘rov yuborish oralig‘ida muddati tugagan bo‘lishi mumkin. Yangi hisob ma’lumotlarini qaytadan oling.

### Copilot provayderlar ro‘yxatida ko‘rinmaydi

**Dashboard → Providers** bo‘limida `copilot-m365-web` yoqilganiga ishonch hosil qiling. Ayrim tariflarda provayder sukut bo‘yicha yashirilgan bo‘lishi mumkin.
