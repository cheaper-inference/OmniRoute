## Chat yakunlashlari

```bash
POST /v1/chat/completions
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "cc/claude-opus-4-6",
  "messages": [
    {"role": "user", "content": "Write a function to..."}
  ],
  "stream": true
}
```

#### Har bir soʻrov uchun hisobni biriktirish

Provayderda bir nechta ulanish (hisoblar yoki kalitlar) mavjud boʻlsa, OmniRoute odatda
hisob tanlash strategiyasi orqali ulardan birini tanlaydi. Buning oʻrniga soʻrov
`x-omniroute-connection` sarlavhasi yordamida muayyan ulanishni biriktirishi mumkin:

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <your OmniRoute API key>" \
  -H "Content-Type: application/json" \
  -H "x-omniroute-connection: <connection id>" \
  -d '{"model": "codex/gpt-5.5", "messages": [{"role": "user", "content": "hi"}]}'
```

- **Identifikatorni qayerdan topish mumkin.** Boshqaruv panelida provayder sahifasini oching
  (**Boshqaruv paneli → Provayderlar → <provayder>**) va ulanish qatoridagi `xxxxxxxx…` identifikator belgisini
  bosing — bu ulanishning toʻliq identifikatorini nusxalaydi.
- **Qaysi soʻrovlar uni hisobga oladi.** `/v1/chat/completions`, `/v1/messages` va
  `/v1/responses` dagi bitta modelli soʻrovlar (`provider/model`). Kombinatsiyalar sarlavhani eʼtiborsiz qoldiradi:
  buning oʻrniga har bir kombinatsiya bosqichi uchun hisobni bosqichning oʻz ulanishi orqali biriktiring.
- **Biriktirish afzallik emas, qatʼiy talabdir.** Faqat biriktirilgan ulanish ishlatiladi.
  Soʻrov ichidagi xatolik hisobning sovish davrini qayd etadi, ammo ayni provayderning
  boshqa hisobiga **oʻtmaydi**.
- **Sovish davri va kvota biriktirishni bekor qiladi.** Biriktirilgan ulanish sovish davrida,
  kvotasi tugagan yoki kvota siyosati tomonidan bloklangan boʻlsa, keyingi soʻrovlar xuddi
  biriktirilmagan trafik kabi provayderning boshqa ulanishlariga oʻtadi.
- **Nomaʼlum yoki oʻchirilgan identifikatorlar xatolikka olib keladi.** Provayderning faol pulida boʻlmagan
  (oʻchirilgan, faolsizlantirilgan yoki boshqa provayderga tegishli) identifikator mos hisob
  qolmasligiga olib keladi, shuning uchun soʻrov sezdirmasdan boshqa yoʻnalishga yuborilish oʻrniga
  xatolik bilan yakunlanadi.

Claude Code maxsus sarlavhalarni `ANTHROPIC_CUSTOM_HEADERS` orqali yuboradi. Uni
`~/.claude/settings.json` faylidagi `env` blokiga yoki har bir loyiha uchun boshqa hisobni
biriktirish maqsadida loyiha darajasidagi `.claude/settings.json` fayliga joylashtiring:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<your OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<your OmniRoute API key>",
    "ANTHROPIC_CUSTOM_HEADERS": "x-omniroute-connection: <connection id>",
  },
}
```

Manba: `src/sse/handlers/chat.ts` (sarlavhani oʻqish), `src/sse/services/auth.ts` va
`src/sse/services/sessionAffinityPin.ts` (biriktirishni bekor qilish va pulda yoʻqligini tekshirish).

> **Xarajat telemetriyasi sarlavhalari:** oqimsiz muvaffaqiyatli javoblar `X-OmniRoute-*` xarajat telemetriyasi toʻplamini ham oʻz ichiga oladi — `X-OmniRoute-Response-Cost` (USD, qatʼiy 10 ta oʻnlik xona; bepul yoki narxi belgilanmagan holatlar uchun `0.0000000000`), `X-OmniRoute-Tokens-In` / `X-OmniRoute-Tokens-Out`, `X-OmniRoute-Model`, `X-OmniRoute-Provider`, `X-OmniRoute-Latency-Ms`, `X-OmniRoute-Cache-Hit` va `X-OmniRoute-Fallback-Attempts` (faqat > 0 boʻlganda), shuningdek `X-OmniRoute-Request-Id` va `X-OmniRoute-Version`. Ular chat yakunlashlari, `/v1/responses`, `/v1/messages` **hamda media yakuniy nuqtalari** — `/v1/embeddings`, `/v1/images/generations`, `/v1/audio/speech`, `/v1/audio/transcriptions`, `/v1/rerank`, `/v1/videos/generations`, `/v1/music/generations` va `/v1/moderations` (xarajat har doim `0`) tomonidan chiqariladi. Narxlash mavjud boʻlsa, media xarajati har bir modallik boʻyicha (har bir rasm, soniya, belgi yoki qidiruv birligi uchun) hisoblanadi, aks holda `0` boʻladi (xatoda ishlashda davom etadi).

> **Keshga mos tushish xarajati semantikasi:** semantik keshga MOS TUSHGANDA (`X-OmniRoute-Cache-Hit: true`) yuqori oqimga hech qanday chaqiruv amalga oshirilmaydi, shu sababli `X-OmniRoute-Response-Cost` qiymati `0.0000000000` boʻladi (mos tushgan natijani taqdim etishning **qoʻshimcha** xarajati). Asl yoki yuzaga kelishi mumkin boʻlgan xarajat `X-OmniRoute-Cost-Saved` da alohida koʻrsatiladi. Billing tizimlari `X-OmniRoute-Response-Cost` qiymatlarini jamlashi kerak (keshga mos tushishlar xarajatsiz); kesh tahlili esa `X-OmniRoute-Cost-Saved` qiymatlarini jamlashi mumkin.

## Eksklyuziv boshqariladigan seans ijaralari

Eksklyuziv boshqariladigan seans ijarasi — ixtiyoriy, mijozga bogʻliq boʻlmagan marshrutlash shartnomasi: bitta faol egasi bitta mos OmniRoute ulanishini egallaydi. U modelni ijaraga bermaydi, OAuth talab qilmaydi, muayyan mijozni identifikatsiya qilmaydi yoki muayyan provayderni talab etmaydi.

Autentifikatsiya qiluvchi API kaliti `lease:exclusive` vakolat doirasiga va aniq koʻrsatilgan, boʻsh boʻlmagan `allowedConnections` roʻyxatiga ega boʻlishi kerak. Maʼlumotlar bazasidagi mutatsiya chegarasi kalit yaratish va qisman yangilash vaqtida ikkala maydonning birgalikda mavjud boʻlishini taʼminlaydi.

```http
POST /api/v1/session-leases
Authorization: Bearer <managed-api-key>
Content-Type: application/json
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>

{"action":"acquire","model":"glm/glm-4.6"}
```

Muvaffaqiyatli egallash, yangilash va boʻshatish javoblari vaqt belgilarini, `state` va aniq musbat `generation` qiymatini koʻrsatadi, biroq tanlangan ulanish yoki hisob maʼlumotlarini hech qachon oshkor qilmaydi. Yangilash va boʻshatish amallari generatsiyani JSON tanasida yuboradi:

```json
{ "action": "renew", "generation": 1 }
```

```json
{ "action": "release", "generation": 1, "reason": "OWNER_EXIT" }
```

Faol ijara egasi joriy bogʻlanishi uchun maxfiylikni saqlovchi koʻrsatish metamaʼlumotlarini aniq soʻrashi mumkin:

```json
{ "action": "status", "generation": 1 }
```

```json
{
  "state": "ACTIVE",
  "generation": 1,
  "acquiredAt": "2026-08-28T12:00:00.000Z",
  "renewedAt": "2026-08-28T12:00:30.000Z",
  "expiresAt": "2026-08-28T12:02:30.000Z",
  "connection": {
    "displayName": "Primary Codex",
    "provider": "codex"
  }
}
```

Ushbu ixtiyoriy status amali bitta maʼlumotlar bazasi tranzaksiyasida noaniq egasi, autentifikatsiya qilingan boshqariladigan API kaliti va aniq faol generatsiya orqali himoyalanadi. `displayName` faqat sozlangan ulanish nomining chetlardagi boʻshliqlari olib tashlangan koʻrinishidir; xavfsiz sozlangan nom mavjud boʻlmasa, u `null` boʻladi. OmniRoute hech qachon uning oʻrniga email yoki yaratilgan hisob identifikatorini qoʻymaydi. Provayder qiymati maxfiy boʻlmagan koʻrsatish yorligʻi boʻlib, hech qachon yaratilgan mos provayder identifikatori boʻlmaydi. Hisob maʼlumotlari, tokenlar, cookie-fayllar, ulanish yoki API kalitlarining xom identifikatorlari, egasi xeshlari, himoyalash sirlari va ichki marshrutlash maʼlumotlari chiqarib tashlanadi.

Notoʻgʻri kalit, notoʻgʻri egasi, eskirgan generatsiya, mavjud boʻlmagan, muddati tugagan, boʻshatilgan va bekor qilingan qidiruvlarning barchasi ulanish metamaʼlumotlarisiz bir xil `409 LEASE_FENCE_STALE` xatosini qaytaradi. Sigʻimni kutish javobini olgan mijozda tekshirish uchun faol bogʻlanish mavjud emas. Marshrutlash faol ijarani boshqa ulanishga oʻtkazganda, ayni generatsiya haqiqiyligicha qoladi va status eski bogʻlanishni emas, yangi bogʻlanishni atomar ravishda qaytaradi. Mavjud mijozlar oʻzgarishsiz qoladi, chunki egallash, yangilash, boʻshatish va kutish javoblari avvalgi tuzilishini saqlab qoladi.

Ushbu server shartnomasi standart OpenAI Codex `/status` xatti-harakatini oʻzgartirmaydi. Standart Codex hozirda oʻz model provayderi va ichki autentifikatsiya/hisob holati haqida xabar beradi, ammo ixtiyoriy maxsus provayder hisobi metamaʼlumotlarini koʻrsatmaydi; keyingi mijoz integratsiyasi ushbu amalni chaqirishi va `connection.displayName` qanday koʻrsatilishini hal qilishi kerak.

Shundan soʻng har bir boshqariladigan inferensiya soʻrovi ikkala boshqaruv sarlavhasini ham yuboradi:

```http
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>
X-OmniRoute-Lease-Generation: 1
```

Aniq egasi, generatsiya, faol ulanish va autentifikatsiya qilingan API kaliti har bir qoʻllab-quvvatlanadigan yuqori oqim urinishidan bevosita oldin himoyalanadi. Egasi va generatsiyani boshqa kalit bilan qayta yuborish, hatto oʻsha kalit ayni ulanishga ruxsat bersa ham, muvaffaqiyatsiz tugaydi. Xom egasi qiymatlari doimiy saqlanmaydi, jurnallarga yozilmaydi, soʻrov suratida saqlab qolinmaydi yoki yuqori oqimga uzatilmaydi.

Vaqtinchalik bandlik HTTP `429` javobini `Retry-After` bilan birga qaytaradi:

```json
{
  "state": "WAITING_FOR_CAPACITY",
  "error": { "type": "lease_error", "code": "LEASE_CAPACITY_UNAVAILABLE" },
  "reason": "NO_FREE_ELIGIBLE_CONNECTION",
  "retryAfter": 30
}
```

Bu javob faqat odatiy mos toʻplam boʻsh boʻlmaganini va barcha boʻsh nomzodlar boshqa faol ijaralar tomonidan egallanganini anglatadi. Qoʻllab-quvvatlanmaydigan modellar/provayderlar, siyosat nomuvofiqligi, vaqtinchalik cheklov, kvota, holat va boshqa odatiy moslik xatolari mavjud OmniRoute javoblarini saqlab qoladi.

### `x-omniroute-compression`

Har bir soʻrov uchun siqish rejasini almashtirish. Eng yuqori ustuvorlikka ega — marshrutlash kombinatsiyasi almashtirishidan, faol profildan, avtomatik ishga tushirishdan va paneldagi standart sozlamadan ustun turadi. Qiymatlar:

| Qiymat        | Taʼsir                                                                                                                  |
| ------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `off`         | Ushbu soʻrov uchun siqish qoʻllanmaydi.                                                                                 |
| `default`     | Paneldan olingan standart profil (faol profilni eʼtiborsiz qoldiradi). Yoʻqotishli mexanizmlar oʻchirilgan qoladi.      |
| `safe`        | Faqat takrorlarni olib tashlash va boʻshliqlarni birlashtirish.                                                         |
| `allow-lossy` | Ushbu soʻrov uchun operator rejasini, jumladan xulosalar va uslubiy qayta yozishlarni saqlab qoladi.                    |
| `engine:<id>` | Yoqilgan boʻlsa, bitta mexanizm, masalan, `engine:rtk`. Shu mexanizm uchun har bir soʻrov boʻyicha ixtiyoriy yoqish.    |
| `<combo>`     | Avval nomi boʻyicha (katta-kichik harflarni farqlamasdan), keyin id boʻyicha moslashtiriladigan nomlangan kombinatsiya. |

Izohlar:

- Nomaʼlum qiymatlar eʼtiborsiz qoldiriladi (soʻrov hech qachon rad etilmaydi); aniqlash odatiy operator ustuvorligiga oʻtadi.
- Agar bir nechta kombinatsiya bir xil nomga ega boʻlsa, aniq moslik uchun kombinatsiya **id** qiymatini yuboring.
- Nomi `off` yoki `default` boʻlgan kombinatsiyani nomi orqali tanlab boʻlmaydi (bu kalit soʻzlar avval talqin qilinadi); bunday kombinatsiyaga uning id qiymati orqali murojaat qiling.
- Asosiy siqish kaliti qatʼiy toʻsiqdir: siqish global miqyosda oʻchirilgan boʻlsa, ushbu sarlavha uni yoqa olmaydi.

Qoʻllangan reja javob sarlavhasida qaytariladi:

```
X-OmniRoute-Compression: <mode>; source=<source>
```

bu yerda `<source>` quyidagilardan biri: `request-header`, `routing-override`, `active-profile`, `auto-trigger`, `default` yoki `off`.

## Embeddinglar

```bash
POST /v1/embeddings
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "nebius/Qwen/Qwen3-Embedding-8B",
  "input": "The food was delicious"
}
```

Mavjud provayderlar: Nebius, OpenAI, Mistral, Together AI, Fireworks, NVIDIA, **OpenRouter**, Jina AI.

Katalog identifikatorlari `provider/model` formatida bo‘ladi (misol: `jina-ai/jina-embeddings-v5-omni-small`). Reestrda mavjud prefikssiz Jina model identifikatorlari (masalan, `jina-embeddings-v5-text-small`, `jina-reranker-v3.5`) ham aniqlanadi. Jina embed/rerank/classify/segment avval boshqaruv panelidagi `jina-ai` hisob ma’lumotlaridan foydalanadi; `JINA_AI_API_KEY` faqat boshqaruv panelida kalit mavjud bo‘lmaganda zaxira variant sifatida ishlatiladi. `jina-reader` kartasi faqat Reader / `r.jina.ai` uchun (`POST /v1/web/fetch`) mo‘ljallangan va hech qachon embedding yoki rerank xizmatlarini taqdim etmaydi.

Multimodal qo‘llab-quvvatlashni ko‘rsatuvchi reestr modellari provayderga bog‘liq bo‘lmagan, tuzilmali 32 tagacha
elementni ham qabul qiladi. Media element turlari: `text`, `image`, `audio`, `video` va `document`. Ularning media `source`
qiymati `{"type":"url","url":"https://..."}` yoki
`{"type":"base64","data":"...","media_type":"..."}` bo‘ladi.

Jina v5 Omni (`jina-ai/jina-embeddings-v5-omni-small`, `jina-ai/jina-embeddings-v5-omni-nano`
va oilaviy taxallus `jina-ai/jina-embeddings-v5-omni` → omni-small) Jina’ning mahalliy
EmbeddingsV5Request hujjatlarini ham qabul qiladi va ularni **o‘zgartirmasdan** `https://api.jina.ai/v1/embeddings` manziliga uzatadi:

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "task": "retrieval.query",
  "normalized": true,
  "input": [
    { "text": "a red bicycle" },
    { "image": "https://example.com/bike.png" },
    { "content": [{ "text": "caption" }, { "image": "data:image/png;base64,..." }] }
  ]
}
```

Mahalliy `{ image | audio | video | pdf }` qiymatlari ochiq HTTPS URL, `data:` URI yoki xom
base64 bo‘lishi mumkin. OmniRoute bu obyektlarni satrga aylantirmaydi va mahalliy rasm URL manzillarini yuklab olmaydi — Jina
ochiq mediaga o‘zi murojaat qiladi. Qo‘shimcha Jina maydonlari (`task`, `normalized`, `truncate`, `embedding_type`)
uzatiladi. Faqat matn bilan ishlaydigan Jina SKU’lari matn bo‘lmagan hujjatlarni hamon rad etadi.

Xavfsizlik va uzatish cheklovlari:

- Masofaviy media URL manzillari ochiq HTTPS bo‘lishi kerak. Kanonik `{type,source:url}` elementlari
  server tomonida yuklab olinadi (qayta yo‘naltirishni takroriy tekshirish, vaqt cheklovi, hajm cheklovlari, ochiq DNS, ulanishni mahkamlash) va
  provayder chaqiruvidan oldin ichki ko‘rinishda joylashtiriladi. Jina’ning mahalliy `{image:"https://..."}` elementlari
  xuddi shu ochiq HTTPS tekshiruvidan so‘ng o‘zgartirilmasdan uzatiladi; URL manzilini Jina yuklab oladi.
- Ichki base64 media har bir element uchun dekodlangan holda 8 MiB, butun so‘rov bo‘yicha esa dekodlangan holda 16 MiB bilan cheklanadi.

Provayder uchun o‘zgartirish (kanonik elementlar hech qachon o‘zgartirilmasdan uzatilmaydi):

- Jina multimodal modellari: har bir yuqori darajadagi element bitta modal kalitli obyektga
  (`text` / `image` / `audio` / `video` / `pdf`) aylantiriladi, ichki media uchun data URI’lardan foydalaniladi; har bir
  yuqori darajadagi element uchun bitta vektor.
- Gemini Embedding 2 oilasi: bitta yuqori darajadagi massiv `content.parts` (`text` yoki `inline_data`) bilan yagona mahalliy
  `models/{model}:embedContent` so‘roviga aylantiriladi.
- llama.cpp (`llama-cpp/<model>`, mahalliy server yuklagan istalgan model): kanonik `text` elementlari
  oddiy satrlarga, `image` / `audio` / `video` elementlari esa har biri bitta
  `{"content": [part]}` obyektiga aylantiriladi; bunda llama-server’ning ichki ma’lumotli chat kontent qismlaridan (`image_url`,
  `input_audio`, formati `wav` / `mp3` / `flac`, `input_video`) foydalaniladi; har bir yuqori darajadagi element uchun
  bitta vektor. Server `--embedding --mmproj …` bilan ishga tushirilishi kerak; proyektorsiz
  mediani serverning o‘zi rad etadi. `document` qo‘llab-quvvatlanmaydi.
- Aniq modallik metama’lumotlarisiz noma’lum/dinamik modellar tuzilmali kirishni HTTP 400 bilan rad etadi.

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "input": [
    { "type": "text", "text": "A red bicycle" },
    {
      "type": "image",
      "source": { "type": "url", "url": "https://example.com/bicycle.png" }
    }
  ],
  "dimensions": 512,
  "encoding_format": "float"
}
```

Qo‘llab-quvvatlanmaydigan model/modallik kombinatsiyalari elementni majburan o‘zgartirish o‘rniga HTTP 400 qaytaradi. Eski satr/token so‘rovlaridagi kirishga
taalluqli bo‘lmagan kengaytma maydonlari o‘zgartirilmasdan uzatilishda davom etadi.

```bash
# Barcha embedding modellarini ro‘yxatlash
GET /v1/embeddings
```

## Tasvir yaratish

```bash
POST /v1/images/generations
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "openai/gpt-image-2",
  "prompt": "A beautiful sunset over mountains",
  "size": "1024x1024"
}
```

Mavjud provayderlar qatoriga OpenAI (GPT Image 2), xAI (Grok Image), Together AI (FLUX), Fireworks AI, Nebius (FLUX), Hyperbolic, NanoBanana, **OpenRouter**, **ZenMux**, SD WebUI (mahalliy), ComfyUI (mahalliy) kiradi.

`n` `data[]` ichida `n` ta tasvirni qaytaradi. Yuqori darajadagi API har bir chaqiruv uchun bittadan tasvir qaytaradigan provayderlarga
(Black Forest Labs, Stability AI, Leonardo, Ideogram, Haiper, Hyperbolic, Magnific/Freepik,
NVIDIA NIM, Cloudflare Workers AI) yuqori darajadagi APIga `n` ta alohida chaqiruv yuboriladi, bunda bir vaqtda ko‘pi bilan 4 ta chaqiruv bajariladi. Belgilangan
`seed` qiymati chaqiruv indeksi bo‘yicha siljitiladi (`seed`, `seed + 1`, …), shu sababli tasvirlar farq qiladi, ammo ularni
qayta yaratish mumkin bo‘lib qoladi. `n` qiymatining yuqori chegarasi 10. Chaqiruvlardan biri muvaffaqiyatsiz tugasa, butun so‘rov
muvaffaqiyatsiz hisoblanadi. Tarqatib chaqirish formatlari ro‘yxati
`open-sse/handlers/imageGeneration/fanOut.ts` faylidagi `SINGLE_IMAGE_FANOUT_FORMATS` ichida berilgan.

ZenMux mavjud API kaliti ulanishidan qayta foydalanadi va `zenmux/` yoki `zm/` prefikslarini qabul qiladi:

- `zenmux/openai/gpt-image-2` ZenMux’ning OpenAI Images API xizmatidan foydalanadi. Parametrlar qatoriga `size`,
  `quality`, `n`, `output_format`, `output_compression`, `background` va `response_format` kiradi.
- `zm/meta/muse-image-1.0` kabi boshqa nashriyotchilar ZenMux’ning Vertex AI `:predict`
  yakuniy nuqtasidan foydalanadi. `n` `sampleCount`ga, `aspect_ratio` `aspectRatio`ga va `image_size`
  (`1K`, `2K`, `4K`) `sampleImageSize`ga moslanadi. Piksellarda berilgan `size` faqat tomonlar nisbatini belgilaydi,
  piksel o‘lchamlari esa kafolatlanmaydi. Qo‘llab-quvvatlanadigan nisbatlar, aniqliklar va sonlar modelga qarab farq qiladi.
- `zm/inclusionai/ming-image-0.1-design` o‘z o‘lchamlarini o‘zi tanlaydi. `size`,
  `aspect_ratio` va `image_size`ni ko‘rsatmang; ularni aniq ko‘rsatish HTTP 400 javobiga olib keladi. PNG, JPEG va WebP
  formatlarini `output_format` orqali so‘rash mumkin.

Ushbu integratsiya matndan tasvir yaratishni qo‘llab-quvvatlaydi, namunaviy tasvirni tahrirlashni emas. Vertex
natijasi `data[].b64_json` formatiga me’yorlashtiriladi; `response_format: "url"` yuqori darajadagi
HTTPS URL manzilini yoki faqat tasvir baytlari mavjud bo‘lganda base64 ma’lumotlar URL manzilini qaytaradi. Bo‘sh yoki filtrlangan natijalar
bo‘sh muvaffaqiyatli javob o‘rniga xatoni qaytaradi. Modellardan foydalanish imkoniyati ZenMux hisobiga bog‘liq.
[ZenMux’ning Vertex API hujjatlari](https://docs.zenmux.ai/api/vertexai/generate-images) va
[OpenAI Images API hujjatlari](https://docs.zenmux.ai/api/openai/generate-an-image) bilan tanishing.

```bash
# Barcha tasvir modellarini ro‘yxatlash
GET /v1/images/generations
```

## Hujjat OCR’i

```bash
POST /v1/ocr
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "mistral/mistral-ocr-latest",
  "document": {
    "type": "document_url",
    "document_url": "https://example.com/invoice.pdf"
  }
}
```

`model` OCR provayderini `provider/model` prefiksi orqali tanlaydi; prefikssiz model identifikatori (masalan,
`mistral-ocr-latest`) ro‘yxatdan o‘tgan provayderiga moslashtiriladi, `model` ko‘rsatilmasa esa sukut bo‘yicha
Mistral (`mistral-ocr-latest`) ishlatiladi. Ro‘yxatdan o‘tgan provayderlar (`open-sse/config/ocrRegistry.ts`):

| Provayder identifikatori      | Model identifikatori | `model` qiymati                                                     | Izohlar                                                                                                                      |
| ----------------------------- | -------------------- | ------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `mistral`                     | `mistral-ocr-latest` | `mistral/mistral-ocr-latest` (yoki prefikssiz `mistral-ocr-latest`) | Sinxron — javob yagona yuqori darajadagi chaqiruvdan to‘g‘ridan-to‘g‘ri qaytariladi.                                         |
| `azure-document-intelligence` | `prebuilt-read`      | `azure-document-intelligence/prebuilt-read`                         | Asinxron yuqori darajadagi xizmat (`analyze` + so‘rovnoma) — quyiga qarang.                                                  |
| `vertex-deepseek-ocr`         | `deepseek-ocr-maas`  | `vertex-deepseek-ocr/deepseek-ocr-maas`                             | Sinxron, Vertex AI’ning `openapi/chat/completions` hamkor yakuniy nuqtasi orqali — autentifikatsiya/URL uchun quyiga qarang. |

Uchala provayder ham bir xil Mistral shaklidagi javob tanasini qaytaradi:

```json
{
  "pages": [{ "index": 0, "markdown": "# Extracted text..." }],
  "model": "mistral-ocr-latest",
  "usage_info": { "pages_processed": 1 }
}
```

### Azure Document Intelligence so‘rovnoma oqimi

Azure Document Intelligence’ning `analyze` API’si asinxron ishlaydi: dastlabki so‘rov tana o‘rniga
`Operation-Location` sarlavhasini qaytaradi va natija so‘rovnomalar orqali tekshirilishi kerak. Ishlov beruvchi
(`open-sse/handlers/ocr.ts`) ushbu URL manzilini har soniyada, ko‘pi bilan 30 marta tekshiradi; `ok` bo‘lmagan so‘rovnoma javobi yoki `"failed"` holatida darhol muvaffaqiyatsiz tugaydi (tekshirishni
davom ettirmaydi) va urinishlar limiti tugagandan keyin ham amal bajarilayotgan bo‘lsa, `504` qaytaradi. Yakuniy Azure javobi
chaqiruvchiga qaytarilishidan oldin Mistral ishlatadigan o‘sha `pages`/`markdown` shakliga me’yorlashtiriladi,
shu sababli mijoz kodi provayder uchun alohida holatni qayta ishlashi shart emas.

### Vertex AI DeepSeek OCR autentifikatsiyasi va yakuniy nuqtani aniqlash

`vertex-deepseek-ocr` OmniRoute chat/tasvir trafigi uchun allaqachon qo‘llab-quvvatlaydigan xuddi shu Vertex AI autentifikatsiyasidan
qayta foydalanadi (`open-sse/executors/vertex.ts`): ulanishning API kaliti Service Account JSON hisob ma’lumotlari
(JWT-bearer oqimi orqali qisqa muddatli OAuth kirish tokeniga almashtiriladi) yoki o‘z holicha ishlatiladigan, avvaldan yaratilgan OAuth kirish tokeni bo‘ladi. Yuqori darajadagi yakuniy nuqta URL manzili Vertex’ning
umumiy `openapi/chat/completions` hamkor yakuniy nuqtasi bo‘lib, ulanish loyihasi va
hududidan tuziladi — aniq ko‘rsatilgan `providerSpecificData.project`/`providerSpecificData.region` doimo ustunlik qiladi;
aks holda loyiha Service Account JSON’dagi `project_id`dan olinadi va hudud uchun sukut bo‘yicha
`us-central1` ishlatiladi. Har ikkala aniqlash jarayoni `open-sse/handlers/ocr.ts` ichida
(`resolveVertexOcrAccessToken`, `resolveVertexOcrBaseUrl`) amalga oshiriladi va `handleOcr`ga yuborilishidan oldin
`src/app/api/v1/ocr/route.ts` tomonidan ishlatiladi.

### Model narxlari (`pricing`)

OmniRoute model narxini bilganida, yozuv `pricing` obyektini oʻz ichiga oladi. Narx xarajatlarni hisobga olish uchun ishlatiladigan narxlar jadvalidan olinadi: ichki standart qiymatlar, sinxronlangan narxlar va `/api/pricing` orqali oʻrnatilgan ustuvor qiymatlar. Bular roʻyxat narxlari boʻlgani sababli, obuna provayderlari ham har bir token uchun narxni koʻrsatadi.

```json
"pricing": {
  "prompt": "0.000005",
  "completion": "0.000025",
  "input_cache_read": "0.0000005",
  "input_cache_write": "0.00000625",
  "input": 5,
  "output": 25,
  "cached": 0.5,
  "cache_creation": 6.25
}
```

| Maydonlar                                                       | Birlik                              | Izohlar                                                                                                                                                     |
| --------------------------------------------------------------- | ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `prompt`, `completion`, `input_cache_read`, `input_cache_write` | Har bir token uchun USD, oʻnli satr | OpenRouter bilan mos, hech qachon eksponent yozuvida boʻlmaydi. Ikki kesh maydoni faqat kesh narxi mavjud boʻlganda koʻrsatiladi.                           |
| `input`, `output`, `cached`, `cache_creation`                   | 1 mln token uchun USD, son          | Katalogning oldingi versiyalaridagi maydonlar mavjud mijozlar uchun saqlangan. Narx qatorida mavjud boʻlsa, `reasoning` va `long_context` ham koʻrsatiladi. |

- **Kombinatsiyalar** oʻzlarining birinchi koʻrinadigan maqsadi narxini oladi. Ichki `auto/*` kombinatsiyalari maqsadni soʻrov vaqtida tanlaydi, shuning uchun ularda `pricing` mavjud emas.
- **Bepul modellar** narxi nol boʻlganda `"0"` (va `0`) qiymatini koʻrsatadi. Narx qatori mavjud boʻlmagan model ham katalog uni bepul deb belgilasa (`free: true`) yoki ichki bepul modellar katalogida keltirilgan boʻlsa, `"0"` qiymatini koʻrsatadi.
- **Nomaʼlum narx:** yozuvda `pricing` kaliti mavjud emas.
- **Kredit asosida hisoblanadigan provayderlar** (masalan, Kiro) har bir token uchun emas, har bir soʻrov uchun haq oladi. Ularning yozuvlari avvalgi raqamli har 1 mln tokenlik maydonlarni saqlab qoladi va har bir token uchun satr maydonlariga ega boʻlmaydi.
- **Variantlar** (fikrlash darajasi identifikatorlari, fikrlashsiz taxalluslar, aniqlash va shlyuz akslari) yoʻnaltiriladigan model narxini nusxalaydi.
- Maydonlar faqat bazaviy tariflarni oʻz ichiga oladi. Uzun kontekst darajalari (`long_context` raqamli maydoni) va xizmat darajasi koeffitsiyentlari (masalan, Codex fast yoki flex) `prompt` yoki `completion` qiymatini oʻzgartirmaydi.
- Obyekt barcha autentifikatsiya usullari, jumladan `x-api-key` va `anthropic-version` ishlatilgan Anthropic uslubidagi soʻrov uchun ham bir xil (`{ "object": "list",
"data": [...] }` koʻrinishidagi javob saqlanib qoladi). Amalga oshirish: `src/app/api/v1/models/catalogPricing.ts`.

### Model identifikatori prefikslari (`?prefix=`)

Aksariyat modellar **provayder prefiksi** ostida taqdim etiladi. Qaysi prefiks olinishi `MODELS_CATALOG_PREFIX_MODE` funksional bayrogʻi orqali boshqariladi va soʻrov parametri yordamida **har bir soʻrov uchun** alohida oʻzgartirilishi mumkin — bu server miqyosidagi sozlamani barcha uchun oʻzgartirmasdan toza roʻyxat olishni istaydigan mijoz uchun foydalidir:

```bash
GET /v1/models?prefix=alias        # har bir model uchun bitta id — qisqa taxallus prefiksi
GET /v1/models?prefix=dual         # ikkala shakl (server standarti)
GET /v1/models?prefix=canonical    # faqat toʻliq provayder id prefiksi
```

| Rejim       | Chiqaradi                                                | Izohlar                                                                                                                                                                                                                                      |
| ----------- | -------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dual`      | `cc/claude-sonnet-4-6` **va** `claude/claude-sonnet-4-6` | **Standart.** Ikkala id ham bir xil modelga yoʻnaltiriladi; shakllardan birini qatʼiy belgilagan mijoz konfiguratsiyalari ishlashda davom etishi uchun saqlangan. Katalog hajmini taxminan ikki baravar oshiradi.                            |
| `alias`     | `cc/claude-sonnet-4-6`                                   | Har bir model uchun bitta yozuv. Alohida taxallusi boʻlmagan provayderlar ham oʻz yozuvini chiqaradi, shuning uchun hech narsa yoʻqolmaydi.                                                                                                  |
| `canonical` | `claude/claude-sonnet-4-6`                               | Toʻliq provayder id prefiksi ostida har bir model uchun bitta yozuv. Alohida taxallusi boʻlmagan provayderlar (masalan, `antigravity/…`, `agy/…`) ham bu yerda oʻzining yagona id qiymatini chiqaradi, shuning uchun hech narsa yoʻqolmaydi. |

`dual` rejimidagi aksni soʻrov parametrisiz ham aniqlash mumkin: unda asosiy id qiymatiga ishora qiluvchi `parent` maydoni mavjud.

Model tanlagichini koʻrsatadigan mijozlar `?prefix=alias` parametrini soʻrashi kerak — [OmniCopilot VS Code kengaytmasi](../guides/VSCODE-COPILOT.md) ham shunday qiladi.

### Aniqlash filtrlari (`?capability=`, `?min_context=`, `?kind=`, `?q=`)

`GET /v1/models` ixtiyoriy aniqlash filtrlarini qabul qiladi. Ularning hech biri berilmasa, javob oʻzgarmaydi. Ular chaqiruvchi allaqachon koʻra oladigan katalogni toraytiradi (avval API kaliti ruxsatlari qoʻllanadi) va OpenAI uslubidagi `limit` / `after` sahifalashidan oldin bajariladi:

```bash
GET /v1/models?capability=vision&capability=tool_calling   # roʻyxatdagi har bir imkoniyat true boʻlishi kerak
GET /v1/models?capability=vision,reasoning&min_context=200000
GET /v1/models?kind=embedding                              # katalogdagi `type`; u mavjud boʻlmagan qatorlar `chat` hisoblanadi
GET /v1/models?q=sonnet&limit=10                           # id yoki nom boʻyicha registrga bogʻliq boʻlmagan moslik
```

| Parametr      | Qiymatlar                                                                                           |
| ------------- | --------------------------------------------------------------------------------------------------- |
| `capability`  | `attachment`, `reasoning`, `structured_output`, `temperature`, `thinking`, `tool_calling`, `vision` |
| `min_context` | manfiy bo‘lmagan butun son, `context_length` bilan taqqoslanadi                                     |
| `kind`        | `chat`, `audio`, `embedding`, `image`, `moderation`, `music`, `rerank`, `video`                     |
| `q`           | 1–200 ta belgi                                                                                      |

Noma’lum qiymat yoki manfiy bo‘lmagan butun son hisoblanmaydigan `min_context` (masalan, `1.5`)
HTTP `400` qaytaradi va xabarda yaroqli qiymatlar ro‘yxati keltiriladi. Amalga oshirilishi:
`src/app/api/v1/models/catalogFilters.ts`.

### Modellarning qisqa ro‘yxati (`POST /v1/models/query`)

`POST /v1/models/query` xuddi shu katalogdan `GET /v1/models` bilan bir xil
autentifikatsiya va har bir kalitga tegishli ko‘rinish qoidalari asosida qisqa, deterministik ro‘yxatni qaytaradi:

```bash
POST /v1/models/query
Authorization: Bearer your-api-key
Content-Type: application/json

{ "capabilities": ["vision", "tool_calling"], "min_context": 128000, "max_output": 16000,
  "kind": "chat", "q": "gpt", "owned_by": "openai", "exclude": ["openai/gpt-4o"], "limit": 5 }

→ { "object": "list", "data": [ ...models ] }
```

Har bir maydon ixtiyoriy. `capabilities` va `exclude` massiv yoki vergul bilan ajratilgan satrni
qabul qiladi; `max_output` `max_output_tokens` bilan taqqoslanadi. Natijalar avval `owned_by`, keyin `id`
bo‘yicha saralanadi. `limit` uchun standart qiymat `20`, `100` dan katta qiymatlar esa `100` bilan cheklanadi. Yaroqsiz JSON, noma’lum
maydon yoki yaroqsiz qiymat HTTP `400` qaytaradi.

### Alohida yashirilgan chat modellari

Provayder sahifasida **Yashirilgan** deb belgilangan model katalogdan chiqarib tashlanadi va bevosita
so‘ralganda HTTP `404` / `model_not_found` bilan rad etiladi. Tekshiruv aniqlangan
provayder va modeldan foydalanadi, jumladan provayder taxalluslari, mos provayder tuguni prefikslari va
ulanishning standart qiymatlari. Kombinatsiya yashirilgan nishonlarni o‘tkazib yuboradi va ko‘rinadigan muqobildan foydalanishi mumkin; agar
bajariladigan nishon qolmasa, u xuddi shu xato kodini qaytaradi. Yashirishni bekor qilish keyingi
so‘rovdan boshlab kuchga kiradi. Faqat tasvirga tegishli ko‘rinish sozlamalari xuddi shu ID ga ega chat modelini
yashirmaydi.

Bu alohida model sozlamasi katalogda
e’lon qilish va avtomatik yo‘naltirish nomzodlarini filtrlab, bevosita jo‘natishni saqlab qoluvchi
[modelni ochish ruxsat etilgan/taqiqlangan ro‘yxatlaridan](../routing/MODEL_EXPOSURE_LIST.md) alohida hisoblanadi. API kalitining model
ruxsatlari mustaqil ravishda qo‘llanishda davom etadi. Katalog prefiksi uchun standart rejim `dual` bo‘lib qoladi.

### Fikrlashsiz model variantlari

Fikrlash imkoniyatiga ega Claude modellari uchun `/v1/models`, shuningdek, identifikatori `claude-3-omniroute-no-thinking/` prefiksi bilan boshlanadigan **fikrlashsiz** variantni e’lon qiladi:

```
claude-3-omniroute-no-thinking/<provider>/<model>
```

Ushbu identifikatorni tanlash (masalan, har doim `thinking` blokini biriktiradigan Claude Code konfiguratsiyasida) fikrlash bostirilgan holda haqiqiy `<provider>/<model>` ga qayta aniqlanadi — `/v1/messages` yo‘lida `thinking:{type:"disabled"}` qo‘llanadi yoki `/v1/chat/completions` yo‘lida `reasoning`/`reasoning_effort` maydonlari olib tashlanadi. Variant faqat fikrlashni qo‘llab-quvvatlaydigan **va** `disabled` qiymatini qabul qiladigan Claude oilasiga mansub modellar uchun ro‘yxatga kiritiladi (shuning uchun, masalan, `disabled` qiymatini rad etadigan faqat adaptiv modellar chiqarib tashlanadi). Operatorlar `ModelSpec.noThinkingAlias` orqali har bir model uchun ushbu variantni majburan yoqishi yoki o‘chirishi mumkin.

## ElevenLabs orqali audio yaratish

OmniRoute ichida ElevenLabs API kalitingiz bilan `elevenlabs` provayder ulanishini sozlang. Mijozlar oʻzlarining **OmniRoute** kaliti (`Authorization: Bearer $OMNIROUTE_API_KEY`) bilan autentifikatsiyadan oʻtadi; shlyuz saqlangan provayder kalitini `xi-api-key` sifatida taqdim etadi. ElevenLabs kalitini hech qachon shlyuzning bearer tokeni sifatida yubormang.

| Usul | Yoʻl                        | Javob                                      | API kaliti endpoint toifasi |
| ---- | --------------------------- | ------------------------------------------ | --------------------------- |
| POST | `/v1/sound-generation`      | Asl audio baytlari                         | `elevenlabs`                |
| POST | `/v1/music`                 | Asl audio baytlari                         | `music`                     |
| POST | `/v1/music/stream`          | Oqimli audio baytlari                      | `music`                     |
| POST | `/v1/music/detailed`        | Asl multipart audio va kompozitsiya rejasi | `music`                     |
| POST | `/v1/music/detailed/stream` | Asl SSE metamaʼlumotlari va audio qismlari | `music`                     |
| POST | `/v1/music/plan`            | JSON kompozitsiya rejasi                   | `music`                     |

Ushbu endpointlar mavjud `/v1/audio/speech`, `/v1/audio/transcriptions`, `/v1/voices`, `/v1/text-to-speech/{voiceId}` va `/v1/speech-to-text` yoʻnalishlarini toʻldiradi. `output_format` va `enable_logging` kabi asl JSON maydonlari hamda soʻrov parametrlari saqlanadi. `/v1/music/detailed` javoblarida multipart chegaralari saqlanadi; ularni multipart sifatida tahlil qiling. `/v1/music/detailed/stream` kompozitsiya metamaʼlumotlari va SSE hodisalaridagi base64 audio qismlari bilan `text/event-stream` qaytaradi. Oltita yoʻnalishning barchasi CORS dastlabki soʻrovlarini qoʻllab-quvvatlaydi.

```bash
export OMNIROUTE_BASE_URL="http://localhost:20128"
export OMNIROUTE_API_KEY="your-omniroute-api-key"

# Qisqa ovoz effekti. Davomiyligi: 0,5 dan 30 soniyagacha.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/sound-generation?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text":"A single soft bell chime","duration_seconds":1,"model_id":"eleven_text_to_sound_v2"}' \
  --output effect.mp3

# Musiqa davomiyligi millisekundlarda ifodalanadi: 3000 dan 600000 gacha.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"prompt":"Gentle instrumental piano","music_length_ms":10000,"force_instrumental":true,"model_id":"music_v1"}' \
  --output music.mp3
```

Audioni bosqichma-bosqich uzatish uchun ayni JSON tanasi bilan `/v1/music/stream` dan foydalaning. Kompozitsiya `prompt` yoki `composition_plan` qiymatlaridan aynan bittasini qabul qiladi; `/v1/music/plan` uchun `prompt` talab qilinadi va u ixtiyoriy ravishda `source_composition_plan` ni qabul qiladi. Asl sxemalar qoʻshimcha provayder maydonlarini saqlaydi, shuning uchun kompozitsiya rejasi versiyalari va nozik sozlash parametrlari ElevenLabs’ga yetib boradi.

Birlashtirilgan `/v1/music/generations` endpointi `elevenlabs/music_v1`, `elevenlabs/music_v2` va `elevenlabs/music_v2_5` ni ham qabul qiladi. Faol ElevenLabs ulanishi mavjud boʻlsa, bu modellar musiqa katalogida koʻrsatiladi. Ushbu endpoint `{"created":...,"data":[{"b64_json":"...","format":"mp3"}]}` ni qaytaradi. Undagi `duration` maydoni soniyalarda beriladi va `music_length_ms` ga moslashtiriladi; aniq koʻrsatilgan `music_length_ms` ustunlikka ega. `instrumental` qiymati `force_instrumental` ga moslashtiriladi, bunda asl maydon ustunlikka ega. Oqimli uzatish uchun asl oqimli endpointlardan, faqat kompozitsiya rejasiga asoslangan soʻrovlar uchun esa asl kompozitsiya endpointidan foydalaning.

```bash
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music/generations" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"elevenlabs/music_v1","prompt":"Gentle instrumental piano","duration":10,"instrumental":true}'
```

Endpoint, model, budjet va ulanish cheklovlari yuqori oqimga murojaat qilishdan oldin qoʻllanadi. Asl yoʻnalishlar yuqori oqimdagi holat kodlari va xato tanalarini oʻzgartirmasdan qaytaradi, jumladan tarif rejasi cheklovi uchun `402` va kvota chegarasi uchun `429`. Mavjud boʻlsa, `character-cost`, `song-id`, `request-id` va `retry-after` sarlavhalari saqlanadi. Bepul kredit qoldigʻi har bir musiqa modeli, chiqish formati yoki API funksiyasidan foydalanish imkoniyatini kafolatlamaydi: har bir soʻrov uchun ruxsatni ElevenLabs belgilaydi. Birlashtirilgan endpoint OmniRoute’ning meʼyorlashtirilgan xato konvertida xato holati kodlarini saqlaydi.

Yuqori oqim shartnomalari: [ovoz effektlari](https://elevenlabs.io/docs/api-reference/text-to-sound-effects/convert),
[musiqa kompozitsiyasi](https://elevenlabs.io/docs/api-reference/music/compose) va
[oqimli musiqa tafsilotlari](https://elevenlabs.io/docs/api-reference/music/compose-detailed-stream).

> (oMLX, vLLM, Infinity, shlyuz ortidagi TEI, …) ham yo‘naltiriladi. Loopback
> tugunlari (`localhost`, `127.0.0.1`, `172.16.0.0/12`) har doim foydalanishga yaroqli, shuningdek operator
> `OMNIROUTE_LOCAL_PROVIDER_NODE_HOSTS` ichida ko‘rsatgan host nomlari ham (masalan,
> `http://reranker:8080/v1` kabi Docker/Compose xizmat nomi; ular doimo to‘g‘ridan-to‘g‘ri chaqiriladi,
> `HTTP(S)_PROXY` yoki ulanishga biriktirilgan proksi orqali hech qachon chaqirilmaydi). Boshqa har qanday
> hostdagi tugunlardan — LAN qurilmasi yoki Tailscale piri — faqat operator
> `RERANK_REMOTE_PROVIDER_NODES` funksiya bayrog‘ini yoqqanida **va** tugunning asosiy URL manzili provayderning
> chiquvchi URL siyosatidan (`OMNIROUTE_ALLOW_LOCAL_PROVIDER_URLS` / `OMNIROUTE_ALLOW_PRIVATE_PROVIDER_URLS`)
> o‘tganida foydalanish mumkin.
> Xotira mexanizmining qayta saralash bosqichi bu marshrutni loopback orqali chaqiradi,
> shu sababli ayni qoida Xotira sozlamalaridagi `rerankProviderModel` uchun ham amal qiladi.
>
> **Mahalliy server formatlari:** tugun avval `<base>/v1/rerank` manzilida, 404 holatida esa
> `<base>/rerank` manzilida (Infinity, TEI) chaqiriladi. Yuqori oqim tanasi Cohere/OpenAI yozilishini
> (`documents`, `return_documents`) ham, TEI yozilishini (`texts`, `return_text`) ham uzatadi va yuqori
> oqim javobi Cohere konvertiga me’yorlashtiriladi: TEI’ning oddiy `[{index, score, text}]` formati,
> yengil shlyuzlardan keladigan `{results: [{index, score}]}` hamda Voyage uslubidagi `{data: [...]}`
> formatlarining barchasi mijozga ball bo‘yicha saralangan va `top_n` bilan cheklangan
> `{results: [{index, relevance_score, document?}]}` ko‘rinishida qaytariladi.

> **Provayder tugunlarini aniqlash:** OpenAI bilan mos provayder tugunidagi modellar `GET /v1/models`
> ichida tugun prefiksi ostida ko‘rinadi. Endpoint metama’lumotiga ega bo‘lmagan qatorlar (odatda mahalliy
> `/v1/models` ro‘yxatlarida) tugunning `apiType` qiymatini meros qilib oladi, shuning uchun

backendi) ulangan. U API/boshqaruv paneli bilan bir xil portdagi `/v1/responses`,

`app/server-ws.mjs` + `scripts/dev/responses-ws-proxy.mjs` + `src/app/api/internal/codex-responses-ws/route.ts` fayllarida amalga oshirilgan.

**Autentifikatsiya:** qo‘l siqish vaqtida Bearer API kaliti. Birga taqdim etilgan HTTP server (`server-ws.mjs`)
faol kirish nuqtasi bo‘lishi kerak (`app/server-ws.mjs` mavjud bo‘lsa, standart holatda shunday bo‘ladi).

#### Model identifikatori: oddiy ChatGPT identifikatoridan foydalaning (`codex/` prefiksisiz)

## Mustaqil foydalanish (`/api/usage/om-usage`)

Istalgan API kaliti boshqaruv autentifikatsiyasisiz **oʻzining** foydalanish maʼlumotlari va kvotalarini oʻqishi mumkin. Bu mijoz (CLI, OmniCopilot paneli) kalit egasiga uning xarajatlarini koʻrsatish uchun foydalanadigan endpointdir.

```bash
# Matn shakli (tarixiy kelishuv — terminal uchun oddiy matn)
curl -H "Authorization: Bearer <your-api-key>" \
  http://localhost:20128/api/usage/om-usage

# Tuzilmaviy shakl — UI foydalanadigan format
curl -H "Authorization: Bearer <your-api-key>" \
  "http://localhost:20128/api/usage/om-usage?format=json"
```

Kalitda **`allowUsageCommand`** yoqilgan boʻlishi kerak (standart holatda oʻchiq — boshqaruv panelidagi API kalitlari menejeri uni har bir kalit uchun alohida yoqadi). U boʻlmasa, endpoint `403` javobini qaytaradi.

`?format=json` diskriminatsiyalangan tuzilmani qaytaradi, shuning uchun chaqiruvchi rad etish javobidan maʼlumot maydonini hech qachon oʻqimaydi. Muvaffaqiyatli holatda:

```jsonc
{
  "allowed": true,
  // faqat kalit har bir kalit uchun foydalanish limitlarini (kunlik/haftalik USD) tanlaganida mavjud:
  "personal": {
    "dailySpentUsd": 1.25,
    "dailyLimitUsd": 5,
    "dailyResetAtIso": "…",
    "weeklySpentUsd": 8,
    "weeklyLimitUsd": 20,
    "weeklyResetAtIso": "…" /* … */,
  },
  // tanlangan provayder kvotasining oniy nusxasi yoki hali hech narsa keshlanmagan boʻlsa null:
  "provider": { "connectionId": "…", "provider": "claude", "plan": "…", "quotas": {/* … */} },
  // UI bir nechta provayderni yonma-yon koʻrsatishi uchun har bir ulanishning oniy nusxasi:
  "providers": [
    { "connectionId": "…", "provider": "claude" /* … */ },
    { "provider": "codex" /* … */ },
  ],
}
```

Rad etilganda (`401` yaroqsiz kalit / `403` ruxsat berilmagan) ayni yoʻnalish
`{ "allowed": false, "error": { "message": "…" } }` javobini qaytaradi — mavjud, ammo boʻsh `personal`/`provider` (kalitga ruxsat berilgan, ammo hali hech qanday maʼlumot olinmagan) rad etishdan farqli holatdir va ularni faqat JSON shakli ajratib koʻrsatadi.

**Autentifikatsiya:** chaqiruvchining `isValidApiKey` orqali tekshiriladigan oʻz Bearer API kaliti — bu `requireManagementAuth` ortida qoladigan boshqaruv interfeysi (`/api/keys/…`) _emas_.

### Xom va chegara qiymatiga moslashtirilgan kvota foizlari

`/api/usage/om-usage` natijasidan foydalanishda chaqiruvchilar **oddiy matnli chiqish** va tuzilmaviy **JSON chiqishi** taqdim etadigan foizlar oʻrtasidagi farqni hisobga olishlari kerak:

| Jihat                    | Oddiy matn formati (`/api/usage/om-usage` / `@@om-usage`)                                                   | JSON formati (`?format=json`)                                                                        |
| :----------------------- | :---------------------------------------------------------------------------------------------------------- | :--------------------------------------------------------------------------------------------------- |
| **Chiqish maydoni**      | `NN% left` (masalan, `20% left`)                                                                            | `provider.quotas` / `providers[].quotas`                                                             |
| **Oʻlchov**              | **Chegara qiymatiga moslashtirilgan foydalanish mumkin boʻlgan limit**: chegaradan yuqori qolgan sigʻim     | **Yuqori oqimdagi xom kvota**: provayderning moslashtirilmagan oʻlchovi                              |
| **Chegara masshtabi**    | Himoyalangan zaxira `0% left` sifatida koʻrinishi uchun `effectiveRemainingPercent()` orqali masshtablanadi | Yoʻq (provayder xabar qilgan xom oniy nusxa qiymatlari)                                              |
| **Chegara maʼlumotlari** | Koʻrsatilgan foizga kiritilgan                                                                              | Har bir ulanish uchun `quotaWindowThresholds` ichida saqlanadi (yoki serverning standart qiymatlari) |
| **Asosiy isteʼmolchi**   | Interaktiv CLI’lar, terminal soʻrovlari, inson operatorlari                                                 | Dasturiy integratsiyalar, boshqaruv panellari, tahlil va billing kuzatuvchilari                      |

#### Chegara qiymatiga moslashtirish formulasi

OmniRoute yuqori oqimdagi resurslarning tugab qolishiga yoʻl qoʻymaslik uchun proaktiv kvota chegaralarini qoʻllab-quvvatlaydi (ular ulanishning `quotaWindowThresholds` parametri, provayderning standart qiymatlari yoki global chidamlilik sozlamalari orqali belgilanadi). Kvota oynasida chegara qiymati (masalan, `cutoff = 25%`) faol boʻlsa, matn rendereri qolgan limitni quyidagicha hisoblaydi:

- Agar `remaining <= cutoff` boʻlsa: `0%` qaytaradi.
- Agar `remaining > cutoff` boʻlsa: `((remaining - cutoff) / (100 - cutoff)) * 100` qaytaradi.

Formatlangan matnli chiqish bu qiymatni eng yaqin butun songa yaxlitlaydi (`Math.round(...)`).

#### Koʻrgazmali misol

**60% xom foydalanish** (demak, **40% xom qolgan kvota**) va sozlangan **qolgan kvota uchun 25% chegara** qiymatiga ega provayder oynasini koʻrib chiqaylik:

| Koʻrinish                     | Hisoblash                                          | Qolgan miqdor |        Nazarda tutilgan foydalanish         |
| :---------------------------- | :------------------------------------------------- | :-----------: | :-----------------------------------------: |
| **Xom JSON (`?format=json`)** | Yuqori oqim oniy nusxasi (`quotas[window]`)        |    **40%**    |                   **60%**                   |
| **Matn formati (`NN% left`)** | `((40 - 25) / (100 - 25)) * 100 = (15 / 75) * 100` |    **20%**    | **80%** (agar `100 - remaining` hisoblansa) |

- **Nima uchun matnda 20% qolgan deb koʻrsatiladi:** Hisobda qolgan 40% jismoniy kvotaning 25%i chegara siyosati tomonidan zaxiralangan. Router ushbu ulanishga yoʻnaltirishni toʻxtatishidan oldin chaqiruvchi foydalanish mumkin boʻlgan 75% zaxiraning faqat 15%iga ega. Masshtablash ulanish aynan yoʻnaltirish toʻxtatiladigan paytda tugaganlik holatini (`0% left`) koʻrsatishini taʼminlaydi.
- **Nima uchun JSON xom qiymatlarni saqlaydi:** JSON foydali yuklamasi provayderning aniq oniy nusxasini (`UsageSnapshot`) qaytaradi, shuning uchun tashqi vositalar server tomonida yoʻqotishli masshtablashsiz yuqori oqimdan foydalanishning haqiqiy koʻrsatkichlari va ulanish darajasidagi `quotaWindowThresholds` maʼlumotlariga kira oladi.

#### Isteʼmolchilarni migratsiya qilish boʻyicha koʻrsatmalar

Agar tashqi integratsiya (masalan, muharrir plagini yoki agent kengaytmasi) avval matn
endpointidan (`NN% left`) maʼlumotlarni ajratib olgan va foydalanilgan foizni `100 - NN` sifatida hisoblagan boʻlsa, `?format=json` formatiga oʻtish quyidagilarni anglatadi:

- JSON qiymatlarini toʻgʻridan-toʻgʻri oʻqish **yuqori oqimdagi haqiqiy sarfni** aks ettiradi (yuqoridagi misolda 60% foydalanilgan).
- Agar integratsiya matn endpointining foydalanish mumkin boʻlgan limit semantikasini saqlab qolmoqchi boʻlsa, ulanish darajasidagi qayta belgilashlar uchun `quotaWindowThresholds` dan foydalanib,
  samarali qolgan miqdor formulasini mijoz tomonida hisoblab chiqishi mumkin.

### Har bir kalit uchun keshni chetlab oʻtish

| Qiymat   | Xatti-harakat                                                                         |


Sinxronlangan/import qilingan modellar uchun `PUT /api/provider-models` soʻrovi `provider`, `modelId` va
`maxOutputTokenOverride` qiymatlarini qabul qiladi: musbat butun son chiqish tokenlarining qoʻlda belgilangan
chegarasini oʻrnatadi, `null` esa uni tozalab, standart qiymatni tiklaydi.
`GET /api/provider-models?provider=<provider>` ushbu qiymatlarni `modelOutputOverrides` ichida,
jumladan, maxsus model qatoriga ega boʻlmagan modellar uchun ham qaytaradi. Bekor qiluvchi sozlama ish
vaqtidagi `max_output_tokens` imkoniyatidan foydalanadi va model qayta sinxronlangandan keyin ham saqlanib
qoladi. OpenAI bilan mos provayder sahifasi xuddi shu tahrirlash/tozalash boshqaruvlarini taqdim etadi va
tasvirlarni aniq qoʻllab-quvvatlaydigan modellarni belgilaydi.

Maxsus Chat Completions tugunlari mulohaza yuritishni aniq rad etish sozlamalarini yuqori oqimdagi
backend tizimiga moslashtiradi. Muvaffaqiyatli ulanish sinovi `/models` yozuvi tan olingan `owned_by`
qiymatini tasdiqlaydigan har bir aniq model IDsi uchun chat shabloni boshqaruvlarini avtomatik tanlaydi:
`vllm`, `sglang` yoki `llamacpp`. Shaffof OpenAI bilan mos oʻrovchilar asl model yozuvini ichki
`openai` obyekti ichida saqlab qolishi mumkin; aniqlash bunday qobiqlarning uchtagachasini kuzatadi.
Egalik maʼlumoti mavjud boʻlmagan, nomaʼlum yoki ziddiyatli boʻlgan modellar odatiy OpenAI xatti-harakatini
saqlab qoladi. Aniqlash mavjud katalog soʻrovidan qayta foydalanadi, hech qanday completion tokenini
yaratmaydi va ulanishning oxirgi nuqtasi oʻzgarganda bekor qilinadi.

Bunday metamaʼlumotlarni taqdim etmaydigan backend uchun xatti-harakatni qatʼiy belgilash maqsadida
mavjud provayderni qisman yangilash APIsidan foydalaning:

```json
{
  "providerSpecificData": {
    "reasoningControl": "chat-template"
  }
}
```

Ushbu tanani `PUT /api/providers/<connection-id>` orqali yuboring. Bu ulanishda `none` qiymatidagi
aniq mulohaza yuritish darajasi `chat_template_kwargs.thinking=false` va
`chat_template_kwargs.enable_thinking=false` shaklida yuboriladi. Server tomonidagi mulohaza yuritish
qoidasi muayyan darajani majburan belgilamasa, aniq mahalliy shablon qiymatlari ustuvor boʻlib qoladi.
Sozlama faqat maxsus OpenAI bilan mos ulanish Chat Completions tanasini yuborganda qoʻllanadi;
Responses soʻrovlari va odatiy provayderlar oʻzlarining mahalliy soʻrov tuzilishini saqlab qoladi.
Odatiy OpenAI `reasoning_effort` qiymatini oʻzgarishsiz uzatishni majburlash uchun `reasoningControl`
qiymatini `openai` ga oʻrnating yoki avtomatik aniqlashdan foydalanish uchun uni tashlab keting yoxud
`null` qiymatiga oʻrnating.

Claude Code avtomatik rejimi klassifikatori soʻrovlarida aniq mulohaza yuritish boshqaruvlari boʻlmasa,
mahalliy fikrlash standart boʻyicha oʻchiriladi. Aniqlash model nomlari yoki completion chegaralaridan
emas, Claude formatidagi soʻrovlardagi klassifikatorning tizim markeridan foydalanadi. Tanadagi aniq
boshqaruvlar, qoʻllab-quvvatlanadigan daraja/fikrlash sarlavhalari, marshrutlash qoidalari va aniqlangan
model darajasi oʻzlarining mavjud ustuvorligini saqlab qoladi. Klassifikatorning ikkala bosqichi ham oʻz
promptlari, completion chegaralari, toʻxtash ketma-ketliklari va yuqori oqimdagi haqiqiy ruxsat
qarorlarini saqlab qoladi; ikkinchi bosqich hali ham soʻralgan koʻrinadigan mulohazani oddiy matn
sifatida yaratishi mumkin.

### Versiya va reliz kanali

```bash
GET /api/system/version
```

Faqat loopback orqali foydalaniladigan boshqaruv marshruti (administrator autentifikatsiyasi). Ishlayotgan versiya, eng so‘nggi chop etilgan versiya va avtomatik yangilanish holatini qaytaradi. `releaseChannel` va `channels` qo‘shimcha maydonlardir (3.8.54 liniyasi); `channel` o‘z ma’nosini saqlab qoladi — boshqaruv paneli yangilagichi foydalanadigan joylashtirish rejimi (`npm`, `source` yoki `docker-compose`).

```json
{
  "current": "3.8.52",
  "latest": "3.8.52",
  "updateAvailable": false,
  "channel": "npm",
  "autoUpdateSupported": true,
  "autoUpdateError": null,
  "news": null,
  "releaseChannel": "latest",
  "channels": { "latest": "3.8.52", "next": "3.8.53-rc.1" }
}
```

- `releaseChannel` — ishlayotgan tuzilmaning npm kanali: `-nightly.*` versiyalari uchun `nightly`,
  boshqa dastlabki relizlar (`-rc.*`, `-beta.*`, `-alpha.*`) uchun `next`, `channels.latest` dagidan
  eskiroq asosiy versiyaning barqaror versiyasi uchun `lts`, aks holda `latest`. Chop etish vaqtida
  npm dist-tag qiymatini tanlaydigan `scripts/release/dist-tag.mjs` bilan bir xil qoidalardan foydalanadi.
- `channels` — `npm view omniroute dist-tags` orqali olingan har bir dist-tag ning eng so‘nggi chop
  etilgan versiyasi (registrning HTTP zaxira varianti bilan), `latest` kabi 10 daqiqalik TTL bilan
  keshlanadi. `latest` har doim mavjud (avval `latest` maydoniga, so‘ng `"unavailable"` qiymatiga
  qaytadi); `next`, `nightly` va `lts` faqat tegishli dist-tag mavjud bo‘lganda ko‘rsatiladi.
  `Cache-Control: no-cache` so‘rovi ikkala qidiruvni ham yangilaydi.

Kanal modeli (`latest` = 4.0 GA chiqishigacha v3, `next` = rc, `nightly` = `develop` tuzilmalari,
`lts` = 4.0 GA dan keyingi v3 tuzatishlari) `docs/ops/RELEASE_STRATEGY.md` faylida tavsiflangan.

## Token limitlari

Har bir API kaliti uchun **token** budjetlari (yuqoridagi USD asosidagi budjetdan alohida). Soʻrov yoʻlida bevosita qoʻllanadi: kalitning joriy davrdagi sarfi limitiga yetganda, soʻrovlar `429 Too Many Requests` bilan rad etiladi. Limitlar muayyan `model` yoki `provider` doirasida belgilanishi yoxud kalit boʻylab `global` tarzda qoʻllanishi mumkin; bir nechta limit soʻrovga mos kelsa, eng qatʼiy limit ustun keladi.

```bash
# Kalitning token limitlarini ko‘rsatish (joriy davrdagi sarfni ham o‘z ichiga oladi)
GET /api/usage/token-limits?apiKeyId=key-123

# Token limitini yaratish yoki yangilash
POST /api/usage/token-limits
Content-Type: application/json

{
  "apiKeyId": "key-123",
  "scopeType": "model",
  "scopeValue": "openai/gpt-4o",
  "tokenLimit": 1000000,
  "resetInterval": "monthly",
  "enabled": true
}

# Token limitini id bo‘yicha o‘chirish
DELETE /api/usage/token-limits?id=tl-abc
```

> **Sxema izohlari** (`setTokenLimitSchema`): `apiKeyId` va `scopeType` (`model` | `provider` | `global`) majburiy. `scopeType` qiymati `global` boʻlmasa, `scopeValue` majburiy (masalan, `model` doirasi uchun model identifikatori, `provider` doirasi uchun provayder identifikatori). `tokenLimit` musbat butun son boʻlishi kerak (satrdan oʻzgartiriladi). Ixtiyoriy: `id` (yaratish uchun koʻrsatmang, yangilash uchun kiriting), `resetInterval` (`daily` | `weekly` | `monthly`, standart qiymat `monthly`), `resetTime` (`HH:MM`), `enabled` (standart qiymat `true`). `GET` javoblari har bir limitni `tokensUsed`, `remaining`, `windowStart`, `periodStartAt` va `nextResetAt` bilan boyitadi. Bu boshqaruv toifasidagi endpoint (autentifikatsiya authz konveyeri tomonidan markazlashgan tarzda majburiy qoʻllanadi).

1. Mijoz soʻrovni `/v1/*` manziliga yuboradi
2. Marshrut ishlov beruvchisi `handleChat`, `handleEmbedding`, `handleAudioTranscription` yoki `handleImageGeneration` funksiyasini chaqiradi

## Barqarorlik (kengaytirilgan)

OmniRoute vaqtinchalik nosozliklarga qarshi uchta mustaqil mexanizmni taqdim etadi; quyidagi boshqaruv endpointlari operatorlarga ularning holatini ko‘rish va sozlamalarini almashtirish imkonini beradi:

| Qamrov                   | Holat saqlanadigan joy                       | Ko‘rish                                   | Qayta o‘rnatish / tozalash                                                    |
| ------------------------ | -------------------------------------------- | ----------------------------------------- | ----------------------------------------------------------------------------- |
| Provayder uzgichi        | `domain_circuit_breakers` + tezkor xotira    | `/api/monitoring/health`                  | `POST /api/resilience/reset`                                                  |
| Ulanishning kutish davri | Provayder ulanishlaridagi `rateLimitedUntil` | `/api/rate-limits`, `/api/providers/[id]` | (zarurat bo‘lganda qayta yoqiladi; provayderning PUT so‘rovi orqali tozalang) |
| Model blokirovkasi       | Tezkor xotiradagi model mavjudligi reyestri  | `GET /api/resilience/model-cooldowns`     | `DELETE /api/resilience/model-cooldowns`                                      |

`PATCH /api/resilience` provayder uzgichi uchun almashtiruvchi sozlamalarni `providerBreaker.oauth` va `providerBreaker.apikey` ichida qabul qiladi. Har bir profil `degradationThreshold`, `failureThreshold` va `resetTimeoutMs` parametrlarini qo‘llab-quvvatlaydi; ayni maydonlar Boshqaruv paneli → Sozlamalar → Barqarorlik bo‘limida ham mavjud.

```bash
# Bitta model blokirovkasini tozalash
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{"provider":"openai","model":"gpt-4o-mini"}'

# Barcha blokirovkalarni o‘chirish
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -d '{"all":true}'
```

To‘liq konseptual ma’lumotnoma va uzgichning standart sozlamalari uchun [`CLAUDE.md`](../../CLAUDE.md) → "Barqarorlikning bajarilish vaqtidagi holati" va [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md) hujjatlariga qarang.

### Chastota chegarasi navbati va avtomatik yoqish himoya mexanizmi

- **Qo‘llab-quvvatlanadigan yozish yo‘li**: `POST /api/rate-limits` va `{"connectionId": "<id>", "enabled": true|false}` tanasi ulanish uchun chastota chegarasi himoyasini yoqish yoki o‘chirishga mo‘ljallangan boshqaruv endpointidir. `PUT /api/providers/[id]` ataylab `rateLimitProtection` qiymatini o‘zgartirmaydi yoki almashtirmaydi (#11278).
- **`enabled: false` semantikasi**: `enabled: false` qiymatini o‘rnatish ulanish uchun aniq belgilangan himoyani olib tashlaydi, ammo faol API kalitli ulanishni global avtomatik yoqish himoya mexanizmidan (`autoEnableApiKeyProviders = true`) **chiqarmaydi**. `reconcileEnabledConnections` (`open-sse/services/rateLimitManager.ts`) ichida `false` va `undefined` teng hisoblanadi; aniq belgilangan himoyasiz faol API kalitli ulanishlar avtomatik yoqish himoya mexanizmi doirasida himoyalangan holda qoladi.
- **Global o‘chirish**: API kalitli ulanishlarni chastota chegarasi navbatlarisiz ishlatish uchun himoya mexanizmini `RATE_LIMIT_AUTO_ENABLE=false` (muhit o‘zgaruvchisi) yoki `resilienceSettings.requestQueue.autoEnableApiKeyProviders = false` (Sozlamalar → Barqarorlik / `PATCH /api/resilience`) orqali global darajada o‘chiring.

## A2A serveri

OmniRoute tekshirish/boshqaruv panelida foydalanish uchun REST o‘ramasi bilan birga A2A (agentdan agentga) JSON-RPC 2.0 yakuniy nuqtasini taqdim etadi.

### JSON-RPC

```bash
POST /a2a
Authorization: Bearer your-api-key   # OMNIROUTE_API_KEY o‘rnatilmagan bo‘lsa, ixtiyoriy
Content-Type: application/json

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "message/send",
  "params": {
    "skill": "smart-routing",
    "messages": [{"role": "user", "content": "Route this coding task"}]
  }
}
```

Qo‘llab-quvvatlanadigan metodlar (barchasi `settings.a2aEnabled` orqali boshqariladi):

| Metod            | Tavsif                                                               |
| ---------------- | -------------------------------------------------------------------- |
| `message/send`   | Ko‘nikmani sinxron bajarish; `{task, artifacts, metadata}` qaytaradi |
| `message/stream` | Xuddi shu ko‘nikmalar to‘plamini SSE orqali oqimli bajarish          |
| `tasks/get`      | Vazifani `taskId` bo‘yicha olish                                     |
| `tasks/cancel`   | Vazifani `taskId` bo‘yicha bekor qilish                              |

Ichki ko‘nikmalar: `smart-routing`, `quota-management`, `provider-discovery`, `cost-analysis`, `health-report`.

### Agent kartasi

```bash
GET /.well-known/agent.json
```

Ommaviy A2A agent kartasini (nomi, tavsifi, imkoniyatlari, ko‘nikmalar katalogi, autentifikatsiya sxemasi) qaytaradi — ommaviy tarzda 1 soatga keshlanadi. Autentifikatsiya talab qilinmaydi.

### REST yordamchilari

| Metod | Yo‘l                         | Tavsif                                                                                                                  |
| ----- | ---------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| GET   | `/api/a2a/status`            | A2A yoqilganligi + vazifalar statistikasi + keshlangan agent kartasi xulosasi                                           |
| GET   | `/api/a2a/tasks`             | Vazifalar ro‘yxati — `?state=submitted\|working\|completed\|failed\|cancelled`, `?skill=`, `?limit=` (≤200), `?offset=` |
| POST  | `/api/a2a/tasks`             | (REST yordamchisi sifatida amalga oshirilmagan — JSON-RPC `message/send` orqali yarating)                               |

| POST  | `/api/a2a/tasks/[id]/cancel` | Vazifani bekor qilish                                                                                                   |

**Autentifikatsiya:** REST yordamchilari boshqaruv autentifikatsiyasisiz ishlaydi (boshqaruv paneli orqali o‘qish mumkin); JSON-RPC `/a2a` yo‘nalishi sozlangan bo‘lsa, Bearer `OMNIROUTE_API_KEY` dan foydalanadi.

## Autentifikatsiya

To‘rtta hisob ma’lumotlari oilasi (boshqaruv paneli seansi, mahalliy CLI tokeni, `oma_live_…` kirish tokeni, boshqaruv doirasidagi API kaliti) va ularning inferensiya kalitlaridan qanday farq qilishi haqida [Boshqaruv autentifikatsiyasi](../guides/MANAGEMENT-AUTH.md) qo‘llanmasiga qarang.

- Boshqaruv paneli marshrutlari (`/dashboard/*`) `auth_token` cookie-faylidan foydalanadi
- Tizimga kirishda saqlangan parol xeshidan foydalaniladi; aks holda `INITIAL_PASSWORD` ishlatiladi
- `requireLogin` sozlamasini `/api/settings/require-login` orqali yoqish yoki o‘chirish mumkin
- `REQUIRE_API_KEY=true` bo‘lganda, `/v1/*` marshrutlari ixtiyoriy ravishda Bearer API kalitini talab qiladi
- Ushbu ma’lumotnomadagi "boshqaruv tokeni" / "boshqaruv doirasidagi API kaliti" iboralari qo‘llanmada ko‘rsatilgan oilalardan birini anglatadi — alohida, ta’riflanmagan maxfiy ma’lumot turini emas

> **Moslikni buzuvchi o‘zgarish (v3.8.0)** — `/api/v1/agents/tasks/*` va kutish muddatini boshqarish endpointlari endi **boshqaruv autentifikatsiyasini** (boshqaruv panelining `auth_token` cookie-fayli yoki boshqaruv doirasidagi API kaliti) talab qiladi. Ilgari ushbu marshrutlarga autentifikatsiyasiz murojaat qilgan mijozlar `401 Unauthorized` javobini oladi. `588a0333` kommitiga qarang (`fix(auth): require management auth for agent and cooldown APIs`).
