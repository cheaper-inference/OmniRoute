Web Cookie provayderlari OmniRoute’ga API kaliti o‘rniga mavjud brauzer seansingiz orqali AI xizmatidan foydalanish imkonini beradi. Ular veb-sayt orqali xizmatga kirish huquqiga ega bo‘lganingizda va OmniRoute ham ayni autentifikatsiyadan o‘tgan seansdan foydalanishini xohlaganingizda foydalidir.

API kaliti asosidagi provayderlardan farqli ravishda, Web Cookie provayderlari brauzeringiz veb-saytga yuboradigan hisob ma’lumotlari yordamida autentifikatsiyadan o‘tadi.

---

# Boshlashdan oldin

> **Muhim:** Hisob ma’lumotlarini har doim brauzeringizning cookie saqlash joyidan **emas**, balki **jonli tarmoq so‘rovidan** nusxalang.

Ko‘plab autentifikatsiya muammolari cookie fayllarini noto‘g‘ri joydan nusxalash tufayli yuzaga keladi.

## Cookie saqlash joyidan nusxalamang

Aksariyat brauzerlar saqlangan cookie fayllarini quyidagi joyda ko‘rsatadi:

```
DevTools
→ Application (yoki Storage)
→ Cookies
```

Bu cookie fayllari to‘g‘ri ko‘rinsa ham, ular quyidagicha bo‘lishi mumkin:

- eskirgan
- to‘liq bo‘lmagan
- faqat autentifikatsiyadan o‘tgan so‘rovlarda yuboriladigan cookie fayllari mavjud bo‘lmagan

Bu qiymatlardan foydalanish, hatto ular yaroqli ko‘rinsa ham, autentifikatsiya xatolariga olib kelishi mumkin.

## Jonli so‘rovdan nusxalang

Buning o‘rniga muvaffaqiyatli so‘rovdagi cookie fayllaridan foydalaning:

```
DevTools
→ Network
→ Sahifani yangilang
→ Chat yoki suhbat so‘rovini oching
→ Request Headers
→ Cookie
```

`Cookie` so‘rov sarlavhasi brauzeringiz muvaffaqiyatli ishlatgan aniq autentifikatsiya ma’lumotlarini o‘z ichiga oladi.

Aksariyat Web Cookie provayderlari uchun OmniRoute’ga aynan shu qiymatni kiritish kerak.

---

# Umumiy sozlash

Sozlash jarayoni aksariyat Web Cookie provayderlari uchun bir xil.

1. Provayder veb-saytiga kiring.
2. Brauzerning dasturchi vositalarini oching.
3. **Network** yorlig‘ini oching.
4. Sahifani yangilang.
5. Autentifikatsiyadan o‘tgan chat yoki suhbat so‘rovini oching.
6. Kerakli autentifikatsiya hisob ma’lumotlarini nusxalang.
7. OmniRoute’ni oching.
8. **Providers → Add Provider** bo‘limiga o‘ting.
9. Web Cookie provayderingizni tanlang.
10. Hisob ma’lumotlarini kiriting.
11. **Test Connection** tugmasini bosing.
12. Provayderni saqlang.

Talab qilinadigan aniq hisob ma’lumotlari provayderga bog‘liq.

## NoTrack (notrack-web)

NoTrack ([notrack.ai](https://notrack.ai)) — roʻyxatdan oʻtishni talab qilmaydigan bepul foydalanuvchi chat platformasi. Seans birinchi tashrifda anonim tarzda yaratiladi va uchta cookie orqali saqlanadi: `uid`, `si_usr_id` va `si_ses_id`. OmniRoute ayni `/api/dispatch` endpointini bitta model identifikatori (`notrack-c`, taxallusi `ntw`) orqali proksi qiladi.

### Ulanish bosqichlari

1. Brauzeringizda [notrack.ai](https://notrack.ai) saytini oching va anonim seans cookie fayli oʻrnatilishiga ruxsat bering.
2. **Dasturchi vositalari → Tarmoq** boʻlimini oching, sahifani yangilang va istalgan `/api` soʻrovini bosing.
3. **Soʻrov sarlavhalari** boʻlimidan toʻliq `Cookie` sarlavhasi qiymatini nusxalang.
4. OmniRoute ichida **Provayderlar → Provayder qoʻshish → NoTrack Web (Bepul)** boʻlimiga oʻting.
5. Cookie satrini `apiKey` maydoniga joylashtiring va **Saqlash** tugmasini bosing.

OmniRoute joylashtirilgan satrdan `uid`, `si_usr_id` va `si_ses_id` qiymatlarini ajratib oladi hamda faqat shu juftliklardan iborat toza `Cookie` sarlavhasini qayta yaratadi. Agar mavjud boʻlsa, unga tizimga kirgan hisoblar uchun oʻrnatiladigan `nt_session` (`ntk_…` tokeni) ham qoʻshiladi. Agar uchta qiymatdan birortasi mavjud boʻlmasa, operatorlar muqobil shakllarni sinab koʻrishi uchun joylashtirilgan xom satr oʻzgartirilmasdan uzatiladi.

### Model identifikatorlari

| Model identifikatori | Koʻrsatiladigan nom | Izohlar                                                              |
| -------------------- | ------------------- | -------------------------------------------------------------------- |
| `notrack-c`          | NoTrack C           | Standart — yuqori oqimdagi dispetcherlik modeli `C`.                 |
| `C`                  | NoTrack C           | `notrack-c` uchun taxallus (yuqori oqimdagi xom dispetcherlik kodi). |
| `notrack`            | NoTrack C           | `notrack-c` uchun taxallus.                                          |
| `ntw`                | NoTrack C           | `notrack-c` uchun qisqa taxallus.                                    |

Barcha toʻrtta model identifikatori bir xil yuqori oqimdagi dispetcherlik modeliga (`C`) mos keladi.

### Soʻrov parametrlari

Ijrochi soʻrov tanasidagi quyidagi ixtiyoriy maydonlarni qabul qiladi:

| Tana maydoni          | Standart qiymat | Maqsadi                                                                                           |
| --------------------- | --------------- | ------------------------------------------------------------------------------------------------- |
| `notrack_mode`        | `usual`         | Dispetcherlik rejimi (ixtiyoriy shakldagi satr; yuqori oqim `usual`, … qiymatlarini qabul qiladi) |
| `notrack_max_turns`   | `6`             | Yuqori oqim javob berishdan oldin bajarishi mumkin boʻlgan ichki navbatlar soni.                  |
| `notrack_chat_id`     | `null`          | Mavjud yuqori oqim chatini davom ettirish (yangi chat uchun kiritmang).                           |
| `notrack_attachments` | `[]`            | Yuqori oqim biriktirma deskriptorlarining oʻzgartirilmasdan uzatiladigan massivi.                 |
| `notrack_regenerate`  | `false`         | Oldingi navbat uchun javobni qayta yaratishni soʻrash maqsadida `true` qilib belgilang.           |

### Imkoniyatlar

- **Oqimli va oqimsiz** chat yakunlashlari.
- **Vositalarni chaqirish** — soʻrovda `tools: [...]` ni belgilang; ijrochi ularni vosita chaqiruvi konverti shartnomasiga muvofiq ketma-ketlashtiradi va model javoblarini qayta OpenAI `tool_calls` formatiga tahlil qiladi.
- **`response_format`** — `json_object` va `json_schema` qoʻllab-quvvatlanadi. Ijrochi model javobidan birinchi JSON obyektini ajratib oladi va qaytarishdan oldin uni satrga aylantiradi.
- **Mulohaza ishorasi** — yuqori oqim `thinking` hodisasini yuborganda, ijrochi `reasoning` deltasini chiqaradi.

### Cheklovlar

- Yuqori oqim anonim foydalanish kvotalarini qoʻllaydi — limitga yetilganda, ijrochi tushunarli xabar bilan 429 xatosini qaytaradi.
- Barcha model identifikatorlari bir xil yuqori oqimdagi dispetcherlik modeliga mos keladi; har bir model uchun alohida almashtirish imkoniyati mavjud emas.
- Ijrochi yuqori oqimning `/api/chats` endpointini chaqirmaydi, shu sababli chat tarixi va seanslar avtomatik tarzda boshqarilmaydi. Mavjud yuqori oqim chatini davom ettirish uchun `notrack_chat_id` dan foydalaning.

# Veb-cookie provayderlari nimalarni qila oladi va nimalarni qila olmaydi

Veb-cookie provayderlari veb-saytning chat interfeysidan qayta foydalanadi. Ular rasmiy APIlar bilan bir xil imkoniyatlarni **taqdim etmaydi**.

## Qoʻllab-quvvatlanadi

- Mavjud brauzer seansingiz orqali autentifikatsiya qilish
- Hisobingiz orqali mavjud modellardan foydalanish
- Chat javoblarini oqim tarzida olish
- API kaliti talab qilinmaydi

## Qoʻllab-quvvatlanmaydi

- Funksiyalarni chaqirish
- Vositalarni chaqirish
- Fayllarni avtomatik tahrirlash
- Agentga asoslangan IDE ish jarayonlari
- Faqat API orqali mavjud funksiyalar

Bu kutilgan xatti-harakat va **xato emas**.

Agar sizga vositalarni ishga tushirish, fayllarni avtomatik tahrirlash yoki boshqa agent ish jarayonlari kerak boʻlsa, Web Cookie provayderi oʻrniga **API kaliti provayderidan** foydalaning.

---

# Tekshiruvga oid ogohlantirish

Muvaffaqiyatli **Ulanishni sinash** yoki cookie faylini tekshirish faqat taqdim etilgan hisob maʼlumotlari kutilgan formatda ekanini tasdiqlaydi.

#7857 muammosi hal etilmaguncha, muvaffaqiyatli tekshiruv provayder autentifikatsiyadan muvaffaqiyatli oʻtishini **kafolatlamaydi**.

Agar autentifikatsiya hali ham muvaffaqiyatsiz boʻlsa, hisob maʼlumotlarini brauzerning cookie saqlash joyidan emas, balki faol tarmoq soʻrovidan nusxalaganingizni tekshiring.


## Cookie brauzerda ishlaydi, ammo OmniRoute’da ishlamaydi

Baʼzi provayderlar faqat autentifikatsiyalangan soʻrovlar vaqtida yuboriladigan cookie fayllarini oʻz ichiga oladi.

Suhbatni muvaffaqiyatli ochganingizdan soʻng, hisob maʼlumotlarini yangi tarmoq soʻrovidan qayta nusxalang.

---

## Seans muddati tugagan

Web Cookie provayderlari mavjud brauzer seansingizdan foydalanadi.

Agar brauzer seansingiz muddati tugasa yoki tizimdan chiqsangiz, yangi hisob maʼlumotlari toʻplamini nusxalashingiz kerak. Qoʻllab-quvvatlanadigan veb-provayderlar uchun cookie fayllarini yangilashni avtomatlashtirish maqsadida [Brauzer seansini sinxronlash kengaytmasi](../guides/SESSION-SYNC-EXTENSION.md) yordamchi vositasiga qarang.

---

## Ulanish sinovi muvaffaqiyatli, ammo soʻrovlar bajarilmaydi

#7857 muammosi hal etilmaguncha, tekshiruvdan oʻtish autentifikatsiya soʻrovi muvaffaqiyatli boʻlishini kafolatlamaydi.

Muammoni qoʻshimcha tekshirishdan oldin hisob maʼlumotlaringizni yangi autentifikatsiyalangan soʻrovdan qayta nusxalang.

---

## ChatGPT Web "Unsupported ChatGPT integrity dependency" xatosi bilan ishlamaydi

```
[502] ChatGPT Web first-party bridge module failed to load:
pageerror: Unsupported ChatGPT integrity dependency: DD
```

Hisob maʼlumotlari toʻgʻri — bu xato seansdan emas, koʻprik modulidan kelib chiqadi. chatgpt.com har bir joylashtirish uchun modul identifikatorlarini belgilaydi, koʻprik esa avval oʻzi yaratadigan Sentinel yordamchisining identifikatorini qatʼiy belgilab qoʻyardi. Shu sababli yordamchi nomini oʻzgartirgan chatgpt.com qayta qurilishi cookie yaroqli boʻlib qolganiga qaramay, har bir murojaatni buzdi. Ulanishni qayta avtorizatsiya qilish buni tuzata olmaydi.

Modulni sahifaning oʻz ish vaqti muhiti orqali aniqlaydigan buildlar hech qanday identifikatorni qatʼiy belgilamaydi va bu muammoga duch kelmaydi. Agar ushbu xatoni koʻrsangiz, OmniRoute’ni yangilang va ulanish tekshiruvini qayta ishga tushiring.

- Funksiyalarni chaqirish yoki agent ish jarayonlari kerak boʻlganda API kaliti provayderlaridan foydalaning.
