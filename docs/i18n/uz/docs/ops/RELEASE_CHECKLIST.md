## npm Trusted Publishing (3.8.51 dan beri birlamchi) — so‘rov bo‘yicha sahnalashtiriladi, to‘g‘ridan-to‘g‘ri zaxira sifatida

`npm-publish.yml` orqali nashr etadi** npm ishonchli nashriyot (OIDC)** sukut bo'yicha: `stage-npm` ishi (github-hostlangan) GitHub id-tokenini o'sha ishga tushirish uchun qisqa muddatli npm hisob ma'lumotlariga almashtiradi —, ombor sirlarida uzoq muddatli npm tokeni yo'q, 2FA so'rovi, kelib chiqishi biriktirilmagan. Bu npm sanktsiyalarini chetlab o'tish, endi 2FAni o'tkazib yuboradigan tokenlar bekor qilinmoqda; u WS1.3 kafolatini saqlagan holda loyihaning v3.8.48gacha bo'lgan to'liq avtomatik oqimini tiklaydi (sizib ketgan token yolg'iz nashr eta olmaydi — hech qanday token yo'q).

**Bir martalik sozlash (egasi):** npmjs.com → paketi `omniroute` → Sozlamalar → _Ishonchli nashriyot_ → GitHub: egasi `diegosouzapw`, repo `OmniRoute`, ish jarayoni `npm-publish.yml` (atrof-muhit: yo‘q). Bu mavjud bo'lgunga qadar, avtomatik qadam `ENEEDAUTH` bilan bajarilmaydi: `publish_mode=staged` (pastda) yoki `direct` bilan qayta yuborish.

### Bosqichli nashr (so'rov bo'yicha — `publish_mode=staged`)

Npm-publish ish jarayoni endi to'g'ridan-to'g'ri nashr etmaydi: u to'plangan tarballni (`check:pack-boot`) ishga tushiradi va keyin `npm stage publish` — ishga tushiradi, aniq baytlar ro'yxatga olish kitobida saqlanadi,** o'rnatib bo'lmaydi** egasi ma'qullamaguncha. Insonning 2FA darvozasi undan oldin emas, balki isbotni AFTER ga ko'chdi.

**Ish oqimi yashil rangga o'tgandan so'ng ega oqimi:**

1. `npm stage list omniroute` — bosqich identifikatorini toping (ish jarayonining xulosasida ham chop etilgan).
2. Bosqichli baytlarni tekshiring (tavsiya etiladi): `npm stage download <id>`, keyin yuklab olingan tarballni vaqtinchalik prefiksga o'rnating va uni yuklang (`npm run check:pack-boot` bir xil paketni avtomatlashtiradi → o'rnatish → yuklash hukmini CI da).
3. `npm stage approve <id>` — 2FA IS nashrni taklif qiladi. `npm stage reject <id>` bekor qiladi.
4. Nashrdan keyingi tarmoq: nashrdan keyingi tekshiruvchi (v3.8.49 rejasining WS1.4) nashr etilgan versiyani umumiy registrdan toza konteynerga o'rnatadi va uni ishga tushiradi.

**Favqulodda vaziyatni qaytarish:** `publish_mode=direct` bilan `workflow_dispatch` `npm publish` merosini darhol tiklaydi (faqat sahnalashning o'zi noto'g'ri ishlayotgan bo'lsa foydalaning; sababini yozib oling).

**Bir martalik qattiqlashuv (egasi, npmjs.com):** Ishonchli nashriyotni `omniroute` uchun faqat bosqichli rejimda sozlang, shuning uchun sizib chiqqan uzoq muddatli token istalgan joydan to'g'ridan-to'g'ri `npm publish` — CI faqat sahnalashtira olmaydi; faqat egasining 2FA relizlari.

**Buzilgan artefakt o'yin kitobi (o'zgarmagan):** standart refleks sifatida `npm deprecate omniroute@<bad> "<reason> — use <fixed>"` (daqiqa, qaytariladigan); `npm unpublish` faqat 72h/no-dependents oynasida va hech qachon birinchi harakat sifatida. Docker: versiya tegini hech qachon qayta yozmang — ortga qaytarish `latest` oxirgi yaxshi dayjestga qayta ishora qiladi.

**Docker Hub `latest` (har bir barqaror SemVer nashrida talab qilinadi):** `docker-publish` ish jarayoni tegi kerak** ikkalasi ham** `X.Y.Z` va agar `should-promote-latest.sh` mos kelsa, bu eng yuqori barqaror SemVer, `:latest` bilan** bir xil hazm qilish** . Ishdan so'ng: Hub `latest` dayjest yangi SemVer dayjestiga teng va `last_updated` ko'chirildi. Chiqarilgan yozuvlar faqat git-da mavjud tuzatishlar haqida gapirganda, `:latest` eski versiyada qoldirmang. Tezkor ishga tushirishni yaratish `:latest` dan foydalaning; GitOps `X.Y.Z` ni mahkamlashda davom etishi kerak. [Docker chiqarish kanallari](../guides/DOCKER_GUIDE.md#release-channels) va #10317 qarang.

**Docker Hub organization repository (`cheaperinference/omniroute`):** Docker Hub cannot move a repository between namespaces, so `diegosouzapw/omniroute` keeps its pull history and every release, and the `mirror-org-dockerhub` job of `docker-publish` copies each released version (and `:latest` when promoted) from `ghcr.io/cheaper-inference/omniroute` to the organization repository. It needs the `DOCKERHUB_ORG_USERNAME` / `DOCKERHUB_ORG_TOKEN` secrets; without them the job stays green with a "Docker Hub org mirror skipped" warning and the other registries publish normally. To publish a released version there later, run **Actions → Mirror Docker image to the Docker Hub org → Run workflow** with `version=X.Y.Z` (and `promote_latest` for the highest stable version): it copies the existing images, no rebuild.

## Hotfix tezkor yoʻlagi (`hotfix` yorligʻi)

`hotfix` yorligʻi qoʻyilgan PR ogʻir CI matritsasini (9-shard E2E, qamrov ratcheti,
quality-gate, quality-extended) oʻtkazib yuboradi va tezkor, yuqori signal beruvchi tekshiruvlarni saqlab qoladi: build,
unit shardlari, integration, vitest, lint/typecheck, docs-sync, `check:pack-artifact`
va tarball ishga tushish smoke-testi (`check:pack-boot`). Maqsad: ~33 daqiqa oʻrniga ≤15 daqiqada yashil holatga erishish.

**Kirish siyosati — toʻrttalasi ham majburiy (Chromium/VS Code/Node favqulodda yoʻlaklari asosida modellashtirilgan):**

1. **Jiddiylik**: production buzilgan — eʼlon qilingan artefakt ishga tushishda qulaydi /
   xavfsizlik tuzatishi / relizning har bir foydalanuvchisiga taʼsir qiladi. «Muhim» degani «buzilgan» degani emas.
2. **Vakolat**: `hotfix` yorligʻini faqat repository egasi qoʻllaydi. Yorliqning OʻZI
   tasdiq hisoblanadi — campaign PR uchun uni hech qachon oʻzingiz qoʻymang.
3. **Dalil**: PR tavsifi avvalgi toʻliq yashil ogʻir ishga tushirishga (oʻtkazib yuborilgan
   joblar qayta tekshirishi kerak boʻlgan suite) hamda tuzatishning avval muvaffaqiyatsiz, soʻng muvaffaqiyatli oʻtgan testiga havola beradi.
4. **Koʻlam**: faqat cherry-pick — minimal tuzatish, refactorlarsiz, qoʻshimcha oʻzgarishlarsiz.

Oʻtkazib yuborilgan qamrov/ratchet yuzasi release branchdagi keyingi toʻliq ishga tushirish
(uzluksiz release-green) orqali qayta tekshiriladi — yoʻlak tekshiruvni emas, faqat KUTISHNI oʻtkazib yuboradi.
Faqat testlarga oid difflar (barcha fayllar `tests/` ichida, hech biri `tests/e2e/` ichida emas) E2E
matritsasini hech qanday yorliqsiz avtomatik ravishda oʻtkazib yuboradi.

### Build Layout

Repozitoriy uchta alohida chiqish katalogidan foydalanadi — ularni hech qachon aralashtirmaydi:

| Katalog   | Maqsad                                                                | Kuzatildimi? |
| --------- | --------------------------------------------------------------------- | ------------ |
| `src/`    | Ilova manbasi (TypeScript / TSX)                                      | Ha           |
| `.build/` | Oraliq — `next build` chiqishi (`distDir`) yaratish                   | Yo'q (yo'q)  |
| `dist/`   | Yuboriladigan npm toʻplami — `assembleStandalone` tomonidan yigʻilgan | Yo'q (yo'q)  |

> **Operator eslatmasi:** masofaviy VPS tasvir katalogi `/usr/lib/node_modules/omniroute/app/` bo'lib qoladi. Faqat** in-repo** ishlab chiqarish ko'chirildi (`app/` → `dist/`). Joylashtirish ko'nikmalari `dist/` tarkibini masofaviy `app/` dir — ichiga rsync VPS yo'lini o'zgartirishni talab qilmaydi.

**Yagona qurilish oqimi:**

```
npm run build:release
  └─ rm -rf .build dist          (clean)
  └─ next build → .build/next/   (intermediates)
  └─ assembleStandalone          (copies standalone + static + public + natives → dist/)
  └─ writes dist/BUILD_SHA       (HEAD sentinel)
```

Do NOT run `npm run build` keyin alohida `npm run build:cli` — joylashtirish uchun `npm run build:release` foydalaning, qaysi bir buyruqda toza qayta + sentinel qiladi.

### Quruq yugurish (faqat o'qish uchun, istalgan vaqtda xavfsiz)

```bash
npm run release:dry-run-lts-cut                       # the real cut: 3.9.0 from HEAD, previous tag v3.8.59
npm run release:dry-run-lts-cut -- --from <3.9.0-tip> # pin the source commit
```

`scripts/release/dry-run-lts-cut.mjs` executes nothing: it reads git and `gh` and prints the whole sequence — preconditions (source resolves, the source repository has full history — a shallow clone cannot push `stable/v3`, the receiving side rejects the pack at the first grafted parent, so cut from a full clone or `git fetch --unshallow origin` first — previous tag exists, `package.json` is the target version, a `release-freeze` issue is open, no open `Release branch not green` issue on an existing release branch — a branch that does not exist reports `?` unknown, never green — omni-queue lands the release PRs (G11: `config/merge-queue/config.json` valid, its `bases` manage the release branch, `mode` `live`, its label exists), the `release/*` ruleset still blocks deletion and force-push, and `stable/v3` and `develop` do not exist yet), the two branch steps, which dormant-workflow triggers and `if:` conditions turn true (and which stay gated by a repository variable or pinned to the canonical repository), the expected dist-tags (`latest` → 3.9.0, `next` and `nightly` empty) and the rollback. Exit `0` = `RESULT: READY`, `1` = a blocking precondition failed (`✗`), `2` = usage error. `--advisory <id,...>` downgrades a check to a warning (`!`) without hiding it.

3.9.0 versiyasidagi muzlatish hali ochiq bo'lganda haqiqiy kesishning quruq ishlashini bajaring — novdalar tegdan keyin va 12c fazasi muzlashni ko'tarishdan oldin yaratiladi.

### 3.8.58 Repetitsiya (faqat vilkalar)

  --advisory freeze,base-green

#    repository, is refused; every step asks for confirmation on the terminal)
