## 1. Texnologiyalar toʻplami

| Yoʻnalish           | Tanlov                                                                                                                                 |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| Veb-freymvork       | **Next.js 16** (App Router, mustaqil chiqish, global middleware yoʻq)                                                                  |
| Dasturlash tili     | **TypeScript 6.0+** — maqsad `ES2022`, `module: esnext`, `moduleResolution: bundler`, `strict: false`                                  |
| Ishlash muhiti      | **Node.js** `>=22.22.2 <23` yoki `>=24.0.0 <27` (`engines` + `SUPPORTED_NODE_RANGE` orqali majburiy belgilanadi)                       |
| Maʼlumotlar bazasi  | `better-sqlite3` orqali **SQLite** (singleton, WAL jurnallash)                                                                         |
| Ish stoli           | **Electron 41** + `electron-builder` 26.10 (`electron/` ichidagi alohida ish maydoni)                                                  |
| Testlar             | **Node mahalliy test ishga tushirgichi** (modul/integratsiya), **Vitest** (MCP, autoCombo, kesh), **Playwright** (e2e + protocols-e2e) |
| Yigʻish             | `scripts/build/build-next-isolated.mjs` orqali Next.js mustaqil yigʻilishi                                                             |
| Lint/formatlash     | ESLint tekis konfiguratsiyasi + Prettier (Husky pre-commit orqali `lint-staged`)                                                       |
| Modul tizimi        | Hamma joyda ESM (`"type": "module"`)                                                                                                   |
| Boshqaruv paneli UI | **Tailwind CSS 4** + loyihaga qoʻshilgan **Keak CI UI Kit** (`packages/ui-kit`), Lucide ikonkalari — `DESIGN_SYSTEM.md` fayliga qarang |
| Ish maydonlari      | npm ish maydonlari — `open-sse`, `packages/browser-pool`, `packages/ui-kit`                                                            |

Yoʻl taxalluslari (`tsconfig.json`):

- `@/*` → `src/*`
- `@omniroute/open-sse` → `open-sse/index.ts`
- `@omniroute/open-sse/*` → `open-sse/*`
- `@omniroute/ui-kit` → `packages/ui-kit/src`, `@omniroute/ui-kit/*` → `packages/ui-kit/src/*`

Standart HTTP porti: **`20128`** (API va boshqaruv paneli bir xil jarayondan foydalanadi). Maʼlumotlar
katalogi — `DATA_DIR` muhit oʻzgaruvchisi, standart qiymati `~/.omniroute/`.

## 11. Qoidalar

- **Kod uslubi**: 2 boʻsh joyli chekinish, qoʻshtirnoqlar, 100 belgilik kenglik, nuqtali vergullar,
  `es5` yakuniy vergullari — `lint-staged` orqali Prettier tomonidan taʼminlanadi.
- **Importlar**: tashqi → ichki (`@/`, `@omniroute/open-sse`) → nisbiy.
- **Nomlash**: fayllar `camelCase` yoki `kebab-case`, komponentlar `PascalCase`,
  konstantalar `UPPER_SNAKE`.
- **ESLint**: `no-eval`, `no-implied-eval`, `no-new-func` = hamma joyda `error`;
  `no-explicit-any` = `open-sse/` va `tests/` ichida `warn`, boshqa joylarda `error`.
- **TypeScript**: `strict: false` (eski yondashuv). Modullararo chegaralarda
  tiplarni aniqlashdan koʻra aniq tiplarni afzal koʻring.
- **Maʼlumotlar bazasi**: marshrutlar yoki ishlov beruvchilarda hech qachon bevosita SQL yozmang — har doim
  `src/lib/db/` modullari orqali ishlang. Hech qachon barrel-import ishlatmang — muayyan `src/lib/db/*` modullaridan toʻgʻridan-toʻgʻri foydalaning.
- **DB obyektlarini tiplash (#3512)**: DB jadvalidagi satr tuzilmasini yozadigan yoki oʻqiydigan funksiya
  chaqiruv joyidagi `any` yoki ichki anonim tipni emas, balki shu jadval ustunlarini
  1:1 aks ettiradigan nomlangan TS interfeysini qabul qilishi/qaytarishi kerak. Interfeysni
  funksiya yonida joylashtiring (masalan, `src/lib/usage/usageHistory.ts` faylida
  `saveRequestUsage` ustidagi `export interface UsageEntry`), turli yozuvchilar satrni
  bosqichma-bosqich toʻldirganda alohida maydonlarni ixtiyoriy/null boʻlishi mumkin holatda saqlang
  va tuzilmasi chaqiruvchilar orasida farq qiladigan maydon uchun `any` oʻrniga
  `unknown` tipini afzal koʻring (maydonda hujjatlashtiring, masalan, `UsageEntry.tokens`
  ham provayderning xom shaklidagi foydalanish maʼlumotlarini, ham normallashtirilgan shaklni qabul qiladi).
  Shu yoʻl bilan fayldagi `any` soni nolga yetgach, uni
  `check:any-budget:t11` ruxsat etilganlar roʻyxatiga (`scripts/check/check-t11-any-budget.mjs`,
  `maxAny: 0`) qoʻshing, shunda ortga qaytishning oldi olinadi. Bu dastlabki qism uchun qoida —
  kengroq “anonim `any` ishlatmaslik” tozalash jarayoni kod bazasining qolgan qismida iterativ tarzda amalga oshiriladi.
- **Xatolar**: aniq xato turlari bilan try/catch ishlating, pino konteksti bilan jurnalga yozing. SSE oqimlaridagi
  xatolarni hech qachon jimgina yutib yubormang; tozalash uchun bekor qilish signallaridan foydalaning.
- **Xavfsizlik**: hech qachon `eval()` / `new Function()` / bilvosita eval ishlatmang. Barcha
  kirish maʼlumotlarini Zod bilan tekshiring. Hisob maʼlumotlarini saqlashda shifrlang (AES-256-GCM).
  `src/shared/constants/upstreamHeaders.ts` taqiqlanganlar roʻyxatini
  sanitizatsiya/tekshirish qatlami bilan mos holda saqlang.
- **Kommitlar**: Conventional Commits — `feat(scope): subject`. Ruxsat etilgan qamrovlar:
  `db`, `sse`, `oauth`, `dashboard`, `api`, `cli`, `docker`, `ci`, `mcp`,
  `a2a`, `memory`, `skills`.
- **Tarmoqlar**: prefikslar `feat/`, `fix/`, `refactor/`, `docs/`, `test/`,
  `chore/`. Hech qachon bevosita `main` tarmogʻiga kommit qilmang.
- **Husky**: kommitdan oldin `lint-staged` + `check:docs-sync` +
  `check:any-budget:t11` ishga tushadi; yuborishdan oldin `check:any-budget:t11` + `check:tracked-artifacts` ishga tushadi (tezkor tekshiruvlar; `test:unit` bundan mustasno).
