## 🎯 Foydalanish holatlari

### 1-holat: «Menda Claude Pro obunasi bor»

**Muammo:** Kvota ishlatilmay qolib ketadi, intensiv dasturlash vaqtida tezlik cheklovlariga duch kelinadi

```
Kombinatsiya: "maximize-claude"
  1. cc/claude-opus-4-7        (obunadan toʻliq foydalanish)
  2. glm/glm-4.7               (kvota tugaganda arzon zaxira)
  3. if/qwen3.8-max-preview       (favqulodda holat uchun bepul muqobil)

Oylik xarajat: $20 (obuna) + ~$5 (zaxira) = jami $25
$20 toʻlab, cheklovlarga duch kelish = hafsalasizlik
```

### 2-holat: «Xarajat nol boʻlishini xohlayman»

**Muammo:** Obunalarga imkonim yetmaydi, ishonchli AI yordamida dasturlash kerak

```
Kombinatsiya: "zero-cost"
  1. if/kimi-k2.7-code          (bepul kirish sifatida koʻrsatilgan; tezlik cheklovlari amal qilishi mumkin)
  2. kr/qwen3-coder-next        (Kiro bepul muqobili)

Oylik xarajat: $0
Sifat: ish yuklamangiz uchun model, cheklovlar, maxfiylik va SLA talablarini tekshiring
```

### 3-holat: «Uzilishlarsiz, 24/7 dasturlashim kerak»

**Muammo:** Muddatlar yaqin, toʻxtab qolishga yoʻl qoʻyib boʻlmaydi

```
Kombinatsiya: "always-on"
  1. cc/claude-opus-4-7        (eng yaxshi sifat)
  2. cx/gpt-5.5                (ikkinchi obuna)
  3. glm/glm-4.7               (arzon, har kuni yangilanadi)
  4. minimax/MiniMax-M2.1      (eng arzon, 5 soatda yangilanadi)
  5. if/deepseek-v4-flash       (bepul kirish sifatida koʻrsatilgan; tezlik cheklovlari amal qilishi mumkin)

Natija: 5 ta zaxira qatlam barqarorlikni oshiradi; yuqori darajadagi xizmatlar mavjudligi kafolatlanmaydi
Oylik xarajat: $20-200 (obunalar) + $10-20 (zaxira)
```

### 4-holat: «OpenClaw ichida BEPUL AI ishlatmoqchiman»

**Muammo:** Xabar almashish ilovalarida mutlaqo bepul AI yordamchisi kerak

```
Kombinatsiya: "openclaw-free"
  1. if/qwen3.8-max-preview     (bepul kirish sifatida koʻrsatilgan; tezlik cheklovlari amal qilishi mumkin)
  2. if/deepseek-v4-flash       (bepul kirish sifatida koʻrsatilgan; tezlik cheklovlari amal qilishi mumkin)
```

## 📖 Provayderni sozlash

CSV yoki JSON faylidan API kalit ulanishlarini ommaviy qoʻshish uchun **Boshqaruv paneli → Provayderlar → Fayldan import qilish** bandidan foydalaning. Ustunlar joylashuv tartibiga asoslanadi (`provider,name,apiKey,baseUrl,priority`); `provider` allaqachon boshqariladigan provayder yoki mos keluvchi tugun sifatida mavjud boʻlishi kerak. [Provayderlarni CSV yoki JSON faylidan import qilish](../providers/CSV-IMPORT.md) boʻlimiga qarang.

### 🔐 Obuna provayderlari

#### Claude Code (Pro/Max)

```bash
Boshqaruv paneli → Provayderlar → Claude Code’ni ulash
→ OAuth orqali kirish → Tokenni avtomatik yangilash
→ 5 soatlik + haftalik kvotani kuzatish

Modellar:
  cc/claude-opus-4-7
  cc/claude-sonnet-4-6
  cc/claude-haiku-4-5-20251001
```

**Professional maslahat:** Murakkab vazifalar uchun Opus’dan, tezlik uchun Sonnet’dan foydalaning. OmniRoute har bir model boʻyicha kvotani kuzatadi!

OmniRoute hostida brauzer yoʻqmi? Claude Code tizimiga kirilgan istalgan joyda `claude setup-token` buyrugʻini ishga tushiring va bir yillik tokenni **Setup Token** ichki oynasiga joylashtiring. [Claude Code’dan sozlash tokeni bilan foydalanish](../providers/CLAUDE_CODE_SETUP_TOKEN.md) boʻlimiga qarang.

Claude va Claude Code bilan mos keluvchi yoʻnalishlar Opus va Sonnet modellari uchun `max` fikrlash darajasini saqlab qoladi. Haiku modellari `max` darajasini qabul qilmaydi, shu sababli OmniRoute soʻrovni yuqori oqimga yuborishdan oldin uni yuqori fikrlash byudjetiga pasaytiradi.

#### OpenAI Codex (Plus/Pro)

```bash
Boshqaruv paneli → Provayderlar → Codex’ni ulash
→ OAuth orqali kirish (port 1455)
→ 5 soatlik + haftalik tiklanish

Modellar:
  cx/gpt-5.5
  cx/gpt-5.4
  cx/gpt-5.3-codex
  cx/gpt-5.3-codex-spark
```

#### GitHub Copilot

```bash
Boshqaruv paneli → Provayderlar → GitHub’ni ulash
→ GitHub orqali OAuth
→ Oylik tiklanish (har oyning 1-kuni)

Modellar:
  gh/gpt-5.5
  gh/gpt-5.4
  gh/claude-sonnet-4.6
  gh/claude-opus-4.7
  gh/gemini-3.1-pro-preview
```

### 💰 Arzon provayderlar

1. Roʻyxatdan oʻting: [Zhipu AI](https://open.bigmodel.cn)
2. Coding Plan’dan API kalitini oling
3. Boshqaruv paneli → API kalitini qoʻshish: Provayder: `glm`, API kaliti: `your-key`

**Foydalanish:** `glm/glm-4.7` — **Professional maslahat:** Coding Plan xarajatning 1/7 qismiga 3× kvota taklif qiladi! Har kuni soat 10:00 da tiklanadi.

#### Kimi K2 (Oyiga qatʼiy $9)

**Foydalanish:** `kimi/kimi-k2.5` — **Professional maslahat:** 10M token uchun oyiga qatʼiy $9 = amaldagi xarajat $0.90/1M!

**Foydalanish:** `qianfan/ernie-5.1`, `qianfan/ernie-x1.1` yoki OpenAI bilan mos keluvchi boshqa Qianfan model identifikatori.

## 🎨 Kombinatsiyalar

Har bir kartadagi tutqichni sudrab, kombinatsiya kartalarini bevosita **Boshqaruv paneli → Kombinatsiyalar** bo‘limida qayta tartiblashingiz mumkin. Tartib SQLiteʼda saqlanadi va qayta yuklanganda tiklanadi.

```
Boshqaruv paneli → Kombinatsiyalar → Yangisini yaratish

Nomi: premium-coding
Modellar:
  1. cc/claude-opus-4-7 (Asosiy obuna)
  2. glm/glm-4.7 (Arzon zaxira, $0.6/1M)
  3. minimax/MiniMax-M2.7 (Eng arzon oxirgi zaxira, $0.3/1M)

```

```
Nomi: free-combo
Modellar:
  1. if/kimi-k2.7-code (bepul kirish sifatida ko‘rsatilgan; provayder cheklovlari qo‘llanishi mumkin)
  2. kr/qwen3-coder-next (Kiro bepul zaxirasi)

Narxi: hozirda $0 deb ko‘rsatilgan; shartlar va mavjudlik o‘zgarishi mumkin
```

## 🚀 Joylashtirish

### Global npm o‘rnatilishi (Tavsiya etiladi)

```bash
npm install -g omniroute

# Konfiguratsiya katalogini yarating
mkdir -p ~/.omniroute

# .env faylini yarating (.env.example fayliga qarang)
cp .env.example ~/.omniroute/.env

# Serverni ishga tushiring
omniroute
# Yoki maxsus port bilan:
omniroute --port 3000
```

CLI `.env` faylini `~/.omniroute/.env` yoki `./.env` manzilidan avtomatik yuklaydi.

### Tizim treyi rejimi

OmniRouteʼni tizim treyida ishga tushiring:

```bash
omniroute serve --tray
```

Server va trey tayyor bo‘lgach, buyruq yakunlanadi.

Server terminalsiz ishlashda davom etadi.

Tizim treyi rejimi macOS, Windows va grafik Linux seanslarini qo‘llab-quvvatlaydi. Tizim treyi rejimi boshqaruv panelini avtomatik ochmaydi.

Quyidagi amallar uchun trey menyusidan foydalaning:

- Boshqaruv panelini ochish.
- `/dashboard/logs` sahifasini ochish.
- Avtomatik ishga tushirish sozlamasini o‘zgartirish.
- OmniRouteʼni to‘xtatish.

`--tray` parametrini quyidagi parametrlar bilan birga ishlatmang:

- `--daemon`
- `--log`
- `--no-recovery`

Bu rejimlar jarayonni boshqarishning turli usullarini talab qiladi.

Kompyuterga keyingi kirishda ishga tushirishni yoqing:

```bash
omniroute autostart enable
```

Avtomatik ishga tushirish macOS, Windows va grafik Linux seanslarida tizim treyi rejimidan foydalanadi. Grafik interfeyssiz Linux mavjud systemd foydalanuvchi xizmatidan foydalanadi.

Tizimga kirishda ishga tushirishni o‘chiring:

```bash
omniroute autostart disable
```

### O‘chirish

### Void Linux (xbps-src)

Void Linux foydalanuvchilari OmniRouteʼni `xbps-src` kross-kompilyatsiya freymvorki yordamida mahalliy paketlashi va oʻrnatishi mumkin. Bu talab qilinadigan `better-sqlite3` mahalliy bogʻlamalari bilan birga Node.js mustaqil yigʻilishini avtomatlashtiradi.

<summary><b>xbps-src shablonini koʻrish</b></summary>

```bash
# 'omniroute' uchun shablon fayli
pkgname=omniroute
version=3.8.0
revision=1
hostmakedepends="nodejs python3 make"
depends="openssl"
short_desc="Universal AI gateway with smart routing for multiple LLM providers"
maintainer="zenobit <zenobit@disroot.org>"
license="MIT"
homepage="https://github.com/diegosouzapw/OmniRoute"
distfiles="https://github.com/diegosouzapw/OmniRoute/archive/refs/tags/v${version}.tar.gz"
checksum=009400afee90a9f32599d8fe734145cfd84098140b7287990183dde45ae2245b
system_accounts="_omniroute"
omniroute_homedir="/var/lib/omniroute"
export NODE_ENV=production
export npm_config_engine_strict=false
export npm_config_loglevel=error
export npm_config_fund=false
export npm_config_audit=false

do_build() {
	# node-gyp uchun maqsadli CPU arxitekturasini aniqlash
	local _gyp_arch
	case "$XBPS_TARGET_MACHINE" in
		aarch64*) _gyp_arch=arm64 ;;
		armv7*|armv6*) _gyp_arch=arm ;;
		i686*) _gyp_arch=ia32 ;;
		*) _gyp_arch=x64 ;;
	esac

	# 1) Barcha bogʻliqliklarni oʻrnatish — skriptlarni oʻtkazib yuborish
	NODE_ENV=development npm ci --ignore-scripts

	# 2) Next.js mustaqil toʻplamini yigʻish
	npm run build

	# 3) Statik resurslarni mustaqil toʻplamga nusxalash
	cp -r .next/static .next/standalone/.next/static
	[ -d public ] && cp -r public .next/standalone/public || true

	# 4) better-sqlite3 mahalliy bogʻlamasini kompilyatsiya qilish
	local _node_gyp=/usr/lib/node_modules/npm/node_modules/node-gyp/bin/node-gyp.js
	(cd node_modules/better-sqlite3 && node "$_node_gyp" rebuild --arch="$_gyp_arch")

	# 5) Kompilyatsiya qilingan bogʻlamani mustaqil toʻplamga joylashtirish
	local _bs3_release=.next/standalone/node_modules/better-sqlite3/build/Release
	mkdir -p "$_bs3_release"
	cp node_modules/better-sqlite3/build/Release/better_sqlite3.node "$_bs3_release/"

	# 6) Arxitekturaga xos sharp toʻplamlarini olib tashlash
	rm -rf .next/standalone/node_modules/@img

	# 7) Next.js statik tahlili tashlab ketgan pino ish vaqti bogʻliqliklarini nusxalash:
	for _mod in pino-abstract-transport split2 process-warning; do
		cp -r "node_modules/$_mod" .next/standalone/node_modules/
	done
}

do_check() {
	npm run test:unit
}

do_install() {
	vmkdir usr/lib/omniroute/.next
	vcopy .next/standalone/. usr/lib/omniroute/.next/standalone

	# Oʻrnatishdan keyingi xuk bo‘sh Next.js ilova marshrutizatori kataloglarini olib tashlashining oldini olish
	for _d in \
		.next/standalone/.next/server/app/dashboard \
		.next/standalone/.next/server/app/dashboard/settings \
		.next/standalone/.next/server/app/dashboard/providers; do
		touch "${DESTDIR}/usr/lib/omniroute/${_d}/.keep"
	done

	cat > "${WRKDIR}/omniroute" <<'EOF'
#!/bin/sh
export PORT="${PORT:-20128}"
export DATA_DIR="${DATA_DIR:-${XDG_DATA_HOME:-${HOME}/.local/share}/omniroute}"
export APP_LOG_TO_FILE="${APP_LOG_TO_FILE:-false}"
mkdir -p "${DATA_DIR}"
exec node /usr/lib/omniroute/.next/standalone/server.js "$@"
EOF
	vbin "${WRKDIR}/omniroute"
}

post_install() {
	vlicense LICENSE
}
```

### Marshrutlash strategiyalari

orqali sozlang** Boshqaruv paneli → sozlamalari → Routing** . Boshqaruv paneli eng ko'p ishlatiladigan oltita strategiyani ochib beradi; kombinatsiyalar va avtomatik router ichki kengroq to'plamni qo'llab-quvvatlaydi.

**Boshqaruv panelida ko'rinadigan strategiyalar (hisob darajasidagi marshrutlash):**

| Strategiya                      | Tavsif                                                                                                                             |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| **Avval to'ldirish**            | Hisoblardan ustuvor tartibda foydalanadi - asosiy hisob mavjud bo'lmaguncha barcha so'rovlarni bajaradi                            |
| **Round Robin**                 | Sozlanishi mumkin bo'lgan yopishqoq chegara bilan barcha hisoblar bo'ylab aylanish (standart: har bir hisob uchun 3 ta qo'ng'iroq) |
| **P2C (ikki tanlov kuchi)**     | 2 ta tasodifiy hisob va sog'lomroq bo'lgan yo'nalishni tanlaydi - salomatlik haqida xabardorlik bilan yukni muvozanatlashtiradi    |
| **Tasodifiy**                   | Fisher-Yates shuffle yordamida har bir so'rov uchun tasodifiy hisob qaydnomasini tanlaydi                                          |
| **Eng kam ishlatilgan**         | Trafikni teng ravishda taqsimlovchi eng qadimgi `lastUsedAt` vaqt tamg'asi bilan hisob qaydnomasiga yo'nalishlar                   |
| **Xarajat optimallashtirilgan** | Eng past ustuvor qiymatga ega hisob qaydnomasiga marshrutlar, eng arzon provayderlar uchun optimallashtirish                       |

**Kengaytirilgan kombinatsiyalangan va avtomatik strategiyalar** (har bir kombinatsiya yoki `auto/*` prefikslari orqali sozlanishi mumkin - [AUTO-COMBO.md](../routing/AUTO-COMBO.md) ga qarang):

- `priority` - qat'iy tartib, hech qachon round-robins
- `weighted` - har bir model og'irliklari bo'yicha proportsional trafik taqsimoti
- `fill-first` - chegaraga yetguncha birinchi modelni to'kib tashlang
- `round-robin` / `strict-random` / `random`
- `p2c` (ikki tanlov kuchi)
- `least-used` va `cost-optimized`
- `auto` - barcha nomzodlar bo'yicha ballga asoslangan
- `lkgp` (Oxirgi ma'lum bo'lgan yaxshi provayder) - oxirgi muvaffaqiyatli provayderni bog'laydi, keyin qoidalarga qaytadi
- `context-optimized` — eng katta bepul kontekst oynasiga ega modelni tanlaydi
- `context-relay` - keyingi burilishlar uchun zanjirlar uzoq kontekstli modellar

### Chidamlilik va o'chirish to'xtatuvchilari

orqali sozlang** Boshqaruv paneli → sozlamalari → Moslashuvchanlik** .

   - **Asosiy sovutish** — Qayta urinish mumkin bo'lgan yuqori oqimdagi nosozliklar uchun standart sovutish oynasi
   - **Upstream qayta urinish boʻyicha maslahatlardan foydalaning** — Taqdim etilganda nufuzli `Retry-After` hurmat qiladi yoki maslahatlarni tiklash
   - **Maksimal orqaga qaytish qadamlari** — Takroriy nosozliklar uchun maksimal eksponensial orqaga qaytish darajasi

3. **Provayder o'chirgich** — Oxir-oqibat provayder nosozliklarini kuzatib boradi, sozlangan ogohlantirish chegarasida yomonlashgan provayderni belgilaydi va sozlangan nosozlik chegarasiga erishilganda to‘xtatuvchini ochadi:

   - **CLOSED** (Sog'lom) - So'rovlar odatdagidek oqadi
   - **DEGRADED** — Yuqori nosozliklar kuzatilganda, so'rovlar davom etmoqda
   - **OPEN** — Takroriy nosozliklardan keyin provayder vaqtincha bloklanadi
   - **HALF_OPEN** — Provayder tiklanganligini tekshirish

Nol kechikishli kombinatsiyalangan optimallashtirishlar qo'shiladi. Tashlab ket** Nol kechikish optimallashtirish** bu kechikish funksiyalarining zaxira maqsadlarga erishish, TTFT tarixiga asoslangan maqsadlarni o‘tkazib yuborish yoki zaxira so‘rovlarini siqishni oldini olish uchun o‘chirib qo‘yilgan; routing/request yoqish sozlangan xedjlash, bashoratli TTFT oʻtkazib yuborish va proaktiv qayta siqish imkonini beradi.

Oʻchirish** Fikrlash tokeni buferi** yuqori oqim provayderlari qattiq `max_tokens` / `maxOutputTokens` chegaralarini talab qilganda. Yoqilganda, kombinatsiyalangan marshrutlash faqat ma'lum chiqish qopqog'i bo'lgan modellar uchun mantiqiy model bo'sh joyini qo'shadi va xavfsiz buferlangan qiymat ushbu chegaradan oshib ketganda mijoz token chegarasini o'zgarishsiz qoldiradi. Agar mijoz chegarasi allaqachon ma'lum bo'lgan chegaradan yuqori bo'lsa, OmniRoute yuqori oqim so'rovini yuborishdan oldin uni o'sha chegaraga qisqartiradi.

## 🤖 Avtomatik yoʻnaltirish (sozlash talab qilinmaydi)

OmniRoute har bir ulangan provayder boʻylab har bir soʻrov uchun eng yaxshi modelni tanlaydigan **ballarga asoslangan avtomatik yoʻnaltirgich** bilan birga keladi — kombinatsiyalarni qoʻlda yuritish shart emas. Soʻrovni `auto/*` prefikslaridan biri bilan yuboring, OmniRoute esa kechikish, xarajat, muvaffaqiyat darajasi, kontekstga moslik, modelning vazifaga yaroqliligi, soʻnggi xatolar, kvota va avtomatik uzgich holati asosida nomzodlarni baholab, virtual kombinatsiyani tezkor ravishda tuzadi.

| Prefiks        | Optimallashtirish maqsadi                                                                                       |
| -------------- | --------------------------------------------------------------------------------------------------------------- |
| `auto`         | Muvozanatli standart rejim (kechikish × xarajat × muvaffaqiyat darajasi)                                        |
| `auto/coding`  | Dasturlash vazifalari: Claude, GPT-5, GLM, Kimi, Qwen Coder va DeepSeek kod yozish modellarini afzal koʻradi    |
| `auto/cheap`   | Eng past $/token, yuqoriroq kechikishga yoʻl qoʻyadi                                                            |
| `auto/fast`    | Eng past kechikish, xarajatni hisobga olmaydi                                                                   |
| `auto/offline` | Faqat mahalliy provayderlar (Ollama, vLLM, llama.cpp) — tarmoqdan ajratilgan muhitlar uchun foydali             |
| `auto/smart`   | Avvalo mulohaza yuritish sifati (Opus, GPT-5 xhigh, R1, GLM 5.1 reasoning)                                      |
| `auto/lkgp`    | “Oxirgi maʼlum ishlaydigan provayder” — oxirgi muvaffaqiyatli provayderga biriktiradi, keyin qoidalarga qaytadi |

Misol:

```bash
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer $OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "auto/coding",
    "messages": [{ "role": "user", "content": "Refactor this Python function" }],
    "stream": true
  }'
```

## 💻 Ichki CLI

OmniRoute sozlash, diagnostika va ish jarayonini boshqarish uchun ichki CLI (`omniroute …`) bilan taqdim etiladi. Bu boshqaruv panelidagi uchinchi tomon CLI vositalarini (Claude Code, Cursor, Codex, Cline, …) OmniRoute bilan ishlashga sozlaydigan **“CLI Tools” sahifasidan alohida**.

```bash
omniroute setup                    # Interaktiv sozlash ustasi (parol, provayderlar, kombinatsiyalar)
omniroute setup --non-interactive  # CI uchun qulay
omniroute doctor                   # Tizim holati diagnostikasi (maʼlumotlar katalogi, DB, provayderlar, portlar)
omniroute providers available      # Qoʻllab-quvvatlanadigan provayderlarni koʻrsatish
omniroute providers list           # Sozlangan ulanishlarni koʻrsatish
omniroute providers test <id>      # Provayder ulanishini jonli tekshirish
omniroute combos list              # Kombinatsiyalarni koʻrsatish
omniroute combos switch <name>     # Standart kombinatsiyani belgilash
omniroute models                   # Mavjud modellarni koʻrsatish (--json, --search)
omniroute keys add | list | remove # API kalitlarini terminal orqali boshqarish
omniroute backup                   # Konfiguratsiya va DB oniy nusxasini yaratish
omniroute restore [<timestamp>]    # Oniy nusxadan tiklash
omniroute health                   # Batafsil tizim holati (uzgichlar, kesh, xotira)
omniroute quota                    # Provayder kvotasidan foydalanish
omniroute mcp status               # MCP serveri holati
omniroute a2a status               # A2A serveri holati
omniroute tunnel list|create|stop  # Cloudflare/Tailscale/ngrok tunnellari
omniroute reset-password           # Administrator parolini tiklash
omniroute --mcp                    # MCP serverini stdio orqali ishga tushirish
omniroute --port 3000              # Serverni maxsus portda ishga tushirish
```

Maslahat: nosogʻlom provayder ulanishlari haqida ogohlantirish olish uchun `omniroute doctor --json` buyrugʻini monitoring vositangiz bilan birga ishlating.
