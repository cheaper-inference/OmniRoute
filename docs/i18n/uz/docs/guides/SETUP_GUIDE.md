## O'rnatish usullari

### npm (tavsiya etiladi)

```bash
npm install -g omniroute
omniroute
```

Boshqaruv paneli `http://localhost:20128` da ochiladi va API bazasi URL `http://localhost:20128/v1` dir.

> **npm foydalanuvchilari:** Agar npm oʻrnatish skriptlari bloklanganligi haqida ogohlantirsa (masalan, `omniroute`, `better-sqlite3`), [— npm oʻrnatish skriptlari bloklangan muammolarni bartaraf etish boʻlimiga](./TROUBLESHOOTING.md#npm-install-scripts-blocked-warning-global-install) qarang.

### pnpm

```bash
pnpm add -g omniroute@latest --allow-build=better-sqlite3 --allow-build=@swc/core
omniroute
```

> **pnpm foydalanuvchilari:** `--allow-build` bayrog'i `better-sqlite3` va `@swc/core` uchun mahalliy qurilish skriptlarini yoqish uchun talab qilinadi. `pnpm approve-builds -g` buyrug'i pnpm v11 da global o'rnatishlar uchun qo'llab-quvvatlanmaydi.

### Arch Linux (AUR)

```bash
yay -S omniroute-bin
systemctl --user enable --now omniroute.service
```

[AUR paketi](https://aur.archlinux.org/packages/omniroute-bin) OmniRoute o'rnatadi va tizimli foydalanuvchi xizmatini taqdim etadi.

### Manbadan

```bash
npm install
PORT=20128 DASHBOARD_PORT=20129 NEXT_PUBLIC_BASE_URL=http://localhost:20129 npm run dev
```

> **Windows eslatma:** Sukut bo'yicha, OmniRoute eski `%USERPROFILE%\.omniroute` katalogi mavjud bo'lmaganda `%APPDATA%\omniroute` foydalanadi. Boshqa maʼlumotlar katalogi joylashuvini tanlash uchun `DATA_DIR` oʻrnating.

> **Eslatma:** `npm install` birinchi ishga tushirishda `.env.example` dan avtomatik ravishda `.env` hosil qiladi. Keyingi o'rnatishlar mavjud `.env` ustiga yozilmaydi, shuning uchun sozlashlar saqlanib qoladi. Qayta ekish uchun `.env` qayta ishga tushirishdan oldin o'chiring.

### Docker

To'liq Docker sozlamalari uchun [Docker qo'llanmasini](./DOCKER_GUIDE.md) ko'ring, jumladan, Profillarni yaratish va Caddy HTTPS.

### Ish stoli ilovasi (Electron)

OmniRoute Electron 41 + elektron-quruvchi 26.10-da qurilgan ish stoli o‘ramini jo‘natadi. Mavjud skriptlar (ish maydoni ildizi):

```bash
npm run electron:dev          # Run desktop with hot-reload
npm run electron:build        # Build for current OS (auto-detected)
npm run electron:build:win    # Windows installer (NSIS + portable)
npm run electron:build:mac    # macOS (dmg + zip, arm64+x64)
npm run electron:build:linux  # Linux (AppImage + deb + rpm)
npm run electron:smoke:packaged  # Smoke-test packaged build
```

Ish stoli o'rnatuvchilarining relizlari GitHub Releases-ga biriktirilgan. To'liq Electron chuqur sho'ng'in (imzo, IPC ko'prigi, distros) uchun [`ELECTRON_GUIDE.md`](./ELECTRON_GUIDE.md) _(criado em fase posterior)_ ga qarang.

### Boshsiz server (CI/automation)

Qarovsiz sozlashlar uchun (Docker, Kubernetes, CI) foydalaning:

```bash
omniroute setup --non-interactive
omniroute providers test-batch
```

Env vars (`INITIAL_PASSWORD`, `OMNIROUTE_WS_BRIDGE_SECRET` va boshqalar) bilan birgalikda bu sizga to'liq skriptga ega bo'lgan OmniRoute misolini aylantirish imkonini beradi.

### CLI opsiyalari

| Buyruq                  | Tavsif                                                                                                        |
| ----------------------- | ------------------------------------------------------------------------------------------------------------- |
| `omniroute`             | Serverni ishga tushirish (`PORT=20128`, API va boshqaruv paneli bir xil portda)                               |
| `omniroute setup`       | Parol va birinchi provayder uchun boshqariladigan CLI onboarding                                              |
| `omniroute doctor`      | Serverni ishga tushirmasdan mahalliy sog'liqni tekshirishni o'tkazing                                         |
| `omniroute providers`   | CLI dan provayderlarni kashf eting, ro'yxatlang, tasdiqlang va sinab ko'ring                                  |
| `omniroute config`      | CLI asbob konfiguratsiyasi — ro'yxati, konfiguratsiyalarni olish, sozlash, tasdiqlash                         |
| `omniroute status`      | Oflayn holat boshqaruv paneli — versiyasi, DB, asboblar, konfiguratsiya                                       |
| `omniroute logs`        | API dan foydalanish jurnallarini oqimlash ( `--follow` ni qo'llab-quvvatlaydi)                                |
| `omniroute update`      | OmniRoute yangilanishlarini tekshiring yoki qo'llang                                                          |
| `omniroute provider`    | Provayder ulanishlarini boshqarish — qo'shish, ro'yxatga olish, o'chirish, sinovdan o'tkazish, sukut bo'yicha |
| `omniroute --port 3000` | canonical/API portini 3000 ga o'rnating                                                                       |
| `omniroute --mcp`       | MCP serverini ishga tushiring (stdio transport)                                                               |
| `omniroute --no-open`   | Brauzerni avtomatik ochmang                                                                                   |
| `omniroute --help`      | Yordam ko'rsatish                                                                                             |

Boshsiz sozlash bayroqlar yoki muhit o'zgaruvchilari bilan yozilishi mumkin:

```bash
omniroute setup --non-interactive --password "$OMNIROUTE_PASSWORD"
omniroute setup --non-interactive --add-provider --provider openai --api-key "$OPENAI_API_KEY"
omniroute setup --non-interactive --add-provider --provider openai --api-key "$OPENAI_API_KEY" --test-provider
```

Boshqaruv panelini ochmasdan mahalliy diagnostikani ishga tushiring:

```bash
omniroute doctor
omniroute doctor --json
omniroute doctor --no-liveness
```

Boshqarish panelini ochmasdan provayderlarni SSH yoki skriptlardan boshqaring:

```bash
omniroute providers available
omniroute providers available --search openai
omniroute providers available --category api-key
omniroute providers list
omniroute providers test <id-or-name>
omniroute providers test-all
omniroute providers validate
```

## CLI vositasini sozlash

### 1) Provayderlarni ulang va API kalitini yarating

1. Boshqaruv paneli → `Providers` bo‘limini oching va kamida bitta provayderni ulang (OAuth yoki API kaliti orqali).
2. Boshqaruv paneli → `Endpoints` bo‘limini oching va API kalitini yarating.
3. (Ixtiyoriy) Boshqaruv paneli → `Combos` bo‘limini oching va zaxira zanjiringizni sozlang.

### 2) Dasturlash vositangizni yo‘naltiring

```txt
Asosiy URL: http://localhost:20128/v1
API kaliti: [Endpoint sahifasidan nusxalang]
Model:      if/qwen3.8-max-preview (yoki istalgan provayder/model prefiksi)
```

Agar muharriringiz `Authorization: Bearer ...` yubora olmasa, uning o‘rniga token qo‘shilgan moslik asosiy URL manzilidan foydalaning:

```txt
Asosiy URL: http://localhost:20128/api/v1/vscode/YOUR_KEY/
Modellar URL manzili: http://localhost:20128/api/v1/vscode/YOUR_KEY/models
Chat URL manzili: http://localhost:20128/api/v1/vscode/YOUR_KEY/chat/completions
Ollama teglari URL manzili: http://localhost:20128/api/v1/vscode/YOUR_KEY/api/tags
```

Claude Code, Codex CLI, Cursor, Cline, OpenClaw, OpenCode va OpenAI bilan mos SDK’lar bilan ishlaydi.

#### `setup-*` yordamida avtomatik sozlash

Asosiy URL va kalitni qo‘lda kiritish o‘rniga, OmniRoute har bir vositaning
o‘z konfiguratsiyasini amaldagi modellar katalogi asosida yozishiga ruxsat bering. Har bir vosita uchun bitta buyruq:

```bash
omniroute setup-codex        # ~/.codex/<name>.config.toml profillari
omniroute setup-claude       # ~/.claude/profiles/<name>/settings.json
omniroute setup-opencode     # ~/.config/opencode/opencode.json (openai bilan mos)
omniroute setup-cline        # Cline CLI + VS Code kengaytmasi sozlamalari
omniroute setup-kilo         # Kilo Code
omniroute setup-continue     # ~/.continue/config.yaml (Continue / cn)
omniroute setup-cursor       # Cursor ilovasidagi amallarni ko‘rsatadi
omniroute setup-roo          # Roo Code importi + autoImport ko‘rsatkichi
omniroute setup-crush        # ~/.config/crush/crush.json
omniroute setup-zed          # ~/.config/zed/settings.json (openai_compatible)
omniroute setup-goose        # ~/.config/goose/config.yaml
omniroute setup-aider        # ~/.aider.conf.yml
omniroute setup-qwen         # ~/.qwen/settings.json + ~/.qwen/.env
```

Har bir buyruq mahalliy vositani **masofaviy** OmniRoute bilan ishlashga sozlash uchun `--remote <url> --api-key <key>` parametrlarini, shuningdek, oldindan ko‘rish uchun `--dry-run` parametrini qabul qiladi. CLI’ni to‘g‘ri
muhit o‘zgaruvchilari kiritilgan holda va hech qanday konfiguratsiyani yozmasdan ishga tushirish uchun
umumiy `omniroute run <target>` ishga tushirgichidan foydalaning (claude, codex, aider, goose, opencode, qwen, gemini);
har bir vosita uchun eski `omniroute launch` (Claude Code) va
`omniroute launch-codex` (Codex) ishga tushirgichlari hamon mavjud.

To‘liq jadvalni (har bir buyruq nimalarni yozishi, barcha parametrlar, mahalliy va masofaviy rejimlar, asosiy URL
uchun `/v1` qoidalari) ko‘rish uchun **[CLI integratsiyalari](./CLI-INTEGRATIONS.md)** sahifasiga qarang.

Har bir vosita uchun batafsil konfiguratsiya (Claude Code, Codex CLI, Cursor, Cline, OpenClaw, Kilo Code, Copilot va boshqalar) bilan tanishish uchun maxsus **[CLI vositalari qo‘llanmasi](../reference/CLI-TOOLS.md)** sahifasiga qarang.

## Protokolni sozlash (MCP + A2A)

### MCP sozlash (Model kontekst protokoli)

stdio rejimida MCP transportini ishga tushiring:

```bash
omniroute --mcp
```

Tavsiya etilgan tekshirish oqimi:

```bash
# 1. Start MCP server
omniroute --mcp

# 2. From your MCP client, call:
omniroute_get_health        # Should return system health
omniroute_list_combos       # Should return active combos

# 3. Or run the full E2E suite:
npm run test:protocols:e2e
```

#### MCP mijoz konfiguratsiyasi

**Claude kodi:**

Claude Code HTTP orqali ulanadi, `omniroute --mcp` (stdio) ishga tushmaydi. HTTP transporti sukut bo'yicha o'chirilgan: avval uni ishlaydigan serverda yoqing. Boshqaruv paneliga kirish yoqilganda, hisob ma'lumotlari bo'lmagan so'rov `401` oladi, shuning uchun `mcp:connect` (yoki `manage`) ni ushlab turgan API tugmachasini o'tkazing; `manage`/`admin` kalit ham har bir vositaning qamroviga muhtoj (qarang: [MCP Server → MCP asboblar doirasi](../frameworks/MCP-SERVER.md#mcp-tool-scopes) ).

```bash
omniroute mcp enable --transport streamable-http
claude mcp add --transport http omniroute http://localhost:20128/api/mcp/stream \
  --header "Authorization: Bearer your-key"
```

**Cursor / Cline:**

MCP sozlamalaringizga qo'shing (stdio, kalit bilan qo'ng'iroq qiluvchining asosiy egasi bo'lishi uchun):

```json
{
  "mcpServers": {
    "omniroute": {
      "command": "omniroute",
      "args": ["--mcp"],
      "env": {
        "OMNIROUTE_API_KEY": "your-key",
        "OMNIROUTE_BASE_URL": "http://localhost:20128"
      }
    }
  }
}
```

Yoki `mcpTransport` `streamable-http` bo'lsa (uni `/dashboard/mcp` yoki `omniroute mcp enable --transport streamable-http` bilan o'rnating), mijozning masofaviy MCP server yozuvini `http://localhost:20128/api/mcp/stream` ga qarating.

Kalit `Authorization: Bearer <api-key>` sifatida harakatlanadi (qarang: [MCP Server → Masofaviy xostlar uchun masofaviy kirish](../frameworks/MCP-SERVER.md#remote-access-manage-scope-bypass) ; masofaviy kalitga `mcp:connect` va uning read/write doiralari kerak).

**To'liq MCP hujjatlari:** [MCP Server README](../../open-sse/mcp-server/README.md) — 110 vositalari, IDE konfiguratsiyalari, Python/TS/Go mijozlari. Siqish CCR/dedup asboblari uchun operator ma'lumotnomasi (markerlar, dastlabki shartlar, har bir asbob doirasi, qidirish sahifalari, diagnostika): [Siqish dvigatellari → Prerequisites / operator qo'llanmasi](../compression/COMPRESSION_ENGINES.md#prerequisites--operator-guide-ccr--session-dedup).

### A2A sozlash (Agentdan agentga protokoli)

Agent kartasini tasdiqlang:

```bash
curl http://localhost:20128/.well-known/agent.json
```

Vazifa yuboring:

```bash
curl -X POST http://localhost:20128/a2a \
  -H 'content-type: application/json' \
  -d '{"jsonrpc":"2.0","id":"quickstart","method":"message/send","params":{"skill":"quota-management","messages":[{"role":"user","content":"Give me a short quota summary."}]}}'
```

**To'liq A2A hujjatlari:** [A2A Server README](../../src/lib/a2a/README.md) — JSON-RPC 2.0, ko'nikmalar, oqim, vazifaning hayot aylanishi.

## Taym-aut sozlamalari

### Asosiy taym-autlar

Koʻpgina joylashtirishlarda sizga faqat ushbu ikkita oʻzgaruvchi kerak boʻladi:

| Oʻzgaruvchi              | Standart qiymat                                  | Maqsad                                                                                                                                                                       |
| ------------------------ | ------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `REQUEST_TIMEOUT_MS`     | `600000`                                         | Yuqori oqim javobi boshlanishi taym-auti, yashirin Undici taym-autlari, TLS raqamli izi soʻrovlari hamda API koʻprigi soʻrovi/proksi taym-autlari uchun umumiy asosiy qiymat |
| `STREAM_IDLE_TIMEOUT_MS` | `REQUEST_TIMEOUT_MS` qiymatini meros qilib oladi | OmniRoute SSE oqimini bekor qilishidan oldin oqim qismlari orasidagi maksimal tanaffus                                                                                       |

Orqaga muvofiqlik saqlanadi: mavjud `FETCH_TIMEOUT_MS`, `API_BRIDGE_PROXY_TIMEOUT_MS` va boshqa qatlamga xos taym-aut oʻzgaruvchilari ishlashda davom etadi hamda umumiy asosiy qiymatni bekor qiladi.

### Provayderga xos eslatmalar

Claude Code bilan mos yuqori oqimlar (`anthropic-compatible-cc-*`) uchun OmniRoute chiquvchi `X-Stainless-Timeout` sarlavhasini aniqlangan olish taym-autidan hosil qiladi, shunda provayder tomonidagi oʻqish taym-autlari muhit konfiguratsiyangiz bilan mos boʻlib qoladi.

Uchinchi tomon Claude Code bilan mos teskari proksilar uchun OmniRoute standart `anthropic-beta` toʻplamini konservativ holatda saqlaydi va `Client Cache Control` parametri `Auto` holatida qoldirilganda, faqat mijoz taqdim etgan `cache_control` belgilarini uzatadi. Har bir ulanish uchun “Enable redact-thinking beta” parametrini faqat yuqori oqim maxsus ravishda tahrirlangan Claude fikrlash oqimlarini talab qilganda yoqing.

### Kengaytirilgan taym-aut almashtirishlari

| Oʻzgaruvchi                              | Standart qiymat                                                | Maqsad                                                                               |
| ---------------------------------------- | -------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| `FETCH_TIMEOUT_MS`                       | `REQUEST_TIMEOUT_MS` qiymatini meros qilib oladi               | Javob sarlavhalari kelguncha ishlatiladigan yuqori oqim javobi boshlanishi taym-auti |
| `FETCH_HEADERS_TIMEOUT_MS`               | `FETCH_TIMEOUT_MS` qiymatini meros qilib oladi                 | Yuqori oqim javob sarlavhalarini olish uchun Undici vaqt chegarasi                   |
| `FETCH_BODY_TIMEOUT_MS`                  | `FETCH_TIMEOUT_MS` qiymatini meros qilib oladi                 | Yuqori oqim tanasi qismlari orasidagi Undici vaqt chegarasi (`0` uni oʻchiradi)      |
| `FETCH_CONNECT_TIMEOUT_MS`               | `30000`                                                        | Undici TCP ulanish taym-auti                                                         |
| `FETCH_KEEPALIVE_TIMEOUT_MS`             | `4000`                                                         | Undici faol boʻlmagan keep-alive soketi taym-auti                                    |
| `TLS_CLIENT_TIMEOUT_MS`                  | `FETCH_TIMEOUT_MS` qiymatini meros qilib oladi                 | `wreq-js` orqali amalga oshiriladigan TLS raqamli izi soʻrovlari taym-auti           |
| `API_BRIDGE_PROXY_TIMEOUT_MS`            | `REQUEST_TIMEOUT_MS` yoki `600000` qiymatini meros qilib oladi | API portidan boshqaruv paneli portiga `/v1` proksi yoʻnaltirishi taym-auti           |
| `API_BRIDGE_SERVER_REQUEST_TIMEOUT_MS`   | `max(API_BRIDGE_PROXY_TIMEOUT_MS, 300000)`                     | API koʻprigi serveridagi kiruvchi soʻrov taym-auti                                   |
| `API_BRIDGE_SERVER_HEADERS_TIMEOUT_MS`   | `60000`                                                        | API koʻprigi serveridagi kiruvchi sarlavhalar taym-auti                              |
| `API_BRIDGE_SERVER_KEEPALIVE_TIMEOUT_MS` | `5000`                                                         | API koʻprigi serveridagi keep-alive taym-auti                                        |
| `API_BRIDGE_SERVER_SOCKET_TIMEOUT_MS`    | `0`                                                            | API koʻprigi serveridagi soket nofaolligi taym-auti (`0` uni oʻchiradi)              |

> **Eslatma:** Oqimli soʻrovlar uchun `FETCH_TIMEOUT_MS` faqat ulanishni sozlash / yuqori oqimdan birinchi javobni kutish jarayonini qamrab oladi. Oqim faollashgach, OmniRoute uni faqat haqiqiy toʻxtab qolish (`STREAM_IDLE_TIMEOUT_MS`) yoki Undici tanasi nofaolligi (`FETCH_BODY_TIMEOUT_MS`) yuz berganda bekor qiladi.

### Teskari proksi bilan muvofiqlik

Agar OmniRoute’ni Nginx, Caddy, Cloudflare yoki boshqa teskari proksi ortida ishga tushirsangiz, proksi taym-autlari ham OmniRoute oqim/olish taym-autlaridan yuqori ekaniga ishonch hosil qiling.

## Void Linux (xbps-src) andozasi

Void Linux foydalanuvchilari uchun `xbps-src` dan foydalanib mahalliy paket yaratishingiz mumkin. Ushbu blokni `srcpkgs/omniroute/template` sifatida saqlang:

```bash
# Template file for 'omniroute'
pkgname=omniroute
version=3.8.0
revision=1
hostmakedepends="nodejs python3 make"
depends="openssl"
short_desc="Universal AI gateway with smart routing for multiple LLM providers"
maintainer="zenobit <zenobit@disroot.org>"
license="MIT"
homepage="https://github.com/diegosouzapw/OmniRoute"
distfiles="https://github.com/diegosouzapw/OmniRoute/archive/refs/tags/v${version}.tar.gz"
# Regenerate the checksum for each release with:
#   curl -L -o /tmp/omniroute.tar.gz "https://github.com/diegosouzapw/OmniRoute/archive/refs/tags/v${version}.tar.gz" && sha256sum /tmp/omniroute.tar.gz
checksum=PLACEHOLDER_REGENERATE_PER_RELEASE
system_accounts="_omniroute"
omniroute_homedir="/var/lib/omniroute"
export NODE_ENV=production
export npm_config_engine_strict=false
export npm_config_loglevel=error
export npm_config_fund=false
export npm_config_audit=false

do_build() {
	local _gyp_arch
	case "$XBPS_TARGET_MACHINE" in
		aarch64*) _gyp_arch=arm64 ;;
		armv7*|armv6*) _gyp_arch=arm ;;
		i686*) _gyp_arch=ia32 ;;
		*) _gyp_arch=x64 ;;
	esac

	NODE_ENV=development npm ci --ignore-scripts
	npm run build
	cp -r .next/static .next/standalone/.next/static
	[ -d public ] && cp -r public .next/standalone/public || true

	local _node_gyp=/usr/lib/node_modules/npm/node_modules/node-gyp/bin/node-gyp.js
	(cd node_modules/better-sqlite3 && node "$_node_gyp" rebuild --arch="$_gyp_arch")

	local _bs3_release=.next/standalone/node_modules/better-sqlite3/build/Release
	mkdir -p "$_bs3_release"
	cp node_modules/better-sqlite3/build/Release/better_sqlite3.node "$_bs3_release/"

	rm -rf .next/standalone/node_modules/@img

	for _mod in pino-abstract-transport split2 process-warning; do
		cp -r "node_modules/$_mod" .next/standalone/node_modules/
	done
}

do_check() {
	npm run test:unit
}

do_install() {
	vmkdir usr/lib/omniroute/.next
	vcopy .next/standalone/. usr/lib/omniroute/.next/standalone

	for _d in \
		.next/standalone/.next/server/app/dashboard \
		.next/standalone/.next/server/app/dashboard/settings \
		.next/standalone/.next/server/app/dashboard/providers; do
		touch "${DESTDIR}/usr/lib/omniroute/${_d}/.keep"
	done

	cat > "${WRKDIR}/omniroute" <<'EOF'
#!/bin/sh
export PORT="${PORT:-20128}"
export DATA_DIR="${DATA_DIR:-${XDG_DATA_HOME:-${HOME}/.local/share}/omniroute}"
export APP_LOG_TO_FILE="${APP_LOG_TO_FILE:-false}"
mkdir -p "${DATA_DIR}"
exec node /usr/lib/omniroute/.next/standalone/server.js "$@"
EOF
	vbin "${WRKDIR}/omniroute"
}

post_install() {
	vlicense LICENSE
}
```
