Maxsus JSON API tuguni OpenAI yoki Anthropic protokolida gapirmaydigan JSON biznes so‘nggi nuqtasini ulaydi. OmniRoute JSON so‘rovi shablonini to‘ldiradi, uni to‘liq yakuniy URL nuqtasiga yuboradi, javob yo‘lidan javobni o‘qiydi va mijozning o‘ziga xos formatida mijozga qaytaradi (Chat yakunlari, javoblar, xabarlar, ...).

Bu `apiType: "custom-json"` bilan OpenAI-mos tugun; uning identifikatori `openai-compatible-custom-json-<suffix>` ko'rinishiga ega. Boshqaruv paneli shakli hali mavjud emas. Quyidagi provayder-tugun API orqali ushbu tugunlarni yarating va tahrirlang.

## Tugun yarating

`POST /api/provider-nodes` (boshqaruv autifikatsiyasi):

```json
{
  "type": "openai-compatible",
  "apiType": "custom-json",
  "name": "Business API",
  "prefix": "biz",
  "baseUrl": "https://api.example.com/v1/answer",
  "customHeaders": { "X-Tenant": "demo" },
  "customJson": {
    "method": "POST",
    "authType": "api-key",
    "authHeader": "X-Service-Key",
    "requestTemplate": {
      "project_id": "demo-project",
      "question": "{{prompt}}",
      "history": "{{messages}}"
    },
    "responsePath": "data.answer"
  }
}
```

- `baseUrl` bu** to'liq** oxirgi nuqta URL. Hech narsa qo'shilmaydi ( `/chat/completions` yo'q, `/models` yo'q) va boshqa OpenAI-mos keladigan tugunlardan farqli o'laroq, standart URL mavjud emas. U oʻrnatilgan hisob maʼlumotlari yoki `#fragment` boʻlmasdan `http(s)` boʻlishi kerak va u tugun saqlanganida ham, har bir soʻrovda ham har bir provayder tugunidagi kabi bir xil chiquvchi URL himoyasidan oʻtadi.
- Ulanish kalitini yuboradigan tugun (`authType` `bearer` yoki `api-key`, shu jumladan standart) `https://` foydalanishi kerak. Oddiy `http://` faqat loopback xost (`localhost`, `127.0.0.0/8`, `::1`) uchun yoki kalit yubormaydigan `authType: "none"` bilan qabul qilinadi. Shaxsiy LAN manzillari (`10.x`, `172.16-31.x`, `192.168.x`) bundan mustasno emas: bu tarmoqdagi har bir kishi kalitni oʻqishi mumkin. Bunday tugunni saqlash `400` bilan bajarilmaydi va ilgari saqlangan tugun har qanday so'rov yuborilishidan oldin bir xil xabar bilan har bir so'rovda yopilmaydi. LAN dagi kalitli so'nggi nuqta uchun uni TLS orqasiga qo'ying (masalan, teskari proksi-server).
- `customJson` Zod bilan tasdiqlangan; noma'lum kalitlar rad etiladi. Har bir maydon ixtiyoriy:

| Maydon            | Qadriyatlar                            | Standart                                               |
| ----------------- | -------------------------------------- | ------------------------------------------------------ |
| `method`          | `POST`, `PUT`, `PATCH`                 | `POST`                                                 |
| `authType`        | `bearer`, `api-key`, `none`            | `bearer`                                               |
| `authHeader`      | `api-key` ishlatiladigan sarlavha nomi | `X-API-Key`                                            |
| `requestTemplate` | JSON ob'ekti (≤ 64 KB, chuqurlik ≤ 32) | `{ "model": "{{model}}", "messages": "{{messages}}" }` |
| `responsePath`    | dala yo'li yoki butun tana uchun `$`   | `choices[0].message.content`                           |

- Sir hech qachon shablonda emas, ulanishning API kalitida qoladi. `bearer` `Authorization: Bearer <key>` yuboradi; `api-key` `<authHeader>: <key>` yuboradi. Auth sarlavhasi `Host`, `Content-Type`, `Content-Length`, `Connection`, `Transfer-Encoding`, `Authorization`, `Cookie` yoki hop-by-hop sarlavhasi boʻlishi mumkin emas. `none` bilan ulanishlar kalitga muhtoj emas.
- Qo'shimcha statik sarlavhalar tugunning odatiy `customHeaders` foydalanadi (har bir boshqa mos keluvchi tugun bilan bir xil tekshirish; u erda auth sarlavhalariga ruxsat berilmaydi).

`PUT /api/provider-nodes/<id>` bir xil `customJson` qabul qiladi va tugunning har bir mavjud ulanishida `baseUrl` va konfiguratsiyani qayta yozadi. `customJson` qoldirilsa, saqlangan konfiguratsiya saqlanib qoladi; `apiType` `chat` yoki `responses` ga almashtirish uni tugun va uning ulanishlaridan olib tashlaydi.

Keyin odatdagidek tugunga ulanish qo'shing (tugun identifikatori bilan `POST /api/providers` ) va so'rang `<prefix>/<model>`, masalan `biz/assistant-v1`. Yakuniy nuqta hech qanday model ro'yxatini ko'rsatmaydi, shuning uchun model identifikatorlarini qo'lda qo'shing.

## Shablonlarni so'rash

Shablonlar oddiy JSON. Satr qiymati `{{placeholder}}` markerlarini o'z ichiga olishi mumkin; hech narsa baholanmaydi yoki bajarilmaydi va ob'ekt kalitlari hech qachon almashtirilmaydi.

| To'ldiruvchi         | Qiymat                                                                                     |
| -------------------- | ------------------------------------------------------------------------------------------ |
| `{{prompt}}`         | Oxirgi foydalanuvchi xabarining matni (yangi qatorlar bilan birlashtirilgan matn qismlari) |
| `{{messages}}`       | Suhbat OpenAI chat formatida                                                               |
| `{{model}}`          | Soʻralgan model identifikatori, provayder prefiksisiz                                      |
| `{{stream}}`         | Har doim `false` — oxirgi nuqta bitta JSON hujjati bilan javob beradi                      |
| `{{request.<path>}}` | Tarjima qilingan (OpenAI chat formati) soʻrov maydoni                                      |

- Aynan bitta toʻldiruvchi boʻlgan qiymat oʻzining JSON turini saqlaydi (`"{{messages}}"` massivga aylanadi); matn sifatida uzunroq satr ichidagi joy ushlagich kiritiladi.
- Hech narsa hal qilmaydigan to'ldiruvchi to'liq bo'lmagan yukni yuborish o'rniga HTTP 400 bilan so'rovni bajara olmaydi.
- Yo'llar nuqta belgisi va raqamli indekslardan (`data.items[0].text`) foydalanadi. `__proto__`, `prototype` va `constructor` kalitlar va yo'llarda rad etiladi.

## Javoblar

`responsePath` dagi qiymat yordamchi javob bo'ladi: satrlar o'tadi, boshqa JSON qiymatlari ketma-ketlashtiriladi. Yo'qolgan yoki `null` maydoni yoki JSON bo'lmagan tana HTTP 502 ni qaytaradi. Yuqori oqim xato holatlari orqali uzatiladi. Oqimli mijozlar uchun OmniRoute butun JSON javobini kutadi va keyin uni bitta kontent qismi va yakuniy qism sifatida chiqaradi; bu token oqimi emas. Asbob qo'ng'iroqlari va foydalanish maydonlari xaritada ko'rsatilmagan.

## Hech qachon takrorlanmadi

Biznes so'rovi muvaffaqiyatsiz bo'lsa ham yon ta'sirga ega bo'lishi mumkin. OmniRoute shuning uchun uni bir marta yuboradi:

- transportni qayta urinish va yo'naltirish yo'q;
- boshqa ulanishda qayta urinilmaydi (hisobni qayta tiklash) — nosozlik avvalgidek qaytariladi va ulanish sovib qolmaydi;
- bo'sh yoki muvaffaqiyatsiz javob bo'lsa ham, keyingi kombinatsiyalangan maqsadga qaytish yo'q.

Alohida mijoz so'rovlari va bir nechta modellarni aniq chaqiradigan termoyadroviy panellar so'nggi nuqtani mustaqil ravishda chaqiradi.

## Tugunni sinab ko'rish

Ulanishni, ulanishni saqlash** Sinov** tugma va fon holatini tekshirish hech qachon oxirgi nuqtani chaqirmaydi: ular faqat saqlangan konfiguratsiyani tasdiqlaydi va ulanishni tekshirib bo'lmaydigan deb xabar qiladi.

`"apiType": "custom-json"` va tugun maydonlari (`baseUrl`, `apiKey`, `customJson`, ixtiyoriy `customHeaders` va `modelId`) bilan `POST /api/provider-nodes/validate` aynan bitta haqiqiy so‘rov yuboradi, `ping` so‘nggi foydalanuvchi matni sifatida. U `{ "valid": true }` yoki yuqori oqim holatiga javob beradi (hech qachon yuqori oqim tanasi emas).

## Saqlash

Konfiguratsiya `provider_nodes.custom_json_config_json` (migratsiya `240_provider_node_custom_json_config.sql`) da saqlanadi va har bir ulanishning `providerSpecificData.customJson` ga ko'chiriladi.

Amalga oshirish: `open-sse/utils/customJson.ts` (tasdiqlash va shablonlash), `open-sse/executors/customJson.ts` (ijrochi), `open-sse/services/combo/noReplayLatch.ts` va `src/sse/handlers/chat/responsePolicies.ts` (qayta o'ynatishsiz).
