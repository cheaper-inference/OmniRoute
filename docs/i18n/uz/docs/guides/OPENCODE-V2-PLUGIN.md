`@omniroute/opencode-plugin-v2` butun OmniRoute katalogingizni — modellar, kombolar va
avto-kombolarni — ko‘rsatiladigan nomlar, narxlar va bepul tarif limitlari bilan OpenCode v2 model
tanlagichiga qo‘shadi.

Bu `@omniroute/opencode-plugin`dan alohida paket, chunki OpenCode v1 va v2 plaginlarni
turli shartnomalar orqali yuklaydi. OpenCode asosiy versiyangizga mosini tanlang; ular orasida
hech narsa umumiy emas, shuning uchun birini yangilash hech qachon boshqasini yangilashga majburlamaydi.

## Talablar

- OpenCode v2.
- Ulanish mumkin bo‘lgan OmniRoute shlyuzi (standart bo‘yicha `http://localhost:20128`).
- Node.js 22 yoki 24.

## O‘rnatish

Plaginni `opencode.json` fayliga qo‘shing:

```json
{
  "plugins": [
    {
      "package": "@omniroute/opencode-plugin-v2",
      "options": {
        "providerId": "omniroute",
        "baseURL": "http://localhost:20128"
      }
    }
  ]
}
```

Shundan so‘ng modellar `omniroute/<provider>/<model>` ko‘rinishida paydo bo‘ladi; `providerId` ushbu prefiksni va
OpenCode hisob ma’lumotini saqlaydigan integratsiya identifikatorini belgilaydi.

## Hisob ma’lumotlari

Plagin shlyuz kalitini quyidagi uchta joydan ko‘rsatilgan tartibda qidiradi:

1. **OpenCode’da ulangan hisob ma’lumoti.** Plagin integratsiyani ro‘yxatdan o‘tkazadi, shu sababli
   OpenCode’ning o‘z autentifikatsiya jarayoni kalitni saqlashi mumkin. `opencode.json`ga hech narsa yozilmaydi — shu usulni afzal ko‘ring.
2. Har bir loyiha uchun alohida qiymat o‘rnatish maqsadida plagin parametrlaridagi `apiKey`. Bu kalitni siz
   versiyalarni boshqarish tizimiga yuborishingiz mumkin bo‘lgan faylga joylaydi.
3. Muhitdagi `OMNIROUTE_API_KEY`.

Uchalasidan hech biri mavjud bo‘lmasa, katalog bo‘sh qoladi va plagin sizni indamay bo‘sh tanlagich bilan
qoldirish o‘rniga ishga tushishda bu haqda bir marta xabar beradi.

### Boshqaruv tokeni boshqa kalitdir

Kombolar, provayder holati va boyitish ma’lumotlari (ko‘rsatiladigan nomlar, narxlar, bepul tarif limitlari)
shlyuzning `/api/*` endpointlaridan olinadi; aksariyat joriy etishlarda ular inferensiya kaliti emas, balki
**boshqaruv** tokeni bilan himoyalanadi:

```json
"options": {
  "baseURL": "http://localhost:20128",
  "managementReadToken": "<management read token>"
}
```

`managementReadToken` belgilanmagan bo‘lsa, uning o‘rniga `apiKey` ishlatiladi. Shlyuz bu zaxira variantni
rad etsa, katalog baribir e’lon qilinadi, ammo ko‘rsatiladigan nomlar o‘rniga xom model identifikatorlari bilan,
kanonik taxalluslarning dublikatlarini olib tashlamasdan, narxlarsiz va kombolarsiz. Bu sodir bo‘lganda plagin
har bir endpoint uchun bir marta ogohlantirib, endpointni va nimalar yo‘qolganini ko‘rsatadi — shu sababli
imkoniyatlari cheklangan tanlagich hech qachon tushunarsiz bo‘lib qolmaydi.

## Qanday qilib katalog yangi bo'lib qoladi

Katalog dangasalik bilan olinadi va `modelCacheTtlMs` uchun keshlanadi va diskdagi snapshot shlyuzga kirish imkoni bo'lmaganda so'nggi ma'lum bo'lgan katalogni mavjud bo'lib qoldiradi — uzilishlar sizga yangilikdan boshqa hech narsa talab qilmaydi. Modellar va kombinatsiyalar kelishi bilanoq nashr etiladi; avtokombolar, provayderlar ro'yxati va boyitish ustki qatlamlari qo'nganda katlanadi, shuning uchun bitta sekin oxirgi nuqta butun tanlovchini garovda ushlab turolmaydi.

Ismlar `Provider - Model[ (Editor)][ · budget][ (route)]` keyin keladi: provayder identifikatorda bitta (qiyshiq chiziqsiz identifikator prefikssiz ko'rsatiladi), yetakchi `🆓` bepul yozuvlarni belgilaydi va ularning erkin darajali byudjeti `· 1M tokens/month` qo'shimchasi sifatida qolsa, aniq `Editor: Model` nomining muharriri keyingi qavsga o'tganda va boshqa nomlarsiz tahrirlangan holda `combo - <slug>` ko'rsatiladi. bepul belgi. Bir nomga ega bo'lgan ikkita yozuv — `(no-think)` — marshrut qo'shimchasini oladi, shuning uchun ular ajralib turadi. `providerTag` (standart `true`) keyingi muharrir qavsni almashtiradi.

Qo'lda yangilash buyrug'i yo'q: OpenCode v2 buyruqlari qayta qo'ng'iroqlar emas, tezkor shablonlardir, shuning uchun plagin ularni ochib bera olmaydi. Yangilanishlar TTL ga amal qiladi; hostdan faqat katalog yoki ustki qatlam o'zgarganda qayta yuklash so'raladi, har bir yangilashda hech qachon.

## Geminiʼda vositalarni chaqirish

Gemini vosita deklaratsiyalarida `$schema` yoki `additionalProperties` mavjud boʻlgan soʻrovni toʻliq rad etib, `400 INVALID_ARGUMENT` javobini qaytaradi. Plagin ushbu provayderning Gemini modeliga yuboriladigan vosita sxemalaridan bu kalit soʻzlarni olib tashlaydi va boshqa barcha soʻrovlarni oʻzgartirmaydi. `$ref` mavjud boʻlgan vosita oʻzgartirilmay yuboriladi, chunki havolani olib tashlash sxemani «istalgan narsani qabul qilish» darajasigacha kengaytirib yuboradi.
Buni oʻchirish uchun `"geminiSanitization": false` ni belgilang.

## Muammolarni bartaraf qilish; nosozliklarni TUZATISH

| Alomat                                                           | Sabab                                                                                                                                |
| ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| Tanlovchi OmniRoute modelini ko'rsatmaydi                        | Hech qanday kalit hal etilmadi (ishlash bo'yicha ogohlantirishni tekshiring) yoki shlyuzga etib bo'lmaydi                            |
| Xom model identifikatorlari, kombinatsiyalar yo'q, narxlash yo'q | Boshqaruvning so'nggi nuqtalari — to'plami `managementReadToken` tokenini rad etdi                                                   |
| Qisqa yoki bo'sh `freeOnly` katalogi                             | Hech qanday boshqaruv tokeni yoki rad etilgan — tokeni xostlar jurnalidagi yangilanish sarhisobini (`unmatched-free` soni) o‘qimaydi |
| Seans `opencode-<id>/...`-ga biriktirilgan                       | v1 plaginini chop etdi `opencode-<id>`; v2 `<id>` yalang'och nashr etadi, shuning uchun `<id>/...` ostida modelni qayta tanlang      |

Atrof-muhit o'zgaruvchilari ochiq kodli server jarayoniga yetib borishi kerak: xost xizmat sifatida ishlaganda, `opencode models` ishlaydigan qobiq va server muhiti boshqacha, shuning uchun kalitni server o'qigan joyga eksport qiling.
