**Claude Code** CLI (`claude`) vositasini OmniRoute’ga — lokal yoki masofaviy VPS’ga —
har bir model uchun alohida profillar bilan, Codex sozlamasini takrorlagan holda ulang.

---

## Tezkor boshlash

```bash
# Claude Code’ni lokal OmniRoute bilan ishga tushirish (faol kontekstni avtomatik aniqlaydi)
omniroute launch

# Masofaviy OmniRoute bilan (`omniroute connect <host>`dan so‘ng bu avtomatik bajariladi)
omniroute launch --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# Har bir model uchun profil yaratish, so‘ng ulardan birini ishga tushirish
omniroute setup-claude            # ~/.claude/profiles/<name>/settings.json fayliga yozadi
omniroute launch --profile glm52  # OmniRoute orqali glm/glm-5.2’dan foydalanadigan Claude Code
```

## Claude Code shlyuzga qanday ulanadi

Claude Code bu haqda gapiradi**Anthropic Xabarlar API** va atrof-muhit o'zgaruvchilari bilan maxsus so'nggi nuqtaga ishora qilinadi (uning `--base-url` bayrog'i yo'q):

| O'zgaruvchan                                 | Maqsad                                                                                                                  |
| -------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `ANTHROPIC_BASE_URL`                         | Shlyuz ildizi URL (Claude kodi `/v1/messages` ga qo'shiladi).** `/v1` qo‘shimchasi yo‘q.**                              |
| `ANTHROPIC_AUTH_TOKEN`                       | `Authorization: Bearer …` — sifatida yuborilgan OmniRoute kirish tokeni/ API kalitingizdan foydalaning                  |
| `ANTHROPIC_API_KEY`                          | Muqobil: `x-api-key` sifatida yuborilgan. Agar ikkalasi ham o'rnatilgan bo'lsa, `ANTHROPIC_AUTH_TOKEN` g'alaba qozonadi |
| `ANTHROPIC_MODEL`                            | Muayyan modelni majburlash (standart `/model` tanlagichini bekor qiladi)                                                |
| `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY` | `1` → mahalliy `/model` tanlovchisi `/v1/models` dan `claude*`/`anthropic*` modellarini ro‘yxatga oladi                 |
| `CLAUDE_CODE_MAX_OUTPUT_TOKENS`              | Har bir javob uchun chiqish tokenlari (masalan, `65536`)                                                                |
| `CLAUDE_CODE_AUTO_COMPACT_WINDOW`            | Avtomatik siqishni uchun token chegarasi                                                                                |

> Env varslari o'qiladi** ishga tushirilganda bir marta** — ularni o'zgartirgandan so'ng Claude kodini qayta ishga tushiring.

Ruxsat etilgan qator o'rniga aylanadigan hisob ma'lumotlari uchun `~/.claude/settings.json` -da `apiKeyHelper` joriy hisob ma'lumotlarini stdout-ga chop etadigan buyruqqa o'rnating. Claude Code o'z chiqishini sukut bo'yicha besh daqiqa davomida keshlaydi (`CLAUDE_CODE_API_KEY_HELPER_TTL_MS` buni bekor qiladi) va qiymatni `Authorization: Bearer` va `x-api-key` ga yuboradi. Skript hisob ma'lumotlarini chop etishi kerak va boshqa hech narsa — banner bilan birga v2.1.227 + da yordamchini bajara olmaydi.

Entra ID SSO shunday ishlaydi: `scripts/cli/omniroute-sso.mjs token` API kaliti o‘rniga OmniRoute tasdiqlaydigan qisqa muddatli Entra kirish tokenini chop etadi. [`docs/security/ENTRA_SSO.md`](../security/ENTRA_SSO.md) ga qarang.

`omniroute launch` bularning barchasini siz uchun o‘rnatadi: u asosiy URL + tokenini faol kontekstdan hal qiladi (shuning uchun `omniroute connect <vps>` keyin `omniroute launch` ishlaydi), serverning sog‘lig‘ini tekshiradi va `claude` bajaradi.

## Foydalanish atributi: sessiyalar va loyihalar

OmniRoute har bir API kalit so'rovlarini guruhlarga ajratadi** agent seanslari** va qaysini qayd etadi** loyiha** ustida ishlagan har bir seans (`agent_sessions` jadvali), shuning uchun har bir guruh a'zosi, har bir loyiha va har bir sessiya uchun foydalanish va xarajat haqida xabar berish mumkin.

Mijoz sozlamalarisiz nima qayd etiladi:

| Maydon  | Manba                                                                                                                                                    |
| ------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Sessiya | `x-claude-code-session-id` sarlavhasi ( `metadata.user_id.session_id` bilan bir xil qiymat), har bir sessiya uchun barqaror                              |
| Loyiha  | `Primary working directory:` liniyasi Claude Code o'zining muhit xabarida yuboradi; `.claude/worktrees/` ostidagi worktree papkalari ombor nomiga o'tadi |
| Filial  | git statusidan `Current branch:` Claude Kod birinchi xabar bilan yuboriladi                                                                              |
| Mijoz   | `user-agent` (`claude-cli/<version>`)                                                                                                                    |

Codex (`<environment_context><cwd>`) va OpenCode (`x-opencode-session`) bir xil tarzda tan olinadi. bilan kalitlar** jurnalsiz** yoqilgan, faqat sessiya identifikatori va sarlavha bilan ta'minlangan loyiha maydonlarini saqlash; so'rovdan o'qilgan hech narsa (yo'l, filial) saqlanmaydi.

### Loyihani aniq nomlash (tavsiya etiladi)

Ishchi katalog mashinalar orasida farq qiladi, shuning uchun bir xil ombor turli yo'llar ostida ko'rsatilishi mumkin. Buning o'rniga loyihani aniq yuboring: Claude Code har bir model so'roviga `ANTHROPIC_CUSTOM_HEADERS` ro'yxatidagi har qanday sarlavhalarni qo'shadi va OmniRoute ulardan ikkitasini o'qiydi:

| Sarlavha                   | Qiymat                                                                                     |
| -------------------------- | ------------------------------------------------------------------------------------------ |
| `x-omniroute-project`      | Loyiha nomi, masalan `omniroute`                                                           |
| `x-omniroute-project-repo` | Normallashtirilgan masofadan boshqarish pulti, masalan `github.com/diegosouzapw/OmniRoute` |

Ikkalasi ham faqat atribut uchun o'qiladi; ular hech qachon yuqori oqim provayderiga yuborilmaydi.

`ANTHROPIC_CUSTOM_HEADERS` ishga tushirilganda bir marta o'qiladi va sozlamalar fayllari harfiy qiymatlarni saqlaydi, shuning uchun Claude Code ishga tushganda uni hisoblang. Buni `~/.zshrc` yoki `~/.bashrc` ga qo'shing va `claude` loyiha papkasidan boshlashni davom eting:

```bash
claude() {
  local common name repo
  if common=$(git rev-parse --path-format=absolute --git-common-dir 2>/dev/null); then
    name=$(basename "$(dirname "$common")")  # repository name, also inside worktrees
    repo=$(git remote get-url origin 2>/dev/null \
      | sed -E 's#^[a-zA-Z][a-zA-Z0-9+.-]*://([^@/]*@)?##; s#^[^@/]+@([^:]+):#\1/#; s#\.git$##')
  else
    name=$(basename "$PWD")                  # not a git repository: folder name
  fi
  ANTHROPIC_CUSTOM_HEADERS="x-omniroute-project: ${name}${repo:+
x-omniroute-project-repo: ${repo}}" command claude "$@"
}
```

`sed` ifodasi masofaviy URL ichiga o'rnatilgan barcha hisobga olish ma'lumotlarini yo'q qiladi. IDE kengaytmalari Claude kodini qobiqsiz ishga tushiradi, shuning uchun ularning seanslari ishchi katalogga qaytadi.

## Kashfiyot taxalluslari — Claude-ga tegishli bo'lmagan modellarni `/model` tanlovchisida ko'rsatish

Claude Code ning shluz model kashfiyoti faqat `claude` yoki `anthropic` bilan boshlanadigan id-larni ro'yxatga oladi, shuning uchun `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1` yoqilganda asl `/model` tanlovchisi odatda **faqat** OmniRoute ning Claude/Anthropic modellarini ko'rsatadi — `kimi/kimi-k2.6` yoki `glm/glm-5.2` hech qachon paydo bo'lmaydi, garchi u bemalol marshrutlansa ham.

OmniRoute har qanday yoqilgan modelni (va komboni) `claude/…` id ostida aks ettirishi mumkin, shunda u bu filtrdan o'tib, tanlovchida ko'rinadi:

```
kimi/kimi-k2.6            →  claude/kimi/kimi-k2.6      "Kimi K2.6 (OmniRoute)"
glm/glm-5.2              →  claude/glm/glm-5.2         "GLM 5.2 (OmniRoute)"
<combo "custo-otimizado"> →  claude/combo/custo-otimizado
```

Claude Code da ulardan birini tanlaganingizda, OmniRoute marshrutlashdan oldin `claude/` o'rovchini olib tashlab, haqiqiy id-ga qaytaradi — chinakam `claude/<real-claude-model>` id (asl Claude OAuth provayderi) esa har doim o'z holicha qoldiriladi.

Odatiy holda faqat asosiy id-lar aks ettiriladi. Tanlov asosida yoqiladigan `CATALOG_MIRROR_REFINEMENTS_ENABLED` funksiya bayrog'i yoqilganda, katalogda allaqachon ro'yxatga olingan fikrlash-harakati variantlari (masalan, `codex/gpt-6-sol-high`) boshqa har qanday id kabi aks ettiriladi, shunda Claude Code aniq harakat darajasini tanlashi mumkin, so'rov yo'li shakllantira olmaydigan o'rnatilgan `auto/*` id-lar esa aks ettirilmaydi. Harakat variantlari umuman ro'yxatga olinishi yoki olinmasligi baribir `OMNIROUTE_DISABLE_THINKING_LEVEL_VARIANTS` tomonidan boshqariladi — aks ettirish asosiy katalogda mavjud bo'lmagan variantni hech qachon qo'shmaydi.

**Bu odatiy holda o'chiq** va uch darajali nazorat orqali boshqariladi (eng aniq bo'lgani ustun keladi), shuning uchun oddiy OmniRoute Claude Code dan foydalanmaydigan mijozlar uchun o'z katalogini hech qachon ikki barobarga ko'paytirmaydi:

| Daraja    | Qayerda                                                                                                     |
| --------- | ----------------------------------------------------------------------------------------------------------- |
| Model     | Provayder tafsilotlari sahifasi → har bir model uchun «Claude Code da ko'rsatish» o'tkazgichi               |
| Provayder | Provayder tafsilotlari sahifasi → provayder darajasidagi o'tkazgich (uning barcha modellarini qamrab oladi) |
| Global    | Sozlamalar → Funksiya bayroqlari → `EXPOSE_CC_DISCOVERY_ALIASES` (odatiy holda o'chiq)                      |

`EXPOSE_CC_DISCOVERY_ALIASES` muhit o'zgaruvchisi global darajani majburiy yoqadi va boshqaruv panelidagi bekor qilishdan ustun turadi (bunday bo'lganda Funksiya bayroqlari ekranida «muhit o'zgaruvchisi orqali faol» yozuvi ko'rsatiladi). Har bir provayder va har bir model o'tkazgichlari shu zahoti aniqlashtirish kiritadi — masalan, global o'chiq + Kimi provayderi yoqilganda faqat Kimi modellari ko'rinadi.

> ⚠️ **Claude-ga tegishli bo'lmagan modellarda oyna nomuvofiqligi.** Claude Code tanimaydigan har qanday id uchun 200K kontekst oynasini nazarda tutadi (u `/v1/models` dan haqiqiy oynani o'qiy olmaydi). Kattaroq oynaga ega model uchun (masalan, Kimi K2 ning 256K oynasi), avtomatik siqish muddatidan oldin ishga tushib qolmasligi uchun `CLAUDE_CODE_AUTO_COMPACT_WINDOW` qiymatini modelning haqiqiy oynasidan pastroq qilib o'rnating. Yuqorida yaratilgan profillar buni har bir model uchun allaqachon bajaradi.

## Boshqaruv panelidagi ishga tushirish bloki

Claude vosita kartasi (**Boshqaruv paneli → CLI Code**) ushbu instansiya uchun aniq `settings.json` fragmentini aniqlash taxallusi haqidagi maʼlumot tugmasi yonida nusxalash tugmasi bilan ko‘rsatadi:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<OmniRoute manzilingiz>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<OmniRoute API kalitingiz>",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
  },
}
```

Asosiy URL — kartada aniqlangan (shu jumladan, siz kiritgan maxsus almashtirish bilan) va allaqachon normallashtirilgan manzil: `/v1` suffiksisiz va oxirgi qiya chiziqsiz. **Kalit hech qachon ko‘rsatilmaydi**: blok o‘rinbosar bilan taqdim etiladi, shuning uchun skrinshot yoki joylangan parcha kalitni oshkor qila olmaydi. O‘rinbosar ustiga kalitingizni kiriting.

Haqiqiy kontekst oynasi 200K bo‘lmagan har qanday model uchun o‘sha `env` bloki ichiga `CLAUDE_CODE_AUTO_COMPACT_WINDOW` ni qo‘shing — Claude Code o‘zi tanimaydigan har bir identifikator uchun 200K ni qabul qiladi, shu sababli aks holda avtomatik ixchamlash noto‘g‘ri nuqtada ishga tushadi (oldingi bo‘limdagi ogohlantirishga qarang). Parcha tuzuvchisi bu qiymatni ham qabul qiladi, shuning uchun maqsadli model oynasini biladigan chaqiruvchi uni bevosita chiqarishi mumkin.

Manba: `src/shared/services/claudeCliConfig.ts::buildClaudeDiscoverySettingsSnippet` (sof tuzuvchi, modul testlari bilan tekshirilgan), `ClaudeGatewayOnboardingBlock` tomonidan ko‘rsatiladi.

### Bitta hisobni biriktirish (ixtiyoriy)

Har bir Claude Code so‘rovini muayyan provayder hisobidan yuborish uchun o‘sha `env` blokidagi `ANTHROPIC_CUSTOM_HEADERS` orqali `x-omniroute-connection` sarlavhasini qo‘shing:

```jsonc
"ANTHROPIC_CUSTOM_HEADERS": "x-omniroute-connection: <connection id>"
```

Identifikatorni provayder sahifasidagi ulanish qatorida joylashgan `xxxxxxxx…` belgisidan nusxalang. Biriktirish faqat bitta modelli identifikatorlarga (`provider/model`) taalluqli, kombinatsiyalarga emas. Aniq zaxira xatti-harakati uchun [Har bir so‘rov bo‘yicha hisobni biriktirish](../reference/API_REFERENCE.md#account-pinning-per-request) bo‘limiga qarang.

## Profillar (`CLAUDE_CONFIG_DIR`)

Claude Code’da **mahalliy profil fayllari mavjud emas** (Codex’dagi `~/.codex/<name>.config.toml` dan farqli ravishda).
Odatiy mexanizm — `CLAUDE_CONFIG_DIR`: har bir profil uchun alohida konfiguratsiya katalogi bo‘lib,
ularning har biri o‘z `settings.json` fayli, hisob ma’lumotlari, tarixi va keshiga ega.

`omniroute setup-claude` amaldagi `/v1/models` katalogini oladi va har bir model uchun
`~/.claude/profiles/<name>/settings.json` manzilida bittadan profil yozadi hamda
**`setup-codex` bilan bir xil nomlardan** (`glm52`, `kimi-k27`, `deepseek-pro`, …) foydalanadi:

```jsonc
// ~/.claude/profiles/glm52/settings.json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "model": "glm/glm-5.2",
  "effortLevel": "xhigh",
  "env": {
    "ANTHROPIC_BASE_URL": "http://192.168.0.15:20128",
    "ANTHROPIC_MODEL": "glm/glm-5.2",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
    "CLAUDE_CODE_AUTO_COMPACT_WINDOW": "190000",
  },
}
```

> **Autentifikatsiya tokeni hech qachon profilga yozilmaydi.** `omniroute launch --profile <name>`
> orqali ishga tushiring (u faol kontekstdan `ANTHROPIC_AUTH_TOKEN` ni kiritadi) yoki
> `ANTHROPIC_AUTH_TOKEN` ni o‘zingiz eksport qilib,
> `CLAUDE_CONFIG_DIR=~/.claude/profiles/<name> claude` ni ishga tushiring.

**Modellar aniqlangandan keyingi avtomatik sinxronlash (ixtiyoriy).** Provayder modellari
sinxronlanishi amaldagi katalogni o‘zgartirganida OmniRoute ayni
`~/.claude/profiles/<name>/settings.json` fayllarini avtomatik ravishda qayta yaratishi mumkin —
shu tariqa yangi yoki nomi o‘zgartirilgan modellar buyruqni qayta ishga tushirmasdan profillarga ega
bo‘ladi. Bu imkoniyat **standart holatda o‘chirilgan**: uni **CLI Code boshqaruv paneli** orqali
yoqing ("CLI profile auto-sync" → Claude Code) yoki `OMNIROUTE_AUTO_SYNC_CLAUDE_PROFILES=true`
qiymatini o‘rnating (u standart holatda yoqilgan `CLI_ALLOW_CONFIG_WRITES` ni ham hisobga oladi).
Yoqilganda u faqat profil fayllarini yozadi; faol/standart Claude konfiguratsiyangizni,
autentifikatsiyani yoki `~/.claude/settings.json` faylini hech qachon o‘zgartirmaydi.

### Profillarni yaratish va ulardan foydalanish

```bash
# Mahalliy OmniRoute
omniroute setup-claude

# Masofaviy VPS (VPS URL manzilini har bir profilga kiritadi)
omniroute setup-claude --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# Faqat ayrim provayderlar
omniroute setup-claude --only glm,kimi

# Ushbu xostda aniqlanmagan mahalliy CLI provayderlari (zcode, auggie, devin-cli-agentic,
# codex-app-server) uchun ham profillar yozish (mahalliy nishon uchun standart holatda o‘tkazib yuboriladi)
omniroute setup-claude --include-local

# Fayllarga yozmasdan ko‘rib chiqish
```

## Model darajalari (ixtiyoriy)

Claude Code soʻrovlarni imkoniyat darajalariga yoʻnaltiradi. Har bir daraja uchun boshqa provayderlardan foydalanmoqchi boʻlsangiz, muhit oʻzgaruvchilari /
sozlamalar orqali ularni OmniRoute modeliga moslang:

```bash
export ANTHROPIC_DEFAULT_OPUS_MODEL="glm/glm-5.2"
export ANTHROPIC_DEFAULT_SONNET_MODEL="kmc/kimi-k2.6"
export ANTHROPIC_DEFAULT_HAIKU_MODEL="glm/glm-4.7-flash"
```

Aks holda, barcha darajalar uchun yagona `ANTHROPIC_MODEL` (profillar oʻrnatadigan qiymat) ishlatiladi.

## Muammolarni bartaraf etish

**Claude Code shlyuzni eʼtiborsiz qoldiryapti** — `ANTHROPIC_BASE_URL` tarkibida **`/v1`
yoʻqligini** tasdiqlang va `claude`ni qayta ishga tushiring (muhit ishga tushish vaqtida faqat bir marta oʻqiladi). `omniroute launch`
buni siz uchun bajaradi.

**`/model` tanlagichi boʻsh / shlyuz modellari yoʻq** — Claude Code
v2.1.219+ va `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1` talab qilinadi. Tanlagichda faqat `claude*` /
`anthropic*` model identifikatorlari koʻrinadi; boshqa istalgan modelni
`ANTHROPIC_MODEL=<id>` bilan majburan belgilang (profillar aynan shunday qiladi).

**`400 Ambiguous model 'claude-…'`** — Claude Code har doim **prefikssiz**
model identifikatorlarini yuboradi (masalan, `claude-opus-4-8`), shuning uchun Claude Code (`cc/…`) va
Claude (`claude/…`) provayderlarining ikkalasi ham ulanganida, oddiy identifikator ikkita yoʻnalishga mos keladi va
OmniRoute taxmin qilishdan bosh tortadi. Buni ikki usuldan biri bilan tuzating: prefiksli identifikatorni
`ANTHROPIC_MODEL=cc/claude-opus-4-8` orqali belgilang yoki **Prefikssiz Claude modellari uchun Claude Codeʼni afzal koʻrish**
parametrini yoqing — Claude provayderi sahifasidagi almashtirgich yoki
`OMNIROUTE_PREFER_CLAUDE_CODE_FOR_UNPREFIXED_CLAUDE_MODELS=true` (standart holatda oʻchirilgan;
[Muhit](../reference/ENVIRONMENT.md)ga qarang) — bu oddiy `claude-*`
identifikatorlarini Claude Codeʼga yoʻnaltiradi. Aniq provayder prefikslari har doim ustunlik qiladi.

**Autentifikatsiya xatolari** — profilda token saqlanmaydi. `omniroute launch --profile`
buyrugʻidan foydalaning (u tokenni kiritadi) yoki `ANTHROPIC_AUTH_TOKEN`ni eksport qiling.

**Profillar izolyatsiya qilinmagan** — har bir profil alohida `CLAUDE_CONFIG_DIR`ga ega;
seans ichida `echo $CLAUDE_CONFIG_DIR` buyrugʻi
`~/.claude/profiles/<name>` manzilini koʻrsatayotganini tekshiring.
