Neytral `config/cli-tools-manifest.json` shartnomasi kanonik IDs, taxalluslar, ikkilik nomzodlar, sozlash retseptlari, model argumentlari va imkoniyatlarini e'lon qiladi. `bin/cli/cli-manifest.mjs` -dagi oddiy tugun adapteri va `src/shared/constants/cliIntegrationManifest.ts` dagi TypeScript adapteri bir xil faylni o'qiydi. Ish vaqti, katalog, konfiguratsiya, yakunlash, generatorlar va registratsiya `tests/unit/cli/cli-manifest-drift.test.ts` tomonidan birgalikda tekshiriladi. Kataloglanganlik asbobni ishga tushirish yoki sozlash mumkin degani emas. Xususan, 5dive faqat konfiguratsiya bo'lib qoladi.

## Bola muhiti va hayot aylanishi

`omniroute run`, `omniroute launch` va `omniroute launch-codex` OS/terminal muvofiqligi ruxsat etilgan roʻyxatini meros qilib oladi va tanlangan maqsadning hisob maʼlumotlarini kiritadi. Aloqador bo'lmagan provayder va ma'lumotlar bazasi sirlari sukut bo'yicha meros qilib olinmaydi. `--inherit-env` to'liq ota-muhit merosini aniq tiklaydi; faqat tanlangan uchinchi tomon jarayoni ushbu qiymatlarni olishi kerak bo'lganda foydalaning. Bu OS sandbox emas, balki muhitni filtrlash: jarayon hali ham qo'ng'iroq qiluvchining fayl tizimi ruxsatlari bilan ishlaydi.

To'xtatish va tugatish signallari bolaga uzatiladi. Vaqtinchalik konfiguratsiyani olib tashlashdan oldin ishga tushirgich bolaning yaqin hodisasini kutadi. `OMNIROUTE_CHILD_SIGNAL_TIMEOUT_MS` majburiy tugatishdan oldingi imtiyozli davrni nazorat qiladi (standart 5000 millisekund).

## Gemini doimiy sozlash

```bash
omniroute setup-gemini --remote https://omni.example --model provider/model --yes
omniroute configure gemini --model provider/model --yes
omniroute run gemini --model provider/model --dry-run --json
```

Birinchi ikkita buyruq ushbu mashinani tanlangan mahalliy yoki uzoq server uchun sozlaydi. O'rnatish bir-biriga bog'liq bo'lmagan JSON sozlamalarini saqlaydi, Gemini API kaliti authni tanlaydi va so'nggi nuqta va hisob ma'lumotlarini shaxsiy `.gemini/.env` fayliga yozadi. U noto'g'ri JSON qayta yozishdan ko'ra rad etadi. Oxirgi nuqta URLs HTTP(S) boʻlishi kerak, oʻrnatilgan hisob maʼlumotlari, soʻrov parametrlari yoki fragmentlarisiz. Quruq chop etish hisob ma'lumotlarini emas, balki yo'llarni chop etadi.

`GEMINI_CLI_HOME` yoki `--gemini-home` doimiy asosiy ildizni tanlaydi. Haqiqiy `run gemini` o'zining vaqtinchalik uyini yaratadi va keyinchalik olib tashlaydi. Ikkala rejim ham Gemini ning ish maydoni-ishonch tekshiruvlarini chetlab o'tmaydi.

## Codex profillari

`configure codex` modeli va uning OmniRoute provayderining oxirgi nuqtasi bilan shaxsiy `<name>.config.toml` yozadi. Hisob ma'lumotlariga `OMNIROUTE_API_KEY` orqali havola qilinadi, hech qachon o'rnatilgan emas. Ishga tushirish buyrug'i tanlangan modelni `model_providers` ichida emas, balki yuqori darajadagi `model` tugmachasida o'rnatadi.

Alohida profil fayllari joriy hujjatlashtirilgan Codex shartnomasi; `codex --profile <name>` bilan tanlanganda foydalanuvchi konfiguratsiyasini qoplaydi. [Rasmiy profil ma'lumotnomasi](https://learn.chatgpt.com/docs/config-file/config-advanced#profiles) va [OmniRoute Codex qo'llanmasiga](./CODEX-CLI-CONFIGURATION.md) qarang.

## Germetik buyruqni bajarish

Aniq `DATA_DIR` bilan `OMNIROUTE_CLI_SKIP_DEFAULT_DATA_ENV=1` sozlamalari ishga tushirishning standart foydalanuvchi ma'lumotlari katalogining hisob ma'lumotlari muhitiga tushishining oldini oladi. Bu izolyatsiya qilingan testlar uchun foydalidir. U boshqa aniq tanlangan muhit fayllarini o'chirmaydi.

## Ishchi katalog `.env`

CLI `.env` fayllarini shu tartibda o'qiydi va kalitni o'rnatgan birinchi fayl g'alaba qozonadi: aniq `DATA_DIR`, standart ma'lumotlar katalogi, joriy ishchi katalog, keyin paketlar katalogi. Shell o'zgaruvchilari har doim g'alaba qozonadi.

Ishchi katalog boshqa birovga tegishli bo'lishi mumkin (klonlangan ombor, o'ramdan chiqarilgan arxiv) va `omniroute serve` CLI muhitini serverga va server ishlayotgan har bir vositaga uzatadi. Shunday qilib, u erda `.env` faqat `bin/cli/utils/untrustedCwdEnv.mjs` ro'yxatidagi ushbu kalitlarni o'rnatishi mumkin:

| Kalit                           | Qabul qilingan qiymatlar                                                                   |
| ------------------------------- | ------------------------------------------------------------------------------------------ |
| `REQUIRE_API_KEY`               | `true`, `1` yoki `yes` har qanday holatda ham, server yoqilgan deb hisoblaydigan qiymatlar |
| `LANG`, `LC_ALL`, `LC_MESSAGES` | 64 tagacha harf, raqamlar, `_`, `.`, `@` yoki `-`                                          |
| `LANGUAGE`                      | bir xil, ortiqcha `:`                                                                      |
| `TZ`                            | 64 tagacha harf, raqamlar, `_`, `+`, `-` yoki `/`, `/` bilan boshlanmaydi                  |
| `NO_COLOR`, `FORCE_COLOR`       | 16 tagacha harf va raqamlar                                                                |

`REQUIRE_API_KEY` qabul qiladigan har bir qiymat chekni yoqadi, shuning uchun fayl chekni o'zi o'chira olmaydi. Biroq, u natijani hal qilmaydi: server atrof-muhitdan oldin ma'lumotlar bazasida saqlangan `REQUIRE_API_KEY` bekor qilishni o'qiydi, API kalitisiz barcha interfeyslarni tinglash haqida ishga tushirish ogohlantirishi faqat muhitni o'qiydi. `false` ning saqlangan bekor qilinishi bilan `REQUIRE_API_KEY=true` ishchi katalogi API ni ochiq qoldiradi va bu ogohlantirishni yashiradi. `TZ` qoidasi POSIX dan torroq: u `.`, `:`, `,` va `<>` ni rad etadi , shuning uchun `:Area/City` shakli va `EST5EDT,M3.2.0,M11.1.0` kabi qoidalar qobiqda yoki `<DATA_DIR>/.env` o'rnatilishi kerak.

Ismlar katta harf bilan to'liq mos kelishi kerak. Boshqa har qanday satr, tekshirilmagan qiymat va oddiy ASCII harflari, raqamlari va `_` bo'lmagan nom (masalan NUL bayti yoki o'xshash harfli) o'tkazib yuboriladi. CLI o'rnatolmaydigan kalitlarni nomlaydigan va u e'tiborsiz qoldirgan ruxsat etilgan kalitlarni nomlaydigan bitta ogohlantirishni chop etadi, har birida nimani o'zgartirish kerak (`TZ (expected a zone name such as Europe/Berlin)`, `lang (write the name as LANG)`). Ikkalasi ham qiymatlarni chop etmaydi. Ushbu xabarlardagi fayl yo'llari va `.env` yo'li `omniroute doctor` hisobotlari, agar ular nazorat yoki bidi belgilarni o'z ichiga olgan bo'lsa, o'chiriladi. Ishchi katalog ma'lumotlar katalogi yoki paketlar katalogi bo'lsa, cheklov qo'llanilmaydi.

`PORT`, `API_PORT` va `DASHBOARD_PORT` ro'yxatda yo'q. Yuqori darajadagi manbadan URL bazasi bo'lmasa, CLI `localhost:<PORT>` bilan gaplashadi va u erda tinglayotgan narsa CLI ning API kalitini, kontekst tokenini va CLI mashinasi tokenini (`x-omniroute-cli-token`, [CLI_TOKEN.md](../security/CLI_TOKEN.md) ga qarang) qabul qiladi, ularni mahalliy server orqaga qaytarishdan boshqarish uchun qabul qiladi. Ishchi katalogdagi port ushbu faylga tinglovchini tanlash imkonini beradi, shuning uchun qobiqdagi portlarni `<DATA_DIR>/.env` yoki bitta (`serve`, `launch`, `run`) bo'lgan buyruqlarning `--port` varianti bilan o'rnating.

Tahlil qiluvchida `export` sintaksisi yo'q. `export LD_PRELOAD=...` kabi qator `export LD_PRELOAD` o'zgaruvchini nomlaydi; ishchi katalogdan u o'tkazib yuboriladi va boshqa `.env` fayllarida hech narsa o'qilmaydigan o'sha to'g'ridan-to'g'ri nomni o'rnatadi.

CLI kontekstning saqlangan tokenini (kirish tokeni yoki eski API kaliti) faqat shu kontekstning oʻz kelib chiqishi bilan bogʻlaydi: sxema, xost va port, `URL.origin` bilan solishtirganda. Bu CLI ning HTTP mijozi (`--base-url`, `OMNIROUTE_BASE_URL`, `omniroute connect <new-url>`) orqali amalga oshirilgan soʻrovlarga hamda boshqa asbob konfiguratsiyasiga asosiy URL va kalitni yozuvchi `launch`, `launch codex`, `configure` va `setup-*` buyruqlariga taalluqlidir. `--remote` bilan boshqa serverga ishora qilinsa, ular aniq `--api-key` yoki `OMNIROUTE_API_KEY` dan foydalanadi va kontekst belgisi yo'q. Taqqoslash aniq, shuning uchun `localhost` va `127.0.0.1` yoki orqa nuqtali va nuqtasiz xost turli serverlar sifatida hisoblanadi va kontekst tokenini olmaydi. Foydalanuvchi maʼlumotlari, teskari chiziq yoki boʻshliqqa ega URL hech qachon mos kelmaydi, chunki boshqa URL parserlari (masalan, Python’ning `urllib` va `httpx`) undan boshqa xostni oʻqiy oladi. So'rovlar uchun CLI o'zini yuboradi, bu tekshirish faqat sxema va vakolatni qamrab oladi, shuning uchun yo'lda yoki so'rovda bo'sh joy bo'lgan identifikator tokenni saqlaydi.
