> **TOML — yagona ishlaydigan format.** Zamonaviy Codex faqat
> `~/.codex/config.toml` faylini oʻqiydi (codex-cli 0.147.0 bilan tekshirilgan:
> `codex --help` hujjatida `-c/--config` orqali qayta belgilashlar
> "`~/.codex/config.toml` faylidan yuklanishi" koʻrsatilgan). Eski
> `~/.codex/config.yaml` avvalgi npm CLIʼga tegishli boʻlib, indamay eʼtiborsiz
> qoldiriladi. Boshqaruv paneli generatori (`/api/cli-tools/apply`, `codex`
> vositasi) TOMLʼni ehtiyotkor birlashtirish bilan yozadi — mavjud kalitlar va
> boshqa provayder bloklari saqlanadi, API kaliti `OMNIROUTE_API_KEY` ichida
> qoladi (hech qachon fayl ichida emas), qolib ketgan eski `config.yaml` fayliga
> esa tegilmasdan, migratsiya eslatmasi sifatida xabar beriladi.

## Nusxalab qoʻyishga tayyor config.toml

`<YOUR_HOST>` va `<YOUR_KEY>` oʻrniga oʻz qiymatlaringizni kiriting:

```toml
# ~/.codex/config.toml
model                          = "cx/gpt-5.5"
model_provider                 = "omniroute"
model_reasoning_effort         = "xhigh"
model_context_window           = 400000
model_auto_compact_token_limit = 350000
tool_output_token_limit        = 32768    # har bir vosita chaqiruvi uchun tarixni saqlash chegarasi

[model_providers.omniroute]
name                 = "OmniRoute"
base_url             = "http://<YOUR_HOST>:20128/v1"
env_key              = "OMNIROUTE_API_KEY"
requires_openai_auth = false
wire_api             = "responses"
```

```bash
# ~/.bashrc yoki ~/.zshrc — haqiqiy kalit qiymati, hech qachon config.toml ichida emas
export OMNIROUTE_API_KEY="<YOUR_KEY>"
```

### macOS: ChatGPT ilovasiga biriktirilgan Codex

Agar Codexʼni ChatGPT ish stoli ilovasi orqali oʻrnatgan boʻlsangiz, `codex`
binar fayli faqat ilova toʻplami ichida boʻlishi va hali shell `PATH` roʻyxatiga
kiritilmagan boʻlishi mumkin. Resurslar katalogini shell ishga tushirish fayliga
qoʻshing:

```bash
export PATH="/Applications/ChatGPT.app/Contents/Resources:$PATH"
```

Yangi shell oching, soʻng tekshiring:

```bash
command -v codex
codex --version
```

### Autentifikatsiyasiz mahalliy OmniRoute: vaqtinchalik kalit yetarli

Codex birinchi soʻrov CLIʼdan chiqishidan **oldin** `env_key` orqali nomlangan
muhit oʻzgaruvchisi mavjudligini tekshiradi. Agar **mahalliy** OmniRoute
instansiyangiz autentifikatsiyani talab qilmasa, istalgan boʻsh boʻlmagan
vaqtinchalik qiymat ishlaydi:

```bash
export OMNIROUTE_API_KEY="${OMNIROUTE_API_KEY:-local}"
```

OmniRoute serveringiz himoyalangan yoki masofaviy boʻlsa, uning oʻrniga haqiqiy
kalitdan foydalaning.

> **Keng tarqalgan host variantlari**
>
> | Kirish          | URL                           |
> | --------------- | ----------------------------- |
> | Mahalliy tarmoq | `http://192.168.0.1:20128/v1` |
> | Tailscale       | `http://100.x.x.x:20128/v1`   |
> | Loopback        | `http://localhost:20128/v1`   |

## `wire_api = "responses"` — nega u barcha modellar bilan ishlaydi

Codex CLI 2026-yil fevral oyida `wire_api = "chat"` (Chat Completions)ʼni eskirgan deb belgiladi va endi `wire_api = "responses"` (OpenAI Responses API)ʼni **talab qiladi**. v0.138ʼdan boshlab `wire_api = "chat"` sozlamasi ishga tushish vaqtida darhol nosozlikka olib keladi.

Koʻplab provayderlar, jumladan GLM va Kimi, hanuz faqat Chat Completions endpointʼini taqdim etadi. DeepSeek V4 endi mahalliy Responses API bilan birga Anthropic bilan mos endpointʼni ham taqdim etadi; OmniRoute standart holatda Responsesʼdan foydalanadi va har bir DeepSeek ulanishiga Anthropic mosligini tanlash imkonini beradi.

**OmniRoute buni shaffof tarzda hal qiladi:**

```
Codex CLI
  → wire_api = "responses"
  → POST /v1/responses (OmniRoute)
    → OmniRoute provayderning mahalliy protokolini tanlaydi va zarur boʻlganda tarjima qiladi
    → POST /responses (DeepSeek V4) yoki /chat/completions (Mistral / GLM / Kimi / boshqalar)
```

OmniRouteʼdan foydalanganda sizga hech qachon alohida tarjima proksisi kerak boʻlmaydi. **Barcha modellar `wire_api = "responses"`ʼdan foydalanadi** — qolganini OmniRoute bajaradi.

> **`wire_api` standart qiymatdir** — maydonning standart qiymati `"responses"` boʻlib, uni `config.toml` faylidan butunlay chiqarib tashlash mumkin. Uni faqat maqsadni hujjatlashtirmoqchi boʻlsangizgina aniq koʻrsating.

## Kontekst oynasi va ixchamlashtirish

### Token konfiguratsiyasi maydonlari

| Maydon                           | Tavsif                                                                                                                                                                                                                        |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `model_context_window`           | Faol model uchun umumiy token budjeti. Model uchun eʼlon qilingan limitga sozlang.                                                                                                                                            |
| `model_auto_compact_token_limit` | Tarixni avtomatik ixchamlashtirishni ishga tushiradigan chegara. **Maksimum: `model_context_window` qiymatining 90%i** — 90%dan yuqori qiymatlar bildirishsiz eʼtiborsiz qoldiriladi.                                         |
| `tool_output_token_limit`        | Har bir vosita chaqiruvi natijasi uchun tarixda saqlanadigan tokenlar chegarasi. Bitta katta vosita javobi oynani toʻldirib yuborishining oldini oladi. **Bu maksimal chiqish hajmi emas** — bu tarixda saqlash chegarasidir. |
| `compact_prompt`                 | Ixchamlashtirish vaqtida ishlatiladigan tizim prompti uchun bevosita qayta belgilash (v0.138+).                                                                                                                               |

> **`model_max_output_tokens` haqida eslatma**: Bu maydon **Codex CLI konfiguratsiya sxemasiga kirmaydi** (Codex Rust kod bazasida mavjud emas). Sozlansa, u bildirishsiz eʼtiborsiz qoldiriladi. Unga tayanmang — vosita chiqishining qancha qismi tarixda saqlanishini boshqarish uchun `tool_output_token_limit`dan foydalaning.

## Fikrlash darajasi

Model javob berishdan oldin qancha «fikrlashi»ni boshqaradi.

| Qiymat   | Qo‘llanishi                                                      |
| -------- | ---------------------------------------------------------------- |
| `none`   | Fikrlashsiz — to‘g‘ridan-to‘g‘ri javob                           |
| `low`    | Oddiy vazifalar (nomini o‘zgartirish, formatlash)                |
| `medium` | Ko‘rsatilmaganda **server standarti**                            |
| `high`   | O‘rta darajadagi vazifalar (refaktoring, nosozliklarni tuzatish) |
| `xhigh`  | Arxitektura, chuqur tahlil, murakkab muammolar                   |

```bash
# Har bir ishga tushirish uchun alohida sozlash
codex -c model_reasoning_effort=low "x o‘zgaruvchisini count deb qayta nomla"
codex -c model_reasoning_effort=xhigh "autentifikatsiya modulini loyihala"
```

Desktop faqat shifrlangan bloklarni emas, fikrlash matnini ham ko‘rsata olishi uchun fikrlash **xulosasi**ni ham sozlang:

```toml
# ~/.codex/config.toml
model_reasoning_effort = "xhigh"   # yoki qo‘llab-quvvatlanganda ultra
model_reasoning_summary = "detailed"  # auto | concise | detailed | none
```

### OmniRoute fikrlash budjeti (server sozlamasi)

Codex darajasi/xulosasi yuqori oqimga yetib borishi uchun OmniRoute xostida **Settings → AI → Thinking Budget** qiymati **`passthrough`** bo‘lishi kerak. **`auto` rejimi** mijozning barcha `reasoning` / `reasoning_effort` maydonlarini olib tashlaydi va Codex to‘g‘ri sozlangan bo‘lsa ham fikrlash panellarini bo‘sh qoldiradi.

To‘liq qo‘llanma: [THINKING_BUDGET.md](./THINKING_BUDGET.md).

Siqish va prompt keshi bir-biridan mustaqil bo‘lib, `passthrough` rejimida ishlashda davom etadi.

## Profillar — har bir model/ish jarayoni uchun nomlangan konfiguratsiyalar

Profillar model va kontekst oynasini bitta bayroq yordamida almashtirish imkonini beradi. Har bir profil asosiy `config.toml` ustiga qo‘llanadigan oddiy
`~/.codex/<name>.config.toml` faylidir.

> **Nomlash qoidasi (Codex CLI v0.137+):** fayl `~/.codex/<name>.config.toml` ko‘rinishida bo‘lishi shart — **`profile-` prefiksisiz**.
> CLI `-p kimi-k27` parametrini → `~/.codex/kimi-k27.config.toml` sifatida aniqlaydi. Agar fayl topilmasa, standart sozlama bildirishsiz qo‘llanadi.

```bash
codex --profile kimi-k27 "ushbu kod bazasining 10 ming qatorini tahlil qil"
codex -p glm52 "arxitekturani ko‘rib chiq"
codex --profile deepseek-flash "o‘zgaruvchi nomini o‘zgartir"   # tez, arzon
```

### Daraja profillari (bir xil model, turli daraja)

```bash
codex -p low      # cx/gpt-5.5, daraja=low
codex -p medium   # cx/gpt-5.5, daraja=medium

codex -p xhigh    # cx/gpt-5.5, daraja=xhigh (standart)
```

## `omniroute setup-codex` yordamida profillarni avtomatik yaratish

Agar OmniRoute’ni VPS’da ishga tushirsangiz, amaldagi modellar katalogi asosida profil fayllarini avtomatik yaratishingiz mumkin:

```bash
# VPS orqali (20128-portdagi mahalliy OmniRoute’dan foydalanadi)
omniroute setup-codex

# Istalgan kompyuterdan — VPS manzilingizni ko‘rsating
omniroute setup-codex --remote http://100.x.x.x:20128 --api-key sk-xxx

# Fayllarni yozmasdan oldindan ko‘rish
omniroute setup-codex --remote http://100.x.x.x:20128 --dry-run

# Faqat GLM va Kimi profillarini yaratish
omniroute setup-codex --only glm,kimi

# Maxsus katalogga yozish
omniroute setup-codex --codex-home /path/to/.codex
```

Buyruq `/v1/models` ma’lumotlarini oladi, ma’lum modellar uchun moslashtirilgan profillardan foydalanadi, boshqa mos matnli modellar uchun katalog metama’lumotlariga qaytadi va har biri uchun `~/.codex/<name>.config.toml` faylini yozadi. Idempotent — uni qayta ishga tushirish xavfsiz.

Agar asosiy `config.toml` faylida `model_providers.omniroute` ta’rifi bo‘lmasa, aniq ishga tushirilgan
`setup-codex` tanlangan mahalliy yoki masofaviy yakuniy nuqtadan foydalanib, ushbu ta’rifni har bir yaratilgan
ustama konfiguratsiyaga kiritadi. Asosiy fayl o‘zgarishsiz qoladi. Mavjud provayder
ta’rifi, jumladan uning yakuniy nuqtasi va autentifikatsiya sozlamalari meros qilib olinadi. Asosiy
TOML fayli noto‘g‘ri bo‘lsa, profillar yozilishidan oldin yaratish jarayoni to‘xtatiladi.

`--api-key` yoki `OMNIROUTE_API_KEY` taqdim etilganda, yangi ta’riflangan provayder
`env_key = "OMNIROUTE_API_KEY"` ga murojaat qiladi; kalitning o‘zi hech qachon saqlanmaydi yoki
oldindan ko‘rishda chiqarilmaydi. Ushbu o‘zgaruvchini Codex’ni ishga tushiradigan muhitda o‘rnating. Kalit
taqdim etilmasa, autentifikatsiyasiz so‘rovlarni qabul qilishga sozlangan OmniRoute nusxasi
uchun yangi ta’rifda kalit talabi bo‘lmaydi.

Quyida tavsiflangan ixtiyoriy katalog avtomatik sinxronlash funksiyasi ustama konfiguratsiyada mavjud
provayder ta’riflarini saqlab qoladi, ammo yangi provayder sozlamalarini boshlang‘ich tarzda yaratmaydi; avval provayderni
aniq sozlash buyrug‘i yoki boshqaruv paneli orqali sozlang. Mavjud provayder sozlamalari
`--dry-run` oldindan ko‘rish natijalarida ko‘rsatilmaydi, chunki ular operator boshqaruvidagi hisob ma’lumotlarini o‘z ichiga olishi mumkin.

OmniRoute, shuningdek, provayder modellarini muvaffaqiyatli aniqlash/import qilish amaldagi katalogni o‘zgartirgandan so‘ng, ayni shu profil fayllarini **avtomatik sinxronlashi** mumkin. Bu funksiya **ixtiyoriy va sukut bo‘yicha o‘chirilgan**: uni **CLI Code boshqaruv paneli** orqali yoqing ("CLI profile auto-sync" → Codex) yoki `OMNIROUTE_AUTO_SYNC_CODEX_PROFILES=true` qiymatini o‘rnating (u sukut bo‘yicha yoqilgan `CLI_ALLOW_CONFIG_WRITES` parametrini ham hisobga oladi). Yoqilganda, u faqat alohida `~/.codex/*.config.toml` profil fayllarini yozadi; u faol/standart `~/.codex/config.toml` faylini, Codex-lb sozlamalarini, autentifikatsiyani yoki provayder tanlovini hech qachon o‘zgartirmaydi.

## Codex’ni `omniroute launch-codex` yordamida ishga tushirish

Codex’ni ishga tushirishdan oldin OmniRoute instansiyangizning ishlash holatini tekshiradi:

```bash

omniroute launch-codex --profile glm52 -- --yolo "fix this bug"
```

```bash

# -c bayroqlari orqali omniroute provayderini kiritib, codex'ni ishga tushirish (konfiguratsiya yozilmaydi)
```

## Uzoq muddatli vazifalar

Ikkita OmniRoute sukut bo'yicha ko'p soatlik Codex CLI seanslarini jimgina sabotaj qilishi mumkin. Na Codex CLI sozlamasi — ikkalasi ham OmniRoute tomonida yashaydi. Hisob qaydnomalarini o'rnatadigan va bo'sh turgan uzilishlarni o'chirib qo'yadigan yuqori oqim proksi-serverlaridan konfiguratsiyani ko'chiradigan foydalanuvchilar ko'pincha ikkalasini ham urishadi va OmniRoute "uzoq seansni ushlab turolmaydi" degan xulosaga kelishadi.

| Alomat                                                                                                  | Mumkin sabab                                                                          | Tugma                    |
| ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- | ------------------------ |
| Seans hisoblarni almashtirishni davom ettiradi / burilishlar orasida tezkor kesh uzluksizligi yo'qoladi | Seansga yaqinlik TTL `0` (o‘chirilgan)                                                | `sessionAffinityTtlMs`   |
| Ulanish o'rta hisobda uzilib qoladi va mijozga murojaat qilmaydi                                        | 10 daqiqadan so‘ng yuqori oqim bo‘laklarisiz oqim bo‘sh kuzatuvchisi ishga tushirildi | `STREAM_IDLE_TIMEOUT_MS` |

Tegishli munozaralar: [#7126](https://github.com/cheaper-inference/OmniRoute/discussions/7126) (uzoq vazifa tushishi), [#5718](https://github.com/cheaper-inference/OmniRoute/discussions/5718) (nega yaqinlik sukut bo'yicha o'chirilgan). Kuzatuv: [#7287](https://github.com/cheaper-inference/OmniRoute/issues/7287).

### 1. Seansga affinity — bitta suhbatni bitta hisobga qo'ying

**Standart:** `sessionAffinityTtlMs = 0` (nogiron).

**Uni qayerga o'rnatish kerak**

- Boshqaruv paneli →** → Routing sozlamalari** →** Sessiyaga yaqinlik** →** Yaqinlik TTL (sekundlar)** (`ComboDefaultsTab`)
- Yoki `sessionAffinityTtlMs` bilan PATCH sozlamalari** millisekundlar** (Zod diapazoni `0`–`86_400_000`, ya'ni 24 soatgacha)

> Faqat Kodeks `codexSessionAffinityTtlMs` dan #7274 bilan qayta nomlandi. Eski kalit hali ham faqat o'qish uchun taxallus sifatida qabul qilinadi; yangi konfiguratsiyalar `sessionAffinityTtlMs` foydalanishi kerak. Yaqinlik endi tegishli** har qanday** provayder bir marta TTL yuqorida `0`, emas, balki faqat Codex — qarang [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md) → Sessiya yaqinligi.

**0 da qolganda nima buziladi**

Ko'p burilishli Codex suhbatining har bir navbati faol kombinatsiyalangan strategiya tomonidan mustaqil ravishda yo'naltiriladi va bir joyga tushishi mumkin.** har bir burilish uchun turli xil hisob** . Bu yuqori oqim sessiyasi/kesh-kesh uzluksizligini buzadi. OmniRoute faqat Codex sessiya sarlavhalariga (`x-codex-session-id` / `x-session-id` / `x-omniroute-session`) va `prompt_cache_key` / `session_id` kabi tana maydonlariga TTL `0` (`extractSessionAffinityKey` da `src/sse/services/auth.ts`) dan katta bo'lganda maslahat beradi.

**Bir necha soatlik bitta vazifa uchun tavsiya etiladi**

TTL ni o'rnating** vazifaning kutilgan devor soati uzunligidan yuqori** (UI maks** 86400 soniya** = 24 soat):

| Ishning kutilgan uzunligi | Yaqinlik TTL (UI, soniya)   | `sessionAffinityTtlMs` |
| ------------------------- | --------------------------- | ---------------------- |
| Bir necha soat            | `14400` (4 soat)            | `14400000`             |
| Kecha / ~ 12 soat         | `43200` (12 soat)           | `43200000`             |
| To'liq kun                | `86400` (24 soat, maksimal) | `86400000`             |

Ro'yxatdan o'tish qasddan qilingan: affinityni o'chirib qo'yish hisoblar bo'ylab yuk balansini qo'llab-quvvatlaydi; uni yoqish, bitta uzoq agent seansi uchun uzluksizlikni ta'minlaydi. Bu qo'llanma** emas** uzoq Codex vazifalarini bajaradigan standart — operatorlarini o'zgartirish uchun ro'yxatdan o'tish kerak.

### 2. Stream bo'sh vaqt tugashi — sokin fikrlash navbatlarini o'ldirmang

**Standart:** `STREAM_IDLE_TIMEOUT_MS = 600000` (10 daqiqa). O'rnatilmaganda `REQUEST_TIMEOUT_MS` dan meros oladi; umumiy bazaviy chiziq ham 600000. Qarang: [`docs/guides/SETUP_GUIDE.md`](SETUP_GUIDE.md) → Timeouts.

**Standart holatda nima buziladi**

10 daqiqadan ko'proq vaqt davomida jim turadigan Codex mulohaza / asbob burilish** haqiqiy yuqori oqim qismi yo'q** SSE idle watchdog (`open-sse/utils/stream.ts`) tomonidan kuch bilan yopiladi. Mijoz ko'pincha "hech qanday bildirishnomasiz avtomatik ravishda to'xtatilgan" — mos keladigan yalang'och ulanish tushishini ko'radi.

Muhim tafsilot: OmniRoute ning sintetik SSE** yurak urishi tiklanmaydi** bo'sh soat. Faqat haqiqiy yuqori oqim tanasi chunk yangilanadi `lastChunkTime`. Hali ham "o'ylayotgan" sokin model qo'riqchi nuqtai nazaridan to'xtab qolgan yuqori oqim bilan bir xil ko'rinadi.

Tegishli Undici tanasining harakatsizligi: `FETCH_BODY_TIMEOUT_MS` (shuningdek, bir xil 10 daqiqalik asosiy chiziqqa sukut bo'yicha; `0` uni o'chiradi). Oqim uchun `FETCH_TIMEOUT_MS` faqat ulanishni sozlashni qamrab oladi / oqim faol bo'lgandan keyin — birinchi sarlavhalarini qamrab oladi, to'xtash joylari `STREAM_IDLE_TIMEOUT_MS` va `FETCH_BODY_TIMEOUT_MS` tomonidan boshqariladi.

**Bir necha soatlik bitta vazifa uchun tavsiya etiladi**

OmniRoute jarayoni muhitida (`.env` / compose / systemd):

```bash
# Disable stream idle + body inactivity cutoffs for long reasoning turns
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

Yoki ularni siz kutgan eng uzun jim bo'shliqdan yuqoriga ko'taring (qiymatlar millisekundlar):

```bash
# Example: allow up to 2 hours of silence between upstream chunks
STREAM_IDLE_TIMEOUT_MS=7200000
FETCH_BODY_TIMEOUT_MS=7200000
```

Ushbu env parametrlarini o'zgartirgandan so'ng OmniRoute qayta ishga tushiring.

### Beton retsepti — ko'p soatlik Codex vazifasi

1. **Hisobni mahkamlang:** Boshqaruv paneli → sozlamalari → Marshrutlash → Seansga yaqinlik → Affinity TTL = `43200` (12 soat) yoki `86400` (maks. 24 soat).
2. **Bo'sh vaqtni ko'tarish / o'chirish** OmniRoute muhitida:

```bash
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

3. Odatdagi Codex `config.toml` (`wire_api = "responses"`, to'g'ri `base_url`, `OMNIROUTE_API_KEY`) — saqlang, bu ikki xatti-harakatlar uchun Kodeks tomonidagi affinity/idle tugmalari mavjud emas.
4. OmniRoute qayta ishga tushiring, so'ngra uzoq Codex vazifasini boshlang.

### Birlamchi qaror (#7287)

| Tugma                    | Kema standarti       | Ushbu qoʻllanmada oʻzgarish bormi?                                                                   |
| ------------------------ | -------------------- | ---------------------------------------------------------------------------------------------------- |
| `sessionAffinityTtlMs`   | `0` (o'chirilgan)    | **Yo'q** — qo‘shilgan bo‘lib qoladi (yuk balanslash va uzluksizlik; #5718 muhokamasiga qarang)       |
| `STREAM_IDLE_TIMEOUT_MS` | `600000` (10 daqiqa) | **Yo'q** — umumiy trafik uchun 10 daqiqa qoladi; long Codex operatorlari uni oshiradi yoki o'chiradi |

Birorta standartni global miqyosda aylantirish nafaqat Codex emas, balki misolning har bir mijozi uchun xatti-harakatni o'zgartiradi. Tugmalarni hujjatlash; aniq operator qarori boshqacha aytilmaguncha standart sozlamalarni qoldiring.

### Bo'sh kesilganlarni diagnostika qilish

Bo'sh turgan qo'riqchi ishga tushganda, OmniRoute quyidagi shakldagi chiziqni qayd qiladi:

```text
[STREAM] Idle timeout: no data from codex for 600000ms (model: cx/gpt-5.5)
```

`Idle timeout: no data from` uchun Grep (yoki `stream_idle_timeout` kodi / xato nomi `StreamIdleTimeoutError`). Provayder segmenti ushbu so'rov uchun ishlatiladigan OmniRoute bo'lishidan qat'i nazar (`codex`, boshqa provayder identifikatori yoki `provider` noma'lum bo'lsa) — u har doim ham so'zma-so'z `codex` qatori emas.

## Muammolarni bartaraf etish

**`Error: wire_api = "chat" is no longer supported`**
Konfiguratsiyangizdan `wire_api = "chat"` qatorini olib tashlang. `wire_api = "responses"` qilib belgilang yoki maydonni kiritmang (v0.138 dan boshlab standart qiymat — `"responses"`).

**`Error: model not found`**
Model OmniRoute’da toʻgʻri prefiks bilan mavjudligini tekshiring. `omniroute models list` buyrugʻidan foydalaning yoki `/dashboard/providers/<provider>` sahifasini oching.

**`Authentication error`**
`OMNIROUTE_API_KEY` eksport qilinganini tasdiqlang: `echo $OMNIROUTE_API_KEY`.

**`ERROR: Missing environment variable: OMNIROUTE_API_KEY`**
Codex birinchi soʻrovni yuborishdan oldin muhit oʻzgaruvchisi mavjudligini tekshiradi. Himoyalangan serverlar uchun haqiqiy kalitni eksport qiling yoki **mahalliy** OmniRoute nusxangiz autentifikatsiyani talab qilmasa, `OMNIROUTE_API_KEY=local` kabi boʻsh boʻlmagan o‘rinbosar qiymatdan foydalaning. Agar uni `~/.bashrc` yoki `~/.zshrc` fayliga qoʻshgan boʻlsangiz, shell’ni qayta ishga tushiring.

**`Connection refused`**
OmniRoute ishlayotganini va `base_url` host/porti tarmogʻingiz uchun toʻgʻri ekanini tekshiring (mahalliy, Tailscale yoki VPS).

**Seans kontekst chegarasiga yaqinlashganda ishdan chiqadi**
`model_context_window` va `model_auto_compact_token_limit` qiymatlarini aniq belgilang. Yuqoridagi kontekst oynasi jadvaliga qarang.

**Ixchamlashtirish juda kech ishga tushadi**
`model_auto_compact_token_limit` qiymatini oyna hajmining 80–85%igacha kamaytiring. Uni hech qachon 90%dan yuqori belgilamang.

**Profil yuklanmayapti (`-p <name>` indamay eʼtiborsiz qoldiriladi)**
Fayl `~/.codex/<name>.config.toml` manzilida mavjudligini tasdiqlang (`profile-` prefiksisiz). `ls ~/.codex/*.config.toml` buyrugʻini ishga tushiring.

**Uzoq davom etuvchi Codex vazifasi bajarilish oʻrtasida uziladi / soʻrovlar orasida hisoblarni almashtiradi**
[Uzoq davom etuvchi vazifalar](#long-running-tasks) boʻlimiga qarang. Seansga bogʻliqlikni yoqing (TTL vazifa davomiyligidan uzun boʻlsin) va `STREAM_IDLE_TIMEOUT_MS` / `FETCH_BODY_TIMEOUT_MS` qiymatlarini oshiring yoki ularni oʻchirib qoʻying. OmniRoute jurnallarida `Idle timeout: no data from` matnini grep orqali qidiring.
