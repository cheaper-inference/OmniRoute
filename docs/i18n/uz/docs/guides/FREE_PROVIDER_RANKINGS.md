> **Qisqacha**: OmniRoute o‘zining **bepul** provayderlarini model sifati bo‘yicha **Arena AI
> (LMArena uslubidagi) ELO ballari** yordamida saralaydi. Vazifangiz uchun eng kuchli
> modellarni taqdim etuvchi bepul provayderlarni ko‘rish uchun boshqaruv panelidagi
> **Bepul provayderlar reytingi** sahifasini oching — umumiy yoki toifa bo‘yicha
> filtrlangan holda (kodlash, tekshirish, hujjatlashtirish, nosozliklarni tuzatish).

---

## Bu nima

OmniRoute 377 ta provayderni ro'yxatdan o'tkazadi, shu jumladan 155 ta katalog yozuvlari belgilangan**free/no-auth** (no-auth, free-tier OAuth yoki free-tier API key — [Free Tiers Guide](../getting-started/FREE-TIERS-GUIDE.md) va to'liq [Free Tiers katalogiga](../reference/FREE_TIERS.md) qarang). Qo'lga olish: bepul provayderlar model sifati bo'yicha juda farq qiladi. Chegaraviy modelga xizmat ko'rsatuvchi avtorizatsiyasiz provayder kichik eski modelga xizmat ko'rsatuvchidan ko'ra ancha foydalidir.

**Bepul provayderlar reytingi** javoblar"** Qaysi bepul provayder menga eng yaxshi modelni beradi?** " bilan har bir bepul provayderning katalogiga qo'shilish orqali** olomon manbalaridan olingan sifat ballari** dan** Arena AI yetakchilar jadvali** (inson-afzal ELO, LMArena chatbot arenasining orqasida xuddi shu fikr). Keyin provayderlar ularning kuchiga qarab tartiblanadi** Eng yaxshi bepul model** .

Reyting uchta haqiqiy manbadan hisoblanadi:

1. Bepul provayderlar ro'yxati - `NOAUTH_PROVIDERS`, plus `OAUTH_PROVIDERS` / `APIKEY_PROVIDERS` yozuvlari `hasFree` (`src/shared/constants/providers.ts`) bilan belgilanadi.
2. Provayderlar reestridan (`open-sse/config/providerRegistry.ts`) har bir provayderning model katalogi.
3. Arena ELO sinxronlash mexanizmi (`src/lib/arenaEloSync.ts`) tomonidan `model_intelligence` DB jadvalida saqlanadigan ELO-dan olingan vazifalarga mos ballar.

Qo'shilish mantig'i `src/lib/freeProviderRankings.ts` yashaydi.

## Qanday kirish mumkin

### Boshqaruv paneli sahifasi

Boshqaruv panelini oching va **Xarajatlar → Bepul provayderlar reytingi** bo‘limiga
o‘ting yoki to‘g‘ridan-to‘g‘ri quyidagi manzilga kiring:

```
/dashboard/free-provider-rankings
```

Sahifada (`src/app/(dashboard)/dashboard/free-provider-rankings/page.tsx`) quyidagilar
ko‘rsatiladi:

- Eng yuqori o‘rinlarni egallagan bepul provayderlardan iborat **eng yaxshi 3 talik
  shohsupasi** (🥇 🥈 🥉).
- Quyidagi ustunlarga ega to‘liq **reyting jadvali**: **O‘rin**, **Provayder**,
  **Eng yaxshi model**, **Ball**, **O‘rtacha ball**, **Modellar**, **Tur**.
- **Toifa filtri tugmalari**: _Barcha toifalar_, _Standart_, _Kodlash_, _Tekshirish_,
  _Hujjatlashtirish_, _Nosozliklarni tuzatish_.

Har bir provayderning **Tur** belgisi uning qanday qilib bepul ekanini ko‘rsatadi:

| Belgi    | Ma’nosi                                              |
| -------- | ---------------------------------------------------- |
| `NOAUTH` | Har doim bepul, hisob ma’lumotlari talab qilinmaydi  |
| `OAUTH`  | Bepul darajaga ega OAuth provayderi (`hasFree`)      |
| `APIKEY` | Bepul darajaga ega API kaliti provayderi (`hasFree`) |

Ballar xom raqamlar o‘rniga o‘qish uchun qulay yorliqlar (masalan, _Elita_,
_A’lo_, _Juda yaxshi_, _Yaxshi_, _O‘rtacha_) ko‘rinishida beriladi, chunki asosiy
qiymat foiz emas, balki nisbiy reyting sifatidir.

### API so‘nggi nuqtasi

Sahifa hammaga ochiq o‘qish so‘nggi nuqtasi
(`src/app/api/free-provider-rankings/route.ts`) tomonidan quvvatlanadi:

```
GET /api/free-provider-rankings
GET /api/free-provider-rankings?category=coding
GET /api/free-provider-rankings?category=coding&limit=20
```

So‘rov parametrlari (Zod yordamida tekshiriladi):

| Parametr   | Tur    | Standart | Izohlar                                                                                                                    |
| ---------- | ------ | -------- | -------------------------------------------------------------------------------------------------------------------------- |
| `category` | string | (yo‘q)   | `default`, `coding`, `review`, `documentation`, `debugging` qiymatlaridan biri. Birlashtirilgan reyting uchun ko‘rsatmang. |
| `limit`    | number | `50`     | `1–100` oralig‘i bilan cheklanadi.                                                                                         |

Javob tuzilishi:

```json
{
  "rankings": [
    {
      "id": "<provider-id>",
      "name": "<provider name>",
      "icon": "<icon>",
      "color": "<hex color>",
      "textIcon": "<short label>",
      "category": "noauth | oauth | apikey",
      "topModel": {
        "modelId": "<registry model id>",
        "modelName": "<model display name>",
        "score": 0.0,
        "eloRaw": 0,
        "confidence": "high | medium | low",
        "category": "<task category>"
      },
      "averageScore": 0.0,
      "modelCount": 0
    }
  ]
}
```

`eloRaw` — Arena ELO’ning dastlabki qiymati; `score` esa normallashtirilgan vazifaga
moslik qiymatidir (quyiga qarang). Baholangan modellari mavjud bo‘lmagan provayderlar
javobdan chiqarib tashlanadi.

## Ballar qanday ishlaydi

### Manba: Arena AI reyting jadvali

Arena ELO sinxronizatsiya mexanizmi (`src/lib/arenaEloSync.ts`) Arena AI reyting jadvali API dan
(`https://api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`) ikkita reyting jadvalini —
`text` va `code` — yuklab oladi. Agar bu API foydali jadval qaytarmasa, mexanizm Hugging Face
datasets-server dagi rasmiy `lmarena-ai/leaderboard-dataset` ga o'tadi
(`src/lib/arenaEloHfSource.ts`, CC-BY-4.0; `overall` → `text`,
`coding` → `code`); `GET /api/intelligence/sync` `activeSource`, `lastError` va
`lastFailedAt` haqida xabar beradi. Har bir reyting jadvali yozuvi model nomi,
ishlab chiqaruvchi, ELO `score`, ishonch intervali va ovozlar sonini o'z ichiga oladi.

Reyting jadvali toifalari OmniRoute vazifa toifalariga mos keladi:

| Arena reyting jadvali | OmniRoute vazifa toifalari                        |
| --------------------- | ------------------------------------------------- |
| `text`                | `default`, `review`, `documentation`, `debugging` |
| `code`                | `coding`                                          |

### Normallashtirish (vazifaga moslik balli)

Xom ELO ballari har bir reyting jadvali bo'yicha **`[0.4, 0.98]` oralig'idagi vazifaga moslik qiymatiga** normallashtiriladi:

```
taskFit = 0.4 + 0.58 * ((elo - minElo) / (maxElo - minElo))
```

Ball hech qachon `0` yoki `1` ga yetib bormaydi, bu foydalanuvchi o'zgartirishlari uchun
zaxira joy qoldiradi. Bu API javobida ko'rinadigan `score` maydoni va boshqaruv panelida
ko'rsatiladigan yorliqdir.

### Ishonch darajasi

Har bir yozuv Arena ovozlar soniga qarab ishonch darajasini oladi:

| Ishonch darajasi | Ovozlar |
| ---------------- | ------- |
| `high`           | ≥ 5,000 |
| `medium`         | ≥ 1,000 |
| `low`            | < 1,000 |

### Saqlash va dolzarblik

Normallashtirilgan yozuvlar `source = "arena_elo"` bilan `model_intelligence` DB jadvaliga
yoziladi (`src/lib/db/modelIntelligence.ts`). Yozuvlarning **amal qilish muddati
7 kundan keyin tugaydi**, shuning uchun sinxronizatsiyani to'xtatgan provayder eskirgan
ma'lumotlarni taqdim etish o'rniga vaqt o'tishi bilan ro'yxatdan chiqib ketadi.

Sinxronizatsiya **standart holatda yoqilgan**:

- U server ishga tushganda bir marta ishlaydi, keyin esa davriy taymer bo'yicha ishlaydi
  (`src/lib/arenaEloSync.ts`, `src/instrumentation-node.ts` dan ulangan).
- U **bloklamaydi va hech qachon halokatli xatolikka olib kelmaydi** — agar yuqori oqimdan
  yuklab olish muvaffaqiyatsiz bo'lsa, OmniRoute ishlashda davom etadi va reytinglar
  shunchaki oxirgi yaxshi ma'lumotlarni (yoki bo'sh holatni) ko'rsatadi.

Uni ikkita muhit o'zgaruvchisi boshqaradi
([`docs/reference/ENVIRONMENT.md`](../reference/ENVIRONMENT.md) faylida hujjatlashtirilgan):

| O'zgaruvchi               | Standart qiymat   | Maqsadi                                                        |
| ------------------------- | ----------------- | -------------------------------------------------------------- |
| `ARENA_ELO_SYNC_ENABLED`  | `true`            | Chiquvchi sinxronizatsiyadan voz kechish uchun `false` qiling. |
| `ARENA_ELO_SYNC_INTERVAL` | `86400` (24 soat) | Sinxronizatsiya intervali, soniyalarda.                        |

### Qo'lda sinxronizatsiya / holat / tozalash

Operatorlar uchun autentifikatsiyalangan boshqaruv endpointi qo'lda boshqaruvni ta'minlaydi
(`src/app/api/intelligence/sync/route.ts` — boshqaruv autentifikatsiyasini talab qiladi):

```
GET    /api/intelligence/sync          # joriy sinxronizatsiya holati (enabled, lastSync, nextSync, intervalMs)
POST   /api/intelligence/sync          # qo'lda sinxronizatsiyani ishga tushirish; yozmasdan oldindan ko'rish uchun tanasi: { "dryRun": true }
DELETE /api/intelligence/sync          # barcha sinxronizatsiya qilingan arena_elo intellekt yozuvlarini tozalash
```

Agar reytinglar sahifasi bo'sh bo'lsa, qo'lda `POST /api/intelligence/sync` (yoki shunchaki
serverni qayta ishga tushirish) uni qayta to'ldiradi.

### Modellarni reyting jadvaliga moslashtirish

Reyestrdagi model ID lari va Arena model nomlari har doim ham aniq mos kelmaydi. Reytinglash
egiluvchan moslashtirishdan foydalanadi (`src/lib/freeProviderRankings.ts` dagi
`findMatchingIntelligence`):

1. Normallashtirilgan model ID si bo'yicha aniq moslik.
2. Oxirgi versiya qo'shimchasini olib tashlagandan keyingi moslik (masalan, `kimi-k2.6` → `kimi-k2`).
3. Prefiks bo'yicha moslik (reyting jadvalidagi model nomi reyestr ID sinig prefiksi bo'lgan).

Sinxronizatsiya tomonida, ma'lum ishlab chiqaruvchi prefikslari (`anthropic/`, `openai/`,
`google/`, …) olib tashlanadi va kichik taxalluslar jadvali kanonik nomlarni OmniRoute
ichkarida ishlatadigan variantlarga kengaytiradi, shuning uchun modellar istalgan nom ostida
topilaveradi.

### Provayder qanday reytinglanadi

Har bir bepul provayder uchun mexanizm uning katalogidagi har bir modelni baholaydi, keyin:

- **Eng yaxshi model** = provayderning eng yuqori ballga ega modeli.
- **O'rtacha ball** = ushbu provayderning baholangan barcha modellari bo'yicha o'rtacha ball.
- **Modellar** = provayderning nechta modeli Arena balliga ega bo'lgani.

Provayderlar avval **eng yaxshi model balli** bo'yicha, keyin o'rtacha ball bo'yicha
saralanadi. Bu kamida bitta kuchli bepul model taqdim etgan provayderni rag'batlantiradi.

## Undan bepul provayderlarni tanlash uchun foydalanish

1. **Toʻgʻri toifani tanlang.** Agentli/kod yozish ish yuklamalari uchun **Coding** filtridan foydalaning yoki
   umumiy chat uchun uni **All Categories** / **Default** holatida qoldiring. Bir xil provayder
   turli toifalarda turlicha oʻrin egallashi mumkin, chunki uning eng yaxshi modeli har bir reyting jadvalida farq qiladi.
2. **Bir martalik sozlamalar uchun yetakchilarni afzal koʻring.** Agar faqat bitta yoki ikkita bepul
   provayderni ulamoqchi boʻlsangiz, toifangizdagi eng yuqori oʻrinni egallaganlardan boshlang.
3. **Type nishonini tekshiring.** `NOAUTH` provayderlarini ulash eng tezkor (hisob maʼlumotlari
   talab qilinmaydi). `OAUTH` / `APIKEY` bepul tariflari tezkor roʻyxatdan oʻtishni talab qiladi, ammo koʻpincha
   kuchliroq modellarni taqdim etadi. Ulanish bosqichlari uchun [Bepul tariflar qoʻllanmasi](../getting-started/FREE-TIERS-GUIDE.md)ga
   qarang.
4. **Bir nechtasini ulang va Auto-Combo tanlovni amalga oshirsin.** Ushbu sahifa asosidagi Arena ELO maʼlumotlari
   Auto-Combo baholash mexanizmining **vazifaga moslik omili**ni ham taʼminlaydi
   (`open-sse/services/autoCombo/taskFitness.ts`, aniqlash tartibi:
   `user_override → arena_elo → models_dev_tier → static table`). Shunday qilib, eng yaxshi bepul provayderlarni
   ulaganingizdan soʻng, `model: "auto"` (masalan, `auto/coding`) orqali marshrutlash
   har bir soʻrov uchun yuqoriroq sifatli bepul modellarni avtomatik ravishda afzal koʻradi. Toʻliq 16 omilli baholash uchun
   [Auto-Combo](../routing/AUTO-COMBO.md)ga qarang.
