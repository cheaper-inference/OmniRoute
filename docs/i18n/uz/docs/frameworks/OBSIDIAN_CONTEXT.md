## Bu nima

OmniRoute **Obsidian** omboriga **kontekst manbasi** sifatida ulanadi — bu agentlar
oʻrnatilgan MCP serveri orqali oʻqiydigan va yozadigan mahalliy Markdown bilimlar
bazasi. Integratsiya ish stoli ilovasi ichida ishlayotgan **Obsidian Local REST API**
hamjamiyat plaginiga murojaat qiladi, shu sababli agentlar qaydlarni qidirishi,
fayllarni oʻqishi/yozishi/oʻzgartirishi, ombor tarkibini koʻrishi, kundalik/haftalik
davriy qaydlar bilan ishlashi, teglarni boshqarishi, Obsidian buyruqlarini bajarishi
va (ixtiyoriy ravishda) ish stoli↔mobil qurilma oʻrtasidagi ikki yoʻnalishli ombor
sinxronlashuvini muvofiqlashtirishi mumkin.

Mijoz (`src/lib/obsidian/api.ts`) Local REST API'ni quyidagilar bilan oʻraydi:

- Vaqtinchalik `5xx` xatolari uchun **kechikishni oshirib qayta urinish**, `AbortController` orqali **30 soniyalik vaqt chegarasi**.
- **Turlangan xato tasnifi** — `ObsidianAuthError` (401/403),
  `ObsidianNotFoundError` (404), `ObsidianServerError` (5xx), `ObsidianTimeoutError`.
- Keng tarqalgan port xatosini (HTTP `27123` portida, `27124` portidagi MCP yakuniy nuqtasida **emas**) va Tailscale formatini koʻrsatib beradigan, tushunarli **«Obsidian bilan bogʻlanib boʻlmadi» tavsiyasi**.
- Boʻshliqlar/qiya chiziqlarga ega qayd yoʻllari xavfsiz boʻlishi uchun omborga nisbiy **yoʻl kodlanishi**.

## Sozlash

Obsidian tokeni yoki asosiy URL uchun **muhit o‘zgaruvchisi mavjud emas** — ikkalasi ham
`src/lib/db/obsidian.ts` orqali SQLite `key_value` jadvalida (`obsidian` nomlar makonida)
saqlanadi. Token **saqlangan holatda shifrlanadi** (AES-256-GCM, ochiq matn bilan orqaga
moslik zaxira mexanizmi mavjud). Endpoint boshqaruv panelidagi **Context Sources**
ichki oynasidan (`ObsidianSourceCard`) yoki sozlamalar REST API orqali sozlang.

> [!IMPORTANT]
> **Obsidian Local REST API** plagini o‘rnatilgan va ishlab turgan bo‘lishi kerak. Uning
> REST interfeysi **HTTP `127.0.0.1:27123`** manzilida tinglaydi (standart asosiy URL).
> `27124` porti _alohida_ MCP/HTTPS endpoint bo‘lib, sozlamalar marshruti tomonidan
> aniq rad etiladi. Boshqa qurilmadan ulanish uchun `http://<tailscale-ip>:27123`
> manzilidan foydalaning.

### Konfiguratsiya kalitlari (SQLite `key_value`, `obsidian` nomlar makoni)

| Kalit             | Maqsad                                                      | Shifrlangan |
| ----------------- | ----------------------------------------------------------- | ----------- |
| `api_key`         | Local REST API bearer tokeni                                | ha          |
| `base_url`        | REST asosiy URL manzili (standart `http://127.0.0.1:27123`) | yo‘q        |
| `vault_path`      | Vault katalogiga mutlaq yo‘l (sinxronlash uchun)            | yo‘q        |
| `webdav_username` | Yaratilgan WebDAV foydalanuvchi nomi (vault sinxronlashi)   | yo‘q        |
| `webdav_password` | Yaratilgan WebDAV paroli (vault sinxronlashi)               | ha          |
| `webdav_enabled`  | WebDAV vault sinxronlashi yoqilganligi                      | yo‘q        |

### REST orqali sozlash

```bash
# Local REST API tokenini saqlash va tekshirish (POST holatni tekshirish orqali tasdiqlaydi)
curl -X POST http://localhost:20128/api/settings/obsidian \
  -H "Content-Type: application/json" \
  -d '{"token":"<obsidian-rest-api-key>","baseUrl":"http://127.0.0.1:27123"}'

# Ulanish holatini tekshirish (connected, hasToken, baseUrl, vaultPath qiymatlarini qaytaradi)
curl http://localhost:20128/api/settings/obsidian

# Ulanishni uzish (saqlangan tokenni tozalaydi)
curl -X DELETE http://localhost:20128/api/settings/obsidian
```

Barcha metodlar boshqaruv paneli autentifikatsiyasini talab qiladi. `POST` `27124`
portidagi har qanday URL manzilini rad etadi va saqlashdan oldin Local REST API holat
endpointini chaqirish orqali tokenni tekshiradi.

### WebDAV vault sinxronlashi

`src/app/api/settings/obsidian/webdav/route.ts` ixtiyoriy WebDAV asosidagi vault
sinxronlashini boshqaradi (`src/lib/obsidianSync.ts` orqali ishlaydi). Uni yoqish
OmniRoute’ni mahalliy vault katalogiga yo‘naltiradi va tasodifiy WebDAV foydalanuvchi
nomi/paroli juftligini yaratadi:

```bash
# Vault katalogi uchun WebDAV sinxronlashini yoqish (foydalanuvchi nomi/parolini yaratadi)
curl -X POST http://localhost:20128/api/settings/obsidian/webdav \
  -H "Content-Type: application/json" \
  -d '{"vaultPath":"/home/me/MyVault"}'

# WebDAV sinxronlash holatini olish (hisob ma’lumotlari faqat yoqilganida qaytariladi)
curl http://localhost:20128/api/settings/obsidian/webdav

# WebDAV sinxronlashini o‘chirish (hisob ma’lumotlari va boshqariladigan .stignore faylini tozalaydi)
curl -X DELETE http://localhost:20128/api/settings/obsidian/webdav
```

### Har bir API kaliti uchun kontekst manbasi (ixtiyoriy)

Obsidian konfiguratsiyasining amal qilish doirasi `api_key_context_sources` jadvali
(`src/lib/db/apiKeyContextSources.ts`) orqali **har bir API kaliti uchun** alohida
belgilanishi mumkin. MCP chaqiruvi autentifikatsiya qilingan API kaliti identifikatorini
o‘z ichiga olsa, `getObsidianConfigForApiKey()` shu kalitning o‘z tokeni/asosiy
URL/vault yo‘lini (`source: "api_key"`) afzal ko‘radi, aks holda global konfiguratsiyaga
(`source: "global"`) qaytadi.

Sinxronlashga aloqador bo‘lmagan MCP vositalari ushbu konfiguratsiyani o‘qishdan oldin
chaqiruvchining aniqlangan identifikatorini talab qiladi. Identifikatorsiz chaqiruvchi
`Obsidian API token not configured` xabarini oladi va vault so‘rovi yuborilmaydi. HTTP
chaqiruvchilari o‘z so‘rov hisob ma’lumotlari orqali aniqlanadi; stdio chaqiruvchilari
`OMNIROUTE_API_KEY` yoki `ROUTER_API_KEY` orqali aniqlanishi mumkin. Aniqlanmagan HTTP
chaqiruvchisi serverning muhit identifikatorini meros qilib ololmaydi. Faqat to‘ldiruvchi
identifikatorlarning o‘zi kirishga ruxsat bermaydi; `env-key` sifatida aniqlanadigan
yaroqli muhit hisob ma’lumoti qo‘llab-quvvatlanishda davom etadi. Har bir kalit uchun
Obsidian konfiguratsiyasi bo‘lmagan autentifikatsiya qilingan kalitlar global zaxira
konfiguratsiyasidan foydalanishda davom etadi. To‘rtta `obsidian_sync_*` vositasi
o‘zining alohida sinxronlash tokeni xatti-harakatini saqlab qoladi.

## MCP vositalari (22)

`open-sse/mcp-server/tools/obsidianTools.ts` faylida belgilangan. Token/asosiy URL har bir chaqiruv uchun aniqlanadi (avval API kalitiga xos, keyin global). OmniRoute **sinxronlash serveri**ga murojaat qiladigan vositalar (toʻrtta `obsidian_sync_*` vositasi) qoʻshimcha ravishda OmniRoute sozlamalarida konfiguratsiya qilingan sinxronlash autentifikatsiya tokenini talab qiladi.

### Oʻqish vositalari (`read:obsidian`)

| Vosita                       | Tavsif                                                                                                             |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `obsidian_check_status`      | Local REST API bilan bogʻlanish va autentifikatsiya holatini tekshiradi.                                           |
| `obsidian_search_simple`     | Qaydlar mazmuni boʻylab toʻliq matnli qidiruv; fayl yoʻllari bilan parchalarni qaytaradi.                          |
| `obsidian_search_structured` | JSON Logic ifodasi (and/or/regex/path filtrlari) yordamida qidiradi.                                               |
| `obsidian_read_note`         | Omborga nisbatan yoʻl orqali qaydni oʻqiydi; ixtiyoriy ravishda muayyan sarlavha/blok/frontmatter qismini oʻqiydi. |
| `obsidian_list_vault`        | Ombordagi fayllar va kataloglarni roʻyxatlaydi (elementlar daraxti).                                               |
| `obsidian_get_document_map`  | Qaydning sarlavhalar tuzilmasini sarlavhalar → qator raqamlari xaritasi sifatida oladi.                            |
| `obsidian_get_note_metadata` | Toʻliq mazmunsiz frontmatter, teglar, havolalar, belgilar/soʻzlar sonini oladi.                                    |
| `obsidian_get_active_file`   | Obsidianʼda hozirda faol boʻlgan faylning yoʻli va mazmunini oladi.                                                |
| `obsidian_get_periodic_note` | Sana uchun kunlik/haftalik/oylik davriy qaydni oladi (koʻrsatilmasa, bugungi sana).                                |
| `obsidian_get_tags`          | Ombordagi barcha teglarni ularning takrorlanish soni bilan roʻyxatlaydi.                                           |
| `obsidian_list_commands`     | Mavjud Obsidian buyruq IDʼlarini roʻyxatlaydi (`obsidian_execute_command` bilan ishlatish uchun).                  |
| `obsidian_sync_status`       | OmniRoute sinxronlash serveri holati: ishlashi, ombor nomi, port, ishlash vaqti, oxirgi sinxronlash.               |
| `obsidian_sync_conflicts`    | Hal qilinmagan sinxronlash ziddiyatlarini roʻyxatlaydi (yoʻl, ziddiyat yoʻli, aniqlangan vaqt).                    |

### Yozish vositalari (`write:obsidian`)

| Vosita                           | Tavsif                                                                                                          |
| -------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `obsidian_write_note`            | Berilgan Markdown mazmuni bilan qayd yaratadi yoki mavjud qayd ustiga yozadi.                                   |
| `obsidian_append_note`           | Qaydga mazmun qoʻshadi; ixtiyoriy ravishda muayyan sarlavha/blokka.                                             |
| `obsidian_patch_note`            | Sarlavha, blok yoki frontmatter maydoniga aniq tarzda qoʻshadi/boshiga qoʻshadi/almashtiradi.                   |
| `obsidian_delete_note`           | Qaydni ombordan butunlay oʻchiradi.                                                                             |
| `obsidian_move_note`             | Qaydni ombor ichida koʻchiradi yoki nomini oʻzgartiradi.                                                        |
| `obsidian_execute_command`       | Obsidian buyrugʻini uning buyruq IDʼsi orqali bajaradi.                                                         |
| `obsidian_open_file`             | Faylni Obsidianʼda ochadi (agar mavjud boʻlmasa, uni yaratadi).                                                 |
| `obsidian_sync_trigger`          | Darhol ikki yoʻnalishli ish stoli↔mobil ombor sinxronlashini ishga tushiradi.                                   |
| `obsidian_sync_resolve_conflict` | Sinxronlash ziddiyatini hal qiladi: `local` (mobil), `remote` (ish stoli) yoki `keep-both` variantini saqlaydi. |

> [!NOTE]
> `obsidian_patch_note` maqsadlari `heading | block | frontmatter` qiymatli `targetType`
> va `append | prepend | replace` qiymatli `operation` parametrlarini, shuningdek,
> ixtiyoriy `createTargetIfMissing` parametrini qabul qiladi. Toʻrtta `obsidian_sync_*`
> vositasi mahalliy sinxronlash serveri bilan (`http://127.0.0.1:27781` standart holatda)
> aloqa qiladi va sinxronlash tokenini talab qiladi.

### Ruxsat doiralari

Oʻqish vositalari `read:obsidian`, yozish vositalari esa `write:obsidian` ruxsatini talab qiladi. Majburiy tekshiruv Notion bilan bir xil — `open-sse/mcp-server/server.ts` faylidagi `withScopeEnforcement()` orqali amalga oshiriladi, `OMNIROUTE_MCP_ENFORCE_SCOPES=true` bilan faollashtiriladi va ruxsat etilgan doiralar `OMNIROUTE_MCP_SCOPES` yoki API kalitining doira kontekstidan olinadi. [MCP-SERVER.md](./MCP-SERVER.md) fayliga qarang.

## Endpointlar

| Metod    | Yoʻl                            | Maqsad                                                             |
| -------- | ------------------------------- | ------------------------------------------------------------------ |
| `GET`    | `/api/settings/obsidian`        | `{ connected, hasToken, baseUrl, vaultPath }` ni qaytaradi.        |
| `POST`   | `/api/settings/obsidian`        | Tokenni saqlaydi va tekshiradi (`27124` portini rad etadi).        |
| `DELETE` | `/api/settings/obsidian`        | Ulanishni uzadi (saqlangan tokenni oʻchiradi).                     |

> ommaviy `/v1` Obsidian proksi endpointi mavjud emas.

## Foydalanish holatlari

- **Vault maʼlumotlariga asoslangan javoblar** — avval `obsidian_search_simple` / `obsidian_search_structured`,
  soʻng `obsidian_read_note`; shu tariqa agent haqiqiy qaydlaringiz asosida javob beradi.
- **Qayd yozish / kundalik yuritish** — agent natijalari, xulosalar yoki kundalik qaydlarni
  (`obsidian_get_periodic_note`) vaultga yozish uchun `obsidian_write_note`, `obsidian_append_note`
  yoki aniq tahrirlash imkonini beruvchi `obsidian_patch_note` dan foydalaning.
- **Vault boʻylab harakatlanish** — oʻqish/yozishdan oldin tuzilmani oʻrganish uchun
  `obsidian_list_vault`, `obsidian_get_document_map` va `obsidian_get_tags` dan foydalaning.
- **Obsidian avtomatlashtirish** — agent orqali plaginlar/buyruqlarni boshqarish uchun
  `obsidian_list_commands` + `obsidian_execute_command`; qaydni UI’da koʻrsatish uchun
  `obsidian_open_file` dan foydalaning.
- **Mobil sinxronlash** — WebDAV sinxronlashni yoqing, soʻng kompyuter↔mobil qurilma
  oʻrtasidagi sinxronlashni muvofiqlashtirish va ziddiyatlarni hal qilish uchun
  `obsidian_sync_trigger` / `obsidian_sync_status` / `obsidian_sync_conflicts` /
  `obsidian_sync_resolve_conflict` dan foydalaning.
