## Umumiy ko‘rinish

Barcha OmniRoute boshqaruv API marshrutlari uchta himoya darajasidan biriga tasniflanadi. Tasnif statik bo‘lib, `src/server/authz/routeGuard.ts` faylida belgilangan va boshqa autentifikatsiya tarmoqlaridan oldin tekshiriladi.

## Darajalar

### 1-darajali — LOCAL_ONLY

**Muallif:** `isLocalOnlyPath(path)` → loopback xostni tekshirish** Aylanib o'tish:** Sukut bo'yicha yo'q. Soʻrov `manage` koʻlami bilan yaroqli API kalitiga ega boʻlsa, `LOCAL_ONLY_MANAGE_SCOPE_BYPASS_PREFIXES` yoʻllar uchun tor kesma (qarang [: Qoʻllash doirasini kesish](#manage-scope-carve-out) ).

Ushbu marshrutlar bola jarayonlarini ishlab chiqaradi yoki ish vaqti kodini bajaradi. Ularni orqaga qaytarilmaydigan trafikga ta'sir qilish joriy JWT (masalan, Cloudflared/Ngrok tunnel orqali) olgan tajovuzkorga ma'lum CVE sinfida ( [GHSA-fhh6-4qxv-rpqj](https://github.com/advisories/GHSA-fhh6-4qxv-rpqj) ) — ishlab chiqarish jarayonini ishga tushirish imkonini beradi.

**GHSA-fhh6-4qxv-rpqj nima (hujum sinfi):** management/agent serveri pastki jarayonni (`npm install`, `node`, brauzer, proksi-server, `git`, `tar`, …) ishga tushiradigan so'nggi nuqtani ko'rsatadi. Agar operator OmniRoute nginx/Cloudflare/Tailscale tunnel orqasiga qo‘ygani va JWT sizib ketgani yoki auth noto‘g‘ri sozlangan — bo‘lsa, tajovuzkor “ API ga qo‘ng‘iroq qilish” ni “hostda buyruqni ishga tushirish” ga aylantiradi (masofadan — bajarish). OmniRoute buni a ni majburlash orqali yopadi** har qanday autentlik tekshiruvidan oldin, so'zsiz, loopback host tekshiruvi** , har bir yumurtlamaga qodir marshrutda: tunnel orqali sizib ketgan token hali ham urug'ga etib bora olmaydi.

**To'liq LOCAL_ONLY to'plami.** Vakolatli manba `LOCAL_ONLY_API_PREFIXES` da `src/server/authz/routeGuard.ts`/ `LOCAL_ONLY_API_PATTERNS` ; Quyidagi jadval joriy holatni aks ettiradi. `check-route-guard-membership` darvozasi har bir `route.ts` ishlab chiqarish qobiliyatiga ega bo'lgan prefikslar ostida sanab beradi va agar birontasi faqat mahalliy uchun tasniflanmagan bo'lsa, CI bajarilmaydi.

**Qoidabuzarlik uchun javob:** `403 LOCAL_ONLY`

#### Boshqarish-ko'lamini kesish

LOCAL_ONLY yo'llarining kichik to'plamiga MAY dan ham qayta-qayta bo'lmagandan kirish mumkin, agar so'rov metama'lumotlari `manage` doirasini (yoki `admin`) o'z ichiga olgan `Authorization: Bearer <api-key>` o'z ichiga olgan bo'lsa. Chiqib ketish `LOCAL_ONLY_MANAGE_SCOPE_BYPASS_PREFIXES` orqali har bir yo'l bo'ylab ochiladi, shuning uchun har qanday yangi LOCAL_ONLY yo'li uchun sukut bo'yicha qat'iy orqaga qaytish bo'lib qoladi. Tasdiqlanmagan so'rovlar va boshqarilmaydigan kalitlarga ega so'rovlar hali ham `403 LOCAL_ONLY` bilan rad etiladi.

Bugungi kunda chetlab o'tiladigan yagona prefiks - `/api/mcp/`. `/api/cli-tools/runtime/` va `/api/services/` ataylab chiqarib tashlanadi, chunki ular ixtiyoriy quyi jarayonlarni (`npm install`, `node`) yaratishi mumkin, bu LOCAL_ONLY darajasining oldini olish uchun mavjud bo'lgan aniq CVE sinfidir.

**#7895 — `mcp:connect` tor doirada:** `/api/mcp/` o'yib chiqarish ALSO tor `mcp:connect` ko'lamini (`src/shared/constants/managementScopes.ts::MCP_CONNECT_SCOPE`) ushlab turgan Bearer kalitini qabul qiladi, `src/server/authz/policies/management.ts` ichida `hasMcpConnectOrManageScope()` orqali tekshiriladi. Bu `/api/mcp/` ONLY — `mcp:connect` boshqa boshqaruv marshrutida (jumladan, har qanday boshqa LOCAL_ONLY aylanib o‘tish prefiksi ham qo‘shilishi kerak) hech narsa bermaydi va u ataylab `MANAGEMENT_API_KEY_SCOPES` dan chiqarib tashlanadi. `manage`/`admin` tugmachasini ushlab turgan kalit hali ham avvalgidek o'yib chiqib ketadi; `mcp:connect` keng boshqaruvga kirishga muhtoj bo'lmagan masofaviy MCP qo'ng'iroq qiluvchilar uchun past imtiyozli muqobildir.

| So'rov                                                    | Yo'l                       | Natija                         |
| --------------------------------------------------------- | -------------------------- | ------------------------------ |
| Orqaga qaytmaydigan, tashuvchi yo'q                       | `/api/mcp/*`               | 403 LOCAL_ONLY                 |
| Loopback bo'lmagan, `manage` doirasi bilan tashuvchi      | `/api/mcp/*`               | Ruxsat bering                  |
| Loopback bo'lmagan, `mcp:connect` doirasi bilan tashuvchi | `/api/mcp/*`               | Ruxsat bering                  |
| Loopback bo'lmagan, `manage`/`mcp:connect` tashuvchi      | `/api/mcp/*`               | 403 LOCAL_ONLY                 |
| Loopback bo'lmagan, `mcp:connect` doirasi bilan tashuvchi | `/api/cli-tools/runtime/*` | 403 LOCAL_ONLY                 |
| Loopback bo'lmagan, `manage` doirasi bilan tashuvchi      | `/api/cli-tools/runtime/*` | 403 LOCAL_ONLY                 |
| Loopback, any/no Bearer                                   | har qanday LOCAL_ONLY      | Ruxsat bering (darvoza o'tadi) |

#### Operatorga rahbarlik va audit

Agar siz OmniRoute teskari proksi-server yoki tunnel (nginx, Caddy, Cloudflare Tunnel, Tailscale, Ngrok) orqasida ishga tushirsangiz, orqaga qaytish tekshiruvi hali ham — yuqori bo'lgan spawn-qobiliyatli marshrutlarni himoya qiladi, mijoz manzili orqaga qaytish bo'lmagan so'rov `403 LOCAL_ONLY` bilan rad etiladi.** auth ishga tushirishdan oldin** , shuning uchun sizib chiqqan JWT spawnga erisha olmaydi. Operatorning ikkita mas'uliyati qoladi:

- **Mijoz IP loopback sifatida soxtalashtirish orqali 403-ni "tuzatmang".** `X-Forwarded-For: 127.0.0.1` yoki manba manzilini orqaga qaytarish uchun qayta yozadigan proksi-serverni o'rnatish ushbu bosqich yopilgan RCE sinfini qayta ochadi. Proksi-server orqali dashboard/API oching — hech qachon spawn-qobiliyatli marshrutlarni.
- **Boshqaruv doirasini aylanib o'tishni minimal saqlang.** Faqat `/api/mcp/` chetlab o'tish mumkin va faqat `manage` -scoped API kaliti bilan. `SPAWN_CAPABLE_PREFIXES` hech qachon chetlab o'tish ro'yxatiga qo'shilmaydi — zod sxemasi ularni rad etadi va `isLocalOnlyBypassableByManageScope` ularni ish vaqtida rad etadi (chuqur himoya), ya'ni asboblar paneli "aylanib o'tish mumkin emas" degan ma'noni anglatadi. Xuddi shu rad etish ro'yxatida bir nechta LOCAL_ONLY marshrutlari ham mavjud bo'lib, ular paydo bo'lmaydi, lekin hech qachon — `/api/oauth/kiro/auto-import` (xost-mahalliy Kiro hisob ma'lumotlari fayllarini o'qiydi), `/api/discovery/` va `/api/issue-agent/` masofadan etib bo'lmasligi kerak. Ish vaqti snapshot yuklagichi ham saqlangan sozlamalar qatoridan bunday yozuvlarni tushiradi va eski JSON import (`/api/settings/import-json`) hech qachon aylanib o'tish tugmachalarini yozmaydi. Har bir `LOCAL_ONLY_API_PREFIXES` yozuvi rad etish roʻyxatida boʻlishi yoki chetlab oʻtish huquqiga ega (`tests/unit/authz/local-only-bypass-spawn-denylist.test.ts`) sifatida koʻrib chiqilishi kerak. `/api/providers/` (masalan, `/login`, `/refresh-cursor`) ostida dinamik-segmentli va statik-yo'l hosil qilish qobiliyatiga ega marshrutlar yassi `SPAWN_CAPABLE_PREFIXES` massivi — bilan emas, balki `src/shared/constants/spawnCapablePrefixes.ts` da regexga asoslangan `SPAWN_CAPABLE_PATTERNS` / `SPAWN_CAPABLE_PATTERN_ANCESTORS` hamroh tomonidan qoplanadi. asboblar paneli `/api/providers/` provayderi uchun qonuniy ravishda foydalanadi CRUD

**Auditga kirish** Xostdan tashqarida hech narsa bu yo‘nalishlarga etib bormasligini tekshirish uchun — :

- ni oching** Avtorizatsiya inventarizatsiyasi** `/dashboard/settings/security` bo'yicha: u jonli LOCAL_ONLY prefikslar ro'yxatini ko'rsatadi, qaysi prefikslar chetlab o'tilishi mumkin va kompilyatsiya vaqtining paydo bo'lishi ("aylanib o'tish mumkin emas") to'plami.
- Yuqoridagi prefikslar uchun teskari proksi/kirish jurnallarini o'rnating. `403 LOCAL_ONLY` o'rniga `200` qaytarilgan har qanday bunday zarba proksi-server haqiqiy mijozni maskalashini bildiradi IP — proksi-serverni tuzatish.
- Ushbu yo'llardan biri uchun OmniRoute jurnallaridagi `403 LOCAL_ONLY` qo'riqchi mo'ljallangan tarzda ishlaydi, bostirish uchun xato emas.

#### Qo'ng'iroq qilish joyini tekshirish eshigi bilan masofadan borish mumkin bo'lgan marshrutlar

Ba'zi marshrutlarga masofaviy boshqaruv panelidan kirish mumkin bo'lib qolishi kerak, lekin mahalliy qo'ng'iroq qiluvchilar uchun xost tomoni tekshiruvini (`which <binary>`, `<binary> --version`, `tailscale status --json`) ishlatishi kerak. Ular `GET` uchun LOCAL_ONLY emas; Buning o'rniga ishlov beruvchi `getRequestPeerLocality()` (`src/shared/utils/apiAuth.ts`) bilan ishonchli tengdoshlar hukmini o'qiydi va faqat `loopback` / `lan` qo'ng'iroq qiluvchilar uchun tekshiruvni boshqaradi. `remote` qo'ng'irog'i tug'ilmaydigan manbalardan (doimiy holat, sozlamalar, fs tekshiruvlari) tuzilgan bir xil javob shaklini oladi, `probed: false` belgisi bilan belgilanadi.

| Marshrut                                                           | Masofaviy qo'ng'iroq qiluvchilar uchun tekshiruv o'tkazib yuborildi       |
| ------------------------------------------------------------------ | ------------------------------------------------------------------------- |
| `POST /api/providers/{id}/test`, `/api/providers/test-batch`       | CLI ish vaqti tekshiruvi (`allowLocalRuntimeProbe`) va CLI-fallback spawn |
| `GET /api/headroom/status`                                         | `which headroom` va python `--version` problari                           |
| `GET /api/tunnels/tailscale`, `GET /api/tunnels/tailscale/check`   | `which tailscale`, `tailscale status/funnel --json`, `which brew`         |
| `GET /api/tunnels/cloudflared` (GET- LOCAL_ONLY dan ozod qilingan) | `which cloudflared` PATH qidiruvi                                         |

Xostni tekshiradigan yangi o'qish marshruti bir xil sxema bo'yicha ishlaydi yoki to'g'ridan-to'g'ri LOCAL_ONLY tasniflanadi.

#### Hisob ma'lumotlarini eksport qilish va tiklash faqat operator tomonidan amalga oshiriladi

Yuqoridagi daraja faqat _ba'zi_ hisob ma'lumotlari talab qilinadimi yoki yo'qligini hal qiladi. Saqlangan hisob ma'lumotlarini yuklab oladigan marshrutlar ishlov beruvchida ikkinchi tekshiruvni qo'shadi: `GET /api/settings/export-json` (shifrlangan provayder ulanishlari va xom API kalitlari), `GET /api/db-backups/export` ( SQLite fayli) va `GET /api/db-backups/exportAll` (to'liq arxiv) `requireOperatorCredential()` (`src/lib/api/operatorCredential.ts`) chaqiruvi. U asboblar paneli seansini, mahalliy CLI mavzusini yoki login o‘chirilgan misolni qabul qiladi va har qanday hajmdagi API tugmachalariga (jumladan `manage` va `admin`) va `oma_` kirish tokenlariga `403` javob beradi. Buzg'unchi o'xshashlar bir xil chegaraga ega: `POST /api/db-backups/import` (yuklangan `.sqlite`, `dryRun=true` kiritilgan), `POST /api/db-backups` (id bo'yicha saqlangan zaxira nusxasini tiklash) va `POST /api/settings/import-json` (eski JSON tiklash) jonli ma'lumotlar bazasini yoki butun settings/connections/API-key to'plamini almashtiradi, shuning uchun mashina hisob ma'lumotlari ham ularni ishga tushira olmaydi. Qayta tiklash nuqtalarini yo'q qilish bir xil chegarani o'z ichiga oladi: `DELETE /api/db-backups` (tozalash — oxirgi N / tomchi D kundan eskiroq saqlash) va `PATCH /api/db-backups` (saqlash sozlamalari), chunki doimiy saqlash `cleanupDbBackups()` har bir avtomatik zaxiralashdan (`src/lib/db/backup.ts`) keyin qo'llaniladigan narsadir, shuning uchun `keepLatest: 1` saqlashi mumkin bo'lgan mashina hisob ma'lumotlari keyingi soniyalarda hamma narsani kesib tashlaydi. Listing va zaxira nusxalarini yaratish (`GET`/`PUT /api/db-backups`) oddiy boshqaruv authini saqlaydi. Sinxronlash tokenini chiqarish (`POST /api/sync/tokens`) bir xil yordamchidan, shuningdek, ishonchli ichki xizmat tokenidan foydalanadi.

### Yangi o'rnatilgan bootstrap `Host` emas, balki haqiqiy tengdoshlar tomonidan faqat orqaga qaytariladigan — hisoblanadi.

Boshqaruv paroli sozlanmagan (va `INITIAL_PASSWORD` yo'q), `src/shared/utils/apiAuth.ts` -dagi `isAuthRequired()` anonim yuklash blokini ochiq saqlaydi.** faqat loopback tengdoshlari uchun** . Orqaga qaytish ishonchli tengdosh signallari asosida belgilanadi: token muhrlangan haqiqiy TCP tengdoshi (`PEER_IP_HEADER` + `VIA_PROXY_HEADER`, siyosat nimani ko'radi), quvur liniyasining o'z `AUTHZ_HEADER_PEER_LOCALITY` qarori (marshrutni qayta ishlovchilar nimani ko'radi, faqat `OMNIROUTE_PEER_STAMP_TOKEN` o'rnatilganda ishonchli) yoki to'g'ridan-to'g'ri qo'ng'iroq qiluvchilar uchun haqiqiy soket tengdoshi. `Host` / `nextUrl.hostname` hech qachon maslahat qilinmaydi va birinchi parolni yozish (`POST /api/settings/require-login`) har bir tarmoq tengdoshi (GHSA-7pq4-8pvv-rx7r) uchun ochiq emas, balki bir xil cheklov ostida. `managementPolicy` o'zining `peerContext` hukmini aniq qabul qiladi, shuning uchun ORIGINAL (oldindan chiziq) so'rovining sarlavhalari buni hech qachon hal qilmaydi.

### 3-darajali — MANAGEMENT (standart)

Boshqa barcha boshqaruv yo'llari. Agar `requireLogin=false` sozlanmasa, autentifikatsiya talab qilinadi. CLI tokenlari ushbu marshrutlarni autentifikatsiya qilishi mumkin (loopback + valid HMAC).

## Baholash tartibi

```
managementPolicy.evaluate(ctx)
  1. isLocalOnlyPath(path)?
     → loopback                                  → keyingi bosqichga oʻtish
     → loopback emas, manage-scope doirasidagi Bearer
        VA isLocalOnlyBypassableByManageScope    → ruxsat berish (management_key)
     → aks holda                                 → rad etish 403 LOCAL_ONLY
  2. isInternalModelSyncRequest(ctx)?
     → ruxsat berish (system)
  3. hasValidCliToken(headers)?
     → ruxsat berish (cli) [loopback + timingSafeEqual HMAC tekshiruvi]
  4. isAlwaysProtectedPath(path) yoki requireLogin=true?
     → isDashboardSessionAuthenticated?
        → ruxsat berish (dashboard_session)
     → chetlab oʻtib boʻlmaydigan yoʻldagi manage-scope doirasidagi Bearer?
        → ruxsat berish (management_key)
     → rad etish 401/403
  5. requireLogin=false?
     → ruxsat berish (anonymous)
```

1-bosqichdagi manage-scope tarmogʻi LOCAL_ONLY marshrutini qanoatlantira oladigan yagona autentifikatsiyalangan yoʻldir; autentifikatsiya bekendi nosozligi holatida 503 qaytariladi (403 emas), shuning uchun amal qilish muddati tugagan DB sezdirmasdan «rad etish» holatiga tushib qolmaydi.
